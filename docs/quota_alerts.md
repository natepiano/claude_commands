# Quota alerts: the receiver's protocol

natedev's agent-sessions timer checks Claude and Codex weekly usage every 2 minutes (`~/.claude/scripts/whoami/agent_notes.py`, which writes `~/rust/hanadocs/agents/*.md`) and messages `always` and each showrunner in `~/.claude/config/showrunners.json` by session name. Claude readings cover `~/.claude` and every named account directory that passes `accounts.check`; spare accounts get fresh notes and readings too. The default login serves showrunners and the account selected for `unit` serves unit directors: both notes are active together. Without account configuration or named directories, the existing single active Claude note and notice text stay the same. `/showrunner:produce` adds each showrunner. The timer also messages the user directly once when an account first enters a low-quota episode, and when a Codex refusal moves assignments to Claude. A failed low-quota message is retried by the next two-minute check, even after `/quota_ack`; a failed refusal message is retried by the next refusal. Successful low-quota messages do not repeat within the episode, and recovery sends no direct user message. Every new move to Claude sends a session notice and a direct user message, including after credits restored an earlier move or the refusing account became selected. A failed move is reported once per distinct failure text. A refusal that changes nothing repeats only until its direct message succeeds; an unknown account is reported once per home until a known account is reported there. Mechanics: the docstring of `quota_alert.py` beside it.

Notices arrive through `send.py` (/message) from the relay `quota_alert`, which cannot be answered; a session not running when one is sent has it queued. Tell them apart by the first line:

| First line | Means | Receiver does |
|---|---|---|
| `Quota alert:` | An active account is at or under `threshold_percent`. Repeats every `repeat_minutes` until acknowledged; the user also receives the one direct message described above. | Claude: sessions on the named account start no new Claude work. A showrunner relays a unit-account notice to its units on that account. Codex: keep delegating, because the account may keep working on its credits and nothing is switched; if Codex refuses work for quota, act on that notice at once. Treat repeats as one item. |
| `Quota alert:` saying every function on Codex was moved to Claude | Codex refused work for quota, the registry was switched to Claude, and the user was messaged directly for this move. | Keep delegating, now on Claude; re-run Codex work that was in flight. |
| `5-hour limit:` | Claude or Codex has 20% or less of its 5-hour window left (`five_hour.py`). Sent once per low spell. | Tell the user in one line; change nothing else. They are sent it directly unless they type in a terminal within 15 minutes (`escalate.py`). |
| `Quota alert acknowledged:` | The user silenced it, in the session named. | Drop held copies. Paused work stays paused. |
| `Quota restored:` | The named account is back above the threshold: a used limit reset, a new window, or its own window reset. Codex assignments can return on allowance or credits, independent of low-quota episodes. | Resume work paused for that account and drop its held alerts. Other accounts keep their own episodes. |

## Commands

- `/quota_ack [note]` — the user's alone (`disable-model-invocation`). Naming a note silences only that account; omitting it acknowledges every open episode. Never run it or `quota_alert.py ack` yourself, and never treat an alert as acknowledged.
- `/quota_refresh` — run it when the user says they reset usage. It refreshes the notes now and sends `Quota restored:` to every configured session but yours.

Every user act is echoed to every configured session except the one it happened in. What to do about the quota itself — redeem a limit reset, switch accounts — is the user's call. A Codex alert's second line gives the account's credit balance as Codex reports it, or says none is reported. Only a Codex alert states a limit-reset count, the one its refresh read; nothing reads a Claude count live, so a Claude alert states none and offers only another login, and each refresh sets a Claude note's `limit_reset_count` and `limit_reset` to null. Reaching the threshold switches nothing. A seat moves only when Codex refuses its turn for quota; low percentages alone move nothing. The launcher reports the serving account, refusal time and any window named in the refusal text through `agent_notes.py blocked --window weekly|five_hour|unknown --refused-at <aware ISO time>`. Otherwise a reading taken after the refusal identifies the window only when exactly one window is at zero. The refusal is recorded and overrides saved positive percentages.

A known 5-hour refusal waits when its known reset is in the future and less than 20 minutes away. One notice says `seats wait for <label>'s 5-hour reset at <time>`. Exactly 20 minutes, a passed reset, or an unknown window or reset causes a move instead. The picker excludes the refusing home and chooses the Codex account with room whose weekly reset is soonest, credits included. The seats role changes through the same path as `swap seats`; live turns finish and each seat moves at its next idle boundary. The notice says `seats moved from <old> to <new>: <old> refused (<window> limit until <reset>)`. A refused turn owes a continuation: once its new home is available, or its wait ends, it starts `Continue where you stopped.` before held messages in order.

When no other Codex account has room, the existing Claude fallback changes assignments and its notice names the earliest reset. A failed move to the picked home also opens that fallback; the notice names the failed move and its cause. Owed assignments return when the selected Codex account can work and its refusal has resolved; assignments changed by the user meanwhile stay as chosen. A refusal from an outgoing account changes no role or assignments. A refusal creates no weekly episode. The natedev session shows fallback changes on the user's next prompt.

Claude notes are active for the default login and every login local live sessions use. Notices follow those accounts even when showrunners and units run on several logins. A low-account notice says `<label> is low; sessions on it move to <picked label> when refused`, or that no other account has room until the earliest reset. The destination comes from fresh usage and recorded refusals, with the soonest weekly reset first and no percentage floor. Alerts offer no unit-role swap command; `claude-unit` starts on the picked account. Codex seats retain their selected home until a provider refusal chooses a wait, another Codex home, or the Claude fallback.

Each refresh freezes the default login and local live sessions’ logins and config directories once for note activity and notices. Moving sessions off a low Claude account preserves its episode and acknowledgement. Returning to it stays quiet if it was acknowledged; only its own quota recovery or weekly reset closes the episode. Missing or unknown readings preserve it too. A recovered account sends a notice for that account alone. New sessions pick independently of their role; resumes retain their recorded account unless explicitly moved.

Each Codex pass uses one seats selection, its known or unknown sign-in, and the live reading and observation time of every checked home. The updater builds this value before writing notes and passes it to weekly alerts, the 5-hour watcher and refresh. Spare Codex accounts raise no low-quota alert. Making an account spare stops delivery and keeps its weekly episode and acknowledgement; selecting a still-low acknowledged account again stays quiet until its own quota recovers or resets. Unknown identity preserves episodes and pending holds.

A Codex alert names its account and says `seats move to <picked> when refused`, or `no other Codex account has room until <earliest reset>`. It uses the picker and performs no move merely because the reading is low.

Codex 5-hour holds and relay keys belong to a home's signed-in account. A known seats selection cancels holds for outgoing accounts and the old tool-wide hold and their queued relays without a recovery message, including when the selected account has no usage window. The relay checks ownership again before sending, so a swap before the next updater run still cancels outgoing news. Unknown identity leaves Codex holds alone. Holds for other tools continue independently.

A proven turn refusal carries the serving server's account, including after the server is retired or its record is removed. Unknown refusing identity is reported as unknown and opens no fallback. A release failure or failed reviewer preparation command is not a provider refusal. Fallback state distinguishes no fallback, an account-owned fallback and a legacy fallback whose owner is unknown.

`~/.local/state/accounts/moves.jsonl` records each transition under an append lock. Entries share the time, tool, subject and stable move id. A seats role write records `requested`, not confirmation; `codex_mesh.py` writes one `confirmed` entry per seat when it resumes on the destination home. Failures, waits and their end, no room and room again are separate entries. Readers skip malformed lines, including when checking for duplicate confirmations. A request omits `reset` when unknown; waits always carry a known reset. Refusal state lives beside it in `refusals.json`. Saving usage is best effort: a store failure is logged and does not prevent alerts; advice text only reads the saved store.

`~/.claude/scripts/lib/py ~/.claude/scripts/accounts/accounts.py burn --since <ISO> [--until <ISO>]` reports points spent per observed day for each account and the roles it served. It reads `~/.local/state/agent-notes/readings.jsonl` and `~/.local/state/accounts/roles.jsonl`; before 2026-10-13 00:00 UTC, the default login's note label identifies historical showrunner usage. From that cutover onward, readings are labeled by account alone, with no role attribution. Historical unit directory selections resolve to the note label of that directory's login before matching readings. An unreadable historical identity refuses the report instead of guessing a note label. Role changes split the report, including when unit directors share the default account. Decreases between paired readings measure spend; an increase in remaining allowance starts a new span, so a weekly refill never becomes negative spend. Window edges and role changes within an observation interval divide its spend in proportion to elapsed time. Unobserved time and the interval across a refill contribute neither spend nor observed days. One reading alone gives no rate. `--until` defaults to now; an ISO timestamp without an offset is interpreted in the user's zone, set in `~/.claude/config/user_zone.conf`. The command reads local data and launches nothing.
