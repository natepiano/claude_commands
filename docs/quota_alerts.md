# Quota alerts: the receiver's protocol

natedev's agent-sessions timer checks Claude and Codex weekly usage every 2 minutes (`~/.claude/scripts/whoami/agent_notes.py`, which writes `~/rust/hanadocs/agents/*.md`) and messages `always` and each showrunner in `~/.claude/config/showrunners.json` by session name. Claude readings cover `~/.claude` and every named account directory that passes `accounts.check`; spare accounts get fresh notes and readings too. The default login serves showrunners and the account selected for `unit` serves unit directors: both notes are active together. Without account configuration or named directories, the existing single active Claude note and notice text stay the same. `/showrunner:produce` adds each showrunner. The timer also messages the user directly once when an account first enters a low-quota episode, and once more if Codex refuses work during that episode. A failed low-quota message is retried by the next two-minute check, even after `/quota_ack`; a failed refusal message is retried by the next refusal. Successful messages do not repeat within the episode, and recovery sends no direct user message. Mechanics: the docstring of `quota_alert.py` beside it.

Notices arrive through `send.py` (/message) from the relay `quota_alert`, which cannot be answered; a session not running when one is sent has it queued. Tell them apart by the first line:

| First line | Means | Receiver does |
|---|---|---|
| `Quota alert:` | An active account is at or under `threshold_percent`. Repeats every `repeat_minutes` until acknowledged; the user also receives the one direct message described above. | Claude: sessions on the named account start no new Claude work. A showrunner relays a unit-account notice to its units on that account. Codex: keep delegating, because the account may keep working on its credits and nothing is switched; if Codex refuses work for quota, act on that notice at once. Treat repeats as one item. |
| `Quota alert:` saying every function on Codex was moved to Claude | Codex refused work for quota, the registry was switched to Claude, and the user was messaged directly once for this episode. | Keep delegating, now on Claude; re-run Codex work that was in flight. |
| `5-hour limit:` | Claude or Codex has 20% or less of its 5-hour window left (`five_hour.py`). Sent once per low spell. | Tell the user in one line; change nothing else. They are sent it directly unless they type in a terminal within 15 minutes (`escalate.py`). |
| `Quota alert acknowledged:` | The user silenced it, in the session named. | Drop held copies. Paused work stays paused. |
| `Quota restored:` | The named account is back above the threshold: a used limit reset, a new window, or a Codex account switch. A Codex one lists what moved back to Codex. | Resume work paused for that account and drop its held alerts. Other accounts keep their own episodes. |

## Commands

- `/quota_ack [note]` — the user's alone (`disable-model-invocation`). Naming a note silences only that account; omitting it acknowledges every open episode. Never run it or `quota_alert.py ack` yourself, and never treat an alert as acknowledged.
- `/quota_refresh` — run it when the user says they reset usage. It refreshes the notes now and sends `Quota restored:` to every configured session but yours.

Every user act is echoed to every configured session except the one it happened in. What to do about the quota itself — redeem a limit reset, switch accounts — is the user's call. A Codex alert's second line gives the account's credit balance as Codex reports it, or says none is reported. Reaching the threshold switches nothing. A Codex switch is made only when Codex itself turns a launch away for quota (its launcher reports the refusal with `agent_notes.py blocked`) while the account is at or under the threshold, and it is undone automatically; the natedev session shows the user each on their next prompt.

With multiple accounts configured, a Claude notice starts with its label and role, for example `Quota alert: claude 3 (unit directors) at 4%`. A unit-account notice includes `swap: /showrunner:accounts swap unit "claude 1"` for the fit spare with the most remaining weekly allowance, or `no spare account has more left`. Unknown, expired, and unfit spare readings cannot produce a recommendation. This is a suggestion for the user; the alert performs no swap. A healthy showrunner account continues its own work when the unit account is low.

Each refresh resolves the default and unit logins once and uses that frozen role value for note activity and notices. Swapping a low Claude account to spare preserves its episode and acknowledgement. Selecting it again stays quiet if it was acknowledged; only its own quota recovery or weekly reset closes the episode. Missing or unknown readings preserve it too. A recovered spare sends a notice for that account alone.

`~/.claude/scripts/lib/py ~/.claude/scripts/accounts/accounts.py burn --since <ISO> [--until <ISO>]` reports points spent per observed day for each account and the roles it served. It reads `~/.local/state/agent-notes/readings.jsonl` and `~/.local/state/accounts/roles.jsonl`; the default login's note label identifies showrunner usage. Historical unit directory selections resolve to the note label of that directory's login before matching readings. An unreadable historical identity refuses the report instead of guessing a note label. Role changes split the report, including when unit directors share the default account. Decreases between paired readings measure spend; an increase in remaining allowance starts a new span, so a weekly refill never becomes negative spend. Window edges and role changes within an observation interval divide its spend in proportion to elapsed time. Unobserved time and the interval across a refill contribute neither spend nor observed days. One reading alone gives no rate. `--until` defaults to now; an ISO timestamp without an offset is interpreted in America/Los_Angeles. The command reads local data and launches nothing.
