## Decisions (unit director, 2026-10-06; each a one-line revert)

- **One request is one turn,** in the director's own thread. Native subagents are not measured.
- **The headline is the continuation turn** (triggered by a tool result): that is what the director does while working, with no wait for a person. Prompt turns get token numbers only.
- **Model-only.** Both arms keep effort `xhigh` and speed `standard`; each filter's drop count prints per session and arm.
- **The transcript fixes the switch,** by `message.model` per request; the roster's times are context. The first request after each model change (the cache rebuild) is dropped from every statistic and counted.
- **Baseline.** Per session, the last 300 filtered Opus requests before the switch; all of its Opus requests are shown beside it. The concurrent control (directors that stayed on Opus) shows what the clock alone did to turn time.
- **Intervals.** 95% bootstrap (2,000 resamples, seed 1) on the difference of medians; fewer than 30 requests in an arm reads `too few`.
- **Verdict is a rule, printed with its inputs** (Phase 4). Evidence of harm on time, turns or repair rounds recommends Opus; otherwise Sonnet stays.
- **Sample gate G1:** at least 4 switched directors with 150 filtered Sonnet continuation requests each, or 10:30 PDT 2026-10-07, whichever comes first. The user wants the answers by midday 2026-10-07, so the deadline replaces the earlier 24 h-after-the-latest-switch fallback (about 17:20 PDT 2026-10-07) and leaves an hour and a half for Phase 5; a one-line revert of `SAMPLE_DEADLINE_PDT`. Directors short of 150 at the deadline read `too few` in the report.
- **Re-runnable** (user, via the showrunner, 2026-10-06: "make sure the report is re-runnable so we can run it again after more time has passed under sonnet"). Every command rebuilds its outputs whole from the live files; `ready` gates only Phase 6, never a command; the results documents are generated by `results`, not written by hand; each report run adds a history line so a later run shows what moved; rows of sessions whose transcript Claude Code has since deleted are carried forward (Phase 5).

### Phase 2 — The comparison sets each director's Opus turns against its Sonnet turns · status: todo

#### Work Order

Work only in worktree `/home/natepiano/worktrees/claude-build-followups-model-study`, branch `build-followups-model-study`. State every time in PDT.

**Goal:** `model_study.py compare` prints, per director and pooled, Opus against Sonnet on response seconds and tokens per request, with 95% intervals, by turn class, beside the concurrent control and the compaction cost.

**Spec:**
- **Input** `turns.jsonl` and `compactions.jsonl` from Phase 1 (`--state-dir`); output a markdown report on stdout and every number in `compare.json`.
- **Arms and filters.** `opus` is `claude-opus-5-5`, `sonnet` is `claude-sonnet-5-5`; other models fall in an `other` count. Drop `switch_turn` requests; keep effort `xhigh` and speed `standard`. Count each drop per director and arm (`switch_turn`, `effort`, `speed`). A director with both arms is *switched*; only Opus, a *control candidate*; only Sonnet, *Sonnet-only* (no baseline, rows for its Sonnet arm alone).
- **Classes.** `continuation/tool_use`, `continuation/end_turn`, `prompt` (every other kind). The headline is `continuation`, the first two pooled. Seconds statistics use requests with non-null `seconds`; prompt requests report tokens only.
- **Statistics per (director, arm, class):** `n`; seconds median, p25, p75, p90; median output, thinking, fresh input (input + write_5m + write_1h), cache_read and context tokens; median output tokens per second (output / seconds, requests of at least 0.5 s); mean API-equivalent cost per request. `percentile(values, p)` interpolates linearly between ranks (`percentile([1, 2, 3, 4], 50) == 2.5`).
- **Prices** (`stats.PRICES`, USD per million tokens, standard speed, from `model-notes.md`, Anthropic's price page 2026-10-06): `claude-opus-5-5` input 4, output 20, cache write 5 min 5, 1 h 8, read 0.20; `claude-sonnet-5-5` input 2, output 10, write 5 min 2.50, 1 h 4, read 0.20. Cost = (input·in + output·out + cache_read·read + write_5m·w5 + write_1h·w1) / 1e6. An unpriced model costs 0 and is counted.
- **Baselines.** For a switched director the Opus arm is the last `BASELINE_REQUESTS = 300` filtered Opus requests before its first Sonnet request; the table also shows all its filtered Opus requests.
- **Differences.** Sonnet minus Opus for median seconds (`continuation`), median output tokens and mean cost per request, each with `bootstrap_diff(a, b, stat, resamples=2000, seed=1)` (95% interval, `random.Random(seed)`). Label `faster` / `slower` (interval below / above zero), `lower` / `higher` for tokens and cost, `no measurable difference` (interval holds zero), `too few` (fewer than 30 requests in an arm). The pooled row uses the switched directors only.
- **Control.** T is the median `first_sonnet` of the switched directors. A control candidate with at least 30 filtered Opus continuation requests on each side of T reports its median seconds before and after T and the change with an interval; the table prints the control's change beside the switched directors' Sonnet-minus-Opus change, with no further arithmetic.
- **Compactions** (Sonnet-minus-Opus by the model of the last request before each compaction): per director and arm, compactions per 100 requests; compactions per active hour (active time is the span of the arm's requests with every gap over 15 minutes removed); median `pre_tokens` and `duration_ms`; total compaction seconds per active hour; and the requests with `after_compact` 1 to 10 against the arm's other requests, as the ratio of mean seconds and of mean cache-write tokens (`write_5m + write_1h`).
- **Output order:** switched directors one row each, pooled row, Sonnet-only rows, control table, compaction table; a closing line per table with its drop counts.
