## Decisions (unit director, 2026-10-06; each a one-line revert)

- **One request is one turn,** in the director's own thread. Native subagents are not measured.
- **The headline is the continuation turn** (triggered by a tool result): that is what the director does while working, with no wait for a person. Prompt turns get token numbers only.
- **Model-only.** Both arms keep effort `xhigh` and speed `standard`; each filter's drop count prints per session and arm.
- **The transcript fixes the switch,** by `message.model` per request; the roster's times are context. The first request after each model change (the cache rebuild) is dropped from every statistic and counted.
- **Baseline.** Per session, the last 300 filtered Opus requests before the switch; all of its Opus requests are shown beside it. The concurrent control (directors that stayed on Opus) shows what the clock alone did to turn time.
- **Intervals.** 95% bootstrap (2,000 resamples, seed 1) on the difference of medians; fewer than 30 requests in an arm reads `too few`.
- **Verdict is a rule, printed with its inputs** (Phase 4). Evidence of harm on time, turns or repair rounds recommends Opus; otherwise Sonnet stays.
- **Sample gate G1:** at least 4 switched directors with 150 filtered Sonnet continuation requests each, or 10:30 PDT 2026-10-07, whichever comes first. ## Phases

### Phase 1 — The extractor turns director transcripts into measured requests · status: done

#### As-built

- `read_session(path, name, director_from) -> SessionRead` (`turns`, `compactions`, `dropped`, `director_from`, `whole_session`) groups `assistant` records with `isSidechain` false by `requestId` (the record `uuid` when absent) into one request each; `isSidechain` true records are counted `sidechain`. A request runs from its first block to its last block's timestamp; usage is the largest value seen per field across its blocks; cache writes split into `write_1h` and `write_5m` (any remainder of `cache_creation_input_tokens` counts as `write_5m`); `stop` is the last block's `stop_reason` when `tool_use` or `end_turn`, else `other`.
- Seconds: the trigger is the nearest earlier non-`assistant` record, in file order, whose timestamp is at or before the first block's timestamp (this skips bookkeeping attachments stamped just after the reply); `seconds` is the last block's timestamp minus the trigger's. No trigger, a negative gap, or a gap over `OVER_LIMIT_SECONDS = 1800` leaves `seconds` null and counts `no_trigger`, `negative` or `over_limit`; values are never clipped and the row stays, because its tokens are real.
- Kind (`prompt_kind`), from the nearest earlier `user` record (attachments and system records skipped): list content with a `tool_result` item is `continuation`; `isCompactSummary` is `compact`; string content takes its `turnOrigin` (`human`, `peer`, `task_notification`); anything else is `other`.
- Director start (`director_boundary`) is the first of: the roster's `director_from_pdt`; the first `user` record whose string content contains `<command-name>/unit:delegate</command-name>`; the first `user` record with `turnOrigin` `human` or `peer` containing `/unit:delegate`; else the session's first request, with `director_from` null and `whole_session` true. Earlier requests are counted `before_director`.
- `director_turns(reads)` sorts one director's session reads by `started` and recomputes `switch_turn` over the combined sequence. `model_study.py` holds `extract(roster, projects_dir, registry_dir, state_dir)`, `atomic_text` and the parser with the `extract` subcommand; the three outputs are written whole through a temporary file.

### Phase 2 — The comparison sets each director's Opus turns against its Sonnet turns · status: done

#### As-built

- `stats.py` holds `TokenPrices` and `PRICES` (USD per million tokens, standard speed): `claude-opus-5-5` input 4, output 20, cache write 5 min 5, 1 h 8, read 0.20; `claude-sonnet-5-5` input 2, output 10, write 5 min 2.50, 1 h 4, read 0.20.
- `percentile(values, p)` interpolates linearly between ranks (`percentile([1, 2, 3, 4], 50) == 2.5`).
- `bootstrap_diff(a, b, stat, resamples=2000, seed=1) -> (b minus a, low, high)` returns the point difference and a 95% interval; `random.Random(seed)` makes it reproducible.
- `request_cost(turn)` = (input·in + output·out + cache_read·read + write_5m·w5 + write_1h·w1) / 1e6. An unpriced model costs 0 and is counted.
- `label_difference(lower, upper, n_a, n_b, metric)` returns `too few` when either arm has fewer than 30 requests; otherwise `faster` / `slower` (seconds) or `lower` / `higher` (tokens and cost) when the interval sits below / above zero, and `no measurable difference` when it holds zero.
- `compare.compare(state_dir) -> ComparisonReport` reads `turns.jsonl` and `compactions.jsonl`, writes `compare.json` whole, prints the markdown report and returns the data. `compare.load_turns` loads the `turns.jsonl` rows.
- Directors come from `turns.jsonl` in first-seen order; `extract.json` is not read, so rows alone keep a director in the comparison.
- Arms: `opus` is `claude-opus-5-5`, `sonnet` is `claude-sonnet-5-5`; any other model falls in an `other` count.
- Filters drop `switch_turn` requests, requests whose effort is not `xhigh` and requests whose speed is not `standard`. Drops are counted per director and arm as `switch_turn`, `effort`, `speed`.
- Director statuses: `switched` (both arms), `control candidate` (Opus only), `Sonnet-only` (Sonnet only; rows for its Sonnet arm alone, no baseline), `no eligible requests` (rows exist but no filtered Opus or Sonnet request; a row in the first table, its drops in `compare.json`, no class rows), and `pooled`.
- Classes: `continuation/tool_use`, `continuation/end_turn`, `prompt` (every other kind). The headline class is `continuation`, the first two pooled. Seconds statistics use requests with non-null `seconds`; `prompt` reports tokens only.
- Statistics per (director, arm, class): `n`; seconds median, p25, p75, p90; median output, thinking, fresh input (input + write_5m + write_1h), cache_read and context tokens; median output tokens per second (requests of at least 0.5 s); mean `request_cost` per request.
- `BASELINE_REQUESTS = 300`: a switched director's Opus arm is its last 300 filtered Opus requests before its first Sonnet request; the table also shows all its filtered Opus requests.
- Differences are Sonnet minus Opus on median `seconds` (`continuation`), median `output` tokens and mean `cost`, each with a 95% `bootstrap_diff` interval and a `label_difference` label. The pooled row uses the switched directors only.
- Control: T is the median first-Sonnet request of the switched directors, derived from the rows. A control candidate qualifies with at least 30 filtered Opus continuation requests on each side of T; its earlier side is the last 300 filtered Opus requests before T. Qualification counts all filtered continuation requests; the before and after medians and the change interval use timed requests only. The control table prints the control's change beside the switched directors' Sonnet-minus-Opus change with no further arithmetic.
- Compactions, per (director, arm) and keyed by the model of the last request before each compaction: compactions per 100 requests; compactions per active hour (the arm's request span with every gap over 15 minutes removed); median `pre_tokens` and `duration_ms`; compaction seconds per active hour; and the requests with `after_compact` 1 to 10 against the arm's other requests, as the ratio of mean seconds and of mean cache-write tokens (`write_5m + write_1h`).
- Output order: switched directors one row each, the pooled row, Sonnet-only rows, the control table, the compaction table; each table closes with a `Drops —` line.
- `model_study.py compare [--state-dir D]` runs it and exits 0.
- 20 tests in `test_stats.py` and `test_compare.py` cover percentile values, a reproducible seeded bootstrap, cost per price column, label rules including `too few`, and synthetic `turns.jsonl` driven through the command line and `compare.json` (filters and counts, the 300-request baseline, classes, the control median, compaction rates and post-compaction ratios).

- `scripts/model_study/compare.py` — filters, classes, baselines, control, compactions, markdown tables, `compare.json`.

**Gotchas:**

- A control median can be null; `seconds_per_active_hour` is null when any attributed compaction has no `duration_ms`.
- The class table prints an arm only when it has requests, while `compare.json` keeps that arm's all-null statistics.
- `switch_turn` is used as `turns.jsonl` carries it, never recomputed per file.

**Ruled out:**
- Reading `extract.json` in `compare` — it is not a specified input and goes stale.
- A pooled compaction row in `compare.json` — derived from the switched directors' rows instead.
- Every earlier Opus request as the control's earlier side — measures drift, not the switch.

### Phase 3 — The phase table counts turns and repair rounds for the same work · status: done

#### As-built

`scripts/model_study/phases.py` joins each completed phase in the run files to its director's requests. The join key is the director's session ids from `turns.session_ids(entry, registry_dir)` (roster plus registry), used both to pick the run files and to pick the requests; a row's `director` is the roster name. A phase's requests are every request of the director that starts inside the phase interval, with arm, effort and speed unfiltered; `phase_arm` names the phase `opus`, `sonnet` or `mixed`.

`phases(state_dir, runs_dir, roster, registry_dir) -> PhaseReport` writes `phases.json` (`{phases, comparisons, drops}`) through a temporary file and `os.replace`, returns the data and prints nothing; `markdown(report)` renders it. The hub `model_study.py phases` takes `--state-dir`, `--runs-dir`, `--registry-dir` (default `~/.claude/sessions`) and `--roster`, and prints the markdown.

- **Rows.** `phases[]` keys: `director`, `plan`, `phase_id`, `phase_title`, `arm`, `requests`, `director_seconds`, `cost_usd`, `output_tokens`, `repair_rounds`, `findings_opened`, `abandoned_batches`, `phase_elapsed_seconds`, `work_order_words`, `work_order_lines` and three per-1,000-word rates (requests, seconds, cost). A size is null when the recorder wrote none or an unusable one, and a recorded 0 stays 0; the three rates are null when the size is null or 0. A null or 0 size and a null rate print as a dash. Rows keep run and event order within a director and are sorted by director only.
- **Comparisons.** `comparisons[]` holds one entry per roster director whose `switched_by_pdt` is set, then a last entry named `Pooled switched`. Each maps four metrics (requests, seconds and cost per 1,000 Work Order words, and repair rounds) to `{opus_n, sonnet_n, opus_median, sonnet_median, value, low, high, label}`, as Sonnet minus Opus. With 8 or more phases per arm the interval comes from `stats.bootstrap_diff` on medians and the label is `fewer`, `more` or `no measurable difference`; with fewer, the label is `too few phases (n=<a> against <b>)` and `value`, `low` and `high` are null.
- **Drops.** `drops` is `{stopped, errored, empty}` (live 5, 2, 75). `errored` counts a finish status that is neither `completed` nor `stopped`; `empty` counts completed phases whose interval holds no request of the director.

**Files:**
- `scripts/model_study/phases.py` — the join, `phase_arm`, row building, per-arm comparisons with their own label function, `phases`, `markdown`.
- `scripts/model_study/model_study.py` — the `phases` subcommand.
- `scripts/model_study/test_phases.py` — 9 tests: the join, repair events, drops, the short-sample label, a registry-added session, a roster rename, missing, invalid and zero sizes, the bootstrap labels, pooled scope and row order.

**Binds later work:** The report that renders `phases.json` reads the shape above: nullable sizes and rates, `drops.errored`, and the `too few phases` label. Live, every comparison reads `too few phases` (every switched director has under 8 Sonnet-only phases; pooled has 6), so that report states the small sample and still lists every row, and puts `drops` in its limits. The history and results that carry `phases.json` whole take it as written; a restarted director's later runs join through the registry, and `--registry-dir` defaults to the same `~/.claude/sessions` as `extract`.

**Gotchas:**
- The bootstrap interval branch is exercised by the tests only.
- "Switched" is the roster's `switched_by_pdt`, which can differ from the row-derived status in `compare.json`.
- Requests are matched by session id, never by the `name` in `turns.jsonl`, so a stale name hides no phase.
- A phase that starts and never finishes, and a finish with an unreadable interval, are not counted anywhere, including `drops`.
- The label function lives in `phases.py`: `stats.label_difference` and `compare.difference` fix 30 requests per arm and use the words `faster`, `slower`, `lower` and `higher`.
- 63 of 363 live `phase_started` events (36 of 133 live rows) carry no Work Order size.

**Ruled out:** filtering phase requests by effort, speed or `switch_turn`; counting started-but-unfinished phases.

### Phase 4 — The report states each director's numbers and a verdict, with an interim run · status: done

#### As-built

`scripts/model_study/report.py` renders the report from `compare.json`, `phases.json` and `extract.json`: `render(comparison, phases, extracted, now, final=False)`, `message(comparison, phases, extracted, now, final, path)`, `ready(comparison, now=None) -> tuple[bool, list[str]]` and `work_section(phases)`. The title line says `INTERIM` or `FINAL` with the time in PDT. Sections in order: the user's measure, Verdict, per-director table, pooled turn classes, control, compactions, work per phase, Limits.

- **User's measure.** One line per switched director plus `Pooled switched`: `<name>: median continuation-turn seconds Opus <a> → Sonnet <b> (<±c%>)`. The percent is (Sonnet median − Opus median) / Opus median from the two `continuation` medians, so a director whose interval label is `too few` still has a percent; it is absent when the Opus median is 0 or an arm is empty (that arm prints `n/a`).
- **Verdict.** Mechanical: `opus` when pooled `continuation` seconds read `slower` or work requests or repair rounds read `more`; else `sonnet` when cost per request reads `lower` or seconds read `faster`; else `sonnet stays (no measurable difference; evidence thin)`. `too few` and `too few phases` count as no evidence. The block ends `Default for enh-showrunner Phase 6: opus|sonnet`.
- **Short message.** First line `From model-study-unit: <INTERIM|FINAL> director model study — <verdict>.`, then the user's-measure lines, the Verdict block, the director table, a Limits line and the report path. Director rows are cut from the end so the whole message is 60 lines or fewer, and the table then ends `… N more directors in report.md`.
- **`ready`.** Returns whether the sample gate holds: four switched directors with 150 filtered Sonnet continuation requests each (`classes.sonnet.continuation.n`), or `SAMPLE_DEADLINE_PDT` (2026-10-07 10:30 PDT). Live it already holds.
- **Limits.** Per-director sample and drop counts, the `phases.json` drops, the phases-per-arm sample line, and a roster director that `extract.json` has but `compare.json` lacks as `<name>: no requests extracted.` with its six drop counts.
- **Hub.** `report` takes `--interim` or `--final`, `--message`, `--no-extract`, `--now`, `--state-dir`, `--projects-dir`, `--registry-dir`, `--runs-dir`, `--roster`; it writes `report.md` into the state dir and prints a message or the path. `ready` takes `--now`, prints a count per switched director and exits 3 until the gate holds, else 0. `compare.compare` returns its data without printing; the `compare` subcommand prints `compare.markdown(result)`.

**Files:**
- `scripts/model_study/report.py` — the renderer, verdict, message and `ready`.
- `scripts/model_study/test_report.py` — 15 tests on synthetic fixtures, with `extract`, `compare` and `phases` patched on the CLI paths.
- `scripts/model_study/model_study.py` — the `report` and `ready` subcommands, `compare` printing the markdown.
- `scripts/model_study/compare.py` — `compare.compare` writes `compare.json` and returns the data.

**Binds later work:** The re-runnable results and the final report extend `render` and `message` with the signatures above; `work_section` takes only `phases`. Any line added to `message` counts toward its 60-line cap. The percent reads the two `continuation` medians, never `differences.seconds.value`. `ready` and `report --final --message` already exist; the final report calls `ready`. Keys read: `classes.opus` and `classes.sonnet` `continuation.seconds_median`, `classes.sonnet.continuation.n`, `phases["comparisons"]`.

**Gotchas:**
- Work-per-phase lines come from `phases["comparisons"]` minus `Pooled switched` (the roster's `switched_by_pdt`), not from `compare.json`'s status, so a director can have a table row and no work line, or the reverse.

### Phase 5 — The study can be re-run as the sample grows · status: done

#### As-built

- Carry-forward: a roster session id whose transcript file is gone keeps its rows. `extract` copies each line of the previous `turns.jsonl` and `compactions.jsonl` whose `session` is a gone id into the new files and keeps that session's previous state; a session whose transcript exists is read afresh and never carried. Carried and live rows of a director are merged by `started`, and `turns.recompute_switch_turns(rows)` (which `director_turns` also calls) recomputes `switch_turn` over the merge, so a live row that follows carried rows on one model is not a switch. - `extract.json` gains `session_states`, a dict keyed by session id (roster id or registry-added id): `{director, requests, dropped (six counts), transcript_gone, director_from, whole_session}`. A director's summary is `director_from` = min of the non-null per-session boundaries, `whole_session` = any, `dropped` summed over its states. `phases.py` takes a director's ids from `session_states` first, then the roster, then the registry, so a restarted session's runs keep joining after the registry stops listing its id.
