### Phase 3 — /build:queue reads a lock-free snapshot and answers in under a second every time  · status: done

#### As-built

Every exclusive section, `admit_head` included, publishes this way, also on an exception path; a failed write never changes the section's result. A bump takes no lock and writes no snapshot.

### Phase 4 — One decision pass decides for every waiting step, and the check and the queue read both call it  · status: done

#### As-built

- `admission_pass(inputs: QueueInputs, now: float) -> PassResult` in `memory_admit.py` is the one decision for every waiting row. It is pure: no file, `/proc`, environment or clock read, and no write. It calls `admission_walk` once for each input scenario and reads every row's decision from that one walk. A running step that ends is its own scenario: `inputs_after_steps_end(inputs, ended)` makes the changed copy, and one walk runs on it. `queue_decision` and `reservation_blocker` are gone.
- `PassResult` holds `rows: tuple[PassRow, ...]` in queue order, `head: HeadPriority | NoHeadPriority`, `totals: AdmissionDecision` (`decide(available, total, 0, memory)`), `recovery: RecoverySpacing`, `head_marks: tuple[HeadMark, ...]` and `override: OverrideKept | OverrideEnded`. `PassRow` holds `owner` (`<pid>-<start_time>`, from `waiter_owner`), `decision`, `reason`, `blocker: BlockingIndex | NoSingleBlocker | BlockerNotRequested` and `admission: ProposedAdmission | NotAdmitted`. `ProposedAdmission` holds `rank`, `recovery` and `override`. A `HeadMark(path, waiter)` sets `holds_younger` and `priority_since` on a head that has no `priority_since`. `OverrideEnded.action` is `"admitted"` or `"lapsed"`.
- Rules of the pass: each admitted row charges its need to the rows after it. In a recovery window (`RecoveryStarts`) at most one row admits; its proposal sets `next_start_at = now + RECOVERY_START_SECONDS`, and `PassResult.recovery` keeps the start due. `next_recovery(recovery, pressure, now)` is the one recovery change. `estimate_expired(waiter, now)` is the one expiry rule (estimate `HEAD_SECONDS` or more old): the row holds with `EstimateExpired(estimated_at)`, a `WaitReason`, and keeps its place and its room. A `ReadingUnavailable` host holds every row.
- Proposed, not committed. `check` builds `QueueInputs` with `gather_queue_inputs` from the readings it already took, adds its own waiter row, sets `blockers_for` to its own owner, calls the pass and commits only its own row. `commit_pass_effects` writes its proposal's `recovery` and `override`, or `PassResult.recovery` and `PassResult.override` when its row does not admit, before the reservation write. `check` writes the head marks and prints `memory admission: estimate expired while waiting for the lock; refresh on the next poll` when its own row expires. A launch with no ledger (no `admission/` folder) decides alone through `decide()`.
- `QueueInputs.blockers_for: frozenset[str]` names the owners that get a blocker; every other row has `BlockerNotRequested`. `blocking_index(owner, endings)` finds the one running step whose end admits the row. `blocker_identity(index, reservations, processes, proc) -> Blocker` resolves it at the process and sidecar boundary, for `check`, `blocker_snapshot` and `current_blocker`. The snapshot codec (`snapshot_value`, `parse_snapshot_value`) writes a `frozenset` as a sorted list.

### Phase 11 — Every later step of one verify.sh run keeps the queue place of the run's first step  · status: todo
**Depends on:** Phase 10 (the queue service holds the queue and the place record)
**Blocked by:** none past Phase 10. Builds showrunner ask, 2026-10-31.

#### Work Order

**Goal:** berth measured one `verify.sh lint` at about 45 min of queue time over three steps (10:21, 21:47, about 15) for a few minutes of work. Each step joined the back of the queue. After this phase, every later step of one `verify.sh` run takes the queue place of the run's first step. A step takes memory only while it runs; no memory is held between steps. The place ends when the run ends.

**Spec:**
1. **What verify passes.** The outermost `verify.sh` sets `BUILDLOG_RUN=<pid>:<start time>` once, from its own pid and the start-time field of `/proc/<pid>/stat`. A nested `verify.sh` keeps the value it got. `memory_gate.sh` passes it to `admission_client.py admit` with each step. The pid and start time together never match a reused pid.
2. **The waiter owner today.** The service keys each waiter's place by its owner, `waiter_owner(row)` = `<pid>-<start_time>` (`memory_admit.py` :3554), and its first `since` (Phase 5 Spec 3). Each step of one `verify.sh` run is a different child process, so each step is a different owner and joins at the back.
3. **Run identity at the service boundary.** `admission_protocol.py` defines `RunIdentity(pid: int, start_time: int) | NoRun()`. The client parses `BUILDLOG_RUN` once and sends the result in each `admit` as `run`. A missing or malformed value gives `NoRun`, and the step keeps its own place as today. `RunPlace(run: RunIdentity, since: float, first_owner: str)` is the service's one record per run. Both types go through the generic codec (`snapshot_value`, `parse_snapshot_value`) in the protocol and in `state.json`; there is no second form.
4. **Rule.** The first waiter of a run makes its `RunPlace` with its own `since`. A later waiter with the same `RunIdentity`, from any child owner, takes that `since` as its place; its own owner, episode and reservation stay its own. The service watches the run's process with `os.pidfd_open`, as it watches owners, and drops the `RunPlace` when no live process has that pid and start time. A run never holds a reservation or a token between steps: a step takes memory only while it runs. The user's rulings stay: one place in line across memory and the CPU token, no `head_since`, and the user's queue priority (`QueuePriority`, resources Phase 26) has no end time. `waiter_order` stays `(priority_rank, since, pid)`; the run changes only the `since` it reads.
5. **Restart.** `RunPlace` entries persist in `state.json` with the waiter places. At start the service opens a pidfd for each run and drops a run whose process is gone.
6. **Tests.** Every case uses the one shared fixture in `admission_test_support.py` (in-process server, fake clock, per-test socket):
   - A run's second step that arrives after two other waiters goes before them, and goes back to normal order after its run's process ends.
   - A service restart between two steps of one run keeps the `RunPlace`; the second step takes the first step's `since`.
   - Two steps of one run with different child owners share one place; each has its own episode and reservation.
   - Nested `verify.sh`: the inner run keeps the outer `BUILDLOG_RUN`, so its steps take the outer run's place.
   - PID reuse: a process with the run's pid and a different start time does not match, and its step gets its own place.
   - `NoRun`: a step with no or a malformed `BUILDLOG_RUN` gets its own place, as today.
   - `RunIdentity`, `NoRun` and `RunPlace` round-trip through the protocol and `state.json`.
7. **Docs.** `docs/as-built/build-memory-admission.md`: the run place, its end, and `BUILDLOG_RUN`.
