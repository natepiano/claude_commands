# sdlc-devtools-rerun

> **Status: IMPLEMENTATION PLAN — phased, delegate-ready.** Make the production tools safe to run again after a stop or a failure part way. Each phase fixes one cause in one shared place, moves every copy onto it, and adds a check that refuses a new copy, or names the copies its check cannot see. Phase 1 is the file writer.

> **Production: sdlc** — unit `devtools-unit`; production doc `docs/plans/sdlc-production.md`

> **Runs after:** the sdlc-devtools-tests plan is done (sdlc showrunner, 2026-10-30: this plan runs after it). This binds every phase below.

## Phases

### Phase 1 — Every state file write goes through the one file writer  · status: todo
**Depends on:** sdlc-phases Phase 20 (b8afa569: `write_text_atomic` keyword `create_parent`) on main
**Owner:** phases-unit (sdlc showrunner, 2026-10-30); the rest of this plan stays with devtools-unit.

#### Work Order

**Goal:** a stop at any line of any state write in a Python module leaves the old file or the new file, never part of one; every such write uses `scripts/lib/atomic_file.py`; and a test refuses each new local copy that it can see (**The check**, below).

**Spec:**

- The one place: `write_text_atomic(path, text, *, create_parent=True)` in `scripts/lib/atomic_file.py` (temp file beside the target from `mkstemp`, `fsync`, mode kept for an existing file and `0o666 & ~umask` for a new one, `os.replace`, folder `fsync`; `create_parent=False` leaves a missing folder an error). The phase builds on it and adds no second writer (sdlc showrunner, 2026-10-30). Its one change is a keyword-only `mode: int | None = None`: with a mode, the temp file gets that mode before `os.replace`, so the file never shows a wider mode; `None` keeps today's rule. unit-board-unit agrees the `atomic_file.py` change. Callers that publish private files pass `mode=0o600`: `accounts.py:2509` `_atomic_write` (it sets `0o600` on every write) and the `worker_names.py:79` recovery image. A caller that needs a private folder makes it before the call, as `accounts.py:2510` does now. A caller that writes bytes of text writes that text through it. A caller whose bytes are not text goes to the sdlc showrunner before the Work Order; the phase adds no writer for it.
- **Copies.** Each function outside `atomic_file.py` that writes a temp file and then replaces the target with it (`os.replace`, `Path.replace`, `Path.rename`) becomes one call to the shared writer. The caller keeps its own serialization at the call, for example `atomic_file.write_text_atomic(path, json.dumps(value, indent=2) + "\n")`, so no file changes its bytes. A local writer function (`_atomic`, `_atomic_write`, `write_atomic`, `atomic_json`, `atomic_text`, `atomic_write_text`, `write_json`, `_write_json`, `_atomic_json`, `replace_text`, `_replace`) is deleted, and its callers call the shared writer. The fixed temp names (`<name>.tmp`) go with the copies.
- **In-place rewrites.** A rewrite that truncates the data file (`seek(0)` + `truncate()`, or `write_text` on a state file that a later run reads back) moves to the shared writer. These callers hold `flock` on the data file itself, and a replace gives the path a new inode, so a lock on the old inode no longer serializes writers. Each such caller first moves its lock to a sibling `<name>.lock` file that it never replaces, then writes with the shared writer under that lock. Every reader and appender of a replaced file is a caller too: it takes the sibling lock first and opens the data file only while it holds that lock, and a function that replaces the file and then appends opens it again after the replace. Example: `worker_names.migrate_locked_journal` (`worker_names.py:56`) rewrites a journal in place under the data-file lock, and `accounts/moves.py` `append_move` (open `:294`, append `:312`) and `append_routing` (open `:447`, append `:461`) append through that same handle after it; `role_map.py:562` also calls it. **Transition:** a process that started before the merge still locks the data file, and an old writer that opened the file before a replace writes to the old inode. The merge restarts each daemon that imports a changed module, through that daemon's own service restart, and the checkpoint notice names them with their owners. A merge never stops or resumes a Claude or Codex session: a session uses shutdown's stop and resume only (sdlc showrunner, 2026-10-30).
- **Copies the sweep fixes added** move too: `quota_alert._write_state` (fixed `.state.tmp`), `detection_rules` `staged_receipt`, `worker_names` lines 77-86, `silence.release`, `hana_shot._write_launch_state`, `issue_score/client._write_pending`, `style_admin.replace_text`, `bulk_rename.atomic_json` and `BatchIntent.recover`, `five_hour.save_delivery`, `codex_winddown._save_quiet_notice_state`.
- **Out of scope** (author's scope note): append-only journals (`a` mode, one line per write, readers skip a part last line), except a journal rewrite such as `worker_names.migrate_locked_journal`, which is in scope; moves of whole files or folders that are not a write (archives, `*.removing` renames); exclusive-create files (Phase 5). Remaining work, which this phase and its check do not cover: shell scripts (`mv "$tmp" "$target"`), which have no shared writer yet, and Python in a string that a child runs (`send.py:213` `RELAY_EXEC`), which the parser cannot read. The as-built names both.
- **The check.** New `scripts/lib/test_one_file_writer.py` parses every `scripts/**/*.py` except test files, fixtures and `*_test_support.py`. It refuses (1) a function, other than in `atomic_file.py`, in which one name is both written (`write_text`, `write_bytes`, `open(..., "w"|"wb")`, `os.fdopen`, `mkstemp`) and passed as the source of `os.replace`, `Path.replace` or `Path.rename`; (2) a `truncate()` call on a handle opened on a path, outside `atomic_file.py`; (3) a whole-file JSON write outside `atomic_file.py`: `write_text` or `write_bytes` whose argument holds a `json.dumps` call, or `json.dump` into a handle opened with `"w"`; and (4) a forwarding wrapper: a function whose body is only one call to `write_text_atomic` that passes on its own parameters. Each refusal names `path:line` and says "use scripts/lib/atomic_file.py". The check cannot tell a plain-text state file from an output file, so it does not refuse a plain-text `write_text`; the dispatch list names those state files, and they move with the rest. The merge gate finds this test module itself (sdlc-devtools-tests Phase 1).
