# Showrunner automation: unit start, checkpoint merge, lifecycle, updates, dailies and waits

## What it is

A set of Python (standard library) scripts in `scripts/production/` that run the fixed, repeatable steps of a production, so a showrunner and its unit directors have little left to remember. One command starts a unit: with a written plan, with a brief the unit director turns into a plan, or on standby. One command merges a checkpoint: ancestry, scope, conflicts, merge, tests, push, promotion to the installed checkouts and the Mac, the review-ledger row and the log line. Other commands open, promote and wrap a production; register its scheduled updates and write its times, log lines and footer; build the dailies input from the status script; count CI points and send the first review-watch alert once; and do the mechanical part of waits, renames and quota alerts. A unit director ends each phase in one fixed order: the code commit first, then the shrink in its own commit beside the next phase. Unit directors take their model and effort from `config/agents.conf`. The stall watch and the status script treat a unit that is waiting on someone else as waiting, not stalled. A unit marked retired in the production doc drops out of the status script, the dailies, the waits and the stall watch, and a `simple` dailies gives each unit that only waits one line in a group.

The problem it solves is the number of manual steps a showrunner has to carry. Each of these was a list in `commands/showrunner/produce.md` that the showrunner had to run by hand, in the right order, on every merge and every tick. The commands now hold the mechanics. The command docs keep only the decisions that need judgment.

## How it works

### Shared conventions

- **Production-doc reader** (`scripts/production/add_unit.py`): `read_production(path) -> Production` (`doc`, `slug`, `merge_branch`, `checkout`, `showrunner_session`, `log`, `zone`), `production_field(lines, field) -> str` (reads `- **<field>:** …`; raises `Refusal` when the field is missing, so no `str | None` crosses the boundary), `cell_value(value) -> str` (the first backticked span, else the text before ` — `), and `unit_rows(lines) -> tuple[int, list[str]]` (the insert index and the data rows of `## Units`). Every other production script imports these four; none parses the doc itself. The slug is the doc's file name less `-production.md`, and `Log` must be relative to the showrunner checkout.
- **Retired units** (`add_unit.py`): marking a Units row is the whole act of retiring a unit. The row stays in the doc, and no caller's command line changes. `plan_cell_is_retired(plan_cell: str) -> bool` decides: the Plan cell begins with the lower-case whole word `retired`, alone or straight after one opening parenthesis, leading spaces ignored (`^\s*\(?retired\b`), as in `(retired by the user, worktree removed)`. The word later in the cell, later inside a leading parenthesis (`(run done; retired by the user)`), `retiredness` and `Retired` each leave the row live. Rows are read by column heading: `unit_table(lines) -> list[dict[str, str]]` returns each row as its cells by heading, so a doc that still has the old Session column reads like one without it. `live_unit_table(lines, slug)` returns the rows that are not retired and `retired_units(lines, slug) -> set[str]` the Unit values of those that are. `unit_status.sh`, the dailies builder, `waiting.py` and the stall watch skip a retired unit. `merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` read every row.
- **Gone units** (`add_unit.py`, user 2026-10-08): a unit is also retired, with no hand edit, when it has neither a worktree of its own nor a tmux session marked as it. `unit_is_retired(cells, marks)` is the one rule and `live_unit_table` and `retired_units` both read it, so dailies, waits, `live_units.py` (unit status, broadcast, the Codex wind-down) and `stall_watch.py` drop such a unit together. `worktree_is_linked` wants `<worktree>/.git` to be a file: a main checkout, where it is a directory, is shared and holds no unit. The worktree is asked first, so a unit whose session is only restarting keeps its row. `SessionMarks` reads the marks from tmux once per read, and only when some row has no worktree; a tmux that cannot say which sessions exist keeps the row. Nothing removes a retired unit from the registry, because the registry lists no units. The rule reads the machine it runs on: a reader run where the worktrees and sessions are not (another host) would see every unit as gone. Tests give fixture rows a linked worktree or a marked session in a stand-in tmux, so none asks the real tmux.
- **The checked doc** (`showrunners.py`): `checked_doc(instance: Path) -> CheckedDoc | NoCheckedDoc` returns the production doc that a notifier instance directory's `conf` passes to `production_check.sh` on its `CHECK=` line: `shlex.split` the value, then take the token after the one whose basename is `production_check.sh`. `CheckedDoc(path: Path)` and `NoCheckedDoc(reason: str)` are `NamedTuple`s; a missing conf, line or token, or a relative path, is `NoCheckedDoc`. `live_units.py` and `stall_watch.tick` find retired rows through it. `add_unit.py` imports `showrunners`, so `showrunners.py` never imports `add_unit.py`.
- **Merge-branch history** (`merge_checkpoint.py`): `merge_branch_history(checkout, merge_branch) -> MergeBranchHistory` reads `git log --first-parent` subjects matching `Merge <unit> phase <N>[ shrink] (<short>)`. It offers `last_merge()`, `last_for_unit(unit)`, `last_code_for_unit(unit)`, `code_merge_count()` and `has_code_merge(unit, phase)`, with absence as `NoMerge`. A shrink merge never counts as a code merge. `LAST_MERGED[unit]`, the CI count, the STATE block, the wrap report and the agenda all read it.
- **Step lines**: each command prints `<step>: ok|held|failed — <one line>` and stops at the first `held` or `failed`. The dailies builder also prints `<step>: unavailable — <reason>` and continues, for the steps `phase tables`, `bevy upgrade`, `children`, `counts` and `saved report`. `add_unit.py`, `production_lifecycle.py`, `update_registration.py`, `ci_points.py`, `waiting.py` and `dailies_input.py` exit 0, or 2 on a refusal. `merge_checkpoint.py` exits 1 on a hold or failure, and its last line is always `send <unit>: <message>`.
- **Named states**: every optional or alternative value crossing a reader boundary is a `NamedTuple` union (`FieldPresent | FieldAbsent`, `PushedTip | NotYetPushed`, `EtaFresh | EtaStale | EtaPassed | EtaNone`, and so on), never a string or `None`.
- **State directory**: `DAILIES_STATE_DIR` (`<SCRATCH>/dailies_input_state`, in `produce.md`'s State list) is the one `--state-dir` for the dailies builder, every stateful `ci_points.py` call and every stateful `waiting.py` call. It holds `eta_seen.json`, `ci_points.json`, `ci_run.json`, `review_watch.json`, `quota_seen.json`, `agenda_seen.json` and the scratch-test logs.

### Unit start: `add_unit.py` and `/showrunner:add_unit`

`add_unit.py --production <doc> <name> (--plan <path> | --brief <words> | --standby) [--port N] [--owns <paths>] [--resume <sessionId> --cwd <dir> [--restart-note <file> --session-name <name> --tmux-session <name>]] [--timeout S] [--check]`, run through `scripts/lib/py`.

- **Request.** `launch_request` builds `RequestedUnitLaunch`, whose request-only fields are `requested_name` and `unit = <name>-unit`. A name that already ends in `-unit` (or `_unit`) loses that ending first, so `feature-log-unit` launches exactly as `feature-log` does, not as `feature-log-unit-unit`. The shared `UnitLaunchConfiguration` carries `production`, `branch`, `worktree`, `plan: PlanGiven | BriefGiven | Standby`, `port`/`owns: OmittedCell | SuppliedCell`, `session: NewSession | ResumedSession`, and `timeout`. Exactly one of the three launch states is required; `--resume` also needs `--cwd` and `--plan`. `launch_kind` is `UnitRestoreLaunch(session_id, note, session_name, tmux_session)` when `--restart-note`, `--session-name` and `--tmux-session` are all given with `--resume` (only `/shutdown restart` passes them), else `NewWorkLaunch`; any other mix is refused.
- **Shutdown check.** After `launch_request` and before `preflight`, `main` takes the shutdown launch barrier and runs `launch_permission` (`docs/as-built/shutdown-and-restart.md`) with the restore's session id for a `UnitRestoreLaunch`, else as new work, and holds the barrier through the return of `launch_session`. A launch that a shutdown holds (an account hold, or a restore whose own shutdown record has not stopped) exits 2 with `add_unit: <reason>; /shutdown restart first`; an unreadable shutdown state, restores included, exits 2 with `add_unit: shutdown state unreadable: <detail>`. `--check` also runs this check.
- **Preflight** (`preflight(request: RequestedUnitLaunch, selected: UnitLaunchAccount) -> ReadyToLaunch`): Claude is trusted in `session_cwd` on the selected account (`herdr.claude_trust` on `~/.claude.json` for the default account, else `<dir>/.claude.json`; a new worktree that does not exist yet is checked by its main checkout's key, `repository_trust_key`), else exit 2 with `<unit>: Claude is not trusted in <folder> on <account label>. Run: <trust_command>` before any stub, row or worktree is written (`docs/as-built/herdr-adoption.md`); the checkout is on the merge branch; the Units table has no other unit on this branch or worktree; an existing row for this unit (`ExistingUnitRow`) is adopted when its Plan, Worktree and Branch cells agree, and its Port and Owns stand (a supplied `--port`/`--owns` must match); a re-run's mode matches the recorded one (`recorded_mode` reads the commit subject, then a `standby` Plan cell, then the stub's `## Source`); the worktree path is free or already this branch's; no local or origin branch exists unless the row and worktree do; a `--plan` exists on the merge branch with the `> **Production:` header; a brief stub, if present, holds the same words. A restore (`UnitRestoreLaunch`) is checked against its own row only: the row must exist and its Plan cell must agree, its Worktree and Branch cells replace the naming pattern's, and the mode, worktree, branch and plan-header checks, which describe new work, are skipped; `main` creates no worktree and launches in the recorded `--cwd` (`session_cwd`), whether or not it is the row's Worktree (`docs/as-built/shutdown-and-restart.md`). Preflight returns `UnitLaunch(identity=UnitIdentity(unit, session), ...)` with the row and director; `session` is `requested_name`, the name the session is launched under, and it is not recorded. A tmux session already marked as the unit is taken as launched; a live tmux session of that name that is not so marked refuses in `main` before any write. `--check` runs `launch_request`, the shutdown check and `preflight` only. Over a marked unit a restore refuses on `ClaudeUnknown` and kills the stale tmux session on `ClaudeNotRunning` before launching.
- **Steps**, each skipped when already done: the brief stub beside the production doc at `<its directory>/<branch>.md` (Production header, `## Source`, a zone stamp and the user's words); the Units row (Plan cell `standby` for a standby unit); commit `production(<slug>): add unit <unit> (<plan|brief|standby>)` on the merge branch, which is not pushed here and goes out with the next merge push (user, 2026-10-08); `git worktree add` from the local merge branch, with no push of the unit branch (the unit's first checkpoint push sets its upstream), plus `branch.<branch>.cargoBerthTarget` when the repo has `.claude/config/berth.toml`; the tmux session; the wait for `/remote-control is active` (default 90 s, last 15 pane lines on timeout); one LOG line `added <unit> (<mode>), worktree <path>`. A row is written under the doc's own headings, so a doc that still has the Session column gets `—` there. It prints `<unit> started: tmux attach -t <session>`. A restore (`UnitRestoreLaunch`) makes no such wait: once the session is launched, or found already running, it runs the LOG step, prints `<unit> restore launched: tmux attach -t <session>` and returns 0; its caller confirms the session through the session registry.
- **Launch.** `systemd-run --user --scope --unit=<sanitized tmux session name>-<epoch seconds> tmux new-session -d -s <name> -c <cwd> -e SHOWRUNNER_UNIT=<slug> -e SHOWRUNNER_UNIT_ID=<unit> zsh -ic "ENABLE_TOOL_SEARCH=true command claude --model <m> [--effort <e>] [--resume <id>] --remote-control <name> -n <name> --settings '{\"disableAgentView\": true}' <prompt>; exec zsh"`, with every `CLAUDE_*` variable removed from the environment. The prompt is `/unit:direct <plan>` for a plan, or `/review:direct <production doc>` for the unit named `review-unit` when the doc has a `- **Review pool:** ` line (`docs/as-built/review-pool.md`); for a brief, write the full phased plan into the stub, send it to the showrunner and wait for approval; for standby, do nothing until the showrunner sends work; for a resume, "you are now `<unit>`" with the plan's absolute path in the worktree; for a restore, the same identity followed by the restart note, with `-n`/`--remote-control` and the tmux session taken from `--session-name` and `--tmux-session`. A restore's prompt is recorded as a `conversation_pause` scheduled prompt before launch (`record_scheduled_restore_prompt`; a failure exits 1 with `add_unit: restart prompt not recorded: …`).
- **Unit status.** A unit's run state is stored nowhere. `unit_lookup.run_state(worktree) -> UnitState` reads it at each call from the `/unit:direct` run records (`~/.local/state/plan-delegate/runs/*.jsonl`, or under `PLAN_DELEGATE_HISTORY_DIR`): among the records whose first event is `run_started` with `working_dir` equal to the unit's resolved Worktree cell it takes the one with the newest `run_started_at`; none is `standing-by`, a last event of `run_finished` is `run-finished`, anything else is `running`. A line caught half-written is left out; records that cannot be read raise `OSError`, and the stall watch then prints `<unit>: its run state is unknown` and leaves that unit alone for the tick. `showrunners.py status` and `showrunners.py ready` still parse their old arguments, do nothing and exit 0, because sessions started before 2026-10-08 hold text that calls them; delete both once no such session is left. Consequences: a standing-by unit handed work is watched for stalls only from the start of its run; a run that died without its finish event reads as running until the next run in that worktree.
- **Callers.** `produce.md` `<LaunchUnits/>` runs `add_unit.py --production PRODUCTION_DOC <name> --plan <unit plan>` per unit (`<name>` is the Unit value less `-unit`; `--standby` for a unit waiting on work). When the production doc has a `- **Review pool:** ` line, `<LaunchUnits/>` first commits the review plan on the merge branch and launches `review-unit` ahead of every other unit (`add_unit.py --production PRODUCTION_DOC review --plan <review plan> --owns "—"`); after each merged code checkpoint the showrunner sends it `review merge: unit <unit>; phase <phase>; session dir <path>; design check: <verdict>`, its session dir the first field `unit_run.py` prints (Unit lookup, below), and at wrap it tells `review-unit` to end, then runs `review_pool.py stop --production <slug>` (`docs/as-built/review-pool.md`). `/showrunner:promote_unit` runs: find the session, check fit (normalized unit name), plan, `add_unit.py … --resume <sessionId> --cwd <cwd> --plan <plan> --check`, `/exit` the session, then the same command without `--check`, then tell the user (both names when the name changed). Typing `/compact` into a blocked unit director and **Resume** stay the showrunner's own.

### Director model and effort: `config/agents.conf`

- `[assignments]` has `production=claude`; `[production.claude]` has `director=opus:xhigh`. There is no `[production.codex]`: unit directors launch only on Claude, and the showrunner is whichever session runs `/showrunner:produce`. The header Consumers list names `production unit directors (add_unit.py)`.
- `director_agent(request) -> DirectorAgent(model, effort: DefaultEffort | Effort(value))` runs `bash -c 'source "$1" && agents_resolve production.director && printf …'` with the `agents_config.sh` from the script's own checkout (`Path(__file__).resolve().parents[1] / "agents/agents_config.sh"`); `AGENTS_CONFIG_FILE` comes from the caller (default `~/.claude/config/agents.conf`). A resolver failure is exit 2 with its first `ERROR:` line; a family other than `claude` is exit 2 with `unit directors launch only on claude; production.director resolves to <family> (<model>)`. Both happen in `preflight`, so `--check` refuses too. `--effort` is passed only for `Effort(value)`.
- **One-family pinning** (`scripts/agents/agents_config.sh`): a function with exactly one family set is pinned to it (`_agents_pinned_family`). Every-function switches (`agents_set_all_assignments <family>`, `agents_set_model <agent>` with no function) leave it as it is and add it to `AGENT_KEPT_FUNCTIONS`; `agent_admin.sh` prints `# kept production on claude: its only set`. A switch aimed at it (`agents_set_assignment production codex`, `agents_set_model <codex agent> production`, `agents_set_row production.director <codex agent>`) prints `ERROR: 'production' runs only on claude: [production.claude] is its only set.`, returns 1 and leaves the file untouched. `/agent production.director <model>:<effort>` changes the row.
- **Resume** in `<LaunchUnits/>` first runs `shutdown.py launch-blocked --restart-of <session-id>` and goes on only on exit 1 (exit 0: a shutdown holds the unit, either through an account hold or because its own shutdown record has not stopped yet, and `/shutdown restart` brings the unit back; a unit whose own record has stopped is let through under an account hold). It then gets its flags: `bash -c` sourcing `agents_config.sh`, `agents_resolve production.director`, the same non-Claude refusal, then `agents_claude_args`. Only then `claude --resume <session-id> <flags> --remote-control <session> -n <session>`.

### Phase end on the unit side

`docs/delegate/phase_end.md` defines `<PhaseEnd/>`, the one order a loop or verbose phase ends in: (1) code commit (`<CheckpointCommit/>`, with the phase `status: done` and its Work Order still in place); (2) the code-ready notice, whose hash is mergeable now; (3) the plan review, where a defect in the committed phase becomes a follow-up phase run next; (4) the add-on check; (5) worker cleanup and `finish-phase`; (6) the next phase's launch; (7) the shrink beside the next phase's seats, its commit and the shrink notice. With no phase left, step 7 runs, then `<FinalGate/>`. A due `<PeriodicCI/>` point outside a production runs step 7 before step 6, so CI sees a clean tree. The other phase-end docs point to it in one line.

- `<ShrinkCommit/>` (`commands/unit/checkpoint.md`) stages only the plan doc and an approved next-items file, refuses any other staged path, commits `shrink(<plan-slug>): phase N — <title>`, runs `<PushCheckpoint/>` and owns no reservation.
- The shrink notice is `From <unit>: phase <N> shrink <hash> — plan doc only.` or `… — plan doc and <next-items path>.`
- A failed shrink blocks only `<ShrinkCommit/>`; the next `<CheckpointCommit/>` refuses while an earlier `done` phase still has a Work Order.
- **Closing work in the recorder** (`scripts/delegate/progress_history.py`). `start-activity` succeeds whenever the run is active and a phase has been started in it, still active or already closed by `finish-phase`, so work after step 5 with no next phase started (the last phase's `shrink` activity) keeps its row. On a closed phase `activity_started` and `activity_finished` carry that phase's `phase_instance_id`, and the phase's status, `finished_at` and elapsed time stay as `finish-phase` left them; `finish-activity` records status, result and elapsed seconds as it does inside a phase. `start-activity` exits 1 with `Start a phase before starting an activity` when the run has no phase, and with `Cannot start an activity: the run is finished` after `finish-run`.
- **An activity left open.** `start-phase` and `finish-run` close an activity still open, inside a phase or on a closed one, as `interrupted`. A repeated `finish-phase` does nothing: `_finish_phase` returns before any cleanup when the phase in state is not active, so an activity opened after the phase closed keeps running.

### Checkpoint merge: `merge_checkpoint.py`

`merge_checkpoint.py --production <doc> <unit> <phase> <hash> --started <ISO> [--review-trial "<line>"] [--parallel "<line>"] [--delivers "<line>"] [--shrink | --as-built] [--also <path>]… [--trailer <line>]… [--regime after|trial] [--holds K] [--merge-defects D] [--excluded "<why>"] [--cancel-prior] [--scratch <dir>]`. `produce.md` `<MergeCheckpoint/>` runs it in the background after the showrunner's own judgments. `--as-built` (2026-10-13, from the herdr trial) merges a unit's closing as-built commit like a shrink: no tests and no review-ledger row, held until a code checkpoint of that phase merged, subject `Merge <unit> phase <N> as-built (<short>) into <branch>`, and scope limited to `.md` paths that include a change to or deletion of the unit's plan. `Promote: none` is read as no promotion, the same as an absent field, and at load every local Promote checkout must exist, so a bad destination refuses before anything is pushed.

- **Doc fields read:** `Merge branch`, `Showrunner checkout`, `Log`, the Units rows (Branch, Owns), `## Hub files` rows naming this unit, **Merge tests**, **Known flakes**, **Push:** (`validate_and_push` default, or `git`) and **Promote:** (`<checkout>[, mac <path>]`, read as `NoPromotion | PromoteTo(checkouts, MacCheckout | NoMac)`). An absent field and `none` (any case) are both `NoPromotion`; at load every local Promote checkout must exist, so a bad destination is refused before anything is pushed.
- **Input rules.** A code checkpoint needs `--review-trial` (exactly `review trial: ux <N> findings, code <N> findings, review-seat minutes <M>, ux check minutes <U>, ux repair minutes <R>`) and a one-line `--delivers`; a shrink refuses `--delivers`. It also needs `--parallel` matching `Parallel: Phase <N>[, Phase <M>…] could start` or `Parallel: none — <reason>`; `Parallel: unknown` is refused with the instruction to add the plan's `**Depends on:**` lines and rerun (`check_parallel`). `--cancel-prior` is refused with `Push: git`. `MergeRequest.delivers` and `excluded` are `str`, `""` for absent.
- **Review numbers.** The unit takes the `--review-trial` line from `progress_history.py review-trial`, which reports the phase in state, active or just closed by `finish-phase`. It counts a `finding_opened` event as a code finding when the event names any lens other than `ux`, or no lens. An event naming `ux` and a code lens adds one to each number; the legacy lens word `both` reads as `adversary,contract` through `_finding_lenses` and adds one to the code number. `merge_checkpoint.py` parses the printed line, so its form is fixed. In the review ledger (`review_regime.py`) the code number is every code finding the phase's review raised from 2026-10-07, and the `craft` lens alone before that date; `report` prints its mean per regime as `code findings per phase (mean)`.
- **Owns rule.** A backticked bare name in an Owns cell owns both the root file and the sibling of the previous path. Without backticks the cell splits on commas before ` — `. **Merge tests** are the backticked spans before the first unquoted `(`; a missing field is refused, an empty one means no commands.
- **Steps:**
  1. *ancestry*: the commit exists; it descends from `LAST_MERGED` (skipped on `FirstMerge`); it is on `origin/<unit branch>` after a fetch, else held with "push your branch". A shrink is held here until `has_code_merge(unit, phase)`. A hash already on the merge branch skips steps 2–7.
  2. *scope*: nothing staged in the merge checkout; every path of `diff --name-only <merge branch>...<hash>` is in Owns, a hub row of this unit, or an `--also` path. A shrink allows only the plan doc and `<plan stem>-next.md`.
  3. *conflicts*: `merge-tree --write-tree --name-only` exit 1 is held, asking the unit to merge the merge branch and send a new hash.
  4. *other units*: overlap of this change's paths with each other unit's branch diff and its worktree's `status --short`, printed as data, never a stop.
  5. *merge*: `<scratch>/merge_<short>.msg` (subject `Merge <unit> phase <N>[ shrink] (<short>) into <merge branch>`, body `--delivers` or `Phase plan shrink.`, then trailers), `merge --no-ff -q -F`.
  6. *test*: each package owning a changed file (nearest `Cargo.toml`, named by its directory) through `verify.sh test`, each changed `crates/<pkg>/examples/<name>` through `verify.sh example`, then each Merge tests command, into `<scratch>/merge_<short>_test.log` with `<name>_EXIT=<rc>` lines. A command that cannot start is exit 127. A shrink runs none.
  7. *red*: each red command reruns once alone; green alone and listed in Known flakes continues with a LOG note; otherwise `reset --keep HEAD~1` after confirming `HEAD` is this merge and is not on origin.
  8. *push and promote*. `GitPush`: merge `origin/main` with `--no-ff` when it has diverged, push the merge branch (on failure, abort the merge and reset to the old origin tip if origin did not move). `ValidateAndPush`: `validate_and_push.sh --quick --to <merge branch> --fix-commit "ci(<slug>): format fixes after <unit> phase <N>" [--cancel-prior]`, reset to origin on failure. Then each **Promote** checkout through `promote_local_checkout(checkout, merge_branch, tip)`: it must be on `main`; `merge --ff-only <tip>`, where tip is the pushed merge-branch tip; push `main` only when `main ^origin/main ^origin/<merge branch>` is empty. Then the Mac through `pull_mac_checkout(mac, source)`: `ssh mac "cd <mac> && git pull --ff-only natedev:<first Promote checkout> main; printf 'rc=%s\n' $?"`, judged by the printed `rc=`.
  9. *record*: for a code checkpoint, `review_regime.py add --unit --plan <the unit's Plan cell> --phase --regime --started --merged <merge commit time> --holds --merge-defects` plus the five review numbers and any `--excluded`. The ledger names a row by unit, plan and phase (2026-10-12), because a unit that runs a second plan starts again at phase 1; then the LOG line `- HH:MM <zone>: <unit> phase <N> (<hash>) merged as <merge hash>; <tests> green; pushed[; promoted]`. A LOG that already has this line skips the step.
- **Merge report.** Step 8 prints `into: <path> (<branch>) — <why>; unblocks: <what>` as it reaches each place: the merge-branch checkout (`the merge branch collects every unit's checkpoints`; unblocks `<gate id>: <Waiting cell>` for each Gates row whose **Waits on** is `<unit> phase <N>`, else `no gate`), then each Promote checkout and the Mac (`sessions on <machine> run the installed commands from it`; unblocks `the live gate of <unit> phase <N>`). Only a code checkpoint's first merge names a gate.
- **Re-run.** A hash already merged reads `PushedTip | NotYetPushed` from origin, skips the push when pushed, and re-runs every promotion, each a no-op at the tip. A merge not yet pushed is one a killed run left untested, so the re-run runs its merge tests first, and red undoes the merge as on a first run. A failed promote is re-run with the same command.
- **Overrides for tests:** `MERGE_CHECKPOINT_VERIFY`, `MERGE_CHECKPOINT_VALIDATE_AND_PUSH`, `MERGE_CHECKPOINT_REVIEW_REGIME`, `MERGE_CHECKPOINT_SCRATCH`.

The showrunner still judges, before the call: the other units' overlap notice, new public items without a consumer, the design check. After it: `<ChangeReviewFeatureLog/>` for a merge in `~/rust/hana` or `~/rust/hana_catalyst` (one change-review row and one feature-log proposal per user-visible result; `docs/as-built/feature-log.md`), then `<ClearGate/>`, `<CrossUnitChange/>`, `<CIPoint/>` and the review watch. It sends the script's `send <unit>:` line and puts every `into:` line in the user update, adding one in the same form for each unit worktree it then merges the merge branch into.

### Production open, promote and wrap: `production_lifecycle.py`

`production_lifecycle.py load|open|promote-main|wrap --production <doc> [--no-ci] …`. `--no-ci` makes the CI, smoke-launch and Mac-run steps print `<step>: ok — skipped: no CI` and is refused together with a verdict flag.

Exit 3 says nothing about the session, so no caller reads it as "not running". `showrunners.socket_for` raises `OSError` on it: every reader of the showrunners stops with `cannot tell whether <session> is running: <reason>`; `tmux_names.fault` prints the reason and leaves its marker unwritten, so the next tick sends the fault. `stall_watch.tick` takes each unit's Claude from `unit_lookup.marked_units`, which reads the session records itself: a `ClaudeUnknown` unit prints `stall-watch: <unit>: <reason>` and is skipped for that tick; a `ClaudeNotRunning` unit is skipped with no line. `unit_status.sh` does not discard the stderr of its `sessions.py id <pid>` lookup; a pid with no session record yet (exit 1) stays silent. `conversation_pause._session_lookup` tells the two apart. `mac_test.delivery_target` falls back to the holder's name on both, which is right for both: the sender does its own lookup by name.

### Unit lookup: `unit_lookup.py`, and `adopt.py`

A unit's session name is written in one place, the session itself (user, 2026-10-08). Nothing copies it into the production doc, a registry or the showrunner's saved report state, so a rename in Claude or a relaunch leaves nothing to bring in step. The same holds for a showrunner's name.

- **Identity.** A unit is its production's slug plus its Unit value. `add_unit.py` launches the unit's tmux session with `SHOWRUNNER_UNIT=<slug>` and `SHOWRUNNER_UNIT_ID=<unit>` in the session environment. These marks stay with the tmux session through a rename, and through a relaunch of Claude in the same pane.
- **Lookup.** `marked_units(slug) -> dict[str, MarkedUnit]` reads every tmux session's marks, every marked herdr pane in a running herdr session, and the live session records at each call. `MarkedUnit(unit, label, claude, place)`; `place` is `TmuxPlace(pane) | HerdrPlace(session, pane)`, `label` the tmux session label or herdr session name; `claude` is `LiveClaude(name, session_id, socket, pid) | ClaudeNotRunning | ClaudeUnknown(reason)`, taken from the newest live record whose `tmux` field ends in one of the session's panes, or, with an empty `tmux` field, whose pid `herdr_place_of` puts at the place. `ClaudeUnknown` means a session record could not be read, which says nothing about whether Claude runs. No tmux server means no tmux units; `OSError` is raised only when every host read fails, and when two sessions, in either host, carry one unit's mark. CLI: `unit_lookup.py list <slug>` (tab-separated unit, place, label, `live|unknown|stopped`, Claude name, session id, socket), `pane <slug> <unit>` (the bare tmux pane id or `herdr:<session>:<pane>`; exit 1 no such session, 3 cannot tell) and `mark <slug> <unit> <tmux session>`. `every_marked_unit(*, include_tmux=True) -> MarkedProductions(units, faults)` is the one enumeration of every production's units: one read of each host and the records, units by slug then unit id; a production with two sessions on one unit's mark is left out with why, in `faults`, and `marked_units(slug)` raises that. A live unit's `place` is the pane its Claude runs in; reads and typing go through `session_pane.py` (herdr adoption → "Typing into and reading sessions on either host"). Cross-production readers read it once: the shutdown inventory (and so `accounts.py swap unit`), the roster (`live_units.units_in`) and `unit_effort.py`.
- **Readers.** `live_units.py <showrunner>` joins the registered doc's live rows with the lookup and prints the unit, its pane, `live|stopped|unknown|gone` and its name now, tab-separated. `unit_status.sh`, `broadcast.py`, `codex_winddown.py`, `stall_watch.py`, `dailies_input.py`, `waiting.py` and `production_lifecycle.py` take a unit's pane or name from the lookup at the moment of use. Saved state (dailies ETAs, judgments, status blocks, decisions seen, stall stretches) is keyed by unit id.
- **Showrunners.** A showrunner is recorded only by its update timer, `showrunner-<slug>` under `NOTIFIER_STATE_DIR`: `TARGET=session:<Claude session id>` and a check that holds the production doc. The zone is the user's zone setting (`scripts/lib/user_zone.py`), read at each call; a doc's own `User zone` line is not read (2026-10-12). A timer whose check names no doc, or whose doc cannot be read, is not a showrunner's. `showrunners.registered_showrunners()` reads the timers and looks up each name and socket by session id at every call, returning `Showrunner{session, socket, slug, zone, doc}` with `session` and `socket` empty while it is not running; a timer that is not a complete showrunner's is left out with `skipping <instance>: <reason>` on stderr, and session records that cannot be read raise `OSError`. `current_name(slug)` gives the name now; `current_address(slug)` gives `uds:<socket>`, the `to` a unit passes to `SendMessage`; `named(x)` finds a showrunner by its name now or its slug. CLI: `showrunners.py name <slug>` prints the name and `address <slug>` the address (each exit 1 when it is not running), `list` prints slug, name, zone and doc. A unit's launch prompt (`add_unit.prompt_for`) tells it to send to the address, looked up before each message: `SendMessage` refuses a bare name when the sender's account also lists another session under it, such as the offline Remote Control row a session leaves behind when it moves to another account, and the socket names the one session on this machine. `config/showrunners.json` holds only settings (`threshold_percent`, `repeat_minutes`, `stall_minutes`, `faults_to`, `always`); a `showrunners` list left in it is not read and nothing writes the file. `add`, `remove`, `rename` and `import` are gone, as is the doc's `Showrunner session` line. `showrunners.production_slug(doc)` is the doc's file name without `-production.md`. Still stored names: `faults_to` and `always`. A miss on either is told to the showrunners: `tmux_names.fault` sends the fault to every running showrunner, with the reason, when `faults_to` is no live session, and a quota alert names each `always` entry that is no live session (`quota_alert.not_live`).
- **Unit effort (`unit_effort.py <level> [--check]`, `/showrunner:effort`, user 2026-10-12).** For every marked unit with a live Claude, every production, it reads the screen with `session_pane.read_place(place, ansi=True)` and types `/effort <level>` with `type_place` (on tmux, the text then Enter as two `send-keys` calls). It skips, with the reason, a pane with a form, prompt or menu (`❯ 1.`, `Do you want`, `Esc to cancel`, `Enter to confirm`, `Enter to select`), no input box (a `❯` line under a rule), or a draft: text after `❯` that is not all dim (a suggestion, save the cursor's inverse cell). The level must be one `[claude.agents]` lists for the `production.director` model; the row is rewritten first through `agent_admin.sh production.director <model>:<level>`, so a refused write types nothing. `--check` sends and writes nothing.
- **Units table (`units_table.py [--production <doc>]`, `/showrunner:units`, user 2026-10-11).** Prints one Markdown table, `| Unit | Session | Phase | Task |`, a row per live unit, with no pane read, so the showrunner spends no tokens building it. Without `--production` the doc is the one in the update timer addressed to `CLAUDE_CODE_SESSION_ID` (`showrunners.production_of(session_id)`; exit 1 when there is none). Session comes from `live_units.production_units`: the name now, `gone`, `not running` or `unknown`. Phase comes from `phase_table.show_production`: `<n> of <total> · <title>` for the open phase, else `between phases, <done> of <total> done`, `not started`, `plan done`, `no phases` or `no plan`. Task is the open step of the newest run file of the unit's plan (`progress_history.plan_runs`): the newest open activity (`<label>: <text>`), else the newest open pass (`<kind>: <activity>`), cleared at each phase start or finish; cut to 80 characters with `…`, and `—` when none is open. Pipes in a cell are escaped.
- **A unit's newest run (`unit_run.py --production <doc> <unit> [--root <history root>] [--no-mac]`, run through `scripts/lib/py`).** Prints `<run id>\t<natedev|mac>\t<run_started_at as ISO-8601 UTC>`, exit 0. The run id is the run file's stem, which is the session directory's name; `<MergeCheckpoint/>` puts it in the `review merge:` line, and on exit 1 sends `session dir unavailable` there and tells `review-unit` why, which keeps that merge pending for review memory. The Worktree cell comes from the Units table through `add_unit.unit_table` and `cell_value`; no row exits 1 with `unit_run: no Units row for <unit>`. History root: `--root`, else `PLAN_DELEGATE_HISTORY_DIR`, else `~/.local/state/plan-delegate`. Among `runs/*.jsonl` whose `run_started` event's `working_dir` equals the Worktree cell after `os.path.normpath`, the greatest numeric `run_started_at` wins, ties to the first sorted name. An unreadable file, or one with no matching `run_started`, is skipped; a file counts once its `run_started` line reads, and undecodable bytes after it do not demote it, since skipping it would name an older run's session directory. With no local match and no `--no-mac`, one batch-mode `ssh` to `collect.MAC_HOST` (30 s limit) runs the same scan on the Mac; a failure prints `unit_run: Mac unavailable: <reason>` and counts as no match. No match anywhere exits 1 with `unit_run: no run found for <unit> in <worktree>`. `test_unit_run.py` (16 tests) covers the Mac path with a fake `ssh` on `PATH`.
- **Open proposals table (`proposals_table.py [--production <doc>]`, `/showrunner:proposals`, user 2026-10-12).** Prints one Markdown table, `| Proposed by | Proposal | Date | State |`, of every proposal still open for the user. It reads only, and finds the doc as the units table does. Four sources, in this order:
  - **The proposals index**: `index.md` in the folder the production doc's `- **Proposals:**` line names (`proposals_index`; a relative folder is taken from the showrunner checkout). No production named its folder before this, so the line is new and optional; without it there is no index. `index_rows` reads the table by its column names (Date, Proposal, Unit, Summary, Status) and needs only Proposal and Status. A row is dropped when its Status begins with a word in `CLOSED_WORDS`. The Proposal cell is the link's text, then ` — ` and the Summary up to its first semicolon.
  - **The plan backlog** (`PLAN_BACKLOG_DIR`, else `~/.local/state/plan-backlog`): each `ledger.md` line ending `proposed` or `deferred`. The proposer is the `Proposed <date> by <who>` words of the file the line names, else `plan backlog`.
  - **Proposal docs**: `docs/plans/proposal-*.md` in the trunk and each unit's worktree, one row per file name; a unit's copy is read before the trunk's, so the unit is its owner. A doc drops out once its `> **Status:` line no longer says PROPOSAL. Proposer and date come from its `Written <date> by <who>` words, else the owner and the file's last change.
  - **Add-ons**: each top-level entry of `next_items_pending.md` in `/tmp/claude/delegate/<run id>/`, for every run of the unit's plan (`progress_history.plan_runs`), with the list's last change as its date. A plan that has moved to `docs/as-built` is also looked up under `docs/plans`, the path its runs recorded. An entry's text is its `Title:` line, else its bold lead, else the words after its action word, else the first sentence of its `Proposed`, `Need`, `Why needed` or `Why` line. An action word alone (`add`, `change`, `remove`) is never the text (user 2026-10-12, after two rows read `add`).

  **State** says what the user can do, never a bare `next` (user 2026-10-12: "next after what?"). An index row keeps its Status as written, with `waiting for review` printed as `waiting for your review`; a proposal doc and a backlog line marked proposed read the same. A deferred backlog line reads `deferred until you ask for it`. An add-on is the showrunner's to settle (user 2026-10-12, below), so it reads `the showrunner decides: build, save for later, or drop`: the unit sends its add-ons to the showrunner, which answers `current`, `next` or `drop` for each.

  A unit's worktree is taken from its plan path in `phase_table.show_production`. The Proposed by and Proposal cells are cut at 110 characters and State at 140. With no rows it prints `no open proposals`.
- **Nightly list (`scripts/nightly_review/candidates.py`, `/showrunner:nightly`, user 2026-10-12).** Prints one Markdown table, `| Pick | Night | Area | Candidate | Gain per week | State |`, of every nightly-review candidate still open. The ledger (`nightly-review/ledger.md` under `XDG_STATE_HOME`, else `~/.local/state`) is the one record. A night's proposal and each of its Also found and Noted items is a line of its own, `- <night> <scope>[, also found|, noted]: <title> [gain/week: <gain>] — <state>`, open while it ends `proposed` or `deferred`. Printing changes no file but the vault note below.
  - **Order.** `rank` reads the tag: `N min` or `N h` is user-visible time, `N%` is a share of tokens, and a line with no tag or other words is unmeasured. Time comes before tokens, each largest first; unmeasured lines come last, in the ledger's order. `/nightly_next` takes its candidates and their order from this table.
  - **Pick.** Row one reads `recommended` only when its gain is measured; with nothing measured no row is marked.
  - **Vault note.** `write_note(body)` rewrites `~/rust/hanadocs/nightly improvement list.md` after the table prints and after every `record` that exits 0; `NIGHTLY_REVIEW_NOTE`, read at each write, replaces the path. The note is the line `Read <YYYY-MM-DD HH:MM> <zone label> from the nightly review's ledger on <short host>. The nightly review rewrites this note; edits made here are lost.`, a blank line, then the table as printed or `no open candidates`. The read time is in the user's zone, and the host is `socket.gethostname()` up to its first dot. The write is a dot-named temp file in the note's folder, mode `0o644`, then `os.replace`. The ledger stays the one record and the note is a copy: nothing is written when the note's folder is missing or this machine holds no `ledger.md`, so a machine without the ledger never replaces natedev's note. Every step after the path is chosen sits in one `OSError` handler, the two existence checks included, because `Path.is_dir` and `Path.is_file` can raise: a failure prints `candidates: cannot write <path>: <error>` to stderr and leaves stdout and the exit status as they were. The note sits at the vault root, outside the excluded `showrunners/` folder, so the vault's Git sees every rewrite. A test keeps `NIGHTLY_REVIEW_NOTE` on a temp path, because the default is the live vault.
  - **`record <report>`.** The watcher runs it on `Nightly proposal ready: <path>`; the night is the report's folder name. It appends the proposal (`# <title>`, `**Target:**`, `**Gain per week:**`) and each item under `**Also found:**` or `**Noted:**`: a `- ` or numbered line, whose bold lead is its title and whose closing tag is its gain. A paragraph closes the item list, so a list of what was denied that night is no candidate. A line whose start (`- <night> <area>: <title>`) the ledger already holds is not written again: a second run adds nothing, and a decided line keeps its outcome. A report with no title or target exits 1 and writes nothing.
  - **Earlier lines.** Before 2026-10-12 a smaller item's outcome was written on its night's line as `; from Also found: <title> — <outcome>`. Those stay as written; every item still open then got a line of its own.
- **Nested showrunners (`showrunners.py parent|children|root|tree|attach|detach`, `/showrunner:attach`, user 2026-10-09 "showrunners manage showrunners - ad hoc depth", built from 2026-10-12; its plan, `docs/plans/build-followups-nested-showrunners.md`, was removed 2026-10-13 after the live checks closed, and this entry is the record).** A showrunner may report to another, to any depth. All six phases are built: the tree and its rules, the root's count, the dailies row, launch, promote, and wrap with arbitration and restart. The user, 2026-10-12: "the idea of nested showrunners is to be able to have them available for direct interaction from me but also have a natural home under an L1. But then we can have a set of unit directors underneath the nested showrunner to distribute a larger set of work".
  - **One stored fact.** `<SHOWRUNNER_STATE_DIR, else ~/.local/state/showrunner>/<child slug>/parent` holds the parent's slug. Nothing else is stored: `edges()` reads every production with a complete update timer (`timer_slugs`, which starts no process) and keeps an edge only while both ends have one, so a wrapped production leaves no broken tree. It is state and not a doc line, so either side attaches without a commit in the other's checkout.
  - **A child is not a unit.** It has no Units row, because about ten readers take a row to be a unit director.
  - **Lookups.** `parent_of(slug)` (empty for a root), `children_of(slug)`, `root_of(slug)`. The CLI verbs refuse a slug with no update timer; a root prints no parent and no children. `tree` prints `<slug>\t<session name or <not running>>`, two spaces deeper per level.
  - **`attach <child> [<parent>]`** with no parent takes the caller's production (`own_slug`, from `CLAUDE_CODE_SESSION_ID`). It refuses: an end with no update timer; a child that is its own parent; a child already attached (`detach it first`); a parent that already reports to the child. The file is written beside itself and moved over. **`detach <child>`** removes the file, even one whose edge no longer counts, and refuses a child with none.
  - **A cycle** cannot be attached. One written by hand counts for none of its members (`_on_cycle`), so each is a root and `root_of` always ends.
  - **Telling.** Attach and detach send each showrunner one line through `send.py` (`--from showrunners --key showrunner-tree:<child>`), but for the caller's own production, and print `told <slug>`, `<slug> is not running: tell it when it starts` or `could not tell <slug>: <reason>`. A failed send leaves the edge in place.
  - **Rules for the sessions** are `/showrunner:produce` → Throughout → Nested showrunners: the root shows every item that needs the user, and the user may still work with any showrunner directly (user, 2026-10-12); a broadcast is never passed to a child showrunner; the user's words go down one level at a time; an item for the user goes straight to the root; a question between productions goes to the parent.
  - **Machine-wide faults.** `highest_running(runners)` gives each running showrunner with no running one above it. `tmux_names.fault` tells those when `faults_to` is not live, so the user hears once; below a root that is down, the nearest running showrunner hears.
  - **What needs the user, across the tree (phase 2).** Each showrunner's needs-user list holds only its own items. `place_of(slug) -> Place(root, below)` reads the tree once: `root` is empty for a root, and `below` holds every production under a root, nearest level first (`descendants_of`, `user_facing`). A root's open-questions count, its footer's `nothing needed` and its list on request cover its own list and every list below it; any other showrunner covers its own alone. Nothing is copied to the root, so an item its owner clears leaves the root's count at the root's next reply with no message between them. `dailies_render.py --footer` takes `--below <list>` once per lower production and `--reports-to <root>`: a lower list that cannot be read adds the bullet `<slug>: needs-user list unreadable`, keeps the footer from saying `nothing needed`, and never fails the root's footer; a showrunner under a root gets the bullet `reports to <root>`. `update_registration.py footer` and the footer hook pass both from `place_of`. The hook (`open_questions(productions, below)`) checks the count against all those lists and skips the count check while one is unreadable. `update_registration.py open --production <doc>` prints every due item as `<n>. <owner>, since <day and time>: <text>`, oldest first across owners, then `deferred until <time>: <owner>: <text>`, then each unreadable list, then `open: ok — <n> due, <k> deferred`. `scripts/hooks` now imports `scripts/production/showrunners.py`, late, inside `place_of`, because the production scripts import the hook module.
  - **A parent's dailies show each child as one row (phase 3).** Every `dailies_input.py` run ends by saving `<SHOWRUNNER_STATE_DIR or ~/.local/state/showrunner>/<slug>/dailies_last.json` (`last_report` in `dailies_render.py`): `written`, `zone`, `interval` (minutes, `null` when it reports on demand), `units`, `held` and `rows`, each row a name with `started`, `eta`, `earliest` and `latest`, or a name alone when it has no ETA. The rows are this report's chart rows and then one row per production below it, and the counts take theirs in, so a parent reads one file and never the ones further down. The same run reads each direct child's file and its lists into the input (`children`: `name`, `report`, `open`, `unreadable`, `expand`; and `reports_to` under a root), so the renderer still renders from its input alone. A child's times move from its zone to the parent's. The row's note is `<n> units, <k> held`, then `as of HH:MM` past two of the child's intervals (always for one on demand), then `<n> open questions`; a child with no usable file reads `?  no report yet` and the builder prints `children: unavailable` with the reason. `--expand <child|all>` adds `<child>/<row>` rows. Saving the file can fail without failing the report (`saved report: unavailable`). With nothing below and nothing above, the input and the report are unchanged.

Trust counts for the folder, its `--show-toplevel` and its main checkout (a worktree shares its main checkout's trust), never a trusted parent folder (G1 live check, 2026-10-13: the child sat on the trust prompt for the whole wait; `docs/as-built/herdr-adoption.md`).   - **A parent promotes a unit to a child showrunner (phase 5).** `scripts/production/promote_showrunner.py <unit> --production <child doc> --model <id> --effort <level> [--check]`, run by the parent (`/showrunner:promote_showrunner`). `checked(name, child_doc) -> Promotion` refuses (exit 2, nothing stopped) when: the caller runs no production (`showrunners.production_of(CLAUDE_CODE_SESSION_ID)`); the unit (`<name>-unit`) has no Units row, or a retired one; `unit_lookup.marked_units(parent)` has no `LiveClaude` for it; its session record's `status` is `busy`; `unit_effort.verdict` on `read_place(place, ansi=True)` is `Skipped`; `$PLAN_DELEGATE_ACTIVE_DIR/<session id>` exists (a run open keeps its seats); `git status --porcelain` in its Worktree cell is not empty; the child doc is untracked or modified; `add_showrunner.checked(child, parent, ending=<the unit's tmux session label, empty for a herdr unit>, start_in=<the worktree>, config_dir=<its account directory>)` refuses, an untrusted worktree included; or its account directory cannot be read. The last line ends `same account, no move`; `projects` and `sessions` are linked into every account directory, so the resume finds the transcript on either account. `unit_status.sh` lists units from the Units table and their marks only, so the retired row is all it needs. Tests (`test_promote_showrunner.py`) run in process with stand-ins for tmux, the pid, the session lookups, `add_showrunner.main` and the account, and real git in temporary repositories.
  - **A wrap leaves no state files (user, 2026-10-13).** Exiting a showrunner cleans nothing up, by design: its timer, footer switch, review pause, open questions and state folder are what a restart resumes from, a tick to a closed session logs `skip session not running`, and quota alerts skip a showrunner with no address. The wrap is the end. After the `tree` step, `production_lifecycle.tidy_state(slug)` calls `tidy_wrapped.tidy(slug)`, which deletes `<state dir>/footers-off/<slug>`, `review-paused/<slug>.json`, `outstanding/<slug>.json` and the `<slug>/` folder (prompts, dailies, LOG backups; the doc in git keeps the LOG), and prints `tidy: ok — removed <paths relative to the state dir>` or `tidy: ok — no state files`. A failure prints `tidy: kept — …` and the wrap goes on, since leftover files break nothing. `tidy_wrapped.py <doc>…` is the sweep for productions wrapped before this step: it deletes only for a doc whose status line says `wrapped` and whose slug has no `showrunner-<slug>` notifier instance, refuses a slug naming a shared folder (`footers-off`, `review-paused`, `outstanding`), reports each refusal on stderr as `kept: …`, goes on to the next doc and exits 1 if any was refused. Tests: `test_tidy_wrapped.py`, and the wrap test in `test_production_lifecycle.py`.
  - **A wrap leaves no edge (phase 6).** `production_lifecycle.refuse_running_children(slug)` runs before any other wrap step of a running doc: every slug in `showrunners.stored_children(slug)` (each `<state dir>/*/parent` that names it, counted or not) with a `current_address` holds the wrap as `children: held — <a, b> still report(s) to <slug>; wrap each first, or detach it with …`, naming `showrunners.py detach <child>`, and a session-record error fails it. A child whose timer outlived its session does not hold it. After `notifier.sh remove`, `showrunners.release_edges(slug) -> Released(parent, orphans)` unlinks the production's own parent file and each orphan's, and the wrap tells the parent `<slug> wrapped, so it no longer reports to you.` (key `showrunner-tree:<slug>`) and each orphan `<slug> wrapped, so <child> reports to no one: it is a root now.` (key `showrunner-tree:<child>`) through `tell_others`. The step prints `tree: ok — detached from <parent>; <a, b> now root(s); <each tell result>`, or `tree: ok — no parent and no child showrunners`. The files go, not only the edges: an edge to a production with no timer already counts for none, but its file would count again for a later production of the same slug. A rerun after the step finds no files and prints the second form. Tests (`test_production_lifecycle.py`) point `SHOWRUNNER_STATE_DIR`, `SHOWRUNNERS_SESSIONS` and `SHOWRUNNERS_SEND` at temporary stand-ins and give a live session the test process's own pid.
  - **Who decides a shared resource (phase 6).** `produce.md` → Nested showrunners: a contested Mac window or build hold goes to the lowest showrunner whose subtree holds every contender; the order of promotions to a shared destination is the parent's; disk room and quota stay with the root.
  - **Restart (phase 6, read from `scripts/shutdown/`, no change).** The shutdown inventory takes a session to be a showrunner from its update timer's `TARGET` (`_registered_productions`), records its tmux session and its process's config dir, and `restart.py` resumes it with `--resume <id> -n <name>` and `/showrunner:produce <doc> resume`, in the same tmux session, with an account prefix only when that config dir is not `~/.claude`. A child started by `add_showrunner.py` runs on `~/.claude`, so it comes back on the showrunner account. The parent file is keyed by slug and nothing in shutdown touches it, so the child comes back attached. The live check with a scratch child is the showrunner's.
  - **Calls made in the plan**, each a one-line change: the commands are `/showrunner:promote_showrunner` and `/showrunner:add_showrunner`, beside `promote_unit` and `add_unit`; a phone push comes from the showrunner that owns the item; a child shows as one row until expanded; a child's branch never merges into its parent's; the reporting phases came before launch and promote; the showrunner account is the main config dir's login, with no new role in `accounts.py`.
  - **One machine.** The parent file and the timers are local, so a showrunner on the Mac cannot attach to one on natedev.
- **Queued messages.** `send.py` keeps a message that did not arrive in `STATE/queue/session-<Claude session id>.jsonl` when a live session answers to the recipient (`sessions.addressed`: `uds:` socket, name now, or a name it alone once had), and under the name as given when none does, which the `QUEUED` line then says; a `session:<id>` address is always kept under `session-<id>`. A delivered keyed send removes its queued copy, and `send.py retire --to --from --key` removes that key's messages and the sender's unkeyed ones (`/shutdown` uses both). `send.py pending` (no name: the caller's session; or a name) reads the session's file, the files of its name now and its socket, and those of its former names that no live session has now, so what was kept under a name before 2026-10-08 is still found.
- **The tmux label** still follows a rename (`tmux_names.py`). It is a display name; no tool finds a pane by it. `live_sessions` leaves out a session whose process has another live session among its ancestors (`_ancestors`, `PPid:` from `/proc/<pid>/status`): a claude started inside a pane, even through a shell, inherits its `TMUX_PANE`, and the pane is the outer one's. `tick` skips a tmux session already named for one of its sessions before the `more than one Claude session` count (2026-10-11).
- **`adopt.py <production doc> --scratch <SCRATCH> [--gone <unit>]`** moves one production over, run once by its showrunner in its own checkout. For each row that is not retired it finds the one tmux session the old Session cell leads to: the session of a live Claude that has or had that name (`formerNames`), or the tmux session still labelled with it. If any row's session is not found, or two sessions answer to one name, it changes nothing, lists those rows and exits 1; `unit_lookup.py mark`, or `--gone <unit>` for a unit with no session now, then settles each. Otherwise it marks the sessions, moves the saved report state from the old names to unit ids (`rename_state.rename_scratch`), registers the doc, and last removes the Session column and commits the doc without pushing. A second run finds no Session column and changes nothing. A run stopped part way still has the column, so the next run finishes it.
- **Run state is not set.** No command sets a unit's run state and no tmux mark holds one: `unit_lookup.py` has no `state` call, and `adopt.py` carries no run state over. Every reader calls `unit_lookup.run_state` (**Unit status** above). A `SHOWRUNNER_UNIT_STATE` mark left on a running tmux session is not read. A stored mark would be a copy that a unit, the showrunner and adopt each have to keep right, and one registry write could lose it for every finished unit.
- **Not moved.** Queued messages and natedev holds need no move: both are keyed by the Claude session id (**Queued messages** above; a hold file is named by its holder's session id, `docs/as-built/build-targets.md`). Stall-watch stretch files written under old names are left behind, and each unit starts a new stretch.

### Waits, renames and alerts: `waiting.py`

Each subcommand takes `--production`; `main` catches `merge_checkpoint.Stop`, so a bad doc fails as one line. A unit is named by its Unit value, or by its session's name now. `units_from_doc` reads `live_unit_table` and the lookup, so `search`, `quota` and `agenda` pass over a retired unit, and `named_unit` (`scratch-test`, `eta-request`) refuses one as `unknown unit <name>`.

- `scratch-test <unit> --tests "<command>" --state-dir <dir>`: a detached temporary worktree at the unit's branch tip, `merge --no-commit --no-ff <merge branch>`, then `sh -c <tests>` into `<state-dir>/scratch-test-<unit>-<YYYYmmdd-HHMMSS-ffffff>.log`. `ScratchGreen(log) | ScratchRed(last 4 lines, log) | ScratchConflict`; the verdict prints first; the worktree and merge state are always removed; nothing is committed or pushed. A red never says `blocked`; a conflict is a `failed` line, not a red. The log path feeds `ci_points.py notice lift`.
- `waits`: `cargo-berth board --json` overlaps (an `unconfigured` envelope reads `berth not configured`) and the LOG's `block: <waiting> on <unit> (code|files: …), clears ~HH:MM` / `block cleared: …` pairs as `WaitOpen(since) | WaitCleared`. Each open wait prints its age and `act now` at 60 minutes open or 30 minutes past its clear time. A `block:` or `block cleared:` line whose waiting unit is in `retired_units` is dropped; a live unit's wait on a retired unit stays.
- `search <old> <new>`: `git grep -n -F <old> <branch>` and `rg -n -F --hidden --glob !.git <old> <worktree>` for every unit; one line per site.
- `quota --state-dir <dir> [--notice "<text>"]` (else stdin): `Quota alert:` → `HoldQuotaAlert(account, line)` and "start no new delegate work on `<tool>`" (or "delegation continues on Claude…" when the notice says every function moved, or "keep delegating on `<tool>`…" when a Codex notice says nothing was switched); `Quota alert acknowledged:` → `ClearQuotaAlerts`; `Quota restored:` → `RestoreQuotaAlerts` and "delegation on `<tools>` can resume". It sends `From the showrunner: <action>` to every unit through `send.py`; exit 0 prints `send`, exit 1 `queued`, both delivered. Held alerts live in `quota_seen.json` and print as `held: <alert>`.
- `agenda --state-dir <dir>`: `AgendaOpen(unit, phase) | AgendaNotDue` when the current phase (from the last `### STATE` block line `<unit>: Phase …|follow-up …`) began over eight hours ago, or its ETA (from `dailies ETAs:` lines through `phase_eta`) is over eight hours after its start. The start is the unit's previous code merge line in `LOG`, else its `added …` line. Deduplicated by `<unit>|<phase>` in `agenda_seen.json`.
- `eta-request <unit> --phase <phase> --state-dir <dir>`: `EtaRequested | EtaNotYetRequested`; once per `<session>|<phase>` it prints `request /unit:eta: <session>` and writes `{"requested": true}` in `eta_seen.json`.
- `update_state(path, change)` is the one locked writer for all three state files: `fcntl.flock` on `<path>.lock`, re-read under the lock, no write when unchanged, a unique temp file, then `os.replace`. `dailies_input.py` imports it with `eta_requested`.
- `eta_moment(text, line_moment)` resolves a weekday ETA to its nearest occurrence within three days of the log line, and `HH:MM <ZONE>[ tomorrow]` on the line's day.

### Status and stall watch

- **`unit_status.sh` units.** `unit_status.sh <state-dir> <user-zone> --production <production doc>` takes its units from `live_units.py --production <doc>`. `--showrunner <name or slug>` is still accepted for a prompt written before; it finds the showrunner by its name now or its slug, so such a prompt fails after a rename until the showrunner registers again. Each block is headed by the unit id, and its text is read with `session_pane.py read unit <slug> <unit>`.
- **`live_units.py`** lists a production's units that are not retired, in doc order, each with its place and Claude session as they are now. `live_units.py --production <doc>` prints `<unit>\t<place>\t<gone|live|unknown|stopped>\t<name>` per unit, the place as `unit_lookup.place_text` writes it; `live_units.py <showrunner name or slug>` is the older form. A showrunner that no update timer names, or a tmux that cannot say, exits 1 with the reason. `units_of(runner)` and `live_unit_names(runner)` take a `Showrunner`.
- **`unit_status.sh`** `waiting_on_user`: nothing when a spinner shows in the last 12 lines; `FORM WAITING on you in <unit>: …` for `Enter to select`. Otherwise it reads the last turn-end line (`^\s*(— )?(holding|gate|decision|blocked|done):`). `decision`, `gate` and `blocked` are waits on the user: first sight prints `=== DECISION for you from <unit> ===` … `=== end <unit> ===` and records the key in `decisions_seen`; a repeat prints `STILL WAITING on you, <unit>: …`. A wait naming `showrunner` or a peer unit (whole word) is the showrunner's: no wait line, and only `blocked:` prints `BLOCK in <unit>, open <age>: …`, aged from `blocks_open`. Any other turn-end clears the block entry.
- **`stall_watch.py`** runs every minute under a nonblocking lock. Per unit whose tmux session carries the production's mark (`unit_lookup.marked_units`), it skips one whose `unit_lookup.run_state(<Worktree cell>)` is not `UnitState.RUNNING`, deleting its stretch. It also skips a unit whose production row begins with the retired marker, found through the checked notifier doc. It does not use `run done` text from the Plan cell. `WAITING_KINDS = ("done", "blocked", "gate", "decision")` and `HOLDING_KIND = "holding"` build `TURN_END` with a named `kind` group. A last turn-end of a waiting kind writes a fresh stretch and sends nothing. `holding` with nothing running, or no turn-end on screen, is a stall candidate: after `stall_minutes` with no running work (`zsh`, `bash`, `sh`, `implement.sh`, `review.sh`, `verify.sh` descendants) it bumps the unit once and tells the showrunner once per stretch. All sends share one 90-second deadline.

## Invariants

- The production doc is read only through `read_production`, `production_field`, `cell_value` and `unit_rows` (the retired readers read through `unit_rows`); Units rows are read cell by cell, since real rows are backticked and carry commentary.
- `plan_cell_is_retired` is the only test of the retired marker: `unit_is_retired` (which `live_unit_table` and `retired_units` read) and `adopt.unit_rows` call it, and no other file tests the word. The marker counts only at the start of the Plan cell.
- Merge history comes only from `merge_branch_history` over first-parent subjects; `LAST_MERGED` is never an argument or a memory. A shrink merge never counts as a code merge, a CI count or a gate clear.
- Every refusal comes before any write: `add_unit.py` refuses in `launch_request`, the shutdown-state check (before `preflight`), `preflight` or the tmux check before the stub, row or commit, and a shutdown refusal kills no tmux session; `--check` writes and starts nothing. The director resolves in `preflight`, so promotion never stops a session it cannot relaunch.
- `merge_checkpoint.py` leaves the merge branch as it was on red. `reset --keep HEAD~1` runs only when `HEAD` is this merge and is not on origin. Promotion targets the pushed merge-branch tip, never the earlier checkpoint merge. `main` is pushed only when it holds no commits outside `origin/main` and `origin/<merge branch>`, and never with force.
- The dailies builder's one pre-check write is idempotent pruning of this production's retired generated phase notes. Every other write waits until every check has passed. Every builder call passes `--render-state`, the same file the renderer gets as `--state`.
- One state directory: `eta_seen.json` and `review_watch.json` live in `DAILIES_STATE_DIR` for every caller; a second directory forks the once-per-phase and first-alert records. A doc-contract test pins `produce.md` and `dailies.md` to the same path.
- `then` reaches the renderer unchanged; the renderer refuses, it never rewrites.
- The idle group changes only which sections a `simple` dailies prints. The timeline, the footer, the saved state and the `dailies ETAs:` line carry every unit at every length.
- An activity on a closed phase leaves that phase's record as `finish-phase` wrote it: status, `finished_at` and elapsed time. The printed `review trial:` line keeps its form, which `merge_checkpoint.py` parses.
- The stall watch's standing-by, run-finished and retired-row skips, then its waiting-kind reset, run before any bump or notice. The turn-end pattern is built from `WAITING_KINDS` and `HOLDING_KIND`, so the pattern and the wait test cannot drift.
- Unit directors launch only on Claude. `production` has only `[production.claude]`; `claude --resume` never runs without resolved flags.
- `agents_config.sh` is bash only (call it through `bash -c`) and must keep working under `/bin/bash` 3.2 (no associative arrays, no `${var,,}`); the style-fix pipeline runs it unattended every ten minutes on both machines.
- `add_unit.py` asks tmux about a launch name as `=<name>`; a plain `-t <name>` prefix-matches another session. Every other tool addresses a pane by its id.
- Tests never start a real `claude`, `tmux`, `systemd-run`, `ssh`, `validate_and_push.sh` or CI, never write `~/.claude/config/`, `~/.local/state/` or a real production doc, and push only to a temporary bare repository. Python is typed with no `Any` and no file-level ignores.

## Calibration and gotchas

- **`config/agents.conf` clean filter.** `.gitattributes` gives it `filter=claude-agents-conf`, whose clean step (`scripts/agents/clean_agents_conf.sh`) pins staged content to the index: `git diff` is empty for it and a plain `git add` commits nothing. Stage a real change with `AGENTS_CONF_COMMIT=1 git add --renormalize config/agents.conf`, then confirm `git diff --cached --stat` lists it. Merging it into a machine's checkout rewrites that machine's live registry, so live `/agent` retunes there are lost.
- Sourcing `agents_config.sh` may run the Codex catalog refresh when its state is stale; `--check` writes nothing of its own but does not promise zero writes to the registry's state. Tests set `AGENTS_CONFIG_FILE`, `CODEX_CONFIG_FILE`, `CODEX_MODELS_CACHE_FILE` and `CODEX_CATALOG_SYNC_STATE_FILE` (newest) to temporary paths.
- `--check` does no tmux lookup: a tmux name collision can still refuse after promotion has stopped the session.
- A re-run of `add_unit.py` must name its original mode; the mode comes from the commit subject, then the Plan cell, then the stub.
- `ssh`'s own exit status is always 0 here; the Mac pull is read from the `rc=` line it prints. The Mac pulls from `natedev:<first Promote checkout>`.
- `merge_checkpoint.py` counts a `basedpyright` Merge tests command green when its last line is `0 errors, 0 warnings[, 0 notes]`, whatever its exit status.
- CI point: due at 5 code merges; `ci collect` requires job `Test Suite` by name. The review table is `report --since 2026-09-28`.
- `review_watch.json` is written after the push and the LOG line: a crash between them repeats the alert once (at least once).
- Dailies: an ETA first seen over 1 hour ago is stale; an ETA move of 15 minutes or more (`CHANGE_NEEDS_WHY_MINUTES`) needs `eta.why`; `parse_time` treats a time over two hours past as tomorrow; updates are capped at 240 characters for `simple` and 480 for `page`.
- The renderer's ETA-change check reads its own state; `check_render_state` runs before the clock restart, so a refused user-run dailies leaves the clock where it was.
- The renderer exposes no list of required fields, which is why the builder names five itself.
- Agenda threshold is 8 hours; waits act at 60 minutes open or 30 minutes past the clear time; the weekday ETA window is ±3 days.
- `log_events` dates a date-less LOG line by walking backward across midnights; a gap over 24 hours between timestamped lines is invisible.
- Producer output shapes are not the obvious ones: the unconfigured berth board is a JSON envelope with exit 4, the ETA line is `dailies ETAs: <unit> <phase> <eta>; …`, and an account stem can hold a space (`codex 1`). Test fixtures come from calling the producers.
- `unit_status.sh` routes `gate:` exactly as `decision:` and `blocked:`, while the stall watch treats all four waiting kinds as silent; a unit at a gate is quiet in the stall watch and flagged to the user by the status script.
- `unit_status.sh` is zsh.
- Units are found only by their tmux marks. A unit director started in a herdr pane has none: `production_lifecycle.py load` reports it as `session: gone`, and `waiting.py quota` cannot reach it (`docs/as-built/herdr-trial.md`, finding 1).
- `test_unit_status.py` copies `add_unit.py`, `live_units.py` and `showrunners.py` into its test tree, so a new import in `live_units.py` needs a new entry in that list.
- `waiting.py waits` rebuilds waits from the LOG alone, so filtering the doc's rows never reaches it; it filters on the waiting unit's name through `retired_units`.
- The stall watch reads `run-finished` and `standing-by` from the unit's run records (`unit_lookup.run_state`). The production doc contributes the Worktree cell and the retired marker at the start of the Plan cell.
- Idle: `IDLE_LIMIT` is 80 characters; `idle.until` is a naive local time in the report's zone, compared with the renderer's naive local now.
- Recorder: `_event` stamps the phase in state on every event, active or closed; nothing else carries an activity's phase. When the last phase is closed but an activity is open, `progress` prints the scope and round tables from that phase's last recorded values and shows the activity as the running row. `No active phase to report: …` remains for a missing or closed phase with no open activity.
- The recorder other units run is the main checkout's copy under `~/.claude/scripts/delegate/`; a change in a worktree reaches them, and their `review-trial` line, only when promoted.
- `showrunners.py` is mode 0644: call it through `scripts/lib/py`.
- `already at` in a promote line means main was at the tip before the run; no other line uses it.
- In an enrolled repository the shrink's first plan-doc write goes through the Edit tool; a write from a script is never claimed by the first-touch hook.
- Sandboxed seats have no writable temporary directory and cannot run the stall-watch suite; run it from the main tree.

## Why

- **Scripts hold mechanics; command docs hold judgment.** Each showrunner step was given a script-or-judgment verdict. Script: zone time, log and STATE, footer, open/load/wrap, registration and prompt, merge/test/push/promote/record, CI counting and collection, review-watch escalation, gate notices, scratch tests, wait ages, agenda thresholds, rename search, quota fanout, the dailies input. Judgment: relaying the user's words, verifying a unit's claims, compacting a blocked pane, the overlap notice and restructure holds, whether a new public item has a consumer, design-check freshness and defects, the repair owner for red CI, classifying a wait as code, files or preference, landing order, permission blocks, close-out approvals, open topics and who acts next, `then` and goal text, and phone-alert urgency and wording.
- **The mode is in the commit subject**, not a Units column: the subject already records it, and a pre-filled Units row is adopted, never rewritten to the script's form.
- **Code commit before the shrink.** The code-ready notice can go out the moment the phase's code commits; the shrink runs beside the next phase's seats and lands as a plan-doc-only merge with no tests, ledger row or CI count.
- **`LAST_MERGED` is read from merge subjects**, never passed in, so a resumed or compacted showrunner cannot supply a stale value. First-parent history keeps a subject carried in by a merged side branch from counting.
- **A finished run is a named state.** `run-finished` is read from the run record's `run_finished` event; the stall watch reads that named variant and does not infer completion from production-row prose.
- **The Units row is the one retired marker.** Every reader of the Units table follows it, and the status script finds the production doc on its own through `checked_doc`, so retiring a unit changes no caller's command line. The marker counts only at the start of the Plan cell because a live unit's Plan cell can use the word in its commentary.
- **A live unit's wait on a retired unit still prints.** Hiding it would hide a stuck unit.
- **`merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` do not skip retired rows.** A retired unit sends no checkpoint, and the wrap already passes a unit whose branch is gone.
- **No named type carries an activity's phase.** `_event` already stamps the phase in state on every event.
- **The renderer refuses a chained or string `then`** rather than rewriting it: a silent rewrite would hide the defect from the showrunner who wrote it.
- **The review alert is at least once.** Writing `review_watch.json` before the alert would make it at most once, and a lost alert is the worse failure. The alert writes its LOG line directly; routing it through `update_registration.py log` would add a stray `log: ok` line and couple two commands.
- **No `queue` command.** Arrivals are messages in the showrunner's own session, and ordering them is judgment.
- **One verdict type per flag.** `--ci-green` and `--smoke-passed` are separate flags, each checked at its own step against the same tip; a mismatch is a hold line, not a user topic.
- **Resume flags come from a checked `bash -c`, not a one-line substitution:** a failed substitution would run `claude --resume` with no flags and skip the family check.
- **No `[production.codex]`** and no Codex director: unit directors launch only on Claude. Pinning a one-family function keeps every-function switches (`/agent` "all on codex") from breaking director launches.
- **Unit directors default to `opus:xhigh`** (the user, 2026-10-07, moved back from `sonnet:xhigh`). Test fixtures write their own rows, so they test that a row changes the launch, not the live default.
- **The showrunner settles a unit's designs and add-ons (user, 2026-10-12: "when it comes to designs you absolutely should be able to tell units what to do and change. I do not have to be the one to approve").** A unit in a production brings a design choice, a Pending decision about how something is built, and its pending add-ons to the showrunner, whose answer settles them; the showrunner may also change a unit's design unasked. The user keeps two kinds: an action that cannot be undone, and a choice only they know the answer to. The rule is written once per reader: `docs/production_format.md` → `<ProductionUnit/>` item 2 for the unit, `/unit:add_ons` → `<ReviewPendingAddOns/>` for the add-on message and its answer, and `/showrunner:produce` → Throughout → Designs and add-ons for the showrunner. A run outside a production still asks the user. `docs/decision_criteria.md` is unchanged.
- **Open questions show only as a count (user, 2026-10-12).** A showrunner asks each question once in full and records it in `open_for_user`. After that its Waiting on block says only `There are {n} open questions for you.`, n being the `OUTSTANDING` items now due across the productions its session runs. `scripts/hooks/showrunner_footer.py` enforces it (`open_questions`, `open_questions_error`): the count line is the first bullet, any other bullet for the user is refused, and a held quota alert keeps its own line, led by `quota: `. The full list is given only when the user asks, and no command prints it: the showrunner reads its own `OUTSTANDING`. The dailies' sections on what needs the user are unchanged.
- **One source for the zone (2026-10-12).** The user's zone is `config/user_zone.conf`, read through `scripts/lib/user_zone.py`, and nothing else. A production doc's `- **User zone:**` line was parsed in three places: `showrunners.py` (the registry's zone), `add_unit.py` (`Production.zone`, which `merge_checkpoint`, `ci_points`, the dailies builder, `waiting`, `stall_watch` and `update_registration` use) and `hooks/showrunner_footer.py`. Each now returns the setting. A doc that still carries the line loads as before and the line is ignored; a doc without it registers, where before it was refused. `/producer:to_production` no longer writes the line. `progress_history.py eta` reads a typed time in the setting's zone and no longer in the process `TZ`, so `/unit:eta` and `/unit:eta_breakdown` pass no `TZ=`. An empty or missing LOG is not copied, and neither is one unchanged since the newest copy. A failed copy prints `log_backup: <reason>` to the tick's stderr and leaves the check's exit code alone. To restore, copy the wanted file back over LOG. Added after a LOG was emptied by mistake with no copy anywhere.
