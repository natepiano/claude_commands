# Showrunner automation: unit start, checkpoint merge, lifecycle, updates, dailies and waits

## What it is

A set of Python (standard library) scripts in `scripts/production/` that run the fixed, repeatable steps of a production, so a showrunner and its unit directors have little left to remember. One command starts a unit: with a written plan, with a brief the unit director turns into a plan, or on standby. One command merges a checkpoint: ancestry, scope, conflicts, merge, tests, push, promotion to the installed checkouts and the Mac, the review-ledger row and the log line. Other commands open, promote and wrap a production; register its scheduled updates and write its times, log lines and footer; build the dailies input from the status script; count CI points and send the first review-watch alert once; and do the mechanical part of waits, renames and quota alerts. A unit director ends each phase in one fixed order: the code commit first, then the shrink in its own commit beside the next phase. Unit directors take their model and effort from `config/agents.conf`. The stall watch and the status script treat a unit that is waiting on someone else as waiting, not stalled. A unit marked retired in the production doc drops out of the status script, the dailies, the waits and the stall watch, and a `simple` dailies gives each unit that only waits one line in a group.

The problem it solves is the number of manual steps a showrunner has to carry. Each of these was a list in `commands/showrunner/produce.md` that the showrunner had to run by hand, in the right order, on every merge and every tick. The commands now hold the mechanics. The command docs keep only the decisions that need judgment.

## How it works

### Shared conventions

- **Production-doc reader** (`scripts/production/add_unit.py`): `read_production(path) -> Production` (`doc`, `slug`, `merge_branch`, `checkout`, `showrunner_session`, `log`, `zone`), `production_field(lines, field) -> str` (reads `- **<field>:** …`; raises `Refusal` when the field is missing, so no `str | None` crosses the boundary), `cell_value(value) -> str` (the first backticked span, else the text before ` — `), and `unit_rows(lines) -> tuple[int, list[str]]` (the insert index and the data rows of `## Units`). Every other production script imports these four; none parses the doc itself. The slug is the doc's file name less `-production.md`, and `Log` must be relative to the showrunner checkout.
- **Retired units** (`add_unit.py`): marking a Units row is the whole act of retiring a unit. The row stays in the doc, and no caller's command line changes. `plan_cell_is_retired(plan_cell: str) -> bool` decides: the Plan cell begins with the lower-case whole word `retired`, alone or straight after one opening parenthesis, leading spaces ignored (`^\s*\(?retired\b`), as in `(retired by the user, worktree removed)`. The word later in the cell, later inside a leading parenthesis (`(run done; retired by the user)`), `retiredness` and `Retired` each leave the row live. Rows are read by column heading: `unit_table(lines) -> list[dict[str, str]]` returns each row as its cells by heading, so a doc that still has the old Session column reads like one without it. `live_unit_table(lines, slug)` returns the rows that are not retired and `retired_units(lines, slug) -> set[str]` the Unit values of those that are. `unit_status.sh`, the dailies builder, `waiting.py` and the stall watch skip a retired unit. `merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` read every row.
- **Gone units** (`add_unit.py`, user 2026-10-08): a unit is also retired, with no hand edit, when it has neither a worktree of its own nor a tmux session marked as it. `unit_is_retired(cells, marks)` is the one rule and `live_unit_table` and `retired_units` both read it, so dailies, waits, `live_units.py` (unit status, broadcast, the Codex wind-down) and `stall_watch.py` drop such a unit together. `worktree_is_linked` wants `<worktree>/.git` to be a file: a main checkout, where it is a directory, is shared and holds no unit. The worktree is asked first, so a unit whose session is only restarting keeps its row. `SessionMarks` reads the marks from tmux once per read, and only when some row has no worktree; a tmux that cannot say which sessions exist keeps the row. Nothing removes a retired unit from the registry, because the registry lists no units. The rule reads the machine it runs on: a reader run where the worktrees and sessions are not (another host) would see every unit as gone. Tests give fixture rows a linked worktree or a marked session in a stand-in tmux, so none asks the real tmux.
- **The checked doc** (`showrunners.py`): `checked_doc(instance: Path) -> CheckedDoc | NoCheckedDoc` returns the production doc that a notifier instance directory's `conf` passes to `production_check.sh` on its `CHECK=` line: `shlex.split` the value, then take the token after the one whose basename is `production_check.sh`. `CheckedDoc(path: Path)` and `NoCheckedDoc(reason: str)` are `NamedTuple`s; a missing conf, line or token, or a relative path, is `NoCheckedDoc`. `live_units.py` and `stall_watch.retired_units` find retired rows through it. `add_unit.py` imports `showrunners`, so `showrunners.py` never imports `add_unit.py`.
- **Merge-branch history** (`merge_checkpoint.py`): `merge_branch_history(checkout, merge_branch) -> MergeBranchHistory` reads `git log --first-parent` subjects matching `Merge <unit> phase <N>[ shrink] (<short>)`. It offers `last_merge()`, `last_for_unit(unit)`, `last_code_for_unit(unit)`, `code_merge_count()` and `has_code_merge(unit, phase)`, with absence as `NoMerge`. A shrink merge never counts as a code merge. `LAST_MERGED[unit]`, the CI count, the STATE block, the wrap report and the agenda all read it.
- **Step lines**: each command prints `<step>: ok|held|failed — <one line>` and stops at the first `held` or `failed`. `add_unit.py`, `production_lifecycle.py`, `update_registration.py`, `ci_points.py`, `waiting.py` and `dailies_input.py` exit 0, or 2 on a refusal. `merge_checkpoint.py` exits 1 on a hold or failure, and its last line is always `send <unit>: <message>`.
- **Named states**: every optional or alternative value crossing a reader boundary is a `NamedTuple` union (`FieldPresent | FieldAbsent`, `PushedTip | NotYetPushed`, `EtaFresh | EtaStale | EtaPassed | EtaNone`, and so on), never a string or `None`.
- **State directory**: `DAILIES_STATE_DIR` (`<SCRATCH>/dailies_input_state`, in `produce.md`'s State list) is the one `--state-dir` for the dailies builder, every stateful `ci_points.py` call and every stateful `waiting.py` call. It holds `eta_seen.json`, `ci_points.json`, `ci_run.json`, `review_watch.json`, `quota_seen.json`, `agenda_seen.json` and the scratch-test logs.

### Unit start: `add_unit.py` and `/showrunner:add_unit`

`add_unit.py --production <doc> <name> (--plan <path> | --brief <words> | --standby) [--port N] [--owns <paths>] [--resume <sessionId> --cwd <dir>] [--timeout S] [--check]`, run through `scripts/lib/py`.

- **Request.** `launch_request` builds `RequestedUnitLaunch`, whose request-only fields are `requested_name` and `unit = <name>-unit`. The shared `UnitLaunchConfiguration` carries `production`, `branch`, `worktree`, `plan: PlanGiven | BriefGiven | Standby`, `port`/`owns: OmittedCell | SuppliedCell`, `session: NewSession | ResumedSession`, and `timeout`. Exactly one of the three launch states is required; `--resume` also needs `--cwd` and `--plan`.
- **Preflight** (`preflight(request: RequestedUnitLaunch) -> ReadyToLaunch`): the checkout is on the merge branch; the Units table has no other unit on this branch or worktree; an existing row for this unit (`ExistingUnitRow`) is adopted when its Plan, Worktree and Branch cells agree, and its Port and Owns stand (a supplied `--port`/`--owns` must match); a re-run's mode matches the recorded one (`recorded_mode` reads the commit subject, then a `standby` Plan cell, then the stub's `## Source`); the worktree path is free or already this branch's; no local or origin branch exists unless the row and worktree do; a `--plan` exists on the merge branch with the `> **Production:` header; a brief stub, if present, holds the same words. Preflight returns `UnitLaunch(identity=UnitIdentity(unit, session), ...)` with the row and director; `session` is `requested_name`, the name the session is launched under, and it is not recorded. A tmux session already marked as the unit is taken as launched; a live tmux session of that name that is not so marked refuses in `main` before any write. `--check` runs `launch_request` and `preflight` only.
- **Steps**, each skipped when already done: the brief stub beside the production doc at `<its directory>/<branch>.md` (Production header, `## Source`, a zone stamp and the user's words); the Units row (Plan cell `standby` for a standby unit); commit `production(<slug>): add unit <unit> (<plan|brief|standby>)` on the merge branch, which is not pushed here and goes out with the next merge push (user, 2026-10-08); `git worktree add` from the local merge branch, with no push of the unit branch (the unit's first checkpoint push sets its upstream), plus `branch.<branch>.cargoBerthTarget` when the repo has `.claude/config/berth.toml`; the tmux session; the wait for `/remote-control is active` (default 90 s, last 15 pane lines on timeout); one LOG line `added <unit> (<mode>), worktree <path>`. A row is written under the doc's own headings, so a doc that still has the Session column gets `—` there. It prints `<unit> started: tmux attach -t <session>`.
- **Launch.** `systemd-run --user --scope --unit=<name> tmux new-session -d -s <name> -c <cwd> -e SHOWRUNNER_UNIT=<slug> -e SHOWRUNNER_UNIT_ID=<unit> zsh -ic "ENABLE_TOOL_SEARCH=true command claude --model <m> [--effort <e>] [--resume <id>] --remote-control <name> -n <name> --settings '{\"disableAgentView\": true}' <prompt>; exec zsh"`, with every `CLAUDE_*` variable removed from the environment. The prompt is `/unit:direct <plan>` for a plan; for a brief, write the full phased plan into the stub, send it to the showrunner and wait for approval; for standby, do nothing until the showrunner sends work; for a resume, "you are now `<unit>`" with the plan's absolute path in the worktree.
- **Unit status.** A unit's run state is stored nowhere. `unit_lookup.run_state(worktree) -> UnitState` reads it at each call from the `/unit:direct` run records (`~/.local/state/plan-delegate/runs/*.jsonl`, or under `PLAN_DELEGATE_HISTORY_DIR`): among the records whose first event is `run_started` with `working_dir` equal to the unit's resolved Worktree cell it takes the one with the newest `run_started_at`; none is `standing-by`, a last event of `run_finished` is `run-finished`, anything else is `running`. A line caught half-written is left out; records that cannot be read raise `OSError`, and the stall watch then prints `<unit>: its run state is unknown` and leaves that unit alone for the tick. `showrunners.py status` and `showrunners.py ready` still parse their old arguments, do nothing and exit 0, because sessions started before 2026-10-08 hold text that calls them; delete both once no such session is left. Consequences: a standing-by unit handed work is watched for stalls only from the start of its run; a run that died without its finish event reads as running until the next run in that worktree.
- **Callers.** `produce.md` `<LaunchUnits/>` runs `add_unit.py --production PRODUCTION_DOC <name> --plan <unit plan>` per unit (`<name>` is the Unit value less `-unit`; `--standby` for a unit waiting on work). `/showrunner:promote_unit` runs: find the session, check fit (normalized unit name), plan, `add_unit.py … --resume <sessionId> --cwd <cwd> --plan <plan> --check`, `/exit` the session, then the same command without `--check`, then tell the user (both names when the name changed). Typing `/compact` into a blocked unit director and **Resume** stay the showrunner's own.

### Director model and effort: `config/agents.conf`

- `[assignments]` has `production=claude`; `[production.claude]` has `director=opus:xhigh`. There is no `[production.codex]`: unit directors launch only on Claude, and the showrunner is whichever session runs `/showrunner:produce`. The header Consumers list names `production unit directors (add_unit.py)`.
- `director_agent(request) -> DirectorAgent(model, effort: DefaultEffort | Effort(value))` runs `bash -c 'source "$1" && agents_resolve production.director && printf …'` with the `agents_config.sh` from the script's own checkout (`Path(__file__).resolve().parents[1] / "agents/agents_config.sh"`); `AGENTS_CONFIG_FILE` comes from the caller (default `~/.claude/config/agents.conf`). A resolver failure is exit 2 with its first `ERROR:` line; a family other than `claude` is exit 2 with `unit directors launch only on claude; production.director resolves to <family> (<model>)`. Both happen in `preflight`, so `--check` refuses too. `--effort` is passed only for `Effort(value)`.
- **One-family pinning** (`scripts/agents/agents_config.sh`): a function with exactly one family set is pinned to it (`_agents_pinned_family`). Every-function switches (`agents_set_all_assignments <family>`, `agents_set_model <agent>` with no function) leave it as it is and add it to `AGENT_KEPT_FUNCTIONS`; `agent_admin.sh` prints `# kept production on claude: its only set`. A switch aimed at it (`agents_set_assignment production codex`, `agents_set_model <codex agent> production`, `agents_set_row production.director <codex agent>`) prints `ERROR: 'production' runs only on claude: [production.claude] is its only set.`, returns 1 and leaves the file untouched. `/agent production.director <model>:<effort>` changes the row.
- **Resume** in `<LaunchUnits/>` gets its flags first: `bash -c` sourcing `agents_config.sh`, `agents_resolve production.director`, the same non-Claude refusal, then `agents_claude_args`. Only then `claude --resume <session-id> <flags> --remote-control <session> -n <session>`.

### Phase end on the unit side

`docs/delegate/phase_end.md` defines `<PhaseEnd/>`, the one order a loop or verbose phase ends in: (1) code commit (`<CheckpointCommit/>`, with the phase `status: done` and its Work Order still in place); (2) the code-ready notice, whose hash is mergeable now; (3) the plan review, where a defect in the committed phase becomes a follow-up phase run next; (4) the add-on check; (5) worker cleanup and `finish-phase`; (6) the next phase's launch; (7) the shrink beside the new seats, its commit and the shrink notice. With no phase left, step 7 runs, then `<FinalGate/>`. A due `<PeriodicCI/>` point outside a production runs step 7 before step 6, so CI sees a clean tree. The other phase-end docs point to it in one line.

- `<ShrinkCommit/>` (`commands/unit/checkpoint.md`) stages only the plan doc and an approved next-items file, refuses any other staged path, commits `shrink(<plan-slug>): phase N — <title>`, runs `<PushCheckpoint/>` and owns no reservation.
- The shrink notice is `From <unit>: phase <N> shrink <hash> — plan doc only.` or `… — plan doc and <next-items path>.`
- A failed shrink blocks only `<ShrinkCommit/>`; the next `<CheckpointCommit/>` refuses while an earlier `done` phase still has a Work Order.
- **Closing work in the recorder** (`scripts/delegate/progress_history.py`). `start-activity` succeeds whenever the run is active and a phase has been started in it, still active or already closed by `finish-phase`, so work after step 5 with no next phase started (the last phase's `shrink` activity) keeps its row. On a closed phase `activity_started` and `activity_finished` carry that phase's `phase_instance_id`, and the phase's status, `finished_at` and elapsed time stay as `finish-phase` left them; `finish-activity` records status, result and elapsed seconds as it does inside a phase. `start-activity` exits 1 with `Start a phase before starting an activity` when the run has no phase, and with `Cannot start an activity: the run is finished` after `finish-run`.
- **An activity left open.** `start-phase` and `finish-run` close an activity still open, inside a phase or on a closed one, as `interrupted`. A repeated `finish-phase` does nothing: `_finish_phase` returns before any cleanup when the phase in state is not active, so an activity opened after the phase closed keeps running.

### Checkpoint merge: `merge_checkpoint.py`

`merge_checkpoint.py --production <doc> <unit> <phase> <hash> --started <ISO> [--review-trial "<line>"] [--delivers "<line>"] [--shrink] [--also <path>]… [--trailer <line>]… [--regime after|trial] [--holds K] [--merge-defects D] [--excluded "<why>"] [--cancel-prior] [--scratch <dir>]`. `produce.md` `<MergeCheckpoint/>` runs it in the background after the showrunner's own judgments.

- **Doc fields read:** `Merge branch`, `Showrunner checkout`, `Log`, `User zone`, the Units rows (Branch, Owns), `## Hub files` rows naming this unit, **Merge tests**, **Known flakes**, **Push:** (`validate_and_push` default, or `git`) and **Promote:** (`<checkout>[, mac <path>]`, read as `NoPromotion | PromoteTo(checkouts, MacCheckout | NoMac)`).
- **Input rules.** A code checkpoint needs `--review-trial` (exactly `review trial: ux <N> findings, code <N> findings, review-seat minutes <M>, ux check minutes <U>, ux repair minutes <R>`) and a one-line `--delivers`; a shrink refuses `--delivers`. `--cancel-prior` is refused with `Push: git`. `MergeRequest.delivers` and `excluded` are `str`, `""` for absent.
- **Review numbers.** The unit takes the `--review-trial` line from `progress_history.py review-trial`, which reports the phase in state, active or just closed by `finish-phase`. It counts a `finding_opened` event as a code finding when the event names any lens other than `ux`, or no lens. An event naming `ux` and a code lens adds one to each number; the legacy lens word `both` reads as `adversary,contract` through `_finding_lenses` and adds one to the code number. `merge_checkpoint.py` parses the printed line, so its form is fixed. In the review ledger (`review_regime.py`) the code number is every code finding the phase's review raised from 2026-10-07, and the `craft` lens alone before that date; `report` prints its mean per regime as `code findings per phase (mean)`.
- **Owns rule.** A backticked bare name in an Owns cell owns both the root file and the sibling of the previous path. Without backticks the cell splits on commas before ` — `. **Merge tests** are the backticked spans before the first unquoted `(`; a missing field is refused, an empty one means no commands.
- **Steps:**
  1. *ancestry*: the commit exists; it descends from `LAST_MERGED` (skipped on `FirstMerge`); it is on `origin/<unit branch>` after a fetch, else held with "push your branch". A shrink is held here until `has_code_merge(unit, phase)`. A hash already on the merge branch skips steps 2–7.
  2. *scope*: nothing staged in the merge checkout; every path of `diff --name-only <merge branch>...<hash>` is in Owns, a hub row of this unit, or an `--also` path. A shrink allows only the plan doc and `<plan stem>-next.md`.
  3. *conflicts*: `merge-tree --write-tree --name-only` exit 1 is held, asking the unit to merge the merge branch and send a new hash.
  4. *other units*: overlap of this change's paths with each other unit's branch diff and its worktree's `status --short`, printed as data, never a stop.
  5. *merge*: `<scratch>/merge_<short>.msg` (subject `Merge <unit> phase <N>[ shrink] (<short>) into <merge branch>`, body `--delivers` or `Phase plan shrink.`, then trailers), `merge --no-ff -q -F`.
  6. *test*: each package owning a changed file (nearest `Cargo.toml`, named by its directory) through `verify.sh test`, each changed `crates/<pkg>/examples/<name>` through `verify.sh example`, then each Merge tests command, into `<scratch>/merge_<short>_test.log` with `<name>_EXIT=<rc>` lines. A command that cannot start is exit 127. A shrink runs none.
  7. *red*: each red command reruns once alone; green alone and listed in Known flakes continues with a LOG note; otherwise `reset --keep HEAD~1` after confirming `HEAD` is this merge and is not on origin.
  8. *push and promote*. `GitPush`: merge `origin/main` with `--no-ff` when it has diverged, push the merge branch (on failure, abort the merge and reset to the old origin tip if origin did not move). `ValidateAndPush`: `validate_and_push.sh --quick --to <merge branch> --fix-commit "ci(<slug>): format fixes after <unit> phase <N>" [--cancel-prior]`, reset to origin on failure. Then each **Promote** checkout through `promote_local_checkout(checkout, merge_branch, tip)`: it must be on `main`; `merge --ff-only <tip>`, where tip is the pushed merge-branch tip; push `main` only when `main ^origin/main ^origin/<merge branch>` is empty. Then the Mac through `pull_mac_checkout(mac, source)`: `ssh mac "cd <mac> && git pull --ff-only natedev:<first Promote checkout> main; printf 'rc=%s\n' $?"`, judged by the printed `rc=`.
  9. *record*: for a code checkpoint, `review_regime.py add --unit --phase --regime --started --merged <merge commit time> --holds --merge-defects` plus the five review numbers and any `--excluded`; then the LOG line `- HH:MM <zone>: <unit> phase <N> (<hash>) merged as <merge hash>; <tests> green; pushed[; promoted]`. A LOG that already has this line skips the step.
- **Merge report.** Step 8 prints `into: <path> (<branch>) — <why>; unblocks: <what>` as it reaches each place: the merge-branch checkout (`the merge branch collects every unit's checkpoints`; unblocks `<gate id>: <Waiting cell>` for each Gates row whose **Waits on** is `<unit> phase <N>`, else `no gate`), then each Promote checkout and the Mac (`sessions on <machine> run the installed commands from it`; unblocks `the live gate of <unit> phase <N>`). Only a code checkpoint's first merge names a gate.
- **Re-run.** A hash already merged reads `PushedTip | NotYetPushed` from origin, skips the push when pushed, and re-runs every promotion, each a no-op at the tip. A failed promote is re-run with the same command.
- **Overrides for tests:** `MERGE_CHECKPOINT_VERIFY`, `MERGE_CHECKPOINT_VALIDATE_AND_PUSH`, `MERGE_CHECKPOINT_REVIEW_REGIME`, `MERGE_CHECKPOINT_SCRATCH`.

The showrunner still judges, before the call: the other units' overlap notice, new public items without a consumer, the design check. After it: `<ClearGate/>`, `<CrossUnitChange/>`, `<CIPoint/>` and the review watch. It sends the script's `send <unit>:` line and puts every `into:` line in the user update, adding one in the same form for each unit worktree it then merges the merge branch into.

### Production open, promote and wrap: `production_lifecycle.py`

`production_lifecycle.py load|open|promote-main|wrap --production <doc> [--no-ci] …`. `--no-ci` makes the CI, smoke-launch and Mac-run steps print `<step>: ok — skipped: no CI` and is refused together with a verdict flag.

- `load [--resume]`: the checkout must be on the merge branch (or clean before it exists); prints the last `### STATE` block of `LOG`, each unit's last code checkpoint from `last_code_for_unit`, and each unit session as live or gone through `tmux has-session`.
- `open --session <name>` (status `planned` only): creates the merge branch, sets the doc to `running` and writes the session line once, commits `production(<name>): plans for <N> units` with the unit plans, pushes with upstream, adds `LOG` to `.git/info/exclude` and creates it with `# Production log — <name>`. A re-run resumes at the first step not done.
- `promote-main --ci-green <sha> --smoke-passed <sha>`: each verdict must resolve to the merge tip, else held; `origin/main` must be an ancestor of the tip; each Promote destination prints `already at <tip>`, `pushed <tip>` or `advanced to <tip>`; with no destinations it pushes `<tip>:refs/heads/main`; the declared Mac is pulled even under `--no-ci`.
- `wrap [--close-out-done "<exact item>"]…`: each `## Close-out` item must be passed back verbatim, else held; then the verdicts, clean and merged unit worktrees, push, `promote-main`, cargo-berth reservation release, worktree and branch removal (local and origin), `notifier.sh remove showrunner-<slug>`, `showrunners.py remove <session>`, status `wrapped`, commit `production(<name>): wrapped` and push, and a final `| Area | Result |` table. A doc already `wrapped` (a failed final push) resumes at the doc commit and push.
- `produce.md` names each subcommand in `<LoadProduction/>`, `<OpenMergeBranch/>`, `<PromoteMain/>` and `<Wrap/>` and keeps the close-out approvals, the live smoke verdict and the CI, smoke and mirror text.

### Updates, time, log and footer: `update_registration.py`

- `register --production <doc>` on every start and resume (`--session` is still accepted and unused). Needs `CLAUDE_CODE_SESSION_ID`. Order: (1) validate everything while changing nothing: the **Updates** interval (`every N minutes`, default 15; `on the hour` adds `--aligned`), the prompt expanded from `produce.md` between `The prompt:` and `**A tick**` (`<N>`, `<zone>`, `<production doc>` substituted; a missing marker is a failed step), and a production doc with no uncommitted edits; (2) `PROMPT_FILE` (`~/.local/state/showrunner/<slug>/prompt.txt`, root overridable by `SHOWRUNNER_STATE_DIR`); (3) `notifier.sh new showrunner-<slug> --to session:<id> --every <N> --prompt-file … --from showrunner-timer-<slug> --check "zsh …/production_check.sh <doc>"` on every call, which retargets without moving the clock; (4) `stall-watch` and `tmux-names` jobs (`--every 1 --run "<py> <script>"`) only when `notifier.sh status` reports none (`InstancePresent | InstanceAbsent`). It prints the instance's `next_due`. It writes no registry entry, no doc line and no commit: the update timer is the one record of the showrunner.
- `time <ISO or HH:MM>` prints `time: ok — HH:MM <zone>` in the doc's zone, never UTC.
- `log "<event>" [--state <file>] [--before-compaction]` appends `- HH:MM <zone>: <event>`. On every tenth event line and with `--before-compaction` it also writes `### STATE <time>`: one `<unit>: <phase>; last merged phase <N> (<short>)|none; waits on <wait>` line per Units row (phase and wait from `--state`, keyed by session, `not stated` when absent), `Merges accepted but held: …` and `Open for the user: …` from `OUTSTANDING`.
- `footer [--state <file>] [--nothing-needed]`: `FooterState.OFF` (from `scripts/hooks/showrunner_footer.py`) prints `footer: ok — footers off` and nothing else, which drops the Waiting on block too. `ON` runs the renderer's `footer_main` with the zone, the next run (none when the instance is stopped) and `OUTSTANDING` (`~/.local/state/showrunner/outstanding/<slug>.json`). `OUTSTANDING` is rewritten only when `--state` has an `open_for_user` key, keeping each item's earlier `since`.
- `--state` is `SHOWRUNNER_STATE` (`<SCRATCH>/showrunner_state.json`): optional `units` (`{unit, phase, wait}`), `merges_held` (text list) and `open_for_user` (text or `{text, after: YYYY-MM-DDTHH:MM}`). An unknown key or wrong type fails the step, and every item is validated before anything is written.

### Dailies: `dailies_input.py` and `dailies_render.py`

`dailies_input.py --production <doc> --status <file> --judgment <file> --state-dir <dir> --out <file> --render-state <file> [--length simple|page|elaborate] [--holders <dir>] [--notifier <path>] [--user-run] [--at <time>]` writes `dailies_input.json` from the saved `unit_status.sh` output plus the showrunner's judgment file. `dailies.md` runs it, then `dailies_render.py <out> --state <render-state> --log <LOG> --outstanding <OUTSTANDING>`. The scheduled prompt saves `<SCRATCH>/unit_status.txt` and runs `/showrunner:dailies simple`.

- **Units.** `units_from_doc` reads `live_unit_rows`, so the builder asks for no status block and no judgment for a retired unit. The judgment's `unit` is this Units table id, never the session's current name; status blocks and phase records join on it. When rows exist and none is live it refuses with `no live units: every Units row is retired`, after pruning that production's generated phase notes.
- **Status parse.** The file starts `at … / HH:MM UTC`; each `== <session>` opens a block; a session outside the live Units rows, a retired unit's among them (`unknown unit <session>`), a duplicate, a missing block or an unclosed `=== DECISION …` block is refused. Each block is `SessionGone | ClaudeNotRunning | Running` plus flags `FormWaiting | Decision | StillWaiting | Block | TicksFailing`; every other line is `Activity(text)`. It prints `flags first: <session>: …` for session gone, Claude not running, form, decision and a usage limit, and sets `needs_user` for a form, decision or still-waiting flag the judgment left unset.
- **Filled by the builder:** `length`, `zone`, each unit's `unit`, a matching numbered open phase's absent `started` and ETA fields, `build_hold` (true for every unit except a holder's own while holder files exist in `--holders`, default `~/.local/state/build-hold/`; a judgment that supplies it, or markers and holders that disagree, is refused), the `Review watch` topic (via `ci_points.review_watch`, until the line starts `acknowledged`), the `Merge branch` topic (only when held, testing or not pushed), and `next_run`. A judgment value wins; an ETA `time` or `none` keeps the record out entirely. The builder names five required judgment fields itself (`project`, `phase`, `started`, `held`, `update`), with `started` satisfied by the matching record; the renderer names the rest. `then` passes through unchanged.
- **ETA.** `phase_table.py show --production-doc <doc> --json` is called once. Its offset-aware times are converted to the production's User zone. A record is used only when its open phase is numeric, has the matching running plan row, and its number equals the judgment's `Phase <N>`; the title and total remain the judgment's. The record supplies the start, ETA, range, percent, first stated target and reason, so the pane needs no ETA line. A stated basis is collapsed to one line; a projection says `it is now projected from <N>% done`. Every other case follows the pane path unchanged: `unit_status.sh`'s last three distinct ETA lines, normalized by `in_report_zone`. Both paths finish as `EtaNone | EtaStale | EtaPassed | EtaFresh`; a source over an hour old gets `detail: set HH:MM`, and a passed target queues one `request /unit:eta: <unit>` per `<unit>|<phase>`. A held, unchanged ETA stays fresh unless already requested. For a record-backed ETA, `eta_seen.json.text` is its User-zone `YYYY-MM-DDTHH:MM`; the first such build adopts older screen text as unchanged, keeps its `first_seen` and `requested`, and replaces only the text. Screen-backed entries retain the captured line and `also` lines. `requested` survives either path. A timed record also writes `eta.stated` as its stated or projected source minute in the User zone; `record_eta_stated` substitutes the target minute only when the source would make a bare clock resolve to the wrong day. `record_eta_range` omits both recorded range ends when the renderer would place either on the wrong day. No time means no `stated`.
- **Order.** Immediately after `read_production`, `phase_table.py prune --production-doc <doc>` removes this production's retired generated notes; it is the builder's one write before its checks and still runs when every Units row is retired. A prune or show failure prints `phase tables: unavailable — <reason>` and the report continues. Only a unit whose records could not be read takes its start and ETA from the status capture; a prune failure changes nothing else. Then come live units, the one show call, judgment, build hold, review watch, merge branch, `validate_report` (the renderer's `parse_report`), `check_render_state`, the clock, and the remaining writes (`eta_seen.json` through `waiting.update_state`, ORing `requested`; the `request /unit:eta:` lines; `--out`). A refusal leaves the notifier, `--out` and `eta_seen.json` untouched and prints no request. The clock is `notifier.sh status` on a tick and `notifier.sh restart showrunner-<slug>` under `--user-run`, which first creates `LOG`, then appends the `next_due=` line to it.
- **Renderer state check.** `dailies_render.check_render_state(value, state_path, at=None) -> StateClear | StateRefused(field, why)` wraps the renderer's private `load_state`, `resolve_eta_moments`, `check_changes` and `check_idle`.
- **`then`.** `parse_upcoming_work` accepts only a non-empty list of one-line items and returns `UpcomingWork(items) | NoUpcomingWork()`. A string, an item chaining phases (`, then `, `; then`, ` then Phase`, any case) and an item with two `Phase <N>:` heads are refused, naming the item's index. Each item passes `check_words` and `check_then_order` (a leading `<N>:` or `<N>–<M>:` label is this plan's phase even when the item names another plan's doc). A follow-up needs an item naming `the plan at Phase <N>` or `plan done`; a last phase needs the list. `simple` prints `- then: <first item>`; `page` and `elaborate` print each item as `  - <item>` under `- then:`; a single item stays on the `- then:` line.
- **One ETA moment.** `Previous = LastUnitReport(phase, eta: LastReportedEta(text, moment) | NoLastReportedEta, held, first) | NoLastUnitReport`. `resolve_eta_moment` reads a time that names no day on the day it was stated, before anything else: `parse_time(time, eta.stated)`, where `stated` is the builder's anchor: a screen line's `first_seen`, or for a record the source or the corrective target minute described above (2026-10-08). The stated moment comes before the last report's because the same clock stated again a day later is a new time: kept on the equal text, an Oct 6 16:00 target resolved to Oct 5 and read as unchanged and overdue. With no `stated` (an input written by hand) or a `+N` time, it keeps the last moment when the ETA text equals the last report's for the same phase (`same_phase` compares titles after `: `, so a renumber keeps it), at any later time and across midnight; a changed text resolves by `parse_time`. `parse_range_end` puts `earliest` and `latest` on the resolved ETA's own day, then moves one a day so that earliest is at or before the ETA and latest at or after; a `+N` end counts days from the report. Placed from the report's time, the latest end of an ETA that had passed landed a day late. Read against the report's own time instead, a held unit's ETA from hours ago came out as tomorrow. A `+N` time still counts days from the report. `resolve_eta_moments` runs once per report, and the change check and note (`unchanged, overdue`; `overdue` alone when there is no last ETA to compare with and the moment has passed), display, ordering, chart row, saved state (`eta`, `eta_text`), `log_line` and first-ETA drift all read its result. A saved entry with no `eta_text` reads as `NoLastReportedEta`.
- **`idle`.** A unit takes an optional `idle` object, `{"waits_for": "<what it waits for>", "until": "YYYY-MM-DDTHH:MM"}`, which the showrunner's judgment supplies only while the unit waits on a clock gate, a data window or another unit with nothing of its own running; a unit with no known return time gets none. `parse_idle(fields: JsonMap, where: str) -> IdleWait | NotIdle` reads it at every length into `Unit.idle`. `IdleWait(waits_for: str, until: datetime)` and `NotIdle()` are frozen dataclasses. Absent or `null` is `NotIdle`; otherwise the keys are exactly `waits_for` and `until`, `until` matches `STARTED`, and `waits_for` is at most `IDLE_LIMIT` characters and passes `check_words`. `check_idle(report: Report, now: datetime) -> None` raises `InputError` naming `units[{index}].idle.until` when `until <= now`. `main` and `check_render_state` (as `StateRefused`) both call it after `check_changes`, so the builder refuses a passed `until` before it changes the clock.
- **Finished units (2026-10-08).** `units_from_doc` gives each `UnitRow` its `run: UnitState`, from `unit_lookup.run_state(<Worktree cell>)`; unreadable run records refuse the step. `main` drops every unit whose run is `RUN_FINISHED` and whose status block has no `FormWaiting` or `Decision` flag, from `units` and `blocks` both, before the `flags first:` lines and the judgment check, and prints `status: ok — left out, run finished and nothing waiting on the user: <units>`. Such a unit needs no judgment entry and has no section and no chart row; an entry supplied for it is not read. A finished unit that shows a form or a decision keeps its place and needs its entry. Since the lookup change a finished unit on standby is in the status again, which is what made the builder ask for entries nobody could write.
- **A unit's ETA (2026-10-08).** `Eta = TimedEta(time, spread: EtaRange(earliest, latest) | None, percent, why, detail, first, fixes, stated) | NoEta(reason, detail)`. `parse_eta` is the one place that builds either, and it still refuses the input the two states cannot hold: both or neither of `time` and `none`, half a range, and `percent`, `why`, `first` or `fixes` without a time. `percent`, `why`, `detail`, `first` and `stated` stay optional in `TimedEta`: each is its own unstated fact, and `stated` is absent from an input written by hand.
- **Gantt length (2026-10-08, the default).** `LENGTHS` is `gantt`, `simple`, `page`, `elaborate`; `dailies_input.py --length` and `/showrunner:dailies` default to `gantt`, and the scheduled prompt names it. The phase-record join, input, checks, saved state and `dailies ETAs:` log line are the same for every length; `gantt` takes `simple`'s update limit. `render` prints the first line, the section of each topic and unit with `needs_user`, the lines of `major_changes(unit, last, resolved, now, zone_name)` for the other units (phase not `same_phase` as the last report's; `held` differs; `change_minutes` of at least `MAJOR_ETA_MINUTES`, 15, printed by `eta_text`), one line for each unit the saved state has and the report lacks, then the chart and footer as for every length. A unit with no last report has no change line. The prompt is read from `produce.md` at `register`, so a showrunner gets the new default when it runs `register` again.
- **Idle group.** `grouped_wait(length: str, unit: Unit) -> IdleWait | NotIdle` returns the unit's `IdleWait` only when `length == "simple"`, `needs_user` is false, and `needed` and `held` are both `None`; any other unit keeps its full section. `render` gives a grouped unit no `### <unit>: <project>` section and prints `### Waiting and idle` after the last full section and before the topics that do not need the user, one line per unit, `- {unit.name} until {idle_clock(until, now)}: {waits_for}`, ordered by `until`, ties in report order. `idle_clock(moment: datetime, now: datetime) -> str` counts whole days between the two dates: `HH:MM` on the same day, weekday and time (`Sat 22:44`) one to six days ahead, weekday, date and time (`<Day> YYYY-MM-DD HH:MM`) at seven or more, with no zone because the report's first line states it. The timeline, the footer, the saved state and the `dailies ETAs:` line carry every unit; `page` and `elaborate` print every full section and no group.

### CI points and review watch: `ci_points.py`

`ci_points.py due | ci start [--cancel-prior] | ci collect | watch | notice clear <gate> | notice lift <gate> --log <path>`, each with `--production`; `due`, `ci`, `watch` take `--state-dir`; `due` and `ci` take `--no-ci`.

- `due`: `code_merge_count()` minus the count in `ci_points.json` (`{count, tip}`, none counts as zero) is `CiDue` at five or more, else `CiNotDue(n)` (`<n> of 5 code merges since last CI point`); `CiNotUsed` under `--no-ci`. It stays due until `ci collect` records a point.
- `ci start`: `bash validate_and_push.sh --to <merge branch> --fix-commit "ci(<slug>): validation fixes after <unit> phase <N>|production wrap" [--cancel-prior]`; reads `repo`, `sha` and `run_id` from the `=== CI HANDOFF TO AGENT ===` block (`run_id: none` fails); the sha must be the merge-branch tip; writes `ci_run.json` (`repo`, `run_id`, `tip`), the only handoff to `collect`.
- `ci collect`: takes the tip and its code-merge count before `gh run watch --exit-status`, then `gh run view --json headSha,status,conclusion,jobs`. It passes only when `headSha` equals the validated tip and the current tip, the run is `completed` and concluded `success`, job `Test Suite` succeeded, and every other job succeeded or was skipped. Then it records `{count, tip}` and prints `--ci-green <tip>` as the last line, which `promote-main` and `wrap` take as is. Anything else is `ci collect: failed — rerun <check> on <tip>: …`, with no flag; a missing or empty `headSha` is never a pass.
- `watch` / `review_watch(production, state_dir) -> WatchFirstAlert(line, table) | WatchRepeat(line) | WatchBelowThreshold(line)`: runs `review_regime.py watch` under `fcntl.flock` on `review_watch.lock`. On the first exit 3 with no `review_watch.json`, it takes `review_regime.py report --since 2026-09-28`, calls `scripts/message/send.py --to user --need decision --summary "Hana: review watch" --text "<line>; the table is in this session"`, appends `- HH:MM <zone>: review watch: <line>` to `LOG`, then writes `review_watch.json`. A failed send is a `PointFailure` whose text includes the command's stdout or stderr. The dailies builder calls the same function, so the first alert happens once whichever caller reaches it first.
- `notice clear <gate>` drafts `send <waiting unit>: From the showrunner: <gate> clear — <unit> phase <N> is on <merge branch> as <merge hash>. Merge <merge branch> and continue.` (refused until that code merge exists); `notice lift <gate> --log <path>` drafts `… <gate> lifted — your tests pass without <unit> phase <N> (<log>). Continue.` Gates rows read `| <id> | <waiting unit> phase <N> | <unit> phase <N> | … |`.
- Overrides for tests: `CI_POINTS_VALIDATE_SCRIPT`, `CI_POINTS_REVIEW_REGIME`, `DAILIES_REVIEW_REGIME`.

### Session lookups: `sessions.py` exit 1 and exit 3

`sessions.py` exits 1 when no live session matches and 3 when it could not read the session records. Exit 3 says nothing about the session, so no caller reads it as "not running". `showrunners.socket_for` raises `OSError` on it: every reader of the showrunners stops with `cannot tell whether <session> is running: <reason>` where one printed `not running`; `tmux_names.fault` prints the reason and leaves its marker unwritten, so the next tick sends the fault. `stall_watch.unit_socket` prints `stall-watch: pid <pid>: <reason>` and skips the unit for that tick; a pid with no session record yet (exit 1) stays silent. `unit_status.sh` no longer discards the lookup's stderr. `stall_watch.socket_for_target` and `conversation_pause._session_lookup` already told the two apart. `mac_test.delivery_target` falls back to the holder's name on both, which is right for both: the sender does its own lookup by name.

### Unit lookup: `unit_lookup.py`, and `adopt.py`

A unit's session name is written in one place, the session itself (user, 2026-10-08). Nothing copies it into the production doc, a registry or the showrunner's saved report state, so a rename in Claude or a relaunch leaves nothing to bring in step. The same holds for a showrunner's name.

- **Identity.** A unit is its production's slug plus its Unit value. `add_unit.py` launches the unit's tmux session with `SHOWRUNNER_UNIT=<slug>`, `SHOWRUNNER_UNIT_ID=<unit>` and `SHOWRUNNER_UNIT_STATE` in the session environment. These marks stay with the tmux session through a rename, and through a relaunch of Claude in the same pane.
- **Lookup.** `marked_units(slug) -> dict[str, MarkedUnit]` reads every tmux session's marks and the live session records at each call. `MarkedUnit(unit, pane, label, claude)`; `claude` is `LiveClaude(name, session_id, socket, pid) | ClaudeNotRunning | ClaudeUnknown(reason)`, taken from the newest live record whose `tmux` field ends in one of the session's panes. `ClaudeUnknown` means a session record could not be read, which says nothing about whether Claude runs. No tmux server means no units; a tmux that cannot answer raises `OSError`, and so do two sessions carrying one unit's mark. CLI: `unit_lookup.py list <slug>`, `pane <slug> <unit>` (exit 1 no such session, 3 cannot tell) and `mark <slug> <unit> <tmux session>`.
- **Readers.** `live_units.py <showrunner>` joins the registered doc's live rows with the lookup and prints the unit, its pane, `live|stopped|unknown|gone` and its name now, tab-separated. `unit_status.sh`, `broadcast.py`, `codex_winddown.py`, `stall_watch.py`, `dailies_input.py`, `waiting.py` and `production_lifecycle.py` take a unit's pane or name from the lookup at the moment of use. Saved state (dailies ETAs, judgments, status blocks, decisions seen, stall stretches) is keyed by unit id.
- **Showrunners.** A showrunner is recorded only by its update timer, `showrunner-<slug>` under `NOTIFIER_STATE_DIR`: `TARGET=session:<Claude session id>` and a check that holds the production doc. The zone is the doc's own `User zone` line, read at each call; a timer whose check names no doc, or whose doc has no valid zone line, is not a showrunner's. `showrunners.registered_showrunners()` reads the timers and looks up each name and socket by session id at every call, returning `Showrunner{session, socket, slug, zone, doc}` with `session` and `socket` empty while it is not running; a timer that is not a complete showrunner's is left out with `skipping <instance>: <reason>` on stderr, and session records that cannot be read raise `OSError`. `current_name(slug)` gives the name now; `named(x)` finds a showrunner by its name now or its slug. CLI: `showrunners.py name <slug>` prints the name (exit 1 when it is not running), `list` prints slug, name, zone and doc. `config/showrunners.json` holds only settings (`threshold_percent`, `repeat_minutes`, `stall_minutes`, `faults_to`, `always`); a `showrunners` list left in it is not read and nothing writes the file. `add`, `remove`, `rename` and `import` are gone, as is the doc's `Showrunner session` line. `showrunners.production_slug(doc)` is the doc's file name without `-production.md`. Still stored names: `faults_to` and `always`. A miss on either is told to the showrunners: `tmux_names.fault` sends the fault to every running showrunner, with the reason, when `faults_to` is no live session, and a quota alert names each `always` entry that is no live session (`quota_alert.not_live`).
- **Queued messages.** `send.py` keeps a message that did not arrive in `STATE/queue/session-<Claude session id>.jsonl` when a live session answers to the recipient (`sessions.addressed`: `uds:` socket, name now, or a name it alone once had), and under the name as given when none does, which the `QUEUED` line then says. `send.py pending` (no name: the caller's session; or a name) reads the session's file, the files of its name now and its socket, and those of its former names that no live session has now, so what was kept under a name before 2026-10-08 is still found.
- **The tmux label** still follows a rename (`tmux_names.py`). It is a display name; no tool finds a pane by it.
- **`adopt.py <production doc> --scratch <SCRATCH> [--gone <unit>]`** moves one production over, run once by its showrunner in its own checkout. For each row that is not retired it finds the one tmux session the old Session cell leads to: the session of a live Claude that has or had that name (`formerNames`), or the tmux session still labelled with it. If any row's session is not found, or two sessions answer to one name, it changes nothing, lists those rows and exits 1; `unit_lookup.py mark`, or `--gone <unit>` for a unit with no session now, then settles each. Otherwise it marks the sessions, moves the saved report state from the old names to unit ids (`rename_state.rename_scratch`), registers the doc, and last removes the Session column and commits the doc without pushing. A second run finds no Session column and changes nothing. A run stopped part way still has the column, so the next run finishes it.
- **Run state is not set.** `unit_lookup.py state`, the `SHOWRUNNER_UNIT_STATE` mark and the state carried over by `adopt.py` are gone (2026-10-08): the mark was a copy that a unit, the showrunner and adopt each had to keep right, and the first registry write after the lookup was promoted lost it for every finished unit. A mark left on a running tmux session is not read.
- **Not moved.** Queued messages and build holds stay keyed by a session's name. Stall-watch stretch files written under old names are left behind, and each unit starts a new stretch.

### Waits, renames and alerts: `waiting.py`

Each subcommand takes `--production`; `main` catches `merge_checkpoint.Stop`, so a bad doc fails as one line. A unit is named by its Unit value, or by its session's name now. `units_from_doc` reads `live_unit_table` and the lookup, so `search`, `quota` and `agenda` pass over a retired unit, and `named_unit` (`scratch-test`, `eta-request`) refuses one as `unknown unit <name>`.

- `scratch-test <unit> --tests "<command>" --state-dir <dir>`: a detached temporary worktree at the unit's branch tip, `merge --no-commit --no-ff <merge branch>`, then `sh -c <tests>` into `<state-dir>/scratch-test-<unit>-<YYYYmmdd-HHMMSS-ffffff>.log`. `ScratchGreen(log) | ScratchRed(last 4 lines, log) | ScratchConflict`; the verdict prints first; the worktree and merge state are always removed; nothing is committed or pushed. A red never says `blocked`; a conflict is a `failed` line, not a red. The log path feeds `ci_points.py notice lift`.
- `waits`: `cargo-berth board --json` overlaps (an `unconfigured` envelope reads `berth not configured`) and the LOG's `block: <waiting> on <unit> (code|files: …), clears ~HH:MM` / `block cleared: …` pairs as `WaitOpen(since) | WaitCleared`. Each open wait prints its age and `act now` at 60 minutes open or 30 minutes past its clear time. A `block:` or `block cleared:` line whose waiting unit is in `retired_units` is dropped; a live unit's wait on a retired unit stays.
- `search <old> <new>`: `git grep -n -F <old> <branch>` and `rg -n -F --hidden --glob !.git <old> <worktree>` for every unit; one line per site.
- `quota --state-dir <dir> [--notice "<text>"]` (else stdin): `Quota alert:` → `HoldQuotaAlert(account, line)` and "start no new delegate work on `<tool>`" (or "delegation continues on Claude…" when the notice says every function moved, or "keep delegating on `<tool>`…" when a Codex notice says nothing was switched); `Quota alert acknowledged:` → `ClearQuotaAlerts`; `Quota restored:` → `RestoreQuotaAlerts` and "delegation on `<tools>` can resume". It sends `From the showrunner: <action>` to every unit through `send.py`; exit 0 prints `send`, exit 1 `queued`, both delivered. Held alerts live in `quota_seen.json` and print as `held: <alert>`.
- `agenda --state-dir <dir>`: `AgendaOpen(unit, phase) | AgendaNotDue` when the current phase (from the last `### STATE` block line `<unit>: Phase …|follow-up …`) began over eight hours ago, or its ETA (from `dailies ETAs:` lines through `phase_eta`) is over eight hours after its start. The start is the unit's previous code merge line in `LOG`, else its `added …` line. Deduplicated by `<unit>|<phase>` in `agenda_seen.json`.
- `eta-request <unit> --phase <phase> --state-dir <dir>`: `EtaRequested | EtaNotYetRequested`; once per `<session>|<phase>` it prints `request /unit:eta: <session>` and writes `{"requested": true}` in `eta_seen.json`.
- `update_state(path, change)` is the one locked writer for all three state files: `fcntl.flock` on `<path>.lock`, re-read under the lock, no write when unchanged, a unique temp file, then `os.replace`. `dailies_input.py` imports it with `eta_requested`.
- `eta_moment(text, line_moment)` resolves a weekday ETA to its nearest occurrence within three days of the log line, and `HH:MM <ZONE>[ tomorrow]` on the line's day.

### Status and stall watch

- **`unit_status.sh` units.** `unit_status.sh <state-dir> <user-zone> --production <production doc>` takes its units from `live_units.py --production <doc>`. `--showrunner <name or slug>` is still accepted for a prompt written before; it finds the showrunner by its name now or its slug, so such a prompt fails after a rename until the showrunner registers again. Each block is headed by the unit id, and a pane is addressed by its id.
- **`live_units.py`** lists a production's units that are not retired, in doc order, each with its pane and Claude session as they are now. `live_units.py --production <doc>` prints `<unit>\t<pane>\t<gone|live|unknown|stopped>\t<name>` per unit; `live_units.py <showrunner name or slug>` is the older form. A showrunner that no update timer names, or a tmux that cannot say, exits 1 with the reason. `units_of(runner)` and `live_unit_names(runner)` take a `Showrunner`.
- **`unit_status.sh`** `waiting_on_user`: nothing when a spinner shows in the last 12 lines; `FORM WAITING on you in <unit>: …` for `Enter to select`. Otherwise it reads the last turn-end line (`^\s*(— )?(holding|gate|decision|blocked|done):`). `decision`, `gate` and `blocked` are waits on the user: first sight prints `=== DECISION for you from <unit> ===` … `=== end <unit> ===` and records the key in `decisions_seen`; a repeat prints `STILL WAITING on you, <unit>: …`. A wait naming `showrunner` or a peer unit (whole word) is the showrunner's: no wait line, and only `blocked:` prints `BLOCK in <unit>, open <age>: …`, aged from `blocks_open`. Any other turn-end clears the block entry.
- **`stall_watch.py`** runs every minute under a nonblocking lock. Per configured unit, it skips a `RunFinishedUnitDirector` or `StandingByUnitDirector`, deleting its stretch. It also skips a unit whose production row begins with the retired marker, found through the checked notifier doc. It does not use `run done` text from the Plan cell. `WAITING_KINDS = ("done", "blocked", "gate", "decision")` and `HOLDING_KIND = "holding"` build `TURN_END` with a named `kind` group. A last turn-end of a waiting kind writes a fresh stretch and sends nothing. `holding` with nothing running, or no turn-end on screen, is a stall candidate: after `stall_minutes` with no running work (`zsh`, `bash`, `sh`, `implement.sh`, `review.sh`, `verify.sh` descendants) it bumps the unit once and tells the showrunner once per stretch. All sends share one 90-second deadline.

## Invariants

- The production doc is read only through `read_production`, `production_field`, `cell_value` and `unit_rows` (the retired readers read through `unit_rows`); Units rows are read cell by cell, since real rows are backticked and carry commentary.
- `plan_cell_is_retired` is the only test of the retired marker: `live_unit_rows`, `retired_sessions`, `retired_units` and `stall_watch.retired_units` call it, and no other file tests the word. The marker counts only at the start of the Plan cell.
- Merge history comes only from `merge_branch_history` over first-parent subjects; `LAST_MERGED` is never an argument or a memory. A shrink merge never counts as a code merge, a CI count or a gate clear.
- Every refusal comes before any write: `add_unit.py` refuses in `launch_request`, `preflight` or the tmux check before the stub, row or commit; `--check` writes and starts nothing. The director resolves in `preflight`, so promotion never stops a session it cannot relaunch.
- `merge_checkpoint.py` leaves the merge branch as it was on red. `reset --keep HEAD~1` runs only when `HEAD` is this merge and is not on origin. Promotion targets the pushed merge-branch tip, never the earlier checkpoint merge. `main` is pushed only when it holds no commits outside `origin/main` and `origin/<merge branch>`, and never with force.
- The dailies builder's one pre-check write is idempotent pruning of this production's retired generated phase notes. Every other write waits until every check has passed. Every builder call passes `--render-state`, the same file the renderer gets as `--state`.
- One state directory: `eta_seen.json` and `review_watch.json` live in `DAILIES_STATE_DIR` for every caller; a second directory forks the once-per-phase and first-alert records. A doc-contract test pins `produce.md` and `dailies.md` to the same path.
- `then` reaches the renderer unchanged; the renderer refuses, it never rewrites.
- The idle group changes only which sections a `simple` dailies prints. The timeline, the footer, the saved state and the `dailies ETAs:` line carry every unit at every length.
- An activity on a closed phase leaves that phase's record as `finish-phase` wrote it: status, `finished_at` and elapsed time. The printed `review trial:` line keeps its form, which `merge_checkpoint.py` parses.
- The stall watch's standing-by, run-finished and retired-row skips, then its waiting-kind reset, run before any bump or notice. The turn-end pattern is built from `WAITING_KINDS` and `HOLDING_KIND`, so the pattern and the wait test cannot drift.
- Unit directors launch only on Claude. `production` has only `[production.claude]`; `claude --resume` never runs without resolved flags.
- `agents_config.sh` is bash only (call it through `bash -c`) and must keep working under `/bin/bash` 3.2 (no associative arrays, no `${var,,}`); the style-fix pipeline runs it unattended every ten minutes on both machines.
- `add_unit.py` asks tmux about a launch name as `=<name>`; a plain `-t <name>` prefix-matches another session. Every other tool addresses a pane by its id.
- Tests never start a real `claude`, `tmux`, `systemd-run`, `ssh`, `validate_and_push.sh` or CI, never write `~/.claude/config/`, `~/.local/state/` or a real production doc, and push only to a temporary bare repository. Python is typed with no `Any` and no file-level ignores.

## Calibration and gotchas

- **`config/agents.conf` clean filter.** `.gitattributes` gives it `filter=claude-agents-conf`, whose clean step (`scripts/agents/clean_agents_conf.sh`) pins staged content to the index: `git diff` is empty for it and a plain `git add` commits nothing. Stage a real change with `AGENTS_CONF_COMMIT=1 git add --renormalize config/agents.conf`, then confirm `git diff --cached --stat` lists it. Merging it into a machine's checkout rewrites that machine's live registry, so live `/agent` retunes there are lost.
- Sourcing `agents_config.sh` may run the Codex catalog refresh when its state is stale; `--check` writes nothing of its own but does not promise zero writes to the registry's state. Tests set `AGENTS_CONFIG_FILE`, `CODEX_CONFIG_FILE`, `CODEX_MODELS_CACHE_FILE` and `CODEX_CATALOG_SYNC_STATE_FILE` (newest) to temporary paths.
- `--check` does no tmux lookup: a tmux name collision can still refuse after promotion has stopped the session.
- A re-run of `add_unit.py` must name its original mode; the mode comes from the commit subject, then the Plan cell, then the stub.
- `ssh`'s own exit status is always 0 here; the Mac pull is read from the `rc=` line it prints. The Mac pulls from `natedev:<first Promote checkout>`.
- `merge_checkpoint.py` counts a `basedpyright` Merge tests command green when its last line is `0 errors, 0 warnings[, 0 notes]`, whatever its exit status.
- CI point: due at 5 code merges; `ci collect` requires job `Test Suite` by name. The review table is `report --since 2026-09-28`.
- `review_watch.json` is written after the push and the LOG line: a crash between them repeats the alert once (at least once).
- Dailies: an ETA first seen over 1 hour ago is stale; an ETA move of 15 minutes or more (`CHANGE_NEEDS_WHY_MINUTES`) needs `eta.why`; `parse_time` treats a time over two hours past as tomorrow; updates are capped at 240 characters for `simple` and 480 for `page`.
- The renderer's ETA-change check reads its own state; `check_render_state` runs before the clock restart, so a refused user-run dailies leaves the clock where it was.
- The renderer exposes no list of required fields, which is why the builder names five itself.
- Agenda threshold is 8 hours; waits act at 60 minutes open or 30 minutes past the clear time; the weekday ETA window is ±3 days.
- `log_events` dates a date-less LOG line by walking backward across midnights; a gap over 24 hours between timestamped lines is invisible.
- Producer output shapes are not the obvious ones: the unconfigured berth board is a JSON envelope with exit 4, the ETA line is `dailies ETAs: <unit> <phase> <eta>; …`, and an account stem can hold a space (`codex 1`). Test fixtures come from calling the producers.
- `unit_status.sh` routes `gate:` exactly as `decision:` and `blocked:`, while the stall watch treats all four waiting kinds as silent; a unit at a gate is quiet in the stall watch and flagged to the user by the status script.
- `unit_status.sh` is zsh.
- `test_unit_status.py` copies `add_unit.py`, `live_units.py` and `showrunners.py` into its test tree, so a new import in `live_units.py` needs a new entry in that list.
- `waiting.py waits` rebuilds waits from the LOG alone, so filtering the doc's rows never reaches it; it filters on the waiting unit's name through `retired_units`.
- The stall watch reads `run-finished` and `standing-by` from the unit's run records (`unit_lookup.run_state`). The production doc contributes the Worktree cell and the retired marker at the start of the Plan cell.
- Idle: `IDLE_LIMIT` is 80 characters; `idle.until` is a naive local time in the report's zone, compared with the renderer's naive local now.
- Recorder: `_event` stamps the phase in state on every event, active or closed; nothing else carries an activity's phase. When the last phase is closed but an activity is open, `progress` prints the scope and round tables from that phase's last recorded values and shows the activity as the running row. `No active phase to report: …` remains for a missing or closed phase with no open activity.
- The recorder other units run is the main checkout's copy under `~/.claude/scripts/delegate/`; a change in a worktree reaches them, and their `review-trial` line, only when promoted.
- `showrunners.py` is mode 0644: call it through `scripts/lib/py`.
- `already at` in a promote line means main was at the tip before the run; no other line uses it.
- In an enrolled repository the shrink's first plan-doc write goes through the Edit tool; a write from a script is never claimed by the first-touch hook.
- Sandboxed seats have no writable temporary directory and cannot run the stall-watch suite; run it from the main tree.

## Why

- **Scripts hold mechanics; command docs hold judgment.** Each showrunner step was given a script-or-judgment verdict. Script: zone time, log and STATE, footer, open/load/wrap, registration and prompt, merge/test/push/promote/record, CI counting and collection, review-watch escalation, gate notices, scratch tests, wait ages, agenda thresholds, rename search, quota fanout, the dailies input. Judgment: relaying the user's words, verifying a unit's claims, compacting a blocked pane, the overlap notice and restructure holds, whether a new public item has a consumer, design-check freshness and defects, the repair owner for red CI, classifying a wait as code, files or preference, landing order, permission blocks, close-out approvals, open topics and who acts next, `then` and goal text, and phone-alert urgency and wording.
- **The mode is in the commit subject**, not a Units column: the subject already records it, and a pre-filled Units row is adopted, never rewritten to the script's form.
- **Code commit before the shrink.** The code-ready notice can go out the moment the phase's code commits; the shrink runs beside the next phase's seats and lands as a plan-doc-only merge with no tests, ledger row or CI count.
- **`LAST_MERGED` is read from merge subjects**, never passed in, so a resumed or compacted showrunner cannot supply a stale value. First-parent history keeps a subject carried in by a merged side branch from counting.
- **A finished run is a named state.** `run-finished` is read from the run record's `run_finished` event; the stall watch reads that named variant and does not infer completion from production-row prose.
- **The Units row is the one retired marker.** Every reader of the Units table follows it, and the status script finds the production doc on its own through `checked_doc`, so retiring a unit changes no caller's command line. The marker counts only at the start of the Plan cell because a live unit's Plan cell can use the word in its commentary.
- **A live unit's wait on a retired unit still prints.** Hiding it would hide a stuck unit.
- **`merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` do not skip retired rows.** A retired unit sends no checkpoint, and the wrap already passes a unit whose branch is gone.
- **No named type carries an activity's phase.** `_event` already stamps the phase in state on every event.
- **The renderer refuses a chained or string `then`** rather than rewriting it: a silent rewrite would hide the defect from the showrunner who wrote it.
- **The review alert is at least once.** Writing `review_watch.json` before the alert would make it at most once, and a lost alert is the worse failure. The alert writes its LOG line directly; routing it through `update_registration.py log` would add a stray `log: ok` line and couple two commands.
- **No `queue` command.** Arrivals are messages in the showrunner's own session, and ordering them is judgment.
- **One verdict type per flag.** `--ci-green` and `--smoke-passed` are separate flags, each checked at its own step against the same tip; a mismatch is a hold line, not a user topic.
- **Resume flags come from a checked `bash -c`, not a one-line substitution:** a failed substitution would run `claude --resume` with no flags and skip the family check.
- **No `[production.codex]`** and no Codex director: unit directors launch only on Claude. Pinning a one-family function keeps every-function switches (`/agent` "all on codex") from breaking director launches.
- **Unit directors default to `opus:xhigh`** (the user, 2026-10-07, moved back from `sonnet:xhigh`). Test fixtures write their own rows, so they test that a row changes the launch, not the live default.
- **`footer --nothing-needed`** replaced a scan for an invented `needed` key.
- **Not done here, by choice:** renaming `MergeEntry`/`NoMerge` to checkpoint-merge names (churn with no behavior change); named states for `LastUnitReport.held` and `first` (bare optionals older than the ETA states); reporting the builder's `<step>: ok` lines to the user (an implementation transcript).
