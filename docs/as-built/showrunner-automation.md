# Showrunner automation: unit start, checkpoint merge, lifecycle, updates, dailies and waits

## What it is

A set of Python (standard library) scripts in `scripts/production/` that run the fixed, repeatable steps of a production, so a showrunner and its unit directors have little left to remember. One command starts a unit: with a written plan, with a brief the unit director turns into a plan, or on standby. One command merges a checkpoint: ancestry, scope, conflicts, merge, tests, push, promotion to the installed checkouts and the Mac, the review-ledger row and the log line. Other commands open, promote and wrap a production; register its scheduled updates and write its times, log lines and open questions; build the dailies input from the status script; count CI points and log the first review-watch alert once; and do the mechanical part of waits and renames. A unit director ends each phase in one fixed order: the code commit first, then the shrink in its own commit beside the next phase. Unit directors take their model and effort from `config/agents.conf`. The stall watch and the status script treat a unit that is waiting on someone else as waiting, not stalled. A unit marked retired in the production doc drops out of the status script, the dailies, the waits and the stall watch, and a `simple` dailies gives each unit that only waits one line in a group.

The problem it solves is the number of manual steps a showrunner has to carry. Each of these was a list in `commands/showrunner/produce.md` that the showrunner had to run by hand, in the right order, on every merge and every tick. The commands now hold the mechanics. The command docs keep only the decisions that need judgment.

### Shared conventions

- **Production-doc reader** (`scripts/production/add_unit.py`): `read_production(path) -> Production` (`doc`, `slug`, `merge_branch`, `checkout`, `showrunner_session`, `log`, `zone`), `production_field(lines, field) -> str` (reads `- **<field>:** …`; raises `Refusal` when the field is missing, so no `str | None` crosses the boundary), `cell_value(value) -> str` (the first backticked span, else the text before ` — `), and `unit_rows(lines) -> tuple[int, list[str]]` (the insert index and the data rows of `## Units`). Every other production script imports these four; none parses the doc itself. The slug is the doc's file name less `-production.md`, and `Log` must be relative to the showrunner checkout.

- **Retired units** (`retire_unit.py`, `resume_unit.py`, `production_units.py`): the Units row records a completed retirement. The row stays in the doc, and no caller's command line changes. `plan_cell_is_retired(plan_cell: str) -> bool` decides: the Plan cell begins with the lower-case whole word `retired`, alone or straight after one opening parenthesis, leading spaces ignored (`^\s*\(?retired\b`), as in `(retired by the user, worktree removed)`. The word later in the cell, later inside a leading parenthesis (`(run done; retired by the user)`), `retiredness` and `Retired` each leave the row live. Rows are read by column heading: `unit_table(lines) -> list[dict[str, str]]` returns each row as its cells by heading, so a doc that still has the old Session column reads like one without it. `live_unit_table(lines, slug)` returns the rows that are not retired and `retired_units(lines, slug) -> set[str]` the Unit values of those that are. `unit_status.sh`, the dailies builder, `waiting.py` and the stall watch skip a retired unit. `merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` read every row.

`retire_unit.py` finds the live director by its production/unit mark even outside the worktree, alongside worktree sessions and run-history director ids; unreadable marks refuse retirement. It starts `shutdown.py down --here --only … --why "retired; /showrunner:resume_unit brings it back."`, waits on the same deadline for both process exit and a finished shutdown record, and only then forgets the restore. Failed stops or forgets return exit 1; a rerun also finds an exited director by its retained unit shutdown record and retries forgetting it. Immediately before marking the row or removing an already retired unit, it checks the mark, all discovered session ids and their shutdown records again; live or unreadable evidence prevents marking and removal.

Its Plan cell keeps `(retired <date>, worktree removed, session <id>)`, adding `, folder <path>` before the closing parenthesis when the director's resume folder differs from the worktree: the first `cwd` in its transcript whose project folder is the one that holds the transcript, so a unit renamed mid-session resumes under its new name. `resume_unit.py` reads this note from the raw cell before extracting a backtick plan. Older notes resolve the session transcript across all accounts' project folders, counting shared symlinks once and refusing zero or multiple locations or a transcript with no `cwd` matching its project folder. Resume checks the transcript under that start folder and passes `--resume <id> --cwd <folder>` to add_unit; a start folder outside the worktree skips worktree and branch steps. The launch passes the production doc path to add_unit's `--production`; a failed launch returns exit 1, keeps the note, and reuses any worktree already made on a rerun. When the note has no session id, resume uses retire's mark, retained shutdown record and interactive transcript lookup, refusing both dry and real runs if no id is found. The retired note is removed only after a successful launch, preserving the raw plan cell. Add_unit accepts that external start folder only for a plain resume of a retired row, preserving the row's worktree and branch without creating either or changing the row.

- **The checked doc** (`showrunners.py`): `checked_doc(instance: Path) -> CheckedDoc | NoCheckedDoc` returns the production doc that a notifier instance directory's `conf` passes to `production_check.sh` on its `CHECK=` line: `shlex.split` the value, then take the token after the one whose basename is `production_check.sh`. `CheckedDoc(path: Path)` and `NoCheckedDoc(reason: str)` are `NamedTuple`s; a missing conf, line or token, or a relative path, is `NoCheckedDoc`. `live_units.py` and `stall_watch.tick` find retired rows through it. `add_unit.py` imports `showrunners`, so `showrunners.py` never imports `add_unit.py`.

- **Merge-branch history** (`merge_checkpoint.py`): `merge_branch_history(checkout, merge_branch) -> MergeBranchHistory` reads `git log --first-parent` subjects matching `Merge <unit> phase <N>[ shrink| as-built] (<short>)` into `MergeEntry` rows and `Merge <child> hand-off (<short>)` into `ChildHandoffEntry(child, short, merge_branch, merge_hash)` rows (a style child's hand-off; `docs/as-built/style-showrunner.md`). It offers `last_merge()` (either kind), `last_for_unit(unit)`, `last_code_for_unit(unit)`, `code_merge_count()`, `has_code_merge(unit, phase)` and `last_handoff_for_child(child)`, with absence as `NoMerge`. The unit readers guard with `isinstance(entry, MergeEntry)`, so a hand-off never counts as a unit merge. A shrink merge never counts as a code merge. `LAST_MERGED[unit]`, the CI count, the STATE block, the wrap report and the agenda all read it.

- **Step lines**: each command prints `<step>: ok|held|failed — <one line>` and stops at the first `held` or `failed`. The dailies builder also prints `<step>: unavailable — <reason>` and continues, for the steps `phase tables`, `bevy upgrade`, `children`, `counts` and `saved report`. `add_unit.py`, `production_lifecycle.py`, `update_registration.py`, `ci_points.py`, `waiting.py` and `dailies_input.py` exit 0, or 2 on a refusal. `merge_checkpoint.py` exits 1 on a hold or failure, and its last line is always `send <unit>: <message>`.

- **Named states**: every optional or alternative value crossing a reader boundary is a `NamedTuple` union (`FieldPresent | FieldAbsent`, `PushedTip | NotYetPushed`, `EtaFresh | EtaStale | EtaPassed | EtaNone`, and so on), never a string or `None`.

- **Session state**: `showrunners.session_state_dir(<slug>)` is `~/.local/state/showrunner/<slug>/session` (`STATE_DIR` in `produce.md`). It holds `showrunner_state.json`, `dailies_judgment.json`, `dailies_state.json`, `unit_status/` and `dailies_input_state/`, which a scratchpad held before. A new session id, a restart and a reboot keep it; a rename moves it with the slug folder, and a wrap deletes that folder. `showrunners.copy_session_state` copies each of the five that a scratchpad holds and the folder does not; a copy never replaces a file. It runs with no step by anyone: `update_registration.adopt_moved_state`, which every `update_registration.py` call and every `dailies_input.py` run calls first, looks for the files the folder lacks in the scratchpad of the session the update timer's TARGET names (`/tmp/claude-*/*/<session id>/scratchpad`), and rewrites `prompt.txt` when it differs from what `produce.md` gives now. `load --scratch <SCRATCH>` runs the same copy from a named scratchpad.
- **State directory**: `DAILIES_STATE_DIR` (`<STATE_DIR>/dailies_input_state`, in `produce.md`'s State list) is the one `--state-dir` for the dailies builder, every stateful `ci_points.py` call and every stateful `waiting.py` call. It holds `eta_seen.json`, `ci_points.json`, `ci_run.json`, `review_watch.json`, `agenda_seen.json` and the scratch-test logs.

### Unit start: `add_unit.py` and `/showrunner:add_unit`

`add_unit.py --production <doc> <name> (--plan <path> | --brief <words> | --standby) [--permanent] [--account <label>] [--model <model>] [--port N] [--owns <paths>] [--resume <sessionId> --cwd <dir> [--restart-note <file> --session-name <name> --host-session <name> [--probe]]] [--timeout S] [--check]`, run through `scripts/lib/py`.

- **Request.** `launch_request` builds `RequestedUnitLaunch`, whose request-only fields are `requested_name` and `unit`. A name that already ends in `-unit` (or `_unit`) loses that ending first, so `feature-log-unit` launches exactly as `feature-log` does, not as `feature-log-unit-unit`. `unit` is that name when a Units row of the production has exactly that `Unit` cell, else `<name>-unit`. The shared `UnitLaunchConfiguration` carries `production`, `branch`, `worktree`, `plan: PlanGiven | BriefGiven | Standby`, `port`/`owns: OmittedCell | SuppliedCell`, `session: NewSession | ResumedSession`, and `timeout`. Exactly one of the three launch states is required; `--resume` also needs `--cwd` and `--plan`. `launch_kind` is `UnitRestoreLaunch(session_id, note, session_name, host_session, probe)` when `--restart-note`, `--session-name` and `--host-session` are all given with `--resume` (only `/shutdown restart` passes them), else `NewWorkLaunch`; any other mix is refused. The hidden `--probe` is accepted only with `--restart-note`; shutdown passes it for a probe session's record.

- **Shutdown check.** After `launch_request` and before `preflight`, `main` takes the shutdown launch barrier and runs `launch_permission` (`docs/as-built/shutdown-and-restart.md`) with the restore's session id for a `UnitRestoreLaunch`, else as new work, and holds the barrier through the return of `launch_session`. A launch that a shutdown holds (an account hold, or a restore whose own shutdown record has not stopped) exits 2 with `add_unit: <reason>; /shutdown restart first`; an unreadable shutdown state, restores included, exits 2 with `add_unit: shutdown state unreadable: <detail>`. `--check` also runs this check.

- **Preflight** (`preflight(request: RequestedUnitLaunch, selected: UnitLaunchAccount) -> ReadyToLaunch`): Claude is trusted in `session_cwd` on the selected account (`herdr.claude_trust` on `<dir>/.claude.json` for the selected numbered account; a new worktree that does not exist yet is checked by its main checkout's key, `repository_trust_key`), else exit 2 with `<unit>: Claude is not trusted in <folder> on <account label>. Run: <trust_command>` before any stub, row or worktree is written (`docs/as-built/herdr-adoption.md`); the checkout is on the merge branch; the Units table has no other unit on this branch or worktree; an existing row for this unit (`ExistingUnitRow`) is adopted when its Plan, Worktree and Branch cells agree, and its Port and Owns stand (a supplied `--port`/`--owns` must match); a re-run's mode matches the recorded one (`recorded_mode` reads the commit subject, then a `standby` Plan cell, then the stub's `## Source`); the worktree path is free or already this branch's; no local or origin branch exists unless the row and worktree do; a `--plan` exists on the merge branch with the `> **Production:` header, except a plain resume of an existing row (active or retired) continues its transcript and accepts its recorded plan without that header; a resume with a different plan still refuses; a brief stub, if present, holds the same words. A restore (`UnitRestoreLaunch`) is checked against its own row only: the row must exist and its Plan cell must agree, its Worktree and Branch cells replace the naming pattern's, and the mode, worktree, branch and plan-header checks, which describe new work, are skipped; `main` creates no worktree and launches in the recorded `--cwd` (`session_cwd`), whether or not it is the row's Worktree (`docs/as-built/shutdown-and-restart.md`). Preflight returns `UnitLaunch(identity=UnitIdentity(unit, session), ...)` with the row and director; `session` is `requested_name`, the name the session is launched under, and it is not recorded. A herdr session already marked as the unit is taken as launched; a live herdr session of the destination name that is not so marked refuses in `main` before any write. `--check` runs `launch_request`, the shutdown check and `preflight` only. Over a marked unit a resume refuses on `ClaudeUnknown` and ends the stale herdr session (`herdr.stop_session`) on `ClaudeNotRunning` before launching.

- **Steps**, each skipped when already done: the brief stub beside the production doc at `<its directory>/<branch>.md` (Production header, `## Source`, a zone stamp and the user's words); the Units row (Plan cell `standby` for a standby unit); commit `production(<slug>): add unit <unit> (<plan|brief|standby>)` on the merge branch, which is not pushed here and goes out with the next merge push (user, 2026-10-08); `git worktree add` from the local merge branch, with no push of the unit branch (the unit's first checkpoint push sets its upstream), plus `branch.<branch>.cargoBerthTarget` when the repo has `.claude/config/berth.toml`; the herdr session (Launch below); the wait for `/remote-control is active` (default 90 s, last 15 pane lines on timeout); one LOG line `added <unit> (<mode>), worktree <path>`. A row is written under the doc's own headings, so a doc that still has the Session column gets `—` there. It prints `<unit> started: herdr session attach <name>`. A restore (`UnitRestoreLaunch`) makes no such wait: once the session is launched, or found already running, it runs the LOG step, prints `<unit> restore launched: herdr session attach <name>` and returns 0; its caller confirms the session through the session registry. A restore that finds its unit already running names that unit's own herdr session. A live herdr session of that name with no unit mark refuses (exit 2), `herdr.SessionTaken` exits 2, and `herdr.AgentNotReady` exits 1 with the pane screen. New and resumed units select the configured units account through `accounts.account_for_group_launch("unit", ...)`; explicit `--account` or `--config-dir` must name that account. Resume model selection uses explicit `--model`, then the shutdown record, then a live herdr unit's last assistant model (`transcript_model`); otherwise it uses the director model.

- **Launch** (`launch_session`, herdr-adoption Phase 7), new work and restore alike: `herdr.start_server(herdr.shared_session(), <timeout ms>)`, `herdr.open_tab(<shared>, herdr_space(<slug>, <doc>), <session>, <cwd>, environment)`, which opens the unit's tab in its production's workspace of the one herdr session (`agents`; user, 2026-10-26: no launcher starts a herdr session of its own), then `herdr.start_agent(<shared>, pane, kind="claude", agent=<name>, agent_arguments=[--model <m>, [--effort <e>], [--resume <id>], --remote-control <session>, -n <session>, --settings '{"disableAgentView": true}'], opening_prompt=<prompt>)`. `<session>` is `request.identity.session`, or `--session-name` on a restore, and is the tab's title. `<name>` (`host_session_name`) is the agent's full name: `<slug>-<session>` on a new launch, so each production's `review-unit` has its own name (`build-followups-review`, `hana-review`; enh-showrunner add-on, 2026-10-16), and `--host-session` on a restore when that name leads with `<slug>-`; a record from before the prefix led (such as `review`) takes the new launch's name instead (enh-showrunner, 2026-10-16); a session already starting with `<slug>-` is not prefixed twice. The launch prints `herdr.attach_hint(<space>, <session>)`: `herdr session attach agents, workspace <space>, tab <session>`. Characters outside `[A-Za-z0-9_.-]` are replaced by `-`. The pane environment is built from nothing: `SHOWRUNNER_UNIT=<slug>`, `SHOWRUNNER_UNIT_ID=<unit>`, `ENABLE_TOOL_SEARCH=true` and the account variables, `named_account_environment(dir)` for the numbered folder or, on a resume, `accounts.prepared_account(target, resume=True).variables` minus its `remove` names. A probe restore explicitly adds `CLAUDE_PROBE_SESSION=1` to the pane environment; an inherited caller marker is not copied. The prompt is `/unit:direct <plan>` for a plan; for a brief, write the full phased plan into the stub, send it to the showrunner and wait for approval; for standby, do nothing until the showrunner sends work; for a resume, "you are now `<unit>`" with the plan's absolute path in the worktree; for a restore, the same identity followed by the restart note, with `-n`/`--remote-control` and the herdr session taken from `--session-name` and `--host-session`. A restore's prompt is recorded as a `conversation_pause` scheduled prompt before launch (`record_scheduled_restore_prompt`; a failure exits 1 with `add_unit: restart prompt not recorded: …`).

- **Unit status.** A unit's run state is stored nowhere. `unit_lookup.read_run_states() -> RunStates` builds one snapshot per stall-watch tick, watchdog pass or dailies call from the `/unit:direct` run records (`runs/*.jsonl` under `unit_runs.history_root()`). It reads only each file's first line: a JSON object with `event_type == run_started` and a nonempty `working_dir` is a candidate. For each recorded worktree spelling it keeps the largest numeric `run_started_at` (booleans and nonnumbers count as zero), then reads backwards in growing blocks from that file's end to the last JSON object. Middle events are not parsed. A partial first line skips the file; a partial last line falls back to the preceding JSON object. `snapshot.state(worktree) -> UnitState` resolves the Worktree cell before lookup; no record is `standing-by`, a last event of `run_finished` is `run-finished`, anything else is `running`. `snapshot.records` also holds the record path and state by exact recorded `working_dir`, preserving `unit_move`'s string matching. `run_state(worktree) -> UnitState` remains a one-call wrapper. Unreadable records raise `OSError`; bad UTF-8 in a line read raises `UnicodeError`. The stall watch reports `units: their run state is unknown` once and leaves every unit alone for that tick. `showrunners.py status` and `showrunners.py ready` still parse their old arguments, do nothing and exit 0, because sessions started before 2026-10-08 hold text that calls them; delete both once no such session is left. Consequences: a standing-by unit handed work is watched for stalls only from the start of its run; a run that died without its finish event reads as running until the next run in that worktree.

- **Callers.** `produce.md` `<LaunchUnits/>` runs `add_unit.py --production PRODUCTION_DOC <name> --plan <unit plan>` per unit (`<name>` is the Unit value less any `-unit`; `--standby` for a unit waiting on work). When the production doc has a `- **Review pool:** ` line, the showrunner runs `review_pool.py stop --production <slug>` at wrap (`docs/as-built/review-pool.md`); the first review of each type primes the pool. `/showrunner:promote_unit` runs: find the session, check fit (normalized unit name), plan, `add_unit.py … --resume <sessionId> --cwd <cwd> --plan <plan> --check`, `/exit` the session, then the same command without `--check`, then tell the user (both names when the name changed). Typing `/compact` into a blocked unit director and **Resume** stay the showrunner's own.

### Director model and effort: `config/agents.conf`

- `[assignments]` has `production=claude`; `[production.claude]` has `director=opus:xhigh`. There is no `[production.codex]`: unit directors launch only on Claude, and the showrunner is whichever session runs `/showrunner:produce`. The header Consumers list names `production unit directors (add_unit.py)`.
- `director_agent(request) -> DirectorAgent(model, effort: DefaultEffort | Effort(value))` runs `bash -c 'source "$1" && agents_resolve production.director && printf …'` with the `agents_config.sh` from the script's own checkout (`Path(__file__).resolve().parents[1] / "agents/agents_config.sh"`); `AGENTS_CONFIG_FILE` comes from the caller (default `~/.claude/config/agents.conf`). A resolver failure is exit 2 with its first `ERROR:` line; a family other than `claude` is exit 2 with `unit directors launch only on claude; production.director resolves to <family> (<model>)`. Both happen in `preflight`, so `--check` refuses too. `--effort` is passed only for `Effort(value)`.
- **One-family pinning** (`scripts/agents/agents_config.sh`): a function with exactly one family set is pinned to it (`_agents_pinned_family`). Every-function switches (`agents_set_all_assignments <family>`, `agents_set_model <agent>` with no function) leave it as it is and add it to `AGENT_KEPT_FUNCTIONS`; `agent_admin.sh` prints `# kept production on claude: its only set`. A switch aimed at it (`agents_set_assignment production codex`, `agents_set_model <codex agent> production`, `agents_set_row production.director <codex agent>`) prints `ERROR: 'production' runs only on claude: [production.claude] is its only set.`, returns 1 and leaves the file untouched. `/agent production.director <model>:<effort>` changes the row.
- **Resume** in `<LaunchUnits/>` first runs `shutdown.py launch-blocked --restart-of <session-id>` and goes on only on exit 1 (exit 0: a shutdown holds the unit, either through an account hold or because its own shutdown record has not stopped yet, and `/shutdown restart` brings the unit back; a unit whose own record has stopped is let through under an account hold). It then gets its flags: `bash -c` sourcing `agents_config.sh`, `agents_resolve production.director`, the same non-Claude refusal, then `agents_claude_args`. Only then `claude --resume <session-id> <flags> --remote-control <session> -n <session>`.

### Phase end on the unit side

`docs/direct/phase_end.md` defines `<PhaseEnd/>`, the one order a loop or verbose phase ends in: (1) code commit (`<CheckpointCommit/>`, with the phase `status: done` and its Work Order still in place); (2) the code-ready notice, whose hash is mergeable now; (3) the plan review, where a defect in the committed phase becomes a follow-up phase run next; (4) the add-on check; (5) worker cleanup and `finish-phase`; (6) the next phase's launch; (7) the shrink beside the next phase's workers, its commit and the shrink notice. With no phase left, step 7 runs, then `<FinalGate/>`. A due `<PeriodicCI/>` point outside a production runs step 7 before step 6, so CI sees a clean tree. The other phase-end docs point to it in one line.

- `<ShrinkCommit/>` (`commands/unit/checkpoint.md`) stages only the plan doc and an approved next-items file, refuses any other staged path, commits `shrink(<plan-slug>): phase N — <title>`, runs `<PushCheckpoint/>` and owns no reservation.
- The shrink notice is `From <unit>: phase <N> shrink <hash> — plan doc only.` or `… — plan doc and <next-items path>.`
- A failed shrink blocks only `<ShrinkCommit/>`; the next `<CheckpointCommit/>` refuses while an earlier `done` phase still has a Work Order.
- **Closing work in the recorder** (`scripts/direct/progress_history.py`). `start-activity` succeeds whenever the run is active and a phase has been started in it, still active or already closed by `finish-phase`, so work after step 5 with no next phase started (the last phase's `shrink` activity) keeps its row. On a closed phase `activity_started` and `activity_finished` carry that phase's `phase_instance_id`, and the phase's status, `finished_at` and elapsed time stay as `finish-phase` left them; `finish-activity` records status, result and elapsed seconds as it does inside a phase. `start-activity` exits 1 with `Start a phase before starting an activity` when the run has no phase, and with `Cannot start an activity: the run is finished` after `finish-run`.
- **An activity left open.** `start-phase` and `finish-run` close an activity still open, inside a phase or on a closed one, as `interrupted`. A repeated `finish-phase` does nothing: `_finish_phase` returns before any cleanup when the phase in state is not active, so an activity opened after the phase closed keeps running.

### Checkpoint merge: `merge_checkpoint.py`

`merge_checkpoint.py --production <doc> <unit> <phase> <hash> --started <ISO> [--review-trial "<line>"] [--parallel "<line>"] [--delivers "<line>"] [--shrink | --as-built] [--also <path>]… [--trailer <line>]… [--regime after|trial] [--holds K] [--merge-defects D] [--excluded "<why>"] [--cancel-prior] [--scratch <dir>]`. `produce.md` `<MergeCheckpoint/>` runs it in the background after the showrunner's own judgments. `--as-built` (2026-10-13, from the herdr trial) merges a unit's closing as-built commit like a shrink: no tests and no review-ledger row, held until a code checkpoint of that phase merged, subject `Merge <unit> phase <N> as-built (<short>) into <branch>`, and scope limited to `.md` paths that include a change to or deletion of the unit's plan. `Promote: none` is read as no promotion, the same as an absent field, and at load every local Promote checkout must exist, so a bad destination refuses before anything is pushed.

- **Doc fields read:** `Merge branch`, `Showrunner checkout`, `Log`, the Units rows (Branch, Owns), `## Hub files` rows naming this unit, **Merge tests**, **Known flakes** (package names), **Known flaky tests** (nextest test names, as `` `<path::test>`, `<path::test>` ``), **Push:** (`validate_and_push` default, or `git`) and **Promote:** (`<checkout>[, mac <path>]`, read as `NoPromotion | PromoteTo(checkouts, MacCheckout | NoMac)`). An absent field and `none` (any case) are both `NoPromotion`; at load every local Promote checkout must exist, so a bad destination is refused before anything is pushed.
- **Input rules.** A code checkpoint needs `--review-trial` (exactly `review trial: ux <N> findings, code <N> findings, review-worker minutes <M>, ux check minutes <U>, ux repair minutes <R>`) and a one-line `--delivers`; a shrink refuses `--delivers`. It also needs `--parallel` matching `Parallel: Phase <N>[, Phase <M>…] could start` or `Parallel: none — <reason>`; `Parallel: unknown` is refused with the instruction to add the plan's `**Depends on:**` lines and rerun (`check_parallel`). `--cancel-prior` is refused with `Push: git`. `MergeRequest.delivers` and `excluded` are `str`, `""` for absent.
- **Review numbers.** The unit takes the `--review-trial` line from `progress_history.py review-trial`, which reports the phase in state, active or just closed by `finish-phase`. The code number is what the reviewers raised: the sum of `raised` over the phase's `reviewed` code turns in `review_turns/<session>/` (`_raised_code_findings`, the same sum as `review_pool_report.py`'s `Raised`), matched by phase instance. `review.sh` stamps each turn with the phase `--phase` names. A phase with no such turn (a solo review writes none) falls back to the `finding_opened` events: an event is a code finding when it names any lens other than `ux`, or no lens. The ux number always comes from `finding_opened`. An event naming `ux` and a code lens adds one to each number; the legacy lens word `both` reads as `adversary,contract` through `_finding_lenses` and adds one to the code number. `merge_checkpoint.py` parses the printed line, so its form is fixed. In the review ledger (`review_regime.py`) the code number is every code finding the phase's review raised from 2026-10-07, and the `craft` lens alone before that date; `report` prints its mean per regime as `code findings per phase (mean)`.
- **Owns rule.** A backticked bare name in an Owns cell owns both the root file and the sibling of the previous path. Without backticks the cell splits on commas before ` — `. **Merge tests** are the backticked spans before the first unquoted `(`; a missing field is refused, an empty one means no commands.
- **Steps:**
  1. *ancestry*: the commit exists; it descends from `LAST_MERGED` (skipped on `FirstMerge`); it is on `origin/<unit branch>` after a fetch, else held with "push your branch". A shrink is held here until `has_code_merge(unit, phase)`. A hash already on the merge branch skips steps 2–7.
  2. *scope*: nothing staged in the merge checkout; every path of `diff --name-only <merge branch>...<hash>` is in Owns, a hub row of this unit, or an `--also` path. A shrink allows only the plan doc and `<plan stem>-next.md`.
  3. *conflicts*: `merge-tree --write-tree --name-only` exit 1 is held, asking the unit to merge the merge branch and send a new hash.
  4. *other units*: overlap of this change's paths with each other unit's branch diff and its worktree's `status --short`, printed as data, never a stop.
  5. *merge*: `<scratch>/merge_<short>.msg` (subject `Merge <unit> phase <N>[ shrink] (<short>) into <merge branch>`, body `--delivers` or `Phase plan shrink.`, then trailers), `merge --no-ff -q -F`.
  6. *test*: each package owning a changed file (nearest `Cargo.toml`, named by its directory) through `verify.sh test`, each changed `crates/<pkg>/examples/<name>` through `verify.sh example`, then each Merge tests command, into `<scratch>/merge_<short>_test.log` with `<name>_EXIT=<rc>` lines. A command that cannot start is exit 127. `parse_merge_tests(lines, checkout)` reads the commands at input: each backticked entry before the first unbackticked `(` is split with `shlex`, each word passes `expanduser` then `expandvars` (the commands run with no shell), and an entry is refused by name when a `$VAR` is still left, or when its first word is neither on PATH nor an executable file in the checkout (a package name or a directory, as cargo-liner wrote, 2026-10-17). A shrink runs none.
  7. *red*: each red command reruns once alone. When every test in its nextest `FAIL` rows is listed in Known flaky tests, only those tests rerun (`verify.sh --filter <name>` per test, else `-E test(=<name>)`). Green alone continues with a LOG note when that held, or when the command is a package listed in Known flakes; otherwise `reset --keep HEAD~1` after confirming `HEAD` is this merge and is not on origin.
  8. *push and promote*. `GitPush`: merge `origin/main` with `--no-ff` when it has diverged, push the merge branch (on failure, abort the merge and reset to the old origin tip if origin did not move). `ValidateAndPush`: `validate_and_push.sh --quick --to <merge branch> --fix-commit "ci(<slug>): format fixes after <unit> phase <N>" [--cancel-prior]`, reset to origin on failure. Then each **Promote** checkout through `promote_local_checkout(checkout, merge_branch, tip)`: it must be on `main`; `merge --ff-only <tip>`, where tip is the pushed merge-branch tip; push `main` only when `main ^origin/main ^origin/<merge branch>` is empty. Then the Mac through `pull_mac_checkout(mac, source)`: `ssh mac "cd <mac> && git pull --ff-only natedev:<first Promote checkout> main; printf 'rc=%s\n' $?"`, judged by the printed `rc=`.
  9. *record*: for a code checkpoint, `review_regime.py add --unit --plan <the unit's Plan cell> --phase --regime --started --merged <merge commit time> --holds --merge-defects` plus the five review numbers and any `--excluded`. The ledger names a row by unit, plan and phase (2026-10-12), because a unit that runs a second plan starts again at phase 1; then the LOG line `- HH:MM <zone>: <unit> phase <N> (<hash>) merged as <merge hash>; <tests> green; pushed[; promoted]`. A LOG that already has this line skips the step.
- **Merge report.** Step 8 prints `into: <path> (<branch>) — <why>; unblocks: <what>` as it reaches each place: the merge-branch checkout (`the merge branch collects every unit's checkpoints`; unblocks `<gate id>: <Waiting cell>` for each Gates row whose **Waits on** is `<unit> phase <N>`, else `no gate`), then each Promote checkout and the Mac (`sessions on <machine> run the installed commands from it`; unblocks `the live gate of <unit> phase <N>`). It appends the proposal (`# <title>`, `**Target:**`, `**Gain per week:**`) and each item under `**Also found:**` or `**Noted:**`: a `- ` or numbered line, whose bold lead is its title and whose closing tag is its gain. A paragraph closes the item list, so a list of what was denied that night is no candidate. A line whose start (`- <night> <area>: <title>`) the ledger already holds is not written again: a second run adds nothing, and a decided line keeps its outcome. A report with no title or target exits 1 and writes nothing.
  - **Earlier lines.** Before 2026-10-12 a smaller item's outcome was written on its night's line as `; from Also found: <title> — <outcome>`. Those stay as written; every item still open then got a line of its own.

- **Queued messages.** `send.py` keeps a message that did not arrive in `STATE/queue/session-<Claude session id>.jsonl` when a live session answers to the recipient (`sessions.addressed`: `uds:` socket, name now, or a name it alone once had), and under the name as given when none does, which the `QUEUED` line then says; a `session:<id>` address is always kept under `session-<id>`. A delivered keyed send removes its queued copy, and `send.py retire --to --from --key` removes that key's messages and the sender's unkeyed ones (`/shutdown` uses both). `send.py pending` (no name: the caller's session; or a name) reads the session's file, the files of its name now and its socket, and those of its former names that no live session has now, so what was kept under a name before 2026-10-08 is still found.

- **Not moved.** Queued messages and natedev holds need no move: both are keyed by the Claude session id (**Queued messages** above; a hold file is named by its holder's session id, `docs/as-built/build-targets.md`). Stall-watch stretch files written under old names are left behind, and each unit starts a new stretch.

### Waits, renames and alerts: `waiting.py`

Each subcommand takes `--production`; `main` catches `merge_checkpoint.Stop`, so a bad doc fails as one line. A unit is named by its Unit value, or by its session's name now. `units_from_doc` reads `live_unit_table` and the lookup, so `search` and `agenda` pass over a retired unit, and `named_unit` (`scratch-test`, `eta-request`) refuses one as `unknown unit <name>`.

- `scratch-test <unit> --tests "<command>" --state-dir <dir>`: a detached temporary worktree at the unit's branch tip, `merge --no-commit --no-ff <merge branch>`, then `sh -c <tests>` into `<state-dir>/scratch-test-<unit>-<YYYYmmdd-HHMMSS-ffffff>.log`. `ScratchGreen(log) | ScratchRed(last 4 lines, log) | ScratchConflict`; the verdict prints first; the worktree and merge state are always removed; nothing is committed or pushed. A red never says `blocked`; a conflict is a `failed` line, not a red. The log path feeds `ci_points.py notice lift`.
- `waits`: `cargo-berth board --json` overlaps (an `unconfigured` envelope reads `berth not configured`) and the LOG's `block: <waiting> on <unit> (code|files: …), clears ~HH:MM` / `block cleared: …` pairs as `WaitOpen(since) | WaitCleared`. Each open wait prints its age and `act now` at 60 minutes open or 30 minutes past its clear time. A `block:` or `block cleared:` line whose waiting unit is in `retired_units` is dropped; a live unit's wait on a retired unit stays.
- `search <old> <new>`: `git grep -n -F <old> <branch>` and `rg -n -F --hidden --glob !.git <old> <worktree>` for every unit; one line per site.
- `agenda --state-dir <dir>`: `AgendaOpen(unit, phase) | AgendaNotDue` when the current phase (from the last `### STATE` block line `<unit>: Phase …|follow-up …`) began over eight hours ago, or its ETA (from `dailies ETAs:` lines through `phase_eta`) is over eight hours after its start. The start is the unit's previous code merge line in `LOG`, else its `added …` line. Deduplicated by `<unit>|<phase>` in `agenda_seen.json`.
- `eta-request <unit> --phase <phase> --state-dir <dir>`: `EtaRequested | EtaNotYetRequested`; once per `<session>|<phase>` it prints `request /unit:eta: <session>` and writes `{"requested": true}` in `eta_seen.json`.
- `update_state(path, change)` is the one locked writer for all three state files: `fcntl.flock` on `<path>.lock`, re-read under the lock, no write when unchanged, a unique temp file, then `os.replace`. `dailies_input.py` imports it with `eta_requested`.
- `eta_moment(text, line_moment)` resolves a weekday ETA to its nearest occurrence within three days of the log line, and `HH:MM <ZONE>[ tomorrow]` on the line's day.

### Status and stall watch

- **`unit_status.sh` units.** `unit_status.sh <state-dir> <user-zone> --production <production doc>` takes its units from `live_units.py --production <doc>`. `--showrunner <name or slug>` is still accepted for a prompt written before; it finds the showrunner by its name now or its slug (a former slug resolves through `showrunners.named`), so such a prompt fails after a session rename until the showrunner registers again. Each block is headed by the unit id, and its text is read with `session_pane.py read unit <slug> <unit>`.

- **`unit_status.sh`** `waiting_on_user`: nothing when a spinner shows in the last 12 lines; `FORM WAITING on you in <unit>: …` for `Enter to select`. Otherwise it reads the last turn-end line (`^\s*(— )?(holding|gate|decision|blocked|done):`). `decision`, `gate` and `blocked` are waits on the user: first sight prints `=== DECISION for you from <unit> ===` … `=== end <unit> ===` and records the key in `decisions_seen`; a repeat prints `STILL WAITING on you, <unit>: …`. A wait naming `showrunner` or a peer unit (whole word) is the showrunner's: no wait line, and only `blocked:` prints `BLOCK in <unit>, open <age>: …`, aged from `blocks_open`. Any other turn-end clears the block entry.

- **A hold with a stated end (2026-10-17).** A `holding:` turn-end that names a future time is silent in the stall watch until that time, like a waiting kind; the idle clock starts once it passes. `stated_hold_end(line, now, zone)` takes the latest `HH:MM` in the line, with an optional `YYYY-MM-DD` or `MM-DD` before it, in the production's zone unless followed by `UTC` or `GMT`; a time without a date, or a date without a year, is the occurrence nearest now (`hold_days`), so `until 01:00` read at 23:00 is tomorrow, `since 23:50` read at 00:10 is yesterday, and `Thu 10-22 11:47 EDT` is the nearest 22 October. A hold has no upper limit: real holds run for days. Seen on mul_add, bumped at 05:32 during a re-measure window its hold said ends at 16:09.

### Manager tree: `production_tree.py`

- **`production_tree.py --json`** (cargo-handler's manager nesting, user-approved 2026-10-15) prints `{"schema":1,"edges":[{"manager","member","role"}]}` and exits 0. Edges: a showrunner to each child showrunner (`showrunner`, from `showrunners.edges` over the productions whose showrunner runs); a showrunner to each unit director carrying its production's mark (`unit`, from `unit_lookup.every_marked_unit`, herdr only); a unit director to each Codex worker of its run (`impl`, `test`, `review` or `fix`, from `mesh_roster.json`'s `role`, else the role the worker's name ends with); a unit director to each Claude worker of its run, its role the one `board.sh roles` reads for its slot off `board.log` (the latest `register` carrying `role=` or `handoff`; a Claude worker's name ends with its slot, not its role). A Claude worker's session id comes from `impl_worker_<slot>.json`'s `worker_id` when its `family` is `claude`, else from the `workers` ledger, whose short id prefixes a running session id and whose name ends with the slot (2026-10-16, from the user's review of cargo-handler's tree). Managers and showrunner, director or Claude worker members are Claude session ids; a Codex worker has none, so its member is its `thread_id`. Runs are found by scanning every folder under both run roots (`unit_runs.run_roots`), not through the session markers: a director runs independent phases side by side, each in its own run folder, and its one marker names only one of them. On 2026-10-16, 6 of the 15 runs with a live app-server and live roster entries had no marker (5 opened by hand or with `env -u CLAUDE_CODE_SESSION_ID prepare_session.sh` beside the marked run, 1 whose marker a sibling run's `prepare_session.sh` replaced), so their workers had no edge. A run's director is `unit_runs.director(run)`: the session id in the run folder's `director` file, which implement.sh and review.sh rewrite on every dispatch through `unit_runs.py record-director <run folder>` from `CLAUDE_CODE_SESSION_ID` (a Codex worker that dispatches a peer inherits the director's id and writes the same one; a session the run lists as its Claude worker, by launch record or `workers` ledger short id, writes nothing, since a Claude worker has its own id; nothing is written without an id). Scripts write it, so no skill step has to (user direction 2026-10-16: not left to chance). A run nothing has dispatched in since then falls back to `main_agent.session_id` in the `run_started` event that opens the history named by its `progress_history_state.json` (`history_file`), written once by `start-run`; the state's own `main_agent` is not used, since until 2026-10-17 a pass opened inside a Codex worker rewrote it with that worker's thread (3 live runs showed one that day). `progress_history.py`'s window refresh now changes `main_agent` only when the detected session is this director, so a worker's window leaves it alone and the director's next window repairs a run that still carries a worker's thread. A folder with neither has no director and no edges. Only folders with a running app-server or a `workers` ledger are read further; implement.sh puts every Claude worker it launches in that ledger, so a folder without one is skipped before its launch records are read. A unit director also manages each pool reviewer it leases (`review`, from `<REVIEW_POOL_STATE>/<slug>/pool.json`'s `reviewers`, templates left out, for handler-enh 2026-10-16): its member is the reviewer's `thread_id`, and the edge also carries `unit` (the lease's unit), `thread_id`, `state` (`busy` while `busy_pid` runs, else `idle`) and `type`. A reviewer with no lease, or whose lease names a unit with no running director here, has no edge. A Claude manager also has one `AstraEdge` per live Astra thread it holds (`astra-designer` or `astra-reviewer`, from `scripts/astra/astra_roles.py` `live_roles`, with `codex_home` and `state`), and that thread then has no Codex worker edge; a held design role's edge names its current holder (`docs/as-built/long-lived-workers.md#lasting-roles`, Census).

- **Only running ends.** A session counts while `sessions.running_sessions` lists it; a showrunner's session is the `TARGET` of its update timer. A unit whose showrunner is not running has no edge, and a Codex worker has none once its status is `ended` or `failed` or its run's `mesh_server.json` pid is gone. A Claude worker counts while its own session runs, with no server check, since a Claude-only run has no app-server; `board.sh` is called only for a run with a running Claude worker. Only local records are read, with no ssh; cargo-handler joins machines by session id. Unreadable unit marks leave the unit edges out, with the reason on stderr.
- **Speed.** cargo-handler polls it every 30 seconds, against a 1 s timeout. The scan of every run folder, measured 2026-10-16 on natedev over 214 folders at load 99 to 129: 16 to 94 ms for the worker edges, 0.28 s for the whole command.

## Invariants

- The production doc is read only through `read_production`, `production_field`, `cell_value` and `unit_rows` (the retired readers read through `unit_rows`); Units rows are read cell by cell, since real rows are backticked and carry commentary.

- `plan_cell_is_retired` is the only test of the retired marker: `unit_is_retired` (which `live_unit_table` and `retired_units` read) calls it, and no other file tests the word. The marker counts only at the start of the Plan cell.

- Merge history comes only from `merge_branch_history` over first-parent subjects; `LAST_MERGED` is never an argument or a memory. A `chore(<slug>): rename unit <old> to <new>` subject counts every older entry under `<old>` as `<new>`, through a chain of renames; a later unit that reuses `<old>` keeps its own newer entries (unit rename Phase 1, 2026-10-16). A shrink merge never counts as a code merge, a CI count or a gate clear.

- Every refusal comes before any write: `add_unit.py` refuses in `launch_request`, the shutdown-state check (before `preflight`), `preflight` or the live herdr session name check before the stub, row or commit, and a shutdown refusal ends no session; `--check` writes and starts nothing. The director resolves in `preflight`, so promotion never stops a session it cannot relaunch.

- `merge_checkpoint.py` leaves the merge branch as it was on red. `reset --keep HEAD~1` runs only when `HEAD` is this merge and is not on origin. Promotion targets the pushed merge-branch tip, never the earlier checkpoint merge. `main` is pushed only when it holds no commits outside `origin/main` and `origin/<merge branch>`, and never with force.

- The dailies builder's one pre-check write is idempotent pruning of this production's retired generated phase notes. Every other write waits until every check has passed. Every builder call passes `--render-state`, the same file the renderer gets as `--state`.

- One state directory: `eta_seen.json` and `review_watch.json` live in `DAILIES_STATE_DIR` for every caller; a second directory forks the once-per-phase and first-alert records. A doc-contract test pins `produce.md` and `dailies.md` to the same path.

- `then` reaches the renderer unchanged; the renderer refuses, it never rewrites.

- The idle group changes only which sections a `simple` dailies prints. The timeline, the footer, the saved state and the `dailies ETAs:` line carry every unit at every length.

- An activity on a closed phase leaves that phase's record as `finish-phase` wrote it: status, `finished_at` and elapsed time. The printed `review trial:` line keeps its form, which `merge_checkpoint.py` parses.

- The stall watch's standing-by, run-finished and retired-row skips, then its waiting-kind reset, run before any bump or notice. The turn-end pattern is built from `WAITING_KINDS` and `HOLDING_KIND`, so the pattern and the wait test cannot drift.

- Unit directors launch only on Claude. `production` has only `[production.claude]`; `claude --resume` never runs without resolved flags.

- `agents_config.sh` is bash only (call it through `bash -c`) and must keep working under `/bin/bash` 3.2 (no associative arrays, no `${var,,}`).

## Calibration and gotchas

- **`config/agents.conf` holds the committed defaults only.** Each machine's own rows live in the untracked `config/agents.local.conf`, which holds only the rows that differ (`scripts/agents/agents_overlay.sh`). Readers see the overlay over the defaults; `/agent`, `/showrunner:effort` and the catalog sync write only the overlay. A commit that changes `config/agents.conf` is a plain change, and merging it never erases a machine's tuning (the former clean filter hid the local rows from git, and the 2026-10-23 fast-forward replaced them). `agents_overlay.sh migrate --from <copy>` moves a full registry's local rows into the overlay. The former filter's driver is retired: `ensure_git_filters.sh` (SessionStart) removes `filter.claude-agents-conf` from `.git/config` once and clears the stat data the index recorded while the filter ran, so `git status` and `git checkout -- config/agents.conf` see the file as it is (`git_filters_retire` in `scripts/settings/git_filters_table.sh`).

- Sourcing `agents_config.sh` may run the Codex catalog refresh when its state is stale; `--check` writes nothing of its own but does not promise zero writes to the registry's state. Tests set `AGENTS_CONFIG_FILE`, `CODEX_CONFIG_FILE`, `CODEX_MODELS_CACHE_FILE` and `CODEX_CATALOG_SYNC_STATE_FILE` (newest) to temporary paths.

- A re-run of `add_unit.py` must name its original mode; the mode comes from the commit subject, then the Plan cell, then the stub.

- `ssh`'s own exit status is always 0 here; the Mac pull is read from the `rc=` line it prints. The Mac pulls from `natedev:<first Promote checkout>`.

- `merge_checkpoint.py` counts a `basedpyright` Merge tests command green when its last line is `0 errors, 0 warnings[, 0 notes]`, whatever its exit status.

- CI point: due at 5 code merges; `ci collect` requires job `Test Suite` by name. The review table is `report --since 2026-09-28`.

- `review_watch.json` is written after the LOG line: a crash between them repeats the log entry once (at least once).

- Dailies: an ETA first seen over 1 hour ago is stale; an ETA move of 15 minutes or more (`CHANGE_NEEDS_WHY_MINUTES`) needs `eta.why`; `parse_time` treats a time over two hours past as tomorrow; updates are capped at 240 characters for `simple` and 480 for `page`.

- The renderer's ETA-change check reads its own state; `check_render_state` runs before the clock restart, so a refused user-run dailies leaves the clock where it was.

- The renderer exposes no list of required fields, which is why the builder names five itself.

- Agenda threshold is 8 hours; waits act at 60 minutes open or 30 minutes past the clear time; the weekday ETA window is ±3 days.

- `log_events` dates a date-less LOG line by walking backward across midnights; a gap over 24 hours between timestamped lines is invisible.

- Producer output shapes are not the obvious ones: the unconfigured berth board is a JSON envelope with exit 4, the ETA line is `dailies ETAs: <unit> <phase> <eta>; …`, and account labels use one spelling (`codex1`). Test fixtures come from calling the producers.

- `unit_status.sh` routes `gate:` exactly as `decision:` and `blocked:`, while the stall watch treats all four waiting kinds as silent; a unit at a gate is quiet in the stall watch and flagged to the user by the status script.

- `unit_status.sh` is zsh.

- `test_unit_status.py` copies `add_unit.py`, `live_units.py` and `showrunners.py` into its test tree, so a new import in `live_units.py` needs a new entry in that list.

- `waiting.py waits` rebuilds waits from the LOG alone, so filtering the doc's rows never reaches it; it filters on the waiting unit's name through `retired_units`.

- The stall watch reads `run-finished` and `standing-by` from the unit's run records (one `unit_lookup.read_run_states()` snapshot per tick). The production doc contributes the Worktree cell and the retired marker at the start of the Plan cell.

- Idle: `IDLE_LIMIT` is 80 characters; `idle.until` is a naive local time in the report's zone, compared with the renderer's naive local now.

- Recorder: `_event` stamps the phase in state on every event, active or closed; nothing else carries an activity's phase. When the last phase is closed but an activity is open, `progress` prints the short report from that phase's last recorded values, clocks table included, and shows the activity as the stage line. The round table needs `--tables`. `No active phase to report: …` remains for a missing or closed phase with no open activity.

- The recorder other units run is the main checkout's copy under `~/.claude/scripts/direct/`; a change in a worktree reaches them, and their `review-trial` line, only when promoted.

- `showrunners.py` is mode 0644: call it through `scripts/lib/py`.

- `already at` in a promote line means main was at the tip before the run; no other line uses it.

- In an enrolled repository the shrink's first plan-doc write goes through the Edit tool; a write from a script is never claimed by the first-touch hook.

- Sandboxed workers have no writable temporary directory and cannot run the stall-watch suite; run it from the main tree.

## Why

- **Scripts hold mechanics; command docs hold judgment.** Each showrunner step was given a script-or-judgment verdict. Script: zone time, log and STATE, questions, open/load/wrap, registration and prompt, merge/test/push/promote/record, CI counting and collection, review-watch escalation, gate notices, scratch tests, wait ages, agenda thresholds, rename search, the dailies input. Judgment: relaying the user's words, verifying a unit's claims, compacting a blocked pane, the overlap notice and restructure holds, whether a new public item has a consumer, design-check freshness and defects, the repair owner for red CI, classifying a wait as code, files or preference, landing order, permission blocks, close-out approvals, open topics and who acts next, `then` and goal text, and phone-alert urgency and wording.
- **The mode is in the commit subject**, not a Units column: the subject already records it, and a pre-filled Units row is adopted, never rewritten to the script's form.
- **Code commit before the shrink.** The code-ready notice can go out the moment the phase's code commits; the shrink runs beside the next phase's workers and lands as a plan-doc-only merge with no tests, ledger row or CI count.
- **`LAST_MERGED` is read from merge subjects**, never passed in, so a resumed or compacted showrunner cannot supply a stale value. First-parent history keeps a subject carried in by a merged side branch from counting.
- **A finished run is a named state.** `run-finished` is read from the run record's `run_finished` event; the stall watch reads that named variant and does not infer completion from production-row prose.
- **The Units row is the one retired marker.** Every reader of the Units table follows it, and the status script finds the production doc on its own through `checked_doc`, so retiring a unit changes no caller's command line. The marker counts only at the start of the Plan cell because a live unit's Plan cell can use the word in its commentary.
- **A live unit's wait on a retired unit still prints.** Hiding it would hide a stuck unit.
- **`merge_checkpoint.py`, `ci_points.py` and `production_lifecycle.py` do not skip retired rows.** A retired unit sends no checkpoint, and the wrap already passes a unit whose branch is gone.
- **No named type carries an activity's phase.** `_event` already stamps the phase in state on every event.
- **The renderer refuses a chained or string `then`** rather than rewriting it: a silent rewrite would hide the defect from the showrunner who wrote it.
- **The review alert is at least once.** Writing `review_watch.json` before the alert would make it at most once, and a lost alert is the worse failure. The alert writes its LOG line directly; routing it through `update_registration.py log` would add a stray `log: ok` line and couple two commands.
- **No `queue` command.** Arrivals are messages in the showrunner's own session, and ordering them is judgment.
- **One verdict type per flag.** `--ci-green` and `--smoke-passed` are separate flags, each checked at its own step against the same tip; a mismatch is a hold line, not a user topic.
- **Resume flags come from a checked `bash -c`, not a one-line substitution:** a failed substitution would run `claude --resume` with no flags and skip the family check.
- **No `[production.codex]`** and no Codex director: unit directors launch only on Claude. Pinning a one-family function keeps every-function switches (`/agent` "all on codex") from breaking director launches.
- **Unit directors default to `opus:xhigh`** (the user, 2026-10-07, moved back from `sonnet:xhigh`). Test fixtures write their own rows, so they test that a row changes the launch, not the live default.
- **The showrunner settles a unit's designs and add-ons (user, 2026-10-12: "when it comes to designs you absolutely should be able to tell units what to do and change. I do not have to be the one to approve").** A unit in a production brings a design choice, a Pending decision about how something is built, and its pending add-ons to the showrunner, whose answer settles them; the showrunner may also change a unit's design unasked. The user keeps two kinds: an action that cannot be undone, and a choice only they know the answer to. The rule is written once per reader: `docs/production_format.md` → `<ProductionUnit/>` item 2 for the unit, `/unit:add_ons` → `<ReviewPendingAddOns/>` for the add-on message and its answer, and `/showrunner:produce` → Throughout → Designs and add-ons for the showrunner. A run outside a production still asks the user. `docs/decision_criteria.md` is unchanged.
- **Open questions show only as a count (user, 2026-10-12; the reply side changed 2026-10-18).** A showrunner records each question in `open_for_user` before it asks, then asks it once in full with its reviewed text. After that only the status line's counts row (`For you: …`, `docs/as-built/shutdown-and-restart.md`) shows them, as a count of the `OUTSTANDING` items now due across the productions its session runs. No reply carries a footer or a `Waiting on:` block. The full list is given only when the user asks (`update_registration.py open`). The dailies' sections on what needs the user are unchanged.
- **One source for the zone (2026-10-12).** The user's zone is `config/user_zone.conf`, read through `scripts/lib/user_zone.py`, and nothing else. A production doc's `- **User zone:**` line was parsed in three places: `showrunners.py` (the registry's zone), `add_unit.py` (`Production.zone`, which `merge_checkpoint`, `ci_points`, the dailies builder, `waiting`, `stall_watch` and `update_registration` use) and `hooks/showrunner_footer.py`. Each now returns the setting. A doc that still carries the line loads as before and the line is ignored; a doc without it registers, where before it was refused. `/producer:to_production` no longer writes the line. `progress_history.py eta` reads a typed time in the setting's zone and no longer in the process `TZ`, so `/unit:eta` and `/unit:eta_breakdown` pass no `TZ=`. The shell displays in `message/notifier.sh` (`next_due`), `validate_and_push/ci_tick.sh` and `production/smoke_launch.sh` read the helper as well. Tests whose expected times are Pacific pin `USER_ZONE` at module level.
- **LOG backups (2026-10-12).** On every scheduled update tick `production_check.sh` runs `scripts/production/log_backup.py <doc>` for a running production, so every production is covered with no setup of its own. `backup(log: Path, directory: Path, now: datetime) -> Path | None` copies LOG to `<SHOWRUNNER_STATE_DIR or ~/.local/state/showrunner>/<slug>/log-backups/log-<YYYYmmddTHHMM>.md`, stamped in the production's zone, and keeps the newest 48 (`KEEP`). An empty or missing LOG is not copied, and neither is one unchanged since the newest copy. A failed copy prints `log_backup: <reason>` to the tick's stderr and leaves the check's exit code alone. To restore, copy the wanted file back over LOG. Added after a LOG was emptied by mistake with no copy anywhere.
- **`dailies_render.py --footer --nothing-needed`** replaced a scan for an invented `needed` key.
- **Not done here, by choice:** renaming `MergeEntry`/`NoMerge` to checkpoint-merge names (churn with no behavior change); named states for `LastUnitReport.held` and `first` (bare optionals older than the ETA states); reporting the builder's `<step>: ok` lines to the user (an implementation transcript).

## Session hosting

Unit lookup reads only herdr. `Place` is `HerdrPlace(session, pane)`;
`MarkedUnit(unit, claude, place, pid, command)` exposes the server name as `place.session`.
`every_marked_unit()` raises `OSError` when herdr cannot be read, and
`marked_units(slug)` selects one production. A live Claude joins only marks on
its exact PID. A marked shell or other non-Claude process retains its stopped
pane as `ClaudeNotRunning`, for recovery, resume and status. Live or unknown
Claude holders take precedence over stopped panes; only those holders count
toward duplicate faults. With only stopped holders, the first pane is retained.
Duplicate live or unknown marks refuse that production and name each holder's
PID, command and pane. Transfer and rename verification reject former marks
only for live or unknown holders, ignoring leftover non-Claude processes. Registry records join by pid through `herdr_processes` and
`herdr_place_of`; unreadable cwd preserves placement. An unreadable registry
keeps an unresolved Claude as `ClaudeUnknown(reason)`; a registered running Claude without its messaging socket is also unknown, never absent.

Units launch exclusively in herdr and restore through `add_unit.py --host-session`.
Resume models come from transcripts. Existing Units rows can be reused;
running sessions acquire marks only at launch. Promotion waits for Claude
to exit before stopping its herdr server and launching the replacement.
Registration creates the showrunner update and the run-only stall-watch job.
