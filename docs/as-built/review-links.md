# Review links

`commands/review_link.md` publishes review artifacts from either machine. It runs `scripts/review_links/review_link.py FILE... [--new]` and returns one URL per file. Before giving a link, the session fetches it on the same machine with `curl -s -o /dev/null -w '%{http_code}' '<URL>'` and requires `200`. It uses only the review-links service, never a hand-run server.

The host is this machine's Tailscale IPv4 address from `tailscale ip -4`. For example, `http://100.103.14.30:8765/k3x9qa/herdr-issue-draft.html` addresses the interface the server binds. On 2026-10-29 the user's browser refused a bare `natedev` URL even though the Mac's system resolver returned its Tailscale address. The host name also does not resolve on its own machine. IPv4 literals avoid those resolver differences. A URL with natedev's address and a 20-character filename is 53 characters, below the 60-character target.

Files live under `~/.local/share/review-links/<id>/`. The ID is six random lowercase letters or digits selected with `secrets.choice`. A new folder is created exclusively; a taken ID triggers another attempt, up to ten tries before refusal. Filenames retain their names. Markdown links use `<stem>.html`. Missing files, directories, reserved names and output-name collisions refuse the whole request before writing. Reserved names are `.index.json`, `.index.lock` and names starting with `.review-link-`, including case variants. Output names use Unicode case folding so the Mac's case-insensitive filesystem cannot overwrite another input. The collision error names both source files.

The root's `.index.json` maps a sorted list of `(resolved source path, published source filename)` pairs to an ID. Running the command on the same file set reuses its folder and links, even if file order changes. A differently named symlink alias gets a separate ID and leaves the original link intact. An exclusive `fcntl.flock` on the persistent `.index.lock` covers the index read, all publication and cleanup, and the index write. Concurrent publishers therefore preserve each other's entries. Closing the lock file releases the lock, including on error. The session gives the same links and tells the user to refresh. Each output is written to a temporary file in that folder and published with `os.replace`, so a reader sees complete old or new bytes. Files that are no longer outputs are removed, and the folder's modification time is refreshed. Replacement is atomic per file; a bundle is not one atomic transaction. A different file set or a swept folder gets a new ID. `--new` also creates a new ID and makes it the file set's current link; earlier links keep their content until expiry. Each run drops index entries for missing folders. The index is also written to a temporary file and published with `os.replace`. Session shutdown deletes nothing. The ignored `--name` flag remains accepted for older callers.

Markdown is copied alongside a rendered HTML page. The page uses the filename as its title, a phone-width layout, system light/dark colors and marked 12.0.2 from cdnjs. An escaped `<pre>` stays readable if the renderer cannot load. Code blocks and the fallback scroll sideways without wrapping. The renderer escapes raw HTML such as `<details>` as text. GitHub renders that HTML, so use plain Markdown for a draft that must look the same in both places. HTML files, images and other files retain their bytes. Files in one folder can refer to each other by filename.

`scripts/review_links/serve.py` binds only to the IPv4 address from `tailscale ip -4`, on port **8765**. It exits nonzero if lookup or binding fails. It checks the address every 60 seconds. A failed lookup or changed address stops it with status 1 and one stderr line. The systemd user service or launchd user agent must restart it to bind the current address. If stopped Tailscale still reports the same address, the socket stays bound and answers when Tailscale returns. `--port PORT` selects a test port. The server serves regular files under the root. Directories, parent traversal, symlinks outside the root, the private root index and unfinished temporary writes return 404. HTML is UTF-8 `text/html`, images keep their MIME type, and other files are UTF-8 `text/plain`.

At startup and each hour the server deletes folders whose modification time is more than seven days old. It handles both flat ID folders and the earlier `<session>/<UTC stamp>-<label>-<unique suffix>/` layout. A six-character folder containing subdirectories or symlinks takes the legacy path; this preserves a `manual/` session containing only a symlink. Symlinks and non-directory entries, including `.index.json` and temporary files, are skipped. `REVIEW_LINKS_ROOT` overrides storage for both scripts. `REVIEW_LINKS_HOST` overrides the URL host without shortening it. Neither changes the server binding.

## Service checks

The Linux user service is `review-links`; check it with `systemctl --user status review-links` and `journalctl --user -u review-links -n 30`. The Mac user agent is `org.nixos.review-links`; check it with `launchctl print gui/$(id -u)/org.nixos.review-links`. After installation, restart it with `launchctl kickstart -k gui/$(id -u)/org.nixos.review-links`.

Publish a file and fetch its service URL on the same machine with `curl -s -o /dev/null -w '%{http_code}' '<URL>'`. Require `200` before sharing. Production links use plain HTTP within the tailnet. No `tailscale serve` change is needed.

On 2026-10-29 an isolated acceptance server on natedev at `100.103.14.30:18765` served `docs/herdr-issue-draft.md` to curl from the Mac at `100.111.54.14`. It returned HTTP 200 and `<title>herdr-issue-draft.md</title>`. That temporary server and root were removed. This was a test, not a link given to the user. Installed-service checks remain for service integration.
