# Unit tooling: function-length hook, showrunner footers, stall watcher and launcher follow-ups

## What it is

A set of agent-session tools in `~/.claude`, all Python (standard library) or zsh/bash, with tests beside the scripts:

- A PostToolUse hook that blocks an editing agent the moment an edit leaves a Rust function over clippy's `too_many_lines` limit.
- A Stop hook that makes every showrunner reply end with the current footer and a `Waiting on:` block, with a per-production off switch (`/showrunner:footer`) and an adhoc-review pause.
- Production status that reads what is true: run-out wording after a quota reset, Claude found through its tmux pane, footers judged as of their stamp.
- A machine-local showrunner registry (`config/showrunners.json`), a stall watcher that bumps an idle unit director, run-only notifier jobs, and tmux session names that follow Claude session names.
- Cargo-token hygiene: each verify step runs in its own process group that a release or reclaim stops.
- Launcher changes: `implement.sh --to <seat>` carries follow-up work to a seat still open, a Claude seat starts at its registry effort, a pane-derived summary is plain text, and `/unit:report on|off` switches a unit's progress updates.

The hook is judged against this baseline, measured over every hana clippy step: 13.3 `too_many_lines` failed steps per 100 hana clippy steps, 4.9 per 100 where it was the sole cause, and 1.07 h a day of sole-cause seat time.

The Codex hook install (`codex_hooks.py`), the one-command unit start and checkpoint merge (`showrunner-automation.md`), and the hook re-measure live in their own docs.

## How it works

### Function-length hook

Files: `scripts/hooks/fn_length_lib.py` (checker), `scripts/hooks/post-tool-use-fn-length.py` (entry), `scripts/hooks/test_fn_length.py`. `settings.json` registers `"$HOME/.claude/scripts/lib/py" "$HOME/.claude/scripts/hooks/post-tool-use-fn-length.py"` in the `Edit|MultiEdit|Write` PostToolUse group, after basedpyright and before the mul-add hook.

- **Payloads.** One entry serves both agents. `applied_rust_edits(raw) -> AppliedRustEdits(agent, tool, cwd, files) | IgnoredEdit`: Claude `Edit`/`MultiEdit`/`Write` with a `.rs` `tool_input.file_path` gives `agent="claude"`; Codex `apply_patch` (`tool_input.command` is the patch text) gives `agent="codex"` and the `.rs` files named by `*** Add File:`, `*** Update File:` and `*** Move to:` headers (deletes are ignored). The entry returns before any import when the raw text holds neither `.rs` nor `\u`.
- **Check.** `long_functions(rs_file: os.PathLike[str] | str) -> tuple[TooManyLinesLintScope, list[FunctionLength]]` returns the non-exempt functions over the threshold, in source order; empty when the scope is disabled or the file is unreadable or not UTF-8. `TooManyLinesLintScope(enabled, threshold)` and `FunctionLength(name, line, lines, exempt)` are plain `__slots__` classes. The whole file is checked, not only the touched lines.
- **Verdict.** One JSON object: `decision: "block"`, `reason`, `continue: true`, `systemMessage: "fn-length: <summary>"`, and `hookSpecificOutput.additionalContext`. The reason is `fn <name> at <path>:<line> is <N> lines (limit <T>)` joined by `; `, then `: split it now. The edit was applied.`; `<path>` is relative to `realpath(cwd)` when inside it, else absolute. It never names the exemption attributes.
- **Log.** Every block appends one record per affected file to `blocks.jsonl` under `FN_LENGTH_HOOK_STATE` when set, else `~/.local/state/fn-length-hook` (directory mode 0700): `{"at", "agent", "tool", "cwd", "file", "threshold", "functions": [{"name","line","lines"}]}`. Both agents log, so a re-measure can prove both fired.
- **Lint scope.** `read_clippy_lint(rs_file, lint, group) -> ConfiguredClippyLint(level, package_dir) | UnavailableClippyLint` (`NO_PACKAGE`, `UNREADABLE`) walks up to the nearest `Cargo.toml` whose text names `package`; no `lints` text means `UNSET`. `lints.workspace = true` follows `package.workspace` or the ancestors to `[workspace.lints.clippy]`. The level is the `too_many_lines` entry, else `pedantic`, as a string or a `{level = …}` table. The hook fires at warn, deny or forbid. The threshold is `too-many-lines-threshold` from the nearest `clippy.toml` or `.clippy.toml` walking up from the package directory, else 100; a non-integer or negative value disables the hook. `read_clippy_lint` and `target_may_be_no_std` are shared with `mul_add_lib.py`; a change to either affects both hooks.
- **Counting.** `count_body_lines(body)` is clippy's loop: strip the body, split on newlines, and count a line only when code appears outside a comment, carrying block-comment state across lines (`/*` before `//` enters a comment, `*/` leaves it). Strings are not parsed, so `"a // b"` counts when code precedes it. A line of `code /* c */` counts; the signature, attributes and doc comments never do. Threshold 100 means 101 lines fail.
- **Scan.** `measure_functions(source, *, skip_example_tests=False) -> list[FunctionLength]` tokenizes with one regex (`_TOKENS`: line and nested block comments, strings, raw strings, char literals, `#[`/`#![`, delimiters, `!`, and the keywords `fn impl trait mod`), pairs delimiters, and walks tokens once. `body_opener` skips parenthesized and bracketed runs and gives up at `;` or `}` (no body). Names come from `_function_name` (raw identifiers `r#x`, comments between `fn` and the name). Closure lines count in the enclosing body; a nested `fn` is also measured on its own. Macro bodies (`macro_rules!`, `name! { … }`) are skipped via `macro_before`; a keyword is never a macro name and `!=` is never a marker.
- **Exemption.** `_is_exempt` accepts `allow(…)`, `expect(…)` or `cfg_attr(…, allow|expect(…))` naming `clippy::too_many_lines` or `clippy::pedantic`. Outer attributes pending since the last `;`, `{` or `}` attach to the next item: a `fn` is exempt, and everything inside an `impl`, `trait`, `mod` or `fn` block is exempt. `#![…]` exempts the rest of its block. A keyword inside a signature (`-> impl Fn()`) is not an item. With `skip_example_tests`, `#[cfg(test)] mod` blocks in a package-root `examples/` target are skipped.

### Showrunner footer, Stop hook and switch

Files: `scripts/production/dailies_render.py`, `scripts/hooks/stop-showrunner-footer.py`, `scripts/hooks/showrunner_footer.py`, `commands/showrunner/footer.md`, the Footer section of `commands/showrunner/produce.md`, `commands/showrunner/dailies.md`. The Stop hook is the third entry of `settings.json`'s Stop group, after `stop-delegate-continue.py` and `stop-assistant-prose-banned-words.py`.

- **Footer renderer.** `dailies_render.py --footer --zone <IANA zone> [--next-run <HH:MM[+N]>] [--nothing-needed] [--at <YYYY-MM-DDTHH:MM[±HH:MM]>] [--outstanding <outstanding.json>]` prints `footer()`, the same text a dailies report ends with: an empty line, `---`, `HH:MM <zone> update:`, an empty line, then `* ` bullets: `build hold: <name> since HH:MM <ZONE>, for <purpose> - release eta: …` lines (release-state lines nested as `  * `), each Agents line in the dailies report's words (no `### Agents` heading), and last `* next dailies: [Day ]HH:MM <zone>` or `* no dailies scheduled`. ` - nothing needed` is appended only when `--nothing-needed` is set and no outstanding item is visible (a deferred item shows only after its `after` time). `--next-run HH:MM+N` means N days later; `--at` names one occurrence of a repeated hour. Bad input prints `dailies_render: <error>` and exits 2.
- **Waiting on block.** The showrunner, not the renderer, writes it after the footer: two empty lines, `Waiting on:`, an empty line, then `* ` bullets, the user's items first, then ETA items soonest first, then no-ETA items.
- **Stop hook entry.** `stop-showrunner-footer.py` imports only `json`, `os`, `sys` and `typing` until it knows the session is a showrunner. It reads `StopPayload` (`session_id`, `last_assistant_message`, `stop_hook_active`, `agent_id`) and passes when `stop_hook_active` is set, `agent_id` is present, or the session id or reply is empty. A session is a showrunner when a `showrunner-*` notifier instance's `conf` (under `NOTIFIER_STATE_DIR` or `~/.local/state/notifier`) holds `TARGET=session:<id>`. It collects each production's `FooterState` and prints `{"decision": "block", "reason": …}` from `block_reason`. Any exception prints `stop-showrunner-footer: <type>: <message>` to stderr and exits 0.
- **Production.** `read_production(instance_dir) -> Production | None` takes the doc from the last token of the instance's `CHECK`, requires `Status: PRODUCTION — running`, reads the zone from the doc's `- **User zone:**` line, and builds `schedule` from state: `ScheduledDailies(next_due)` when `ENABLED=1`, else `NoDailiesSchedule.PAUSED_OR_UNSCHEDULED`. Anything unreadable gives `None` (the production is skipped).
- **Check.** `block_reason(instance_dirs: list[str], reply: str, states: dict[str, FooterState]) -> str | None`:
  1. No running production, or every production's state `OFF`: pass with no check at all.
  2. When the reply ends in a valid Waiting on block (`waiting_bullets`), `waiting_format_error` runs for each production. ETA bullets lead with `[<Day> ]HH:MM[+1][ (HH:MM[+1]–HH:MM[+1])] - `; no-ETA bullets lead with `no ETA measured - `; others are the user's. It blocks on an ETA mid-line, a zone after a leading time (all-caps word of two to five letters), ETA items out of (day, minutes) order (unmarked is today, `+1` tomorrow, a weekday the next such day in the production's zone, today's own weekday being today), and kinds out of order (user, ETA, no-ETA). The reason names the rule and shows `19:45 (18:20–23:55) - startup Phase 16` and `no ETA measured - <item>`.
  3. For each production still on, the expected footer comes from `render_footer`, which runs `dailies_render.py --footer --zone <zone> --outstanding ~/.local/state/showrunner/outstanding/<slug>.json` (`--next-run` from state `NEXT_DUE` when scheduled; `--nothing-needed` and `--at` from the reply's stamp) with a 10 s timeout; a non-zero exit or timeout raises `FooterError`. The footer lines must appear in the reply's pre-Waiting part; several productions each take an unoccupied match, and a section stamped differently is re-rendered at its own stamp.
  4. Otherwise the reason is `REASON_HEAD`, the current footer rendered with no `--at`, and a `Waiting on:` example.
- **Stamp.** `stamp(lines, now) -> tuple[datetime | None, bool]` reads the last `HH:MM <zone> update:` line; it counts only when at most `STAMP_WINDOW` (5 minutes) old and its zone abbreviation matches the candidate occurrence (both `fold`s are tried, so a footer in the repeated fall-back hour matches). The bool is whether the last footer bullet ends ` - nothing needed`.
- **Switch.** `~/.local/state/showrunner/footers-off/<slug>` (present = off; `SHOWRUNNER_STATE_DIR` replaces `~/.local/state/showrunner`), keyed like `outstanding/<slug>.json`, so it outlives compaction, `claude --resume` and a new instance target. `FooterState` is an enum (`ON`, `OFF`). `/showrunner:footer [on|off]` runs `"$HOME/.claude/scripts/lib/py" "$HOME/.claude/scripts/hooks/showrunner_footer.py" on|off|status`, which acts on every `showrunner-*` instance targeting `$CLAUDE_CODE_SESSION_ID`; `status` prints `<slug> footers on|off` per production; `on` and `off` exit 0 when already so; with no such instance it exits 1 with `no production targets this session`. Off pauses the footer and the Waiting on block together.

### Production status: run-out and pane lookup

- `scripts/whoami/run_out.py`: `Reading(at, used_percent)`, `read_readings`, and `weighted_rate(readings, end) -> float | None`: percent used per second by `end`, each rise between consecutive readings weighted by 0.5^(age / `HALF_LIFE`, 12 h). A drop (a weekly refill or a redeemed reset), time at 100% and a gap over `MAX_GAP` (15 min: the account sat logged out) are skipped, so rises before a refill still count. None until the counted time, weighted, reaches `MIN_SPAN` (1 h).
- `dailies_render.agent_line` extends `weighted_rate` at the latest reading to 100%, rounded to the minute. When it is None, the fallback divides used percent by the time since the later of the weekly refill and now minus `run_out.WINDOW` (24 h).
- Agents line forms (then the unchanged resets part, `N reset(s) available until <Mon D>` / `no resets available` / `resets unknown`): `claude 1: 25%; runs out about Tue 22:02 PDT, before its Sun 23:00 refill; …` (`22:02 PDT today` when today); `…; runs out about Mon 04:00 PDT, so it hits its Sun 23:00 refill first; …`; `…: 1%; does not run out at this pace, so it hits its Sun 23:00 refill first; …` (rate at or below 0); `…: 100%; ran out, back at its Sun 23:00 refill; …`. Unknown usage reads `week's usage unknown; refills …`.
- `agent_section(now, zone, *, at=None)`: with `--at`, when a note's `weekly_usage_checked_at` is later than the stamped minute, each line uses the account's latest reading before the end of that minute (computed in absolute time), and only readings up to it feed the pace; with none the note stands. Notes are the active `~/rust/hanadocs/agents/*.md`; readings live in `~/.local/state/agent-notes/readings.jsonl`.
- `scripts/production/unit_status.sh <state-dir> <user-zone> <session>…` (or `… --showrunner <session>`, which takes that showrunner's units from `live_units.py`: the units in `config/showrunners.json` without each one whose Units row is marked retired) finds each unit's Claude through its pane: `$TM display-message -p -t "$u" '#{pane_pid}'`, then `pane_claude_pid` walks descendants breadth-first over one `ps -eo pid=,ppid=,args=` read in `awk` and takes the first whose args match `^claude([[:space:]]|$)`; none prints `CLAUDE NOT RUNNING`. A unit whose remote-control name differs from its tmux session still reads as running. The script holds no stalled-unit check.

### Showrunner registry and stall watcher

- `config/showrunners.json` (git-ignored with `config/showrunners.lock`; `SHOWRUNNERS_CONFIG` redirects it) holds `threshold_percent` 2, `repeat_minutes` 30, `stall_minutes` 5, `faults_to` `natedev`, `always` `["natedev"]`, and `showrunners: [{session, zone, units, standby?}]`, where `standby` lists the units waiting on work. It replaced the quota-alert JSON; `quota_alert.py` sends to `always` then each configured showrunner, each name once.
- `scripts/production/showrunners.py` converts the file to `ShowrunnerSettings`/`Showrunner` TypedDicts (`load_settings`) and runs `add <session> --zone <zone> [--unit …] [--standby]`, `remove <session> [--unit …]`, `ready <session> --unit <name>` (takes a unit off standby; one not on standby prints `<unit> is not on standby`, exit 0), `rename <session> <new_name>`, `import` and `list`. Each unit reads as `WorkingUnit | StandbyUnit`. `add` and `remove` exit 0 when the file already says it. A change to an absent file starts from `defaults()`; a reader of an absent or invalid file raises `ValueError`, which the callers print as one stderr line with exit 1. `change()` is the only writer: exclusive `fcntl.flock` on the lock file, reread, temp file in the same directory, `os.replace`. `rename` renames a showrunner session and unit entries alike, runs `stall_watch.py rename-state …` to move that name's stretch files, and rewrites `unit_status.sh` arguments in each showrunner's prompt file. `import` reads zone and units from the `unit_status.sh <scratch> <zone> <units…>` command in each running `showrunner-*` prompt (the `--showrunner` form gives zone only). `RunningShowrunner(slug, session, socket, prompt)` carries `PromptUnits(zone, unit_sessions)` or `UnreadablePrompt(reason)`; `missing_showrunners(settings)` matches sockets to find a live instance the config lacks. `list` prints `<session>\t<running|not running>\t<zone>\t<units>` (a standby unit as `<unit>:standby`) and `missing: …` lines.
- `scripts/production/stall_watch.py` runs each minute as the run-only notifier instance `stall-watch`. Per tick, under a non-blocking `flock` on `~/.local/state/stall-watch/lock` (a held lock exits 0 at once): for each unit of each configured showrunner that has a live socket and a live tmux session (`tmux has-session -t =<unit>`, pane `=<unit>:`), find Claude (`claude_pid`: the pane's own process first, then descendants whose command is `claude` or starts `claude `), read its session id and `messagingSocketPath`, and track a stretch.
  - A stretch is `Stretch(pane_hash, since, bump_sent, tell_sent, reported_status)` in `~/.local/state/stall-watch/<sha256(showrunner session NUL unit)>.json`. The hash covers `capture-pane -p -J -S -400`. A changed pane resets it unless something was sent; transcript activity (the session's `.jsonl` and its `subagents/` files) moves `since` forward before a report is sent.
  - A unit whose last turn-end line (`holding|gate|decision|blocked|done:`) is `done:`, `blocked:`, `gate:` or `decision:` is waiting, not stalled: no bump, no report, a fresh stretch; `holding:` stays a stall candidate. A standby unit and a unit whose Units row Plan cell says `run done` or begins with the `retired` marker are skipped. A shell or launcher descendant of Claude (`zsh bash sh implement.sh review.sh verify.sh`, defunct ones skipped) means work is running and resets the stretch. After a report the stretch holds until work runs or the turn-end line changes.
  - Idle for `stall_minutes` with no work: one bump to the unit's own socket (`stall-watch: you have been idle since HH:MM <zone> with nothing running. Continue your run; …`, key `stall-watch:<unit>:<since>:bump`) and one report to its showrunner (`<unit> idle since …, nothing running; bumped. Last status: <line>`, key `…:tell`) per idle stretch.
  - A live showrunner missing from the config is reported once to `faults_to` (`missing-<slug>.json`), naming the exact `showrunners.py add …` command, or placeholders and the reason when its prompt is unreadable.
  - `send_all` starts every `send.py --to uds:<socket> --from stall-watch --key <key> --text …` together and waits at most 90 s for the batch; a failed recipient is retried next tick with the same key; the stretch flag is set only after a successful send.

### Notifier run-only jobs and tmux names

- `notifier.sh new <instance> --every <min> --run <cmd> [--timeout <s>]` makes a run-only instance (`RUN=` in `conf`; not combinable with `--to`, `--from`, `--check`, `--command`, `--prompt-file`, `--hold` or `--aligned`; timeout defaults to 120 s). `cmd_tick` starts each due `RUN=` job outside the tick through `launch_run`: a transient `systemd-run --user --collect --quiet --no-block --unit session-notifier-<name>-<pid>-<random>` on Linux; on macOS a `launchctl submit` job that runs `run-due-and-remove <name> <label>` and removes its own label; with neither launcher it logs `run launcher unavailable: <name>; waiting after tick` to `notifier.log` and runs the job after the tick lock is released. The job claims its slot, runs the command with output to `<instance>/run.log` (replaced each run), has a `zselect` watchdog that sends TERM at the timeout, and appends `run timeout` or `run exit <rc>` to `fire.log`. Non-run jobs still run inside the tick.
- `scripts/production/tmux_names.py` runs each minute as the run-only instance `tmux-names`. It maps `tmux list-panes -a -F '#{session_name}\t#{pane_id}'` to live Claude sessions (`~/.claude/sessions/<pid>.json` with a live pid and a `name`; the pane comes from `TMUX_PANE` in `/proc/<pid>/environ`), and for a session whose name was set by the user (`nameSource == "user"`) and differs from its tmux session runs `tmux rename-session -t =<old> <new>` then `showrunners.change("rename", old, "", [], new)`. A tmux session hosting more than one Claude, or a new name already taken, is skipped and reported once per case to `faults_to` (marker `~/.local/state/tmux-names/<sha256(kind NUL old NUL new)>`). No tmux server exits 0.
- `update_registration.py register`, which `produce.md` `<StartUpdates/>` runs, registers the showrunner (`showrunners.py add <its name> --zone <zone> --unit <each unit's tmux session>`) and creates the `stall-watch` and `tmux-names` instances when `notifier.sh status <instance>` reports none: `notifier.sh new stall-watch --every 1 --run "$HOME/.claude/scripts/lib/py $HOME/.claude/scripts/production/stall_watch.py"`.

### Adhoc review pause

`scripts/production/review_pause.py pause | status | resume both|dailies|footers|none` acts on each production targeting `$CLAUDE_CODE_SESSION_ID`. The record is `~/.local/state/showrunner/review-paused/<slug>.json`, `ReviewPauseRecord{dailies, footers}` with each action an `ActionState`: `untouched`, `attempted`, `done` or `skipped` (legacy booleans read as `done`/`skipped`), written atomically before and after each action. `pause` stops dailies (`notifier.sh stop showrunner-<slug>`, 10 s timeout) when enabled and sets the footer switch when footers are on; `reconcile_attempted(instance, slug, path, record)` (shared by `pause`, `status`, `resume`) turns an `attempted` action into `done` when its effect is observable. A failed stop leaves `attempted`, so a re-run redoes only what did not happen. `resume` undoes only `done` actions the answer selects, then deletes the record. `/adhoc_review` Step 2 runs `pause`; Step 5 runs `status` and, if a record exists, asks `Turn dailies and footers back on? (yes / dailies only / footers only / leave off)`, then `resume` (`yes` is `both`, `leave off` is `none`).

### Cargo token and step groups

- `verify.sh` takes the token with `board.sh acquire <dir> <slot> cargo --pid $$ --hold 3600 --wait 1800`; a failed acquire exits 1 (`waited for the cargo token and did not get it`). Each cargo step runs under `STEP_OWNER_PY`: the parent forwards INT/TERM/HUP to the child's group; the child calls `os.setsid()`, and under `cargo.guard` writes `{"group", "start"}` (pid and `/proc` start-time identity) to `locks/cargo.d/owned` only if `holder_pid` still equals the verify pid (else exit 125), then runs the command.
- `board.sh cleanup_owned_group` runs on `release` and on dead-holder reclaim: it checks the recorded leader's identity, `SIGKILL`s the group, waits 2 s, and fails closed (`board.sh: step group still has running processes`, `… leader identity changed`, `cannot inspect step process group`) with the token left in place. An expired lock whose holder is alive is reclaimed without touching its build; the reclaimed holder is appended to `reclaimed_holders`.
- `board.sh release <session_dir> <agent> <resource> --pid <pid>` refuses a pid that is not the recorded holder's: exit 3 when the caller is in `reclaimed_holders` (the new holder owns the token), else exit 1, reason on stderr. `verify.sh`'s `release_token` always passes `--pid $$`; 0 and 3 count as released, any other status turns a passing run into exit 1.

### Launcher follow-up path

`implement.sh --to <seat> <session_dir> [working_dir] [prompt_file] …` (`--to` first, then the usual positional arguments; the prompt file is the message).

- It skips `seat_name.sh` and addresses the full seat name from `mesh_roster.json` (Codex) or the `seats` ledger (Claude). Before any record it exits 2 with a message when the seat has no matching durable identity (`impl_seat_<slot>.json`: name, slot, family, model, full Claude session id or Codex thread id), is `mesh=none`, is claimed by a live launcher, reads `implementing`, or is busy (roster not followable, or `claude agents --json` status other than `idle`, or gone).
- It then runs the new-seat path: truncate `impl_summary_<slot>.txt`, write `impl_status_<slot>` (`implementing`, then `implemented` or `error`), `start-pass`, a register line (`follow-up to <seat>`), the follow-up, `finish-pass`, `findings.py landed` (or `abandon --edits-landed` on a worker error) under `PLAN_DELEGATE_RESOLVES_ROUND=1`, and the `launcher:` `done` or `blocked` board post. A trailer appended to a copy of the prompt (`impl_follow_message_<slot>.<pid>.txt`) tells the seat to write the summary last, then post `done`. `implemented` is written only after `finish-pass` and `landed` succeed; a failed write posts `blocked`, writes `error` and exits 1. The launcher's exit wakes the unit director as a new seat's does. A trap releases the claim at exit.
- One claim per seat (`impl_claim_<slot>.json`, `{pid, seat, turn_id}`, under `impl_seat_claim.lock`). A claim whose launcher is dead is dropped and its status set to `error`. Codex: `codex_mesh.py can-follow --session-dir <dir> --to <seat> --claim-pid <pid>` checks followability and takes the roster claim before any status write (a second concurrent follow exits 2, nothing recorded); `codex_mesh.py follow --session-dir <dir> --to <seat> --message-file <path> --summary-file … --log-file … [--claim-pid <pid>] [--timeout <s>]` then requires that claim (a changed claim exits 1; without `--claim-pid` it refuses and claims on its own pid); `release-follow` releases an unstarted claim.
- Roster states are typed: `FollowableThread(done|failed)`, `ActiveThread(turn_id, launcher_pid)`, `StartingThread(launcher_pid)`, `WaitingCapacityThread`, `ExhaustedThread`, `InvalidThread(reason)`. A stale `ActiveThread`/`StartingThread` whose launcher pid is dead counts as followable. `_follow_refusal` also asks `thread/read` (through `_read_live_turn`) and refuses on a live turn; `_server_availability` returns `LiveServer(port)` or `ServerRestartRequired`. `follow` starts or reuses the app-server, calls `thread/resume`, starts one turn on the same thread and streams it with `_stream_turn(…, follow=True)` (the loop `start` shares), waiting on the started turn id so an earlier `done` cannot end the wait.
- Claude: `agent_bg.sh --attach <mesh_name> <working_dir> <message_file> <summary_file> <log_file> <id_file> [model]` sends through `send.py --to <name> --from launcher --file` (`QUEUED`/`FAILED` is an error), counts the seat's finished assistant turns (`stop_reason` `end_turn` or `stop_sequence`) in `~/.claude/projects/*/<session id>.jsonl` before sending, records `claude-turn-<n>` on the claim, and waits until the count grows and `claude agents --json` reads `idle`. It exits 1 when the seat vanishes.
- Docs: `commands/unit/delegate.md` and `docs/delegate/write_prompt_contract.md` say a finished Codex seat is reached only through `implement.sh --to`, a repair whose files sit with an open seat may go to it the same way, and a message to a seat without the launcher is for questions only.

### Seat effort, pane summary, `/unit:report on|off`

- `implement.sh` starts a new Claude seat with `AGENT_BG_EFFORT="${AGENT_EFFORT:-}"` beside `AGENT_BG_LEDGER`; `agent_bg.sh` adds `--effort <level>` to `claude --bg` next to `--model`. An empty registry effort passes an explicit empty value, so no `--effort` is added and a caller's own `AGENT_BG_EFFORT` cannot replace the registry. `--attach` does not change a seat's effort.
- When a seat leaves its summary file empty, `agent_bg.sh` fills it from the pane log in its embedded Python: decode UTF-8 with replacement; strip OSC (`ESC ]` to BEL, `ESC \`, or end of text), CSI (`ESC [ [0-?]* [ -/]* [@-~]`) and two- or three-character escapes (`ESC [ -/]* [0-~]`); strip control characters `\x00-\x08`, `\x0b-\x1f`, `\x7f-\x9f` (newline and tab stay); keep the last 4000 characters. With nothing readable left the summary is `The background agent <name> produced no summary.` `LOG_FILE` is never rewritten and a seat-written summary is never touched.
- `scripts/delegate/unit_notifier.sh <claude_session_id> [on|off]` reads the marker `${PLAN_DELEGATE_ACTIVE_DIR:-/tmp/claude/delegate/active}/<session id>` (it names the session directory; its basename is the run id). No mode creates the `delegate-<run id>` instance (`--every` from `PLAN_DELEGATE_PROGRESS_INTERVAL_SECONDS` rounded up to minutes, `--hold`, check `delegate_run.py check`); `off` runs `notifier.sh stop delegate-<run id>` and prints `progress updates off: delegate-<run id>`; `on` runs `notifier.sh start` and prints `progress updates on: delegate-<run id> <next_due line>`. A missing or empty marker exits 1 and changes nothing; a `notifier.sh` failure passes its message and status through; a bad mode word or more than two arguments prints the usage and exits 2.
- `/unit:report [on|off]` (`commands/unit/report.md`): `on` or `off` runs `zsh ~/.claude/scripts/delegate/unit_notifier.sh "$CLAUDE_CODE_SESSION_ID" on|off`, relays its line and composes no report; a failure is relayed as printed. A Codex unit has no notifier, so the command says the switch is unavailable there.

## Invariants

- The Stop hook fails open: any error prints one stderr line and exits 0 with no output. It fires only in a session a running production's `showrunner-*` instance targets, and the non-showrunner path stays on the entry point's own imports plus one `conf` read per instance.
- The fn-length hook never blocks on doubt: no `Cargo.toml`, unreadable TOML, an unbalanced brace, an unknown payload or an internal error passes the edit; an internal error prints one `fn-length hook error: <type>: <message>` `systemMessage` and exits 0.
- The hook mirrors clippy exactly: same count, same threshold source, same exemptions, and it fires only where the package's Cargo lints enable `too_many_lines`, so it never blocks code clippy passes. Approved exceptions pass as clippy lets them.
- One checker (`fn_length_lib`) and one hook command string serve Claude and Codex.
- `settings.json` order: the `Edit|MultiEdit|Write` group keeps basedpyright first with the fn-length hook after it; the Stop group keeps `stop-showrunner-footer.py` after the banned-words hook. An edit to either group keeps every entry.
- The footer comes from `showrunner_footer.render_footer` running `dailies_render.py --footer`; the Stop hook and the dailies report share one `footer()`. The reply is read from `last_assistant_message`, never `transcript_path` (at Stop time the transcript lacks the turn's last entry). At most one block per stop chain (`stop_hook_active`), so a footer that changes between attempts cannot loop the session.
- The footer switch is a named state (`FooterState`), never a bare boolean or `None`; a `None` from `Production.schedule` or a missing stamp becomes a named state at the boundary.
- Every edit of `config/showrunners.json`, a rename included, goes through `showrunners.py`'s locked `change()`; readers call `load_settings` on the live checkout's machine-local file. The file stays untracked (the showrunner writes it at run time).
- tmux targets are `=name` for a session and `=name:` for its pane (`-t name` prefix-matches another session). Stretch files are keyed by name, so a rename moves them.
- Stalled-unit detection belongs to the stall watcher, not `unit_status.sh`. Idleness rests on the pane hash plus transcript and `subagents/` mtimes, never on status-file text.
- The follow-up claim must exist before any status record, so a refusal leaves no stale record. `implement.sh`'s final status write comes after every record step (`finish-pass`, `landed`); unit directors and `launch_implementation.md` read `impl_status_<slot>`. `codex_mesh.py`'s roster states are read by `can-follow`, `follow` and the launcher alike.
- `prepare_session.sh` calls `unit_notifier.sh` with the session id alone to create the instance; that form stays unchanged.
- A failed token acquire exits 1 and a release fails closed when the step group cannot be inspected; callers surface that and never run an unguarded build. Count leftover processes by process group, never `pgrep -f`.
- Python is typed throughout: no `Any`, no file-level type ignores, basedpyright 0 errors and 0 warnings. Tests never touch the real `~/.codex`, `~/.local/state/fn-length-hook`, `~/.local/state/buildlog` or notifier state, never run real `codex`, `cargo` or `claude`, and redirect paths through `FN_LENGTH_HOOK_STATE`, `SHOWRUNNER_STATE_DIR`, `NOTIFIER_STATE_DIR`, `NOTIFIER_SESSIONS_DIR`, `SHOWRUNNERS_CONFIG`, `SHOWRUNNERS_SESSIONS`, `STALL_WATCH_*`, `TMUX_NAMES_*`, `PLAN_DELEGATE_ACTIVE_DIR`, `PLAN_DELEGATE_CONFIG` and `NOTIFIER_NOW_EPOCH`.
- Times in output carry their zone; the footer judges everything as of its stamp.

## Calibration and gotchas

- **fn-length measurement.** Against clippy on obsidian_knife, 544 of 546 functions match in name and count; the two misses sit inside a `macro_rules!` body. Hana main has 0 non-exempt functions over 100 and 43 exempt ones. Cost: +13.4 ms CPU per Rust edit over a bare launch (budget 20 ms), in-process CPU p95 9.75 ms over 1,544 files, 64.5 ms CPU on a 17,321-line file. Judge cost on CPU time (getrusage children user+sys); wall time under load is noise.
- **fn-length import cost dominates.** `tomllib` loads only when the manifest text names `lints` or a clippy config names the threshold; `dataclasses` and `pathlib` stay off the Rust path (an import test pins this). Classes in `fn_length_lib` are plain `__slots__` classes because frozen dataclasses alone broke the 20 ms budget.
- **fn-length blind spots.** Functions inside `macro_rules!` or `name! { … }` bodies are never measured (clippy sees expanded code the scan cannot expand). Edits made through shell commands (Codex `Bash`, `sed`) and growth from rustfmt reflowing a function measured at or under the limit are not seen. A failed `blocks.jsonl` append is silent and never changes the verdict. `cfg(test)` modules in package-root `examples/` targets are skipped because clippy never lints them.
- **Footer cost.** A Stop hook runs at every turn end in every session; the non-showrunner path costs about 4 ms on a quiet machine (bare launch 22 ms quiet, 45–62 ms loaded). Compare cost readings with interleaved bare and hook runs; load swamps any other delta. Replies sent before `<StartUpdates/>` registers the notifier instance are not checked.
- **Footer time.** Adding a `timedelta` to an aware datetime drops `fold`, so the end of a stamped minute is computed in absolute time, or a repeated fall-back hour admits the next hour's readings. Reset count has no history and a stamp has minute resolution, so a reading or Codex reset inside the stamped minute but after the render can still change a re-rendered line; one re-render clears it.
- **basedpyright** exits 3 in every checkout (`pyrightconfig.json` names a `.venv` no checkout has); read its last output line (`0 errors, 0 warnings, 0 notes`), not its exit status. `scripts/hooks` is a pyright execution environment with itself on `extraPaths`, so tests import `fn_length_lib` directly.
- **Stall watch.** `~/.claude/sessions/` keeps stale `<pid>.json` records carrying a live session's id; the live record is the one whose pid answers `os.kill(pid, 0)`. Idle panes stayed byte-identical for 6.5 minutes in a live probe while a busy pane changed only from real activity. A status file reading `implementing` with no live process counts as idle.
- **Notifier launch.** A systemd oneshot (`KillMode=control-group`) kills `&!` children of its `ExecStart`; under `session-notifier` this ended `stall_watch.py` mid-send, so a nudge went out unrecorded and again the next minute. That is why run jobs get their own transient service. `launchctl submit` keeps its job alive (it re-runs every 10 s after exit 0) and launchd ends even `setsid` children when the job exits; a run that must outlive a launchd job needs its own job that removes itself.
- **Launcher races.** A peer turn can overtake a followed turn after `thread/resume`: `follow` exits 1, `impl_status` reads `error`, and the roster stays active while the peer runs, then is restored; a failure of the followed turn survives the peer turn. `board.sh release` exit 3 is benign for `verify.sh`, exit 1 is a real failure. The launcher's own end-of-seat `board.sh release … cargo` ignores failure.
- **Token-wait timing.** `verify.sh` computes `token_wait_s` as `SECONDS - TOKEN_WAIT_STARTED` from bash's whole-second `SECONDS`, so a wait that is really under a second can read `1` and any wait can differ from real time by one second either way; a bound on it needs one second of slack on each side. `board.sh` waits on a held token with `sleep 3` (the acquire retry loop) and on a contended lock file with `sleep 0.05`. `test_waiting_for_peer_call_records_token_seconds` (`scripts/delegate/test_verify_token_wait.py`) therefore never sleeps a fixed time and never names `0`, `3` or `4`: a stub `sleep` first on `PATH` touches a marker file when called as `sleep 3` with `TEST_WAITING` set (the second call's environment only) and then `exec`s the real `sleep`, resolved with `shutil.which` because NixOS has no `/bin/sleep`. The marker proves the second call is blocked on the token. The test measures with `time.monotonic()`, asserts the first call's wait at most `int(first_running_at - first_started_at) + 1`, and keeps the first call holding the token until the second call's lower bound `int(release_at - second_blocked_at) - 1` exceeds that. `release_at` is read before the `release` file is touched, so the second call's real wait can only run longer than the bound; the second wait is asserted at least that bound and greater than the first. Records are matched to their calls by `-{pid}-` in the record `id`. A change to the `sleep 3` retry interval breaks the marker.
- **Pane summary.** The two-character escape pattern uses the ECMA-48 intermediate and final byte classes, never a dot that matches newlines, or a stray ESC eats the newline or tab after it. An unterminated OSC sequence discards the rest of the pane log, accepted because a seat-written summary never reaches the fallback.
- **Effort.** A Claude seat launched without `--effort` inherits `~/.claude/settings.json` (`modelSettings` → model → `effortLevel`, `xhigh` for Sonnet 5.5), so a pane line reading `thinking with xhigh effort` on a `sonnet:low` seat means the launch dropped the effort, not that the pane misleads.
- **`/unit:report off`.** `unit_notifier.sh` exit 1 covers both no active run and a missing notifier instance; only the message says which, so the command relays it as printed. `off` persists in the notifier instance until `on` or `end_session.sh`. `<ProgressContract/>` in `commands/unit/delegate.md` names `/unit:report off` and `/unit:report on` for a Claude unit.
- **Live checks need a person.** An automated bare `claude --bg` probe is refused by the permission classifier, so the seat-effort check (a Claude seat registered `sonnet:low` and launched through `implement.sh` shows `low effort`, not `xhigh`, in its pane) is run by hand. `showrunners.py add` for each showrunner and `import` run on each machine against that machine's own `config/showrunners.json`.
- **Ruled out.** Measuring inside macro bodies. Reset-count history for past stamps (the race is minute-wide and about weekly). Finding Claude by `pgrep -f "--remote-control <unit>"` (the remote-control name need not match the tmux session) and keying units by it. A separate showrunner registry with register/remove (the `showrunner-*` notifier instances already are that set; the config list is the source and a running unconfigured showrunner is a fault). Using the delegate status file as running-work evidence. A hook as the watcher (hooks run inside sessions, not outside them). A tracked `config/showrunners.json` (it would leave `~/.claude` dirty). Detaching a run with `setsid` inside a launchd job. Running a build unguarded after a failed token acquire (overlapping builds cause memory freezes). A waiting marker written by `board.sh` or `verify.sh` for the token-wait test (the stub `sleep` gives the same fact with no production change). Reading `release_at` after touching `release` (a pause there pushes the lower bound past the second call's real end).

## Why

- **Block at the edit, not at the lint.** `too_many_lines` fails `verify.sh lint` and costs a repair loop; telling the agent in the same turn is cheaper than the lint round trip. The user wants no long functions, so exceptions stay rare (tests, or a stated reason in real code) and the hook honors clippy's own `allow` and `expect`.
- **Mirror clippy, check the whole file.** In a pedantic-deny crate every non-exempt function over the limit already fails the lint, so reporting all of them says nothing clippy would not; firing only where Cargo lints enable the lint keeps upstream clones such as `~/rust/bevy` quiet. Fail-open on doubt keeps a wrong hook from blocking passing code.
- **A regex tokenizer, not a parser.** The hook runs on every Rust edit beside basedpyright (one matcher group runs in parallel), so import and CPU cost are the budget; a token scan reproduces clippy's count on real code at a few milliseconds.
- **The success threshold is 75% fewer** `too_many_lines` failed steps per 100 hana clippy steps and 75% less sole-cause seat time per day, leaving room for the edits the hook cannot see (shell edits, rustfmt growth).
- **A Stop hook for footers, not a prompt rule.** A rule that lives only in a prompt is one an agent can drop; the hook checks the final lines of every showrunner reply against the same renderer the dailies use, so the footer cannot drift from the report. The reply comes from `last_assistant_message`, and the render takes the reply's own stamp as `--at` so a footer a minute old still matches.
- **The switch is a file keyed by production slug** so it survives compaction, resume and a retargeted notifier instance; the review pause records what it changed so `resume` restores only that, and per-action states make a failed pause retryable.
- **Footers judged as of their stamp, Claude found through its pane.** A footer re-rendered a minute later must not change under readings that arrived after the stamp; the remote-control name can differ from the tmux session, so only the pane's process tree is reliable.
- **A configured registry plus a stall watcher outside every session.** The registry is machine-local because the units differ per machine; a hook cannot watch (it runs inside a session), so the watcher is a run-only notifier job, and an unconfigured live showrunner is reported as a fault; timers alone never define the set.
- **Run jobs get their own service.** A background child stays in the tick's cgroup or launchd job and dies with it; a separate service keeps the run, its watchdog and its final log write alive.
- **Step groups under the token.** A killed verify used to leave its cargo build running while the token moved on, and overlapping builds are what froze the machine; recording the group before the command starts covers the first instant of a step, and release or reclaim stops only an identity-checked group, never one the holder shares with its caller.
- **Follow-up through the launcher.** The launcher is the only process that watches a worker exit, so only it can record the pass, the landed round and the board post; a bare message to a finished Codex seat is refused and leaves no records. One claim per seat, taken before any status write, keeps concurrent follow-ups from corrupting each other's records.
- **`implemented` after the records.** Unit directors read `impl_status_<slot>`; writing it last means a failed ledger write reads `error`, not success.
- **Effort from the registry, plain-text summaries.** A seat that inherits the global effort ignores the registry row that chose its model; pane bytes with terminal codes in a summary corrupt every reader of that file.
