# Script rerun recovery

Release, skill sync, exclusion, ranking and Rust scaffolding commands resume from live state after an interrupted step.

- `scripts/validate_and_push/validate_ci.sh` records the fixed tree through a copy of the real index with repository hooks disabled. A dirty rerun commits only when that complete tree matches the record, including any force-added ignored files. If a formatter stopped before its output was recorded, the rerun refuses, names the changed paths and preserves the index and worktree. Inspect `git diff`, then either discard with `git checkout -- <paths>` and rerun, or commit the changes yourself; this refusal is the accepted recovery state for unrecorded output.
- `scripts/validate_and_push/push_pr_branch_and_merge.sh` records each successful post-push hook's landed SHA and skips that SHA on a rerun. Hooks have an at-least-once contract: a stop after hook success but before the completion record is published reruns the hook for the same `LANDED_SHA`. Repository hook authors must make that retry safe.
- `scripts/release/push_release.sh` reuses a tag on HEAD and retries both pushes. A tag on another commit fails loudly. `restore_unreleased.sh` skips an existing Unreleased section, commits only outstanding edits to the listed changelogs, and still pushes when the commit already exists. `finalize_changelogs.sh` accepts an already finalized version and continues with later files.
- `scripts/claude_to_codex/sync.py` skips a non-forced skill only when `SKILL.md` exists; an empty directory is incomplete. `run_sync.sh` uses `scripts/prioritize/runner_lock.py` and a `runner.lock` file. The OS releases the flock on exit, including a kill, and the next owner replaces its PID and process start time. An old directory lock has no authority. Concurrent events still mark one pending rerun.
- `scripts/exclude/exclude.sh` checks whether a listed path remains tracked and finishes untracking it. An untracking failure is reported; the ignore rule remains for the next run.
- `scripts/prioritize/renumber.py` has one atomic writer for notes and `backlog-rankings.jsonl`: a same-directory temporary file is flushed and synced before replacement. Notes retain their mode and modified calendar date; on macOS, SetFile preserves creation time before publication. The inode changes. A failed SetFile command becomes an `OSError`, so rollback reports that note and still restores the others. Export failures fail apply, and `--check` checks the export as well as note ranks, so the watcher cannot save success for a missing export. `run_watcher.sh` reconciles the vault's filtered Git index even after an unchanged-input pass, leaving real edits unstaged.
- `scripts/new_rust_project/rust_generate.sh` saves the command options and a unique ownership token in a sibling `.<name>.rust-generate` file before generation. It writes the same token into the generated directory before moving that directory into place. A rerun resumes dependencies, formatting and the commit only when the destination carries that token. A foreign destination is refused even when the saved options match. The token is excluded from commits. After the commit, the script publishes a completed record before removing the token and then the record; a rerun with a completed record only finishes that cleanup. One `publish_file` function writes a sibling temporary file, fsyncs it with Python, and moves it over the destination. The recovery record, directory token, workspace manifest edit and settings copy all use it, on Linux and macOS. Ignore lines, shared dependencies and commits are added only when missing.

`restore_unreleased.sh` uses the [shared lock's shell entry](repair-rounds.md#shared-main-push-lock) when `BASE_BRANCH` is `main`.
It completes changelog edits and commits before the lock hold.
Other base branches take no main push lock.

Messages, run records, unit retirement and held design roles also finish on a rerun after a stop.

- `scripts/message/send.py`: an emergency attempt saves its owner pid and process start before delivery. Only a gone or replaced owner releases the claim; a live owner or an unknown result keeps it. An undelivered emergency releases its claim, so only delivery starts the live window. `accept_sent` saves the clearing record with the acceptance. `pending` prints under the queue lock before it removes queue files. `template_fix_notice` starts its child before it publishes the daily stamp.
- `scripts/direct/progress_history.py`: `_start_phase` saves the event intent, and `_finish_phase_start` repairs a missing `phase_started`. `record_turn_wait` saves the declaration before the wait event. `record_turn_wait` and `finish_turn_wait` share the marker lookup `_turn_waits_for_marker`.
- Native worker cleanup retains staff identity and dispatch history.
  The [worker lifecycle](long-lived-workers.md#retirement-and-resume) defines cleanup, closed panes, and later assignment.
- `scripts/astra/astra_roles.py`: `ExecProcess` saves the process identity through `process_start`. `scripts/astra/astra_work.py`: `create_text_atomic` writes the whole brief, and an identical retry succeeds.
- `scripts/astra/design_roles.py`: creation keeps `not_started` apart from `outcome_unknown` and never starts a second thread. Rebind and checkout moves finish through `_finish_rebind`, and `end` finishes through `_finish_end`. `unbind_run` compares run folders as paths.

`scripts/lib/stop_injection_test_support.py` provides `stop_once`, the one stop helper for these tests. A test that stops a sender in its own process must also end the owner: `PrivateSenderAcceptance.end_owner` in `scripts/buildlog/mac_idle_test_support.py` does this. `process_start` reads `VERIFY_PROC_ROOT` on Linux, so a sender fixture that sets it must give owner facts.

`scripts/lib/rerun_test_support.py` provides one disposable HOME, temporary Git repository, local bare remote and command interruption fixture for these script tests. Its `initialize_repository` routine also initializes projects created by the Cargo stub. Cargo, GitHub and network commands are stubbed; tests never run against user repositories or installed skills.
