# Shutdown and restart

## What it is

`/shutdown` brings every Claude session of one account on natedev and the Mac (showrunners, unit directors, top-level sessions, their seats and their Codex app-servers) to a safe stop: each session first reaches an idle, pushed state, its notifier timers stop, and where it was is recorded. `/shutdown restart` resumes each session in its host and on its desktop, tells it where it was, and restarts its timers. Both act on one account only, so other accounts running on the same machines are never touched. Every session shows its account and remaining quota on a second status-line row, and `/whoami` and `account.py` name it. While an account is held by a shutdown, scheduled work (nightly review, fix pipeline) skips and no unit launches except through restart. CI runners, system services and the machine-wide notifier jobs keep running.

### Accounts

- A process's account is the login in its Claude config dir: `CLAUDE_CONFIG_DIR` from that process's environment, else `~/.claude` (whose file is `~/.claude.json`; any other dir uses `<dir>/.claude.json`). The login is `oauthAccount.emailAddress`. The **label** is the stem of the hanadocs note in `AGENT_NOTES_DIR` (default `~/rust/hanadocs/agents/`) whose stem starts with the tool and whose `login:` matches case-folded (`claude 2`); else the login.
- `process_config_dir(pid) -> Path | None` reads `/proc/<pid>/environ` on Linux and `ps eww -o uid=,command= -p <pid>` on darwin (`parse_darwin_config_dir(output, expected_uid)`: `None` unless the uid matches and a `HOME=` token is present; the last `CLAUDE_CONFIG_DIR=` token wins). An unreadable environment is `None`, never the default dir. `account_of(pid) -> Account | None`.
- `own_claude_account()` raises `UnreadableAccount`; `named_claude_account(text)` takes a `claude*` note stem with a non-empty `login:`, else text holding `@` with no `/`, NUL or whitespace and no leading `.` as a login, else raises `UnknownAccountName`. Every `[account]` verb resolves absent to its own account and given to the named one; either exception prints `shutdown: <message>` and exits 2.
- A `SessionStart` hook runs `account.py --write-label`, which writes `<config dir>/account-label` (label plus newline) atomically and only on change, or deletes it when the account is unreadable. The label file is a cache; nothing else stores an account.
- **Status line.** `statusLine.command` reads `account-label` with the `read` builtin and runs `jq -r --arg pwd … --arg account … -f statusline.jq` (two processes: sh and jq). Row 1 is `<dirname> | <tokens> | <model [effort]>`. Row 2, when any part exists, joins the account, `5-hour <N>% left` and `weekly <M>% left` with ` | `, from `rate_limits.five_hour` / `seven_day` `used_percentage`; `remaining($window)` floors `100 - used` and clamps to 0–100, and a missing window or non-number drops its part. With no part, no second row.

### Inventory

`inventory(login: str, only: frozenset[str] = frozenset()) -> Inventory` keeps the live records in `~/.claude/sessions/` (`NOTIFIER_SESSIONS_DIR`) whose `account_of(pid)` login matches case-insensitively. An unreadable account or a `procStart` unequal to the live process start (pid reuse) goes to `unattributed` (`UnattributedSession{pid, name, reason}`, reason `account unreadable` | `process start mismatch`), never to `sessions`. A non-empty `only` keeps those ids and their seats.

- **Kind:** `showrunner` when its id is the `TARGET` of a `showrunner-<slug>` notifier instance (`showrunners.registered_showrunners()`); `unit` from the `SHOWRUNNER_UNIT` / `SHOWRUNNER_UNIT_ID` marks on its tmux pane (`unit_lookup.marked_units`); `seat` when the record's `kind` is `bg`, owned through any `active/<director id>` run folder's `seats` ledger (`SeatOwner` = `director{session_id}` | `no director`); else `top-level`.
- **Host** (`Host`): `UnitHost{production, unit, doc, tmux_session, plan: plan{path} | no run record}` (plan from the newest run record whose `main_agent.session_id` matches); `TmuxHost{tmux_session, pane: TmuxPane{pane_id, pane_pid} | PaneNotRecorded}` from `TMUX_PANE` without marks; `WindowHost{kind: ghostty | zed, window_shell, desktop: named{name} | not in snapshot}` from a parent walk starting at the session's pid (natedev desktops from `~/rust/hanadocs/agent sessions.md`, the `agent-sessions-snapshot` output); `TerminalHost` (Mac Ghostty or Terminal); `UnknownHost`. `window_shell` is the ancestor directly beneath the terminal process.
- **Checkout:** `git{path, head: branch{name} | detached{commit}, upstream: tracking{ahead} | no upstream, dirty}` | `not a checkout`. **Model:** `model{name}` | `no reply yet`.
- **Servers and timers:** run folders are `SHUTDOWN_DELEGATE_ROOT` (default `/tmp/claude/delegate`) `/active/<session id>`; a live `mesh_server.json` pid is a `CodexServer{run_dir, pid, busy_seats}`, a `mesh_roster.json` seat in `running`/`starting` is busy only with no `launcher_pid` or a live launcher; timers are `NOTIFIER_STATE_DIR/*/conf` with `TARGET=session:<id>`.
- `parse_inventory` / `parse_session` check every `kind` and field and raise `InvalidInventory` naming the field path (`inventory.sessions[0].host.kind is invalid`). The peer's inventory is always decoded through them.

`shutdown.py status [account] [--json] [--here]` prints `<label> · <login>`, each machine's sessions as `  <kind> <name> · <host> · <status> · <branch> ahead N, M dirty` with Codex servers and timers, `  unknown account · <pid> <name> · <reason>`, or `  no sessions on <label>`, then each machine's live record (`<machine>: shutdown <state>`, per entry `  <name>: <progress>` with detail and stop issues). A peer that ssh cannot reach prints `<machine>: unreachable`; one that answers badly prints `<machine>: unavailable (rc N)`; neither fails the local report.

### The record store

One live record per account per machine at `SHUTDOWN_STATE_DIR` (default `~/.local/state/shutdown`) `/<login case-folded>/record.json`.

- `ShutdownRecord{login, label, machine, state, requested_at, requested_by: session{session_id} | terminal, scope: all account sessions | selected{session_ids}, conductor: systemd{unit} | launchd{label} | not started, force: "wait for ready" | "now", entries, stop_issues: list[OrchestrationStopIssue]}`.
- `ShutdownSessionEntry{session: Session, timers: list[TimerRestore{instance, was_enabled, footer: footer{slug} | no footer}], settle_message: not sent | sent{at} | queued{at, reason}, where: said{text, at} | not said, progress, stop_issues: list[SessionStopIssue]}`.
- `SessionProgress`: `waiting`, `ready{at}`, `passive seat ready{at}`, `stopped{at}`, `already gone{at}`, `process identity lost{at}`, `stop failed{at, reason}`, `restarted{at}`, `timers pending{at, timers: list[PendingTimer{instance, reason}]}`, `seat available on demand{at}`, `restart failed{at, reason}`, `manual restart{command}`.
- Store API: `find_live(login) -> LiveShutdownRecord | NoShutdown`; `create(record)` (raises `ShutdownInProgress` with `.live`); `update(login, change: Callable[[ShutdownRecord], None]) -> ShutdownRecord` (runs `change` under the lock, revalidates, writes; `NoLiveRecord` when none; `ValueError` if `change` alters `login` or `machine`); `archive(login)` moves the record to `history/<requested_at>.json` and accepts only `cancelled` or `up`; `live_records()`; `parse_records(text)`. Reads raise `InvalidRecord` (a `ValueError`) naming the file or field path.
- **Locks**, always taken in this order: the launch barrier `<root>/launch.lock`, then `stop.lock` (held for a whole `stop`), then the account's `lock` (held for each read and write). Writes go through a temp file, `fsync` and `os.replace`. `find_live` tells absent from unreadable with `os.lstat`: no account dir or no `record.json` is `no shutdown`; a non-directory account path (symlinks included), a non-regular `record.json`, an account `lock` that cannot be opened or locked, or any other `OSError` raises `InvalidRecord`.
- Timestamps: every `requested_at` and `at` is `settle.record_time()` (`2026-10-09T21:49:10+00:00`): whole seconds, zero UTC offset, equal to its own `isoformat()`. Anything else makes the record unreadable. `settle.now_utc()` is the one clock tests replace.

### States

```
settling ──claim (conductor or peer)──▶ stopping ──stop──▶ down | stop partial
   │                                                            │
   └──cancel claim──▶ cancelled ──▶ archived                    ▼
                                         restart claim ──▶ restarting ──▶ up ──▶ archived
                                                                 └────────▶ restart partial ──(restart again)──▶ restarting
```

A claimed stop always ends `down` or `stop partial`, never `stopping`. A `restarting` record always has a running `up`; an exception after the claim sets `restart partial`. `held-sessions` and `launch-blocked` treat `settling`, `stopping`, `down`, `stop partial`, `restarting` and `restart partial` as held.

### Settling

- **`down [account] [--here] [--only IDS]`** refuses with exit 1 and nothing changed when `github-warm-status` fails, when the peer's `status <login> --json --here` (skipped under `--here`) is unreachable or does not decode (`… nothing was shut down; /shutdown --here shuts down only this machine`), or when either machine has a live record. It runs `begin` here, then on the peer with the same `--requested-by` (`CLAUDE_CODE_SESSION_ID`) and `--only`, cancelling here if the peer's `begin` fails, then launches `shutdown.py conduct <login> [--here]` detached as `systemd-run --user --collect --quiet --no-block --unit shutdown-<label slug>-<pid>` (darwin `launchctl submit -l`), saving it as this machine's `conductor`. A failed launch cancels both machines. `--only` (comma list, hidden) sets `selected` scope, applied to every later inventory.
- **`begin`** creates a `settling` record with one `waiting` / `not sent` / `not said` entry per session, then per entry records and stops its timers in one `update`: `conversation_pause.release(session_id)` supplies the instances a conversation pause already stopped (`was_enabled` unless the pause is `KeptOff`; a paused `showrunner-<slug>` footer becomes `footer{slug}`), and each other instance takes `was_enabled` from `ENABLED=1`. Only `was_enabled` instances get `notifier.sh stop`; a stop failure cancels the record.
- **`refresh <login> [--message IDS…]`** (per machine) re-inventories under the scope: adds new sessions as `waiting` with timers stopped, marks missing ones `already gone` (unless the pid is unattributed, which is a holdout), advances seats, sends due settle messages, and prints `RefreshReport{record, verdicts}` (`counts ready` | `holdout{line}`). An entry counts ready when `already gone`, `stopped` or `process identity lost`; a seat when `passive seat ready`; any other when `ready` and the fresh session is not ahead of its upstream, has no busy Codex seat, and (showrunner) has no `MERGE_HEAD`. A seat goes `passive seat ready` when it is idle and its owner counts ready, is `no director`, is not an entry or is gone.
- **Settle message:** `send.py --to session:<id> --from shutdown --summary "Shutdown of <label>: reach a safe stop" --key shutdown-<login>-<id>`, worded per kind (a unit ends its turn `— blocked: shutdown requested by the user`; a showrunner merges, pushes and appends `### STATE` to its LOG); each ends with `shutdown.py ready --where "…"`. Exit 0 records `sent`, exit 1 `queued{reason}` and retries after 300 s. Seats get no message. A showrunner is messaged only once every unit of its production counts ready and no machine is unreached. The requesting session is never messaged; it runs `ready` itself and ends its turn, and is stopped last.
- **`ready --where TEXT`** finds this machine's `settling` record holding `CLAUDE_CODE_SESSION_ID`, re-inventories, refuses with exit 2 (`push <branch> first`, `Codex seat <name> is still running`, `finish the merge in progress first`, a seat, or not in inventory), else sets `where: said` and `progress: ready` and prints `ready for shutdown: <where>`.
- **`conduct`** loops every 15 s (`SETTLE_INTERVAL_SECONDS`) over `conduct_cycle(login, unreached_since, here) -> ConductorDecision` (`settlement pending{reports}` | `ready to stop{reports}` | `settlement ended{reason}`), running `refresh` here and on the peer. Ready means every entry on both machines counts ready (or `force` is `now`) with both reached. It ends when the record is gone or no longer `settling`.
- **`cancel [account] [--here]`** first claims `settling → cancelled` (`claim_cancel` → `CancelClaimed` | `CancelAlreadyStopping` | `CancelEnded`) on the machine whose conductor runs, stops the conductor (`systemctl --user stop` / `launchctl remove`), restarts each `was_enabled` timer, turns footers on, retires queued shutdown messages, tells each messaged session "Shutdown of <label> cancelled by the user: continue where you were.", and archives; then the peer. Once stopping, cancel prints `shutdown of <label> is already stopping; /shutdown restart brings it back once it is down` and exits 1.
- **`now [account]`** sets `force: "now"` on each reachable `settling`/`stopping` record.

### Stopping

- On ready, `conduct` claims here with `claim_stop_as_conductor` (`settling → stopping`, keeping `force`), then the peer through hidden `claim-stop <login> --force <timing>` (`claim_stop_as_peer`: replays true on a record already `stopping` and only upgrades its force to `now`). Both records are `stopping` before any session is touched. A failed peer claim closes this record with `StopClaimFailed` and alerts.
- `stop(login, …) -> StopReport{record, unattributed, counts}` holds `stop.lock`, enters stopping (`StopUnderway` for `settling`/`stopping`; `StopFinished` for `down`/`stop partial`, which signals nothing and returns that record's report), and walks units → showrunners → top-level → the requester, then seats. A fresh inventory decides identity before readiness: absent → `already gone`; same id with another pid or `proc_start`, or pid unattributed as `process start mismatch` → `process identity lost`, never signalled; `account unreadable` → an issue. A present entry not ready and idle is refused unless `force` is `now`, which first ends busy Codex seats (`codex_mesh.py end`).
- **Signals:** `SIGTERM`, wait 10 s (`STOP_WAIT`) for the pid and `~/.claude/sessions/<pid>.json` to go, match identity again, `SIGTERM`, wait 10 s; still alive → `stop failed` (`alive after two SIGTERMs`). Never `SIGKILL`.
- **Owner resources**, after an owner exits or is gone: `codex_mesh.py stop --session-dir` once per run folder (confirmed by exit 0 and no live pid in `mesh_server.json` / `mesh_retired.json`); a unit's `tmux kill-session -t =<tmux_session>` (confirmed by `has-session` failing); a Ghostty `window_shell` gets `SIGHUP` only when this stop ended its Claude and Ghostty is still its parent (`inventory.terminal_kind`). Other hosts are left as they are. Seats get no signal: they are `stopped` when the owner is stopped or gone, or the owner is absent and no live seat process remains.
- **Issues.** `SessionStopIssue` = `not ready to stop{status, progress}` | `still running{reason}` | `account unreadable` | `seat still live` | `codex server left running{run_dir, cause}` | `unit tmux session left running{tmux_session, cause}`, cause `stop not confirmed` | `owner identity lost`; `OrchestrationStopIssue` = `stop claim failed{machine, reason}` | `machine stop failed{machine, reason}`. Each pass over an entry replaces its issues.
- `_finish`: `down` when every entry is `stopped`, `already gone` or `process identity lost`, no entry has an issue other than a left-running one caused by `owner identity lost`, and the record has no orchestration issue; else `stop partial`.
- `_stop_machines` runs `stop` here and on the peer (hidden verb `stop <login>`, JSON checked by `parse_stop_report`), the requester's machine last. A peer stop that raises, answers non-zero or with an unreadable report is closed with `MachineStopFailed` through `close_failed_stop` (hidden verb `close-failed-stop <login> --reason`, which moves `stopping`/`down` to `stop partial`); local closes run after both machines' stops ran.

### Restart

`restart(account: AccountNamed | AccountNotNamed, *, dry_run: bool, alerts: AlertWhenNotBack | NeverAlert) -> int` runs `up <login>` here and on the peer. The account is the named one, else this process's, else the only `down`/`stop partial`/`restart partial` record on either machine (several → listed, exit 1).

- **`up`** claims (`_claim(login) -> RestartClaimed | NothingToRestart`) `down`/`stop partial`/`restart partial` → `restarting`; only the claimant launches or messages. Already `restarting` prints `already running`, exit 0; no record prints `<machine>: no shutdown of <label> to restart`, exit 0; other states print `… is <state>; nothing restarted`, exit 1.
- Order: units, showrunners, top-level, the requester; each unit is live before any showrunner launches. Before acting on an entry it retires that entry's queued shutdown messages. A live session id gets the note through `send.py --to session:<id> --from shutdown`, its timers, and `restarted`; any other entry is launched.
- **Launch by host.** The resume command is the one shell string: `cd <quoted cwd> && ENABLE_TOOL_SEARCH=true command <shlex.join([claude, --resume, id, -n, name, --remote-control, name, (--model, name), --settings, '{"disableAgentView": true}', prompt])>; exec zsh`, one argv item to `zsh -ic`. Unit → `add_unit.py --production <doc> <unit> --plan <plan> --resume <id> --cwd <cwd> --session-name <name> --tmux-session <tmux> --restart-note <file>` (plan `no run record` → `manual restart`). Showrunner → prompt `/showrunner:produce <doc> resume`, its note sent as a `shutdown` message once live. `WindowHost` → `kdotool set_desktop <n>` (from `~/.config/kwinrc` `[Desktops]`), `systemd-run --user --collect --quiet -- ghostty -e zsh -ic …`, 1.2 s apart, then back to the starting desktop; a Zed session comes back in Ghostty. `TerminalHost` → `open -na "/Applications/Nix Apps/Ghostty.app" --args -e zsh -ic …`. `TmuxHost` → `respawn-pane -k -t <pane_id> -c <cwd> zsh -ic …` when the recorded pane is in the recorded session and is dead or still has the recorded `pane_pid` with no child; else `new-window -t =<s>:` when the session lives; else `new-session -d -s <s>`. `UnknownHost` → `manual restart` with the command printed.
- **Note** (`restart_note`): label, stop and restart times in America/Los_Angeles (`%Y-%m-%d %H:%M %Z`), the recorded `where` (for `not said`: read branch and plan), run `send.py pending` first, keep waiting if it was waiting on the user. Every first prompt is appended to `conversation_pause`'s scheduled prompts before launch (`_record_scheduled_restart_prompt`; `add_unit.py` does the same for units with the exact `prompt_for` string), so the pause hook does not treat it as typed. A failure leaves the entry unlaunched with `restart prompt not recorded: <reason>`.
- **Completion:** each launched session gets up to 90 s to appear in `sessions.live_sessions()`, then `notifier.sh start` per `was_enabled` timer and footers on. Not back → `restart failed{reason}`. A live session whose timers did not all start is `timers pending`; on the next `restart` it gets only those timers if live (`_session_liveness` → `SessionLive`), a full relaunch if closed (`SessionNotLive`; every timer recorded pending as `not yet restored after relaunch` before restore), and nothing if liveness cannot be read (`SessionLivenessUnknown`). Seats never launch: `seat available on demand` when the owner is back or absent, `restart failed{owner <name> not back}` otherwise. All complete → `up`, archived. Otherwise `restart partial`; `status` prints `  <name>: restart failed — <reason>`, `  <name>: timers pending — <instance>: <reason>; …`, `  <name>: manual restart — run: <command>`, and `  run /shutdown restart again to finish`. A rerun touches only what is left. `--dry-run` prints every argv and read-only probe and changes nothing.

### Messages and notifications

- `send.py` relays `--to session:<id>` to the live session's `uds:` socket (`relay_plan(message) -> RelayAttempt | SessionIdWithoutLiveRecipient`); with no live session it queues under `session-<id>` (exit 1), which the resumed session reads with `send.py pending`. Settle, cancel and restart notes carry `--key shutdown-<login>-<session id>`; a delivered keyed send removes its queued copy; `send.py retire --to --from --key` removes that key's messages and unkeyed ones from that sender.
- `settle.alert_user(scope, summary, text, *, machine="")` is the only send to `user` from `scripts/shutdown/`: `--need decision`, and nothing for a `selected` scope. The phone hears only of a holdout (20 min after `requested_at`, then at most hourly, listing each holdout and unreached machine with `/shutdown now` and `/shutdown cancel` as choices), a `stop partial` or orchestration issue, or a restart not fully back ("`<label>` is not fully back", ending "Fix what is named above, then run /shutdown restart again; it brings back only what is left."). From the Mac it routes `--machine natedev`.
- `report_stop(claimed, reports, orchestration_issues, *, failed_records=())` alerts the user first on a partial stop, then always sends the requesting session (if it was a session) the result (`<label> is down` when clean), keyed `shutdown-result-<login>` so `retire` keeps it for that session's `pending` after its restart.
- `conversation_pause.JOB_SENDERS` includes `shutdown`, so shutdown messages never pause a session's timers. `commands/message.md`: an instruction from sender `shutdown` is the user's shutdown request.

### Nothing new starts on a held account

- `shutdown.py launch-blocked [account] [--restart-of SESSION_ID]`: exit 0 with `<label> is held by a shutdown (<state> since <%Y-%m-%d %H:%M %Z>)` when this machine's record is held; exit 1 silent when there is none; exit 3 with one stderr line `shutdown state unreadable: <detail>` when `find_live` raises, when a `cancelled` or `up` record was not archived, or on any exception; exit 2 for an unresolvable account. `--restart-of` becomes `ShutdownUnitRestoreLaunchPurpose(session_id)`, which passes (exit 1) only for a `unit` entry with that id: in `restarting`, one whose progress is not `restarted`, `seat available on demand` or `manual restart`; in `restart partial`, one whose progress is `manual restart`.
- `launch_permission(environment, purpose: NewWorkLaunchPurpose | ShutdownUnitRestoreLaunchPurpose) -> AllowedByShutdownState | BlockedByShutdown(reason) | ShutdownStateUnreadable(detail)` runs `launch-blocked` (30 s timeout) in the caller's environment. Only a silent exit 1 is `AllowedByShutdownState`; exit 1 with output, any other status, an `OSError` or a timeout is `ShutdownStateUnreadable`, its `detail` without the `shutdown state unreadable: ` prefix.
- `launch_barrier()` is an exclusive `fcntl.flock` on `<root>/launch.lock` through a non-inheritable descriptor. `record.create` holds it around its check and write; every launcher holds it from just before `launch_permission` through the return of its spawn, so no record can appear between a launch's check and its spawn. A barrier `OSError` refuses as `shutdown state unreadable: launch barrier: <text>`.
- Callers: `nightly_review.py` `launch` writes `skipped: <reason>` or `skipped: shutdown state unreadable: <detail>` to `launch.log`, then checks `quota_permission() -> QuotaClear | QuotaBelowFloor`. `fix-trigger.sh`, after its `pgrep` guard, execs `launch_permission.py exec-new-work --name fix-trigger -- fix.sh`, which prints `fix-trigger: skipped: …` and exits 0 when held or unreadable, else `os.execv`s the command (freeing the barrier). `add_unit.py`, after `launch_request` and before `preflight`, exits 2 with `add_unit: <reason>; /shutdown restart first` or `add_unit: shutdown state unreadable: <detail>`; a restore launch passes its session id. The showrunner's manual unit resume runs `launch-blocked --restart-of <session-id>` and continues only on exit 1.
- `remove_seats.shutdown_held_sessions() -> HeldSessions | ShutdownStateUnreadable` runs `held-sessions` (30 s): a held session's `active/<id>` run counts as live, so its seats survive until restart; on any failure every `active/<id>` run counts as live with one stderr line.

### Remote calls

`remote.run_remote(args, stdin="", limit: TimeLimit | WhileLinkAlive = STANDARD_TIME_LIMIT) -> tuple[int, str]` runs `shutdown.py` on `other_machine()` over `ssh -o BatchMode=yes` and takes the trailing `rc=<n>` line as the status; no `rc=` line, ssh 255 or a timeout is 255 (unreachable). `STANDARD_TIME_LIMIT` is 120 s. The remote stop uses `WhileLinkAlive` (`-o ServerAliveInterval=15 -o ServerAliveCountMax=4`, no timeout) and retries 255 every 15 s with no overall limit; peer claims and `close-failed-stop` retry 255 too. The peer's stderr is dropped, so a failure meant for the other machine is printed on stdout.

## Invariants

- **Account isolation.** A command for account A never messages, stops, or changes a timer of a session whose account is not A, nor stops a Codex server whose owner is not A's. An unreadable environment or config means "not A": the session is `unattributed` and left alone. Verbs act only on `inventory["sessions"]`, so unattributed sessions are excluded by construction.
- Never stop a busy session unless `/shutdown now`. Never type C-c or Escape into a pane. Stopping a Claude session is `SIGTERM` while idle; never `SIGKILL`.
- Seats hold no process between turns; shutdown never runs `claude rm` or `claude stop` on a seat. Codex servers stop only through `codex_mesh.py stop --session-dir`, never `sweep --stop`; restart starts none (`codex_mesh.py follow` starts one on demand).
- Notifier instances are stopped and started, never removed: the `showrunner-*` instance is the only record that a production exists. Only `was_enabled` instances are stopped, and only those are restarted.
- Never trust ssh's exit status (Tailscale SSH on the Mac returns 0); every remote command's last line is `rc=<n>`.
- Both records are `stopping` before any session is signalled. A claimed stop ends `down` or `stop partial`. Stop issues stay on the record until it is archived.
- A record is archived only from `cancelled` or `up`.
- Every record timestamp comes from `settle.record_time()`.
- Every lock is taken in the order launch barrier, `stop.lock`, account `lock`. Readers holding only the account lock never wait on a running stop.
- Only `AllowedByShutdownState` permits a launch; an unreadable state refuses. The barrier spans check to spawn, never the launched work.
- `settle.alert_user` is the only path to the phone; a `selected` scope never pages.
- Every user-facing time is America/Los_Angeles.
- Tests start no Claude or Codex, touch no live notifier instance, open no window and reach no machine: state dirs come from `SHUTDOWN_STATE_DIR`, `NOTIFIER_STATE_DIR`, `NOTIFIER_SESSIONS_DIR`, `CONVERSATION_PAUSE_STATE_DIR`, `PLAN_DELEGATE_HISTORY_DIR`, `SHUTDOWN_DELEGATE_ROOT`, `AGENT_NOTES_DIR`; commands through `SHUTDOWN_NOTIFIER`, `SHUTDOWN_SEND`, `SHUTDOWN_TMUX`, `SHUTDOWN_OPEN`, `SHUTDOWN_KWINRC` or stand-ins on `PATH`; tests replace `settle.alert_user` or `settle.send_message` and never reach `send.py`.
- `statusline.jq` keeps working without `--arg account`, and a refresh stays two processes.

## Calibration / gotchas

- Timings: settle cycle 15 s; settle message retry 300 s; first holdout alert at 20 min, then at most every 60 min; stop wait 10 s per `SIGTERM`; restart waits 90 s per session; window launches 1.2 s apart; `launch-blocked` and `held-sessions` 30 s; remote calls 120 s except the stop.
- `ps eww` output is unquoted argv then environment, so a config dir path containing whitespace is truncated. macOS `ps eww` shows no environment for platform binaries or other-uid processes yet exits 0; the lookup returns `None` for them.
- `procStart` is Linux `/proc/<pid>/stat` field 22 and darwin `LC_ALL=C TZ=UTC ps -o lstart= -p <pid>`; another locale or zone never matches.
- NixOS Ghostty's comm is `.ghostty-wrappe`; terminal matching strips a leading dot and accepts any prefix of `-wrapped`. Ghostty launched while the KDE session is locked starts no shell.
- `datetime.fromisoformat` accepts any one-character separator, so a timestamp check needs the `isoformat()` round trip; a sub-second timestamp makes the record unreadable.
- `argparse.SUPPRESS` as a subparser's `help` prints `==SUPPRESS==`; hidden verbs are left out of the hand-written `metavar` (`{down,status,now,cancel,restart,launch-blocked}`), so a new public verb is added there by hand.
- `send.py` resolves `session:<id>` only against this machine's live sessions, so the peer's settle messages go out from its own `refresh --message`. `send.py` logs the text's first line as `summary`, not `--summary`.
- `conversation_pause.prompt_source` classes a CLI first prompt as typed unless it is recorded with `record_scheduled_prompts`. The Stop hook rewrites scheduled prompts after the first reply, so a live check reads the pause record, not the prompt.
- A tmux server from an earlier launch can still hold `<name>.scope`, so `add_unit.py`'s scope is `--unit=<sanitized tmux name>-<epoch seconds>`. The resume command ends in `exec zsh`, so a stopped session leaves a shell in its pane; respawning the recorded pane keeps shutdown and restart cycles from adding windows. The Mac has no tmux, so a `TmuxHost` exists only on natedev.
- `_live_session_ids()` skips unreadable registry records, so absence from it is not proof a session closed; `_session_liveness` is the only liveness answer `up` trusts for a pending entry.
- Any Python crash exits 1, so exit 1 from `launch-blocked` means clear only with empty stdout and stderr; `launch-blocked` maps every unexpected exception to exit 3.
- `add_unit.py` imports `launch_permission` and `conversation_pause` inside functions: `live_units.py` and `update_registration.py` import `add_unit` from copied trees that lack `scripts/shutdown` and `scripts/hooks`.
- `/etc/zshrc` runs `compinit` on every interactive zsh start (0.9–2.3 s, past 5 s under load); a test that spawns `zsh -ic` uses `-f`.
- Running `account.py` on the Mac from a temp dir needs a full copy of `~/.claude/scripts` (`agent_notes` imports reach `codex_pacer`, `quota_alert` and `..production`). A live check under a temp `HOME` must link `~/.claude.json` in. Live checks use `down --here --only` and `restart --no-alert` so nothing pages.
- `rate_limits` windows appear only for a subscription login, from the first reply on; Claude Code 2.1.296 sends integer percentages, and `remaining` accepts any number.

## Why

- **Uncommitted edits stay on disk.** A clean, pushed state is idle, nothing ahead of upstream, no merge in flight; committing mid-phase would put work-in-progress commits on unit branches, and pushing uncommitted work would publish it. The record lists dirty files instead.
- **Out of scope:** systemd and launchd timers and services, GitHub runners, sccache, earlyoom, the session-notifier job and its machine-wide instances (`stall-watch`, `tmux-names`, `escalate`, `conversation-pause`), Codex TUI sessions and the desktop apps. The user set "CI runners and system services keep running"; the timers of scheduled work keep firing and the launch check makes them skip.
- **Unknown means "not this account."** Defaulting to `~/.claude` when an environment is hidden would attribute an unknown process to the default account and could stop another account's session.
- **Two claims, one conductor.** Both records move to `stopping` before a signal, so a cancel on either machine cannot race a stop. The peer claim replays on a record already `stopping` and only raises force, because a `now` landing on a peer mid-stop must take effect, and only one conductor can claim.
- **No time limit on the remote stop.** A working stop of many sessions takes as long as it takes; only a dead link (missed keepalives) ends the call.
- **Failure closes run after both stops**, because a record already `stop partial` makes a later `stop` signal nothing.
- **Issues live on the record**, not only in the alert, so `status` and the next restart see what was left running.
- **The phone hears only when the user must act.** `need note` means nothing to do, so a partial stop or not-back restart uses `decision`; the user alert goes before the requester's result so a failed requester send cannot skip it; the requester's result is keyed so `retire` does not remove it before the restarted session reads it.
- **An unreadable session registry is not a closed session**: treating it as closed would relaunch a session that may still run.
- **Restored prompts are recorded as scheduled** so a restart neither pauses the restored timers nor asks the user whether updates may return.
- **A required `pane` with `PaneNotRecorded`** keeps every tmux host explicit; a `NotRequired` field would hide old records.
- **The launch barrier is a process lock, not `flock(1)`**: the Mac has no `flock`. The showrunner's manual resume runs `launch-blocked` without the barrier because separate model steps cannot hold a process lock.
- **The nightly review and fix-pipeline timers keep firing during a shutdown** (system services keep running); the launch check makes their runs skip, and a run already in progress finishes.
- **Peer inventories and records are decoded fully** before use; a reachable peer that answers badly is `unavailable` with its rc and reason, not `unreachable`.
