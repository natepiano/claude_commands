# Shutdown and restart

Refusal-watcher inventories read cached desktop metadata. Their selected shutdown carries `REFUSAL_WATCH_INVENTORY=read existing` into the conductor's command, since the service manager does not inherit the caller's environment. This prevents inventory from invoking the snapshot updater, which itself runs the notes timer.

Claude quota refusals are detected from the newest user or assistant transcript exchange, skipping trailing metadata (`isApiErrorMessage: true`, `error: rate_limit`) or a session-specific file in `~/.local/state/accounts/assumed_refusals/`. This applies to Ghostty, zed and terminal owners as well as tmux and units. At begin, PromptSubject(session_id, login, config_dir) determines TakesPrompts or StoppedTakingPrompts: a newest transcript refusal wins, then a fresh exhausted Claude reading; room or no fresh reading permits a pause. StoppedTakingPrompts starts reaping without a pause or readiness wait; process identity checks still apply. A newer refusal during the wait also reaps on every host. The tmux screen detector remains a second detector. Status keeps the move's target and reason on the progress line.

The argument-free notes timer runs the refusal watcher every two minutes. Sessions on one refusing account share a selected `down --here --only ... --restart --to ... --why ...`; each record's request id joins its journal request and outcome. Restart checks the resumed process's config directory before confirming the move. A source-account process, failed launch or manual restart is a failed move; a proven target process with pending timers is confirmed while those timers remain visible. Cancellation records `failed: cancelled`, removes an assumed refusal and suppresses the unchanged transcript error. Refusal replies with model `<synthetic>` do not replace the last real model used for resume.

## What it is

`/shutdown` stops one account's Claude sessions on natedev and the Mac through one record per top-level session. Each owner settles, stops and optionally returns independently; a busy session or a permission form delays only that owner. Workers, Codex app-servers, timers and host resources belong to their owner. `/shutdown restart` restores recorded sessions, their notes and timers. Other accounts, CI runners and system services keep running.

An account-wide request holds the account against new launches and scheduled work. A selected request holds only its sessions. Each machine conducts its own records; an unavailable peer leaves local work running. `commands/shutdown.md` defines the user command.

### Accounts

`accounts.move(session: str, target: str, *, why="") -> MoveStarted | MoveStartFailed | MoveRefused` resolves one local live id or exact current name and its process account before any mutation. It refuses ambiguous names, workers, unfit or unnoted destinations, the same login and any open record for that owner. It starts `down <current label> --here --only <id> --restart --to <target>` and preserves the requester environment. Unknown hosts print `restart.resume_command(session, target)` before stopping; restart uses that same stable command.

`accounts.move_showrunners(source, target, *, dry_run=False, why="")` selects local inventory showrunners on the source login. It validates the whole target before mutation, skips owners with open records, and starts one `down --here --only <comma-separated ids> --restart --to`. A dry run returns selected ids and display lines, including each production resume command.

`SessionShutdown.target: NotRequired[str]` names `claudeN`; a legacy stored `default` reads as the number of `~/.claude`’s login. Absence means retain `session.config_dir`. New targeted records also store `source_label` and `why` (default `<old label> is out of usage`); repeated requests keep every existing field. `settle.down` forwards `--to` and `--why` to the peer. `restart.account_move_note` supplies one stable account-move explanation for every host, including the showrunner production resume prompt and the unit's continued `/unit:direct` run. Unknown hosts print the same manual line before shutdown and once on live restart. Supervised Ghostty windows restart in place; legacy windows use the recorded desktop fallback described below.

Targeted non-unit launches wrap the usual resume argv in `accounts.py exec <target>`, dropping inherited OAuth tokens and checking readiness again. Units pass `--account <target>` or their recorded `--config-dir`, plus their recorded `--model`, to `add_unit.py`. The launcher saves `@claude_config_dir` and `@claude_model` on every unit tmux session. A manual resume reads the shutdown record first, then those tmux options; an account with no record refuses with a request for `--account`. Recorded directories may be outside the numbered account farm but must exist. The unit role selects only new work. `MoveStartFailed` and `ShowrunnersMoveStartFailed` retain the shutdown exit and output when it exits nonzero; the CLI propagates that failure. `swap unit` selects the role then shuts down with `--restart --to`, refusing open owner records before writing the role.

- A process's account is the login in its Claude config dir: `CLAUDE_CONFIG_DIR` from that process's environment, else `~/.claude` (whose file is `~/.claude.json`; any other dir uses `<dir>/.claude.json`). The login is `oauthAccount.emailAddress`. The **label** is read from the name of the hanadocs note in `AGENT_NOTES_DIR` (default `~/rust/hanadocs/agents/`) whose parsed tool matches and whose `login:` matches case-folded (`claude2.md` → `claude2`); else the login.
- `process_config_dir(pid) -> Path | None` reads `/proc/<pid>/environ` on Linux and `ps eww -o uid=,command= -p <pid>` on darwin (`parse_darwin_config_dir(output, expected_uid)`: `None` unless the uid matches and a `HOME=` token is present; the last `CLAUDE_CONFIG_DIR=` token wins). An unreadable environment is `None`, never the default dir. `account_of(pid) -> Account | None`.
- `own_claude_account()` raises `UnreadableAccount`; `named_claude_account(text)` takes a `claude*` note stem with a non-empty `login:`, else text holding `@` with no `/`, NUL or whitespace and no leading `.` as a login, else raises `UnknownAccountName`. A named account uses that resolver; most absent-account verbs use the own account. `restart.select_account` also infers from eligible session records and account holds on both machines when the own account is unreadable: one candidate wins, otherwise candidates are listed and restart exits 1. An unknown named account prints `shutdown: <message>` and exits 2. An unreachable or older peer cannot prove that candidate set complete, so restart asks for an account.
- A `SessionStart` hook runs `account.py --write-label`, which writes `<config dir>/account-label` (label plus newline) atomically and only on change, or deletes it when the account is unreadable. The label file is a cache; process configuration remains the authority for account attribution.
- **Status line.** `statusLine.command` is `statusline="$HOME/.claude/scripts/statusline"; . "$statusline/statusline.sh"`: sourced, not run, since a second shell measured 1.3 ms of a 4.3 ms render. `statusline.sh` reads `account-label` with the `read` builtin, names `~/.local/state/agent-notes/by-label.json` (or `/dev/null` when it is not readable, a `[` builtin test), collects the session ids in the first line (`TARGET=session:<id>`, which `write_conf` always writes first) of each `${NOTIFIER_STATE_DIR:-~/.local/state/notifier}/showrunner-*/conf`, and execs `jq -r --arg pwd … --arg account … --arg showrunners … --slurpfile labels … -f statusline.jq` (one process; the role lookup adds about 0.3 ms with five timers). Row 1 is `<role> | <account> | <dirname> | <tokens> | <model [effort]>`, and an empty account, or one holding `@`, drops its field. The role, first match wins: `showrunner` when the input's `session_id` is a timer's target, `worker` when `PLAN_DELEGATE_TEAM_ROLE` is non-empty (agent_bg.sh passes it through `--settings` env, which reaches the status line command; it outranks the unit mark because a background session inherits the daemon's environment, and a daemon a unit started carries `SHOWRUNNER_UNIT`), `unit` when `SHOWRUNNER_UNIT` is non-empty, else `unassigned`. Row 2, when any part exists, joins `5-hour <N>% left` and `weekly <M>% left` with ` | `. Each window is the one agent_notes stored for the session's label, the number the quota alerts use, while that reading is at most 600 s old and its `resets_at` is absent or ahead; otherwise `rate_limits.five_hour` / `seven_day`, so the row never goes blank for want of a reading. `remaining($window)` floors `100 - used` and clamps to 0–100, and a missing window or non-number drops its part. With no part, no second row.
- **Readings by label.** Each agent_notes run, after saving `usage.json`, rewrites `by-label.json` from the whole store: for every Claude note, its stem (the label `account-label` holds) maps to that login's `five_hour` and `weekly` as `{left, resets_at, at}` in epoch seconds, `resets_at` null when no window is open. A refused read keeps the last good reading, whose `at` the status line judges. A label holding `@` is left out, so the file carries no login.

### Inventory

`inventory(login: str, only: frozenset[str] = frozenset()) -> Inventory` keeps the live records in `~/.claude/sessions/` (`NOTIFIER_SESSIONS_DIR`) whose process config directory supplies a login matching case-insensitively. An unreadable account or a `procStart` unequal to the live process start (pid reuse) goes to `unattributed` (`UnattributedSession{pid, name, reason}`, reason `account unreadable` | `process start mismatch`), never to `sessions`. A non-empty `only` keeps those ids and their workers.

- **Kind:** `showrunner` when its id is the `TARGET` of a `showrunner-<slug>` notifier instance (`showrunners.registered_showrunners()`); `unit` from the `SHOWRUNNER_UNIT` / `SHOWRUNNER_UNIT_ID` marks on its tmux or herdr pane, read once for every production (`unit_lookup.every_marked_unit`) and kept only for a production with a showrunner timer, whose doc a restart needs; `worker` when the record's `kind` is `bg`, owned through any `active/<director id>` run folder's `workers` ledger (`WorkerOwner` = `director{session_id}` | `no director`); else `top-level`.
- **Host** (`Host`): `UnitHost{production, unit, doc, session_name, session_host: tmux | herdr, plan: plan{path} | no run record}` (plan from the newest run record whose `main_agent.session_id` matches); `TmuxHost{tmux_session, session_ref: TmuxSessionId{session_id} | TmuxSessionIdNotRecorded, server: TmuxServer{pid, started_at} | TmuxServerNotRecorded, pane: TmuxPane{pane_id, pane_pid} | PaneNotRecorded}` from `TMUX_PANE` without marks; `HerdrHost{herdr_session, pane_id}` from the pane environment and its ancestor herdr server; `WindowHost{kind: ghostty | zed, window_shell, desktop: named{name} | not in snapshot}` from a parent walk starting at the session's pid (natedev desktops from `~/rust/hanadocs/agent sessions.md`, the `agent-sessions-snapshot` output); `TerminalHost` (Mac Ghostty or Terminal); `UnknownHost`. `window_shell` is the ancestor directly beneath the terminal process. One tmux display reads the current session name, its `$N` id, the pane pid, the server pid (`#{pid}`) and the server start time (`#{start_time}`, epoch seconds). A missing session id or missing/non-integer server pid or start time is `not recorded`; older hosts without `session_ref`, `server` or the server pid parse the same way.
- **Checkout:** `git{path, head: branch{name} | detached{commit}, upstream: tracking{ahead} | no upstream, dirty}` | `not a checkout`. **Model:** `model{name}` | `no reply yet`.
- **Account directory:** each session carries `config_dir`, the string returned by `process_config_dir(pid)`. One boundary reads the process directory once and resolves its account from that directory, returning `AttributedSessionConfiguration{account, config_dir}` or `UnreadableSessionConfiguration`. A readable environment without `CLAUDE_CONFIG_DIR` gives `~/.claude`; an unreadable environment or account remains `unattributed`. Registries and transcripts stay under the shared `~/.claude/sessions` and `~/.claude/projects` paths.
- **Servers and timers:** run folders are `SHUTDOWN_DELEGATE_ROOT` (default `/tmp/claude/delegate`) `/active/<session id>`; a live `mesh_server.json` pid is a `CodexServer{run_dir, pid, busy_workers}`, a `mesh_roster.json` worker in `running`/`starting` is busy only with no `launcher_pid` or a live launcher; timers are `NOTIFIER_STATE_DIR/*/conf` with `TARGET=session:<id>`.
- `parse_inventory` / `parse_session` check every `kind` and field and raise `InvalidInventory` naming the field path (`inventory.sessions[0].host.kind is invalid`). The peer's inventory is always decoded through them.

### The record store

`SHUTDOWN_STATE_DIR` defaults to `~/.local/state/shutdown`. Each case-folded login directory contains `sessions/<sanitized session id>.json`, optional `hold.json`, `history/`, `lock`, and `conduct.lock`. Characters outside `[A-Za-z0-9_.-]` become `-` in session filenames. Filename collisions are refused, never resolved by overwriting another id. An archived record moves to `history/<requested_at>-<session file name>`; an existing target raises `InvalidRecord`.

`SessionShutdown` carries `login`, `label`, `machine`, `requested_at`, `request_id`, `requested_by` (session id or terminal), `hold` (`account` or `session`), `then` (`stop` or `restart`), `force` (`wait for ready` or `now`), `alerts` (`user` or `none`), the owner's `session`, its workers in the `workers` field, timer snapshots, `settle_message`, `where`, `progress`, `trail`, `stop_issues`, and optional `alerted_at`. A worker never gets its own record. `AccountHold` carries the request's login, label, machine, time, id, origin and continuation. Request grouping uses `request_id`; second-resolution timestamps never establish request ownership.

Public store operations are `session_records`, `all_session_records`, `create_session`, `update_session`, `archive_session`, `set_account_hold`, `clear_account_hold`, and `clear_finished_account_hold`. `lookup_session` returns `ShutdownFound(record)` or `NoShutdown`; `lookup_account_hold` returns `AccountHeld(hold)` or `AccountOpen`. Updates run under the account lock, revalidate and write with a temp file, `fsync` and `os.replace`. Invalid paths, symlinks, invalid fields and mismatched account or session ids raise `InvalidRecord`. Absence is distinct from unreadable state.

`clear_finished_account_hold(login, *, request_ids=())` clears only when no record of the hold's request remains. Non-empty `request_ids` also require that the hold belongs to one of those requests. Selected cancellation or restore supplies the requests it finished; account-wide restore can clear a hold with no records. Account-wide cancellation always clears the hold, even when stopped records remain for restart.

Reads and dry runs convert old files in memory without writing them. `migrate(login)` is called by writing operations before they use the store. It validates every old file and destination before writing any session record or moving a source file; conflicting sanitized filenames or history destinations raise `InvalidRecord`, with no session records written or sources moved. For one session id the current file wins, then the old main file, then the newest old partial file; completed old files supply no session records or hold. Conversion attaches workers, drops record-level issues, preserves an inferred account hold without replacing an explicit one, and assigns `legacy-<machine>-<requested_at>` as the request id. It moves old sources to history and prints one conversion line per source. Status, read verbs and dry runs still see unmigrated files. Internal `records --json --here` and `holds --json --here` expose the session records and account holds used for cross-machine account inference; a peer without these interfaces is not reached.

### States

Each owner's `progress` is `waiting`, `reaping{at, because, detail}`, `ready{at}`, `held by usage limit{at}`, `stopping{at}`, `stopped{at}`, `already gone{at}`, `process identity lost{at}`, `stop failed{at, reason}`, `restarting{at, prior}`, `restarted{at}`, `restart failed{at, reason}`, `manual restart{command}`, or `timers pending{at, timers}`. Stop-only terminal records remain for restore. Confirmed `restarted` records are archived and never launched again.

A `stopping` or `restarting` claim belongs to its worker for `CLAIM_STALE_SECONDS = 120`. An older claim can be replaced; a relaunch resumes from `prior`. A stop worker checks its exact claim before each write, signal and cleanup operation; a relaunch confirms only its own claim. Losing a claim transfers ownership without adding a user outcome. Conductor handoff likewise has no separate user outcome.

A partial stop is `record.stop_incomplete`: `stop failed`, or a terminal stop with non-empty `stop_issues`. A Codex server or unit tmux session left running can therefore coexist with progress `stopped`. Status shows the issues. `/shutdown now --only <name>` has the conductor retry it: a `stop failed` record repeats the stop, forced; a stopped one retries only the cleanup recorded with cause `stop not confirmed` (`_retry_owner_cleanup`) and sends no signal. Issues with cause `owner identity lost` are never retried. A retry that fails again sets `force` back to `wait for ready`, so it is reported once. `relaunch_session` runs the same cleanup retry before it launches a record with unconfirmed cleanup, and ends `restart failed{owner cleanup not confirmed; run /shutdown restart again}` when it stays unconfirmed.

### Settling and selected actions

`down [account] [--here] [--only NAME[,NAME...]] [--restart] [--no-alert]` checks `github-warm-status`, then begins locally and launches this machine's conductor. Each new owner gets `waiting` or `reaping` from its prompt state, its workers, saved timers and stopped timers; a timer-stop failure removes only that owner's request and names it. Existing records print `<name>: already in progress` and keep their continuation, hold, policy and request origin. New owners print `<name>: added`. Repeating a request starts a conductor even when every selected owner already has a record; follow and closing commands retain those original request ids.

Without `--here`, the peer receives `down <login> --here` with the same request id, origin and continuation and conducts independently. Failure prints the peer retry command with its account, ids and `in a terminal on <machine>`; local records are not withdrawn. Non-following down exits 0 once this machine started; a tty down returns follow's result. Only an account-wide request sets an account hold.

`resolve_sessions(login, items, *, here=False)` resolves exact names or ids against account records and inventory, counting each id once and excluding workers. Local ids need no peer lookup; names are checked on both machines unless `--here`. Readable peer records remain candidates when its inventory fails. An unavailable peer prints `<peer>: not reached; names checked on <machine> only`; an unknown or ambiguous item exits 2 and lists candidates. Local ids execute locally; only remaining ids go to the peer. For selected `cancel`, `now` or `restart`, a local live session with no record prints `<name>: no shutdown in progress` and exits 1 without being sent to the peer.

The conductor holds `record.conductor_lock(login)` for its lifetime. A duplicate exits successfully; a quarter-second retry (`CONDUCTOR_LOCK_RETRY_DELAYS`) tolerates a status probe. After release it checks for newly added work so an ending conductor cannot leave a request unattended. Every `SETTLE_INTERVAL_SECONDS = 15`, one inventory feeds `next_step` for each owner. Running actions are skipped until their futures complete. Stops and non-window launches run in a `RESTART_LAUNCH_WORKERS = 6` pool; registry and Remote Control waits use the polling pool. Window hosts launch in order on the conductor's thread with one desktop state restored on exit. `_launch_conductor` starts it with `systemd-run --user` (Linux) or `launchctl submit` (macOS) as `shutdown-<label slug>-<pid>`; neither passes on the caller's environment, so a `HOME` or `SHUTDOWN_STATE_DIR` exported in the calling shell does not reach it. The conductor ends when no record has a step left: each is archived, or stopped with `then: "stop"`, or needs the user (`stop failed`, `restart failed`, `manual restart`, `timers pending`). It clears the account hold once a restarted record of the hold's request is archived and no record of that request remains, then sends the requester one result (`report_stop`).

A waiting non-requester gets the settle message; queued messages retry after `SETTLE_RETRY_SECONDS = 300`. Its first line is fixed, and the launching skills (`<PauseForMove>` in `/unit:direct` and `/showrunner:produce`) act on it: `Pause for move: <label> → <target> (<why>, <time>)` or `Pause for stop: <label> (<why>, <time>)`. The body asks the session to stop at once, without finishing its current step, then run `ready --where` and end its turn; it is never waited on to go idle by itself. A sent message with no ready mark after `REASK_AFTER = timedelta(minutes=2)` is sent once more and `reasked_at` is recorded; no further repeat follows, and a session accepting prompts waits for its ready mark unless the timing is `now`. Reaping bypasses readiness after a refusal or exhausted account reading. Its stop instruction names `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py`, so a session answers through the scripts installed under its own home, whichever checkout made the request. The requester gets no settle message and runs `ready --where` itself. A queued instruction whose request was cancelled or replaced before sending is discarded and never marks another request's record. `ready --where TEXT` updates only this session's waiting, ready or `held by usage limit` record. Ready owners stop when idle, with every worker idle, no form, no merge in progress and nothing ahead of upstream; dirty files stay on disk. `force: "now"` bypasses readiness. Absent owners or lost identity get a stop outcome without signals. An unreadable account holds the record. The requester goes last among the same request's records on this machine, except under `now`, which stops it without waiting for the rest of its request; a showrunner never waits for its units.

At every check, the conductor reads the owner's screen through `settle._screen`: a tmux or unit owner's pane by the pane id in its matching session registry record, an owner on a `HerdrHost` through `session_pane.read_place`; any other host has no pane (`no pane host`). A non-busy owner showing `hit your session limit`, `hit your usage limit`, `hit your weekly limit`, `usage limit reached` or `wait for limit to reset` in its last 15 non-empty lines enters `held by usage limit`, replacing the settle turn. It stops once the owner and all workers are idle, no merge is in progress and nothing is ahead of upstream; the limit menu does not block it as a form. The held state returns to `waiting` when the limit no longer shows, the owner is busy or the pane cannot be read. Leaving the hold sets the settle message to `not sent` in the same locked write, so the owner is asked again at that check, even if its earlier message was sent or queued. A held session gets no holdout alert. For every host, a newest transcript refusal after the pause enters reaping before the screen detector runs; assumed refusals still supply the separate usage hold. Form checks also read the owner's pane by id.

`cancel [account] [--here] [--only NAME[,NAME...]]` restores timers and footers, retires queued shutdown messages, sends `cancelled by the user: continue where you were` to a previously messaged owner, and archives the record. Restoration and the cancelled message run under the account lock before any later request can send its instruction, so cancellation cannot replace that instruction. Selected waiting, ready or `held by usage limit` owners print `<name>: taken out`. A selected `stop failed` record can be withdrawn only when the original process identity is still live; identity checking and withdrawal share the lock, and it prints `<name>: taken out, still running`. A competing stop claim keeps the record. Other retained records print their progress and a full scoped restart command with `in a terminal on <machine>`, exit 1. Selected cancellation clears a hold only if it withdrew that hold's request's last record.

`now [account] [--here] [--only NAME[,NAME...]]` sets `force: "now"` and starts the conductor; it never stops or retries a session itself. Chosen eligible owners print `<name>: stopping now`; an ineligible owner prints `<name> is <progress>; nothing to stop`, exit 1. A multi-selection exits 1 if any selected owner could not be acted on.

### Status

`status [account] [--json] [--here]` shows the inventory, then the records and applicable actions in each machine's block. Waiting, ready and `held by usage limit` lines retain `  <name>: <progress> — <hold details>` and a message note after ` · `. Hold details include `busy`, `showing a form`, `ahead N on <branch>`, `merge in progress`, `Codex worker <name> is still running`, and `message queued: <reason>`; a usage-limit hold omits the form detail. Stop issues print beneath the owner; a failure reason, pending timers and a manual restart command print on the progress line. `--json` prints the inventory alone.

A read-only, non-blocking `conductor_status` probe distinguishes running, not running and unavailable. A lock filename alone is not ownership. With unfinished records and no conductor, status prints full selected down commands to resume, each with `in a terminal on <machine>`. An unreadable or unreachable probe reports `conductor ownership unavailable: <reason>`. Applicable take out, stop now and bring back actions use full script paths, the stored login and exact --only ids, grouped by machine in record order. Reaping owners have stop-now actions too.

### Stopping

`stop_session` claims before signalling and never replaces a stored pid with an observed one. `fresh_session` distinguishes a matching owner (with workers), absent owner, lost identity and unreadable account. Process identity is checked before each `SIGTERM`; two attempts each allow `STOP_WAIT = timedelta(seconds=10)`. No `SIGKILL` or pane input is used. A forced stop first ends busy Codex workers. After the owner exits, cleanup closes its Ghostty window where ownership still matches, stops its Codex servers, then removes its unit's exact tmux session. Workers receive no process signal and keep jobs and transcripts for their next message. Cleanup issues remain on the record.

### Restart

`restart [account] [--only NAME[,NAME...]] [--here] [--dry-run] [--no-alert]` selects its account through `restart.select_account` and runs `up` locally and, unless restricted, on the peer. Selected restart bypasses requester-last, so a stopped requester can return while siblings wait. Waiting, ready, `held by usage limit` or stopping owners print `<name> is <progress>, not stopped; nothing to restart`, exit 1; a fresh claim prints `<name> is already restarting`, exit 0. Refusals are separate from failed relaunches: no failure count, summary or phone alert for refusals alone. Real failures beside refusals are named and can alert.

`relaunch_session(record, *, dry_run, desktop_state)` claims `restarting{at, prior}` before `launch_entry`. The caller owns and restores the desktop state. Eligible records are stopped, already gone, lost identity, manual restart, restart failed, timers pending and stale restarting; already restarted records archive without launching. A manually resumed live session is reconciled without a second launch. Live `timers pending` retries only pending timers; closed sessions relaunch, and unreadable liveness never proves absence. One launch exception marks only its owner as failed.

Non-window owners launch through the pool; window hosts launch serially. Account-wide order is by session name with the requester last (`_entry_order`); the requester is skipped while another record of its request is unfinished, and a showrunner never waits for its units. A pass's launched ids share one registry wait (`SESSION_WAIT_SECONDS = 90.0`, `SESSION_POLL_SECONDS = 0.5`); `confirm_entry` then restores timers and marks live sessions restarted. A session not live after the wait ends `restart failed{session not live after 90 seconds}`. In the conductor (`_confirm_relaunch_pass`) an error confirming one owner marks only that owner as a failed restart and the others in the batch finish as restarted; in `up` such an error ends the run with `<machine>: restart failed: <error>`. `wait_for_confirmation` returns `RegistryConfirmation`, retaining records from its final liveness poll for the Remote Control check. The conductor tracks `ConfirmedRelaunchPass` through `PendingRegistryConfirmation`. Records that finish are archived; failures, manual commands and pending timers remain. Real runs print `<machine>: restarted <n> in <s> s`; dry runs print planned launches without conversion, mutation, archive, hold clearing or a timing line.

- **Launch by host.** Resume parts hold the cwd, environment assignments, Claude arguments, opening prompt and retained or target account. Tmux and desktop hosts render those parts as the same shell string: `cd <quoted cwd> && ENABLE_TOOL_SEARCH=true command <shlex.join([claude, --resume, id, -n, name, --remote-control, name, (--model, name), --settings, '{"disableAgentView": true}', prompt])>; exec zsh`, one argv item to `zsh -ic`. Tmux unit → `add_unit.py --production <doc> <unit> --plan <plan> --resume <id> --cwd <cwd> --session-name <name> --host-session <session> --restart-note <file>`, or `--standby` in place of `--plan` when the row's Plan cell is `standby`. A unit whose row names no Plan and that has no run record is not launched: its entry is `restart failed` with that reason (a dry run prints `cannot restart <name>: <reason>`), never a command with a `<plan>` placeholder. `<unit>` is the recorded unit id exactly: `add_unit` strips one trailing `-unit` from the name it is given and appends its own, so `x-unit` and `x-unit-unit` each resolve to themselves; stripping it in restart as well turned `x-unit-unit` into `x-unit`, a twin unit. `<plan>` is the unit's Plan cell in the production doc's Units row, read at launch (`_units_row_plan` through `add_unit.unit_table` / `cell_value`); the run record's plan is used only when the doc has no single row for the unit. A unit first added from a brief has no run record until its plan runs; its row names the stub plan, which it resumes with. `add_unit` refuses a resume whose plan differs from the row, and a run record's plan differs once the plan moves to as-built. A restore whose row matched adopts that row: `add_unit` skips the recorded-add-mode check and the Production-header check on the plan, both of which describe new work, so a unit first added from a brief, or whose Plan cell now names its as-built doc, restarts. The row also names the restored unit's worktree and branch: the naming pattern `add_unit` gives new work (`<checkout>-<unit>`, `<slug>-<unit>`) is never compared with the row or reserved against other rows on a restore, so a unit whose worktree or branch does not follow the pattern restarts. The session launches in the recorded `--cwd`, where its transcript lives; no worktree or branch is created and the row is never rewritten. A recorded cwd that is not the row's Worktree, or that has another branch checked out than the row's Branch, is launched in without comment: a unit made from an existing session keeps that session's directory while its worktree is elsewhere, so the difference is normal, and its prompt names the row's Worktree and Branch, where it edits. A restore with no Units row is refused (`unit <id> has no Units row; a restore never adds one`), never added as a new unit. Showrunner → prompt `/showrunner:produce <doc> resume`, its note sent as a `shutdown` message once live. `WindowHost` → `kdotool set_desktop <n>` (from `~/.config/kwinrc` `[Desktops]`), `systemd-run --user --collect --quiet -- ghostty -e zsh -ic …`, 1.2 s apart, then back to the starting desktop; a Zed session comes back in Ghostty. `TerminalHost` → `open -na "/Applications/Nix Apps/Ghostty.app" --args -e zsh -ic …`. `TmuxHost` → `respawn-pane -k -t <pane_id> -c <cwd> zsh -ic …` when the recorded pane answers and is dead or still has the recorded `pane_pid` with no child. Pane and session ids are used only while the recorded server pid and start time both match the running server; a restarted server numbers `$N` and `%N` from zero again and can reuse those ids for unrelated sessions. `#{start_time}` is in whole seconds, so the pid tells apart a replacement server started in the same second. Without a recorded server (or with one recorded without its pid), the pane route and both session-id routes are skipped and the recorded name is used. No route compares session names, so a renamed session on the same server does not prevent reuse. Otherwise a new window goes first to the occupied pane's current session id (read in the same pane probe), then to the recorded session id if `display -p -t $N '#{start_time}\t#{pid}'` reports the same server pid and start time (`has-session -t $N` cannot tell a new server's reused id), then to the recorded name if `has-session -t =<name>` answers. Id targets are `$N:`, name targets `=<name>:`. If none answers, `new-session -d -s <recorded name>` creates the session; if another launch created it first, the failed creator opens a window there. `UnitHost` with `session_host: tmux` keeps its recorded-name route through `add_unit.py`; a herdr unit prints a manual conversation resume until `add_unit.py` supports herdr, even when its plan is recorded. `UnknownHost` → `manual restart` with the command printed.
- **Herdr resume.** A herdr host starts its named server and opens a workspace in the recorded cwd with its config directory and shared memory variables. An agent still occupying the recorded pane refuses the restart. Herdr receives the typed resume parts directly, without rendering or parsing a shell command. `--kind claude` selects the executable; arguments after `--` contain only `--resume <id>`, the recorded name and model, Remote Control and settings, with no executable or account wrapper; the restart prompt is sent once after agent readiness. An untrusted folder refuses before starting the server, and a readiness refusal sends no key. Dry runs start no herdr program. Herdr units require manual conversation resume until their launcher supports herdr. Tmux units use `add_unit.py --host-session` (`UnitRestoreLaunch.host_session`); the old `--tmux-session` spelling is gone. An automatic herdr account move refuses before starting the server: `accounts.py exec` removes inherited OAuth credentials and checks account readiness and resolves the numbered login to its directory, which pane environment assignments alone cannot reproduce. Its arguments remain Claude arguments, and manual account moves use the checked accounts wrapper. Old records with `tmux_session` or no `session_host` remain tmux records. No herdr Claude integration is installed.
- **Note** (`restart_note`): label, stop and restart times in the user's zone (`%Y-%m-%d %H:%M %Z`), the recorded `where` (for `not said`: read branch and plan), run `send.py pending` first, keep waiting if it was waiting on the user. Every first prompt is appended to `conversation_pause`'s scheduled prompts before launch (`_record_scheduled_restart_prompt`; `add_unit.py` does the same for units with the exact `prompt_for` string), so the pause hook does not treat it as typed. A failure leaves the entry unlaunched with `restart prompt not recorded: <reason>`.
- **Account on resume:** a non-unit entry whose recorded `session.config_dir` differs from `~/.claude` inserts `account.named_account_prefix(dir)` — `CLAUDE_CONFIG_DIR=<shell-quoted dir> CLAUDE_CODE_REMOTE_MEMORY_DIR=<shell-quoted ~/.claude> ` — immediately before `ENABLE_TOOL_SEARCH=true` inside the resume command. The second variable makes Claude Code use the memory under `~/.claude` directly; through the `projects` link a memory write would ask (`docs/accounts.md`, Memory on a named account). This applies to showrunners, every terminal host, and printed manual commands. Default-directory and legacy entries keep the existing command byte for byte. Tmux units return through `add_unit.py` with the recorded config directory or explicit target account; herdr units print a manual resume command. The restart subprocess environment still strips `CLAUDE_*`; the assignment inside the command reaches tmux independently of its server environment.

### A supervised terminal window

Every window relaunch wraps resume argv with `~/.claude/scripts/lib/py ~/.claude/scripts/lib/relaunch.py run --`, inside the existing shell. The supervisor shares Claude's terminal and process group, catches terminal interrupts itself, and forwards TERM/HUP to its child. Inventory records `SupervisorIdentity(pid, proc_start)` or `NoSupervisor`; old records default to NoSupervisor. Darwin Ghostty retains the terminal host kind and carries the same identity.

For restart, stop verifies the supervisor identity and writes its hold before sending only SIGTERM to Claude. It keeps the window and scroll history. Restart atomically publishes a RelaunchRequest with argv, cwd, prepared account variables and unset names, timestamp and note. The supervisor consumes it and execs itself with the same pid, then runs the next child there. Registry confirmation still proves the resumed session. Stop-only uses the existing cleanup path. A gone or reused supervisor falls back to the existing window launcher: Linux uses the request-time named desktop and restores the old desktop; Darwin uses its existing Ghostty application launch.

The hold lasts 300 seconds. After Claude exits the window says `claude stopped for a restart; waiting for it here` once. On expiry it removes the hold, says `no restart came; this window is free`, and returns the child's exit code. A request prints its note as one line before exec. Legacy or manually started windows without a supervisor retain their previous new-window behavior.

### Remote Control after relaunch

`remote_control(record: SessionRecord) -> Literal["active", "absent"]` reads `sessions_dir() / "<pid>.json"`. A non-empty `bridgeSessionId` is active; missing, empty or unreadable is absent. `SessionRecord` does not carry the field. Its null case was read from the 2.1.296 binary, not observed on a session. `add_unit.wait_for_remote_control` is a different function: it polls pane text, for new-work launches only.

`wait_for_remote_control(records, timeout)` uses the registry records just confirmed live, with `REMOTE_CONTROL_WAIT_SECONDS = 10.0` and `SESSION_POLL_SECONDS = 0.5`. It polls only those small files, never scans `sessions.live_sessions()` again, returns at once when all are active, and starts no poll after the deadline. A slow read can overrun by one poll's reads; there is no thread or timeout around each read. One shared wait per relaunch pass costs usually 1 to 3 s after registry confirmation, at most 10 s plus one poll's reads when one stays absent. The conductor runs the wait in its polling pool while other owners keep moving.

Each confirmed local session still absent starts one detached `remote_control.launch_fixer` and prints `<name>: Remote Control not on yet; turning it on in the background`. Its record finishes as restarted and its exit status stays successful. Saved `alerts: "none"` or command `--no-alert` only silences the fixer's failure push; repair still runs. The command policy travels to the peer's internal up command. If launch fails, the line is `<name>: Remote Control is off; turn it on at its terminal with /remote-control`, and the same failure push is sent when policy allows it. Peer items never start a local fixer or push: the peer's own confirmation starts its fixer.

The helper starts `shutdown-remote-control-<session id prefix>-<pid>` using the restarted session's pid with `systemd-run --user --collect --quiet --no-block` or macOS `launchctl submit`. Python gets `-u` and `PYTHONUNBUFFERED=1`. The internal verb takes a session id, registry pid and process start, a user-facing identity, and required `--alerts user|none`. `remote_control_who` gives `<unit without -unit> unit`, `<production> showrunner`, or the plain session name.

`fix(..., alerts, clock=...)` checks the process and registry identity at every half-second poll. Each observation reads and parses the registry once; identity, idle status and bridge id come from that same write. `sessions.parse_session` shares the existing validation without another file read. It waits `FLAG_WAIT = 60` seconds for the launch flag to take effect (`AlreadyOn`). Then `session_pane.record_place` resolves the confirmed pid's own tmux or herdr pane, without selecting another process sharing the session id. No pane, including Ghostty or Zed windows, fails immediately after that wait. Only a registry `status: "idle"` authorizes typing `/remote-control`; herdr `AgentBlocked` leaves the attempt unconsumed; other input errors consume an attempt and retry, retaining the last error for a final failure. Identity and status are rechecked after pane resolution, immediately before input. This is the sole exception to shutdown's prohibition on typing into panes.

After each of at most `ATTEMPTS = 3` typed commands, the fixer waits `ATTEMPT_WAIT = 30` seconds for the registry bridge id or the pane's `/remote-control is active` marker (`TurnedOn`). Busy, blocked or unreadable sessions keep waiting up to `DEADLINE = 15` minutes from fixer start. A gone or replaced process ends as `SessionGone` with no input or push. Before returning any failure, a fresh observation checks for an exit, replacement or activation. Only `Failed(reason)` with `alerts: "user"` calls `alert_failed`, the sole `shutdown.remote_control` render and `settle.alert_user` path, through natedev from the Mac. Every outcome prints one journal line naming the unit, showrunner or session. Tests use a fake monotonic clock, registry and pane; no test starts this service or types into a real pane.

`MachineRestartResult` retains each missing session's id, name and saved alert policy after archive. Internal `up <login> --here --json` returns a validated object containing `machine`, `label`, `outcome`, `lines`, `no_remote_control` and `refused`. `no_remote_control` holds `{session_id, name, alerts}` entries. `RestartRefusal` is a union: `not stopped` carries id, name and progress; `no shutdown` carries id and name. Local and peer refusals travel as this data; `up` exits 1 when the outcome is `partial` or any session was refused, and no exit status names a refusal. A peer exit other than 0 or 1, or an answer that does not validate (`parse_peer_result`), reads as not reached, so both machines run the same version. `settle.unrecorded_local_sessions` supplies local selected sessions without a record to cancel, now and restore. `PeerRestartResult` validates the wire object; its `outcome` is `done`, `partial` or `nothing`.

### Messages and notifications

Shutdown messages use sender `shutdown`, which the conversation-pause hook treats as scheduled work. Settle, cancellation and restart notes use key `shutdown-<login>-<session id>`; the final requester result uses `shutdown-result-<login>`. Queued messages are read with `send.py pending` after resume. A unit's production showrunner (`showrunners.current_name(production_slug(doc))`, skipped when none runs) gets one line before the unit is stopped, `<unit> is stopping: <why>; it comes back on <target> within minutes` (or `it stays stopped until the user restarts it` for `then: stop`), and one more from the conductor's report or `restart`: `<unit> is back on <target>`, or `<unit> did not come back: <reason>`, again once per new failure. `showrunner_told` records the last line sent; both use key `shutdown-unit-<session id>`. `settle.alert_user(RenderedPush, *, machine="")` is the phone path; the catalog render provides the title, body and ActionRequired. The conductor's alerts pass `machine="natedev"` from the Mac; `restart`'s own alert passes no machine. The not-answering text also goes to the requester under key `shutdown-holdout-<login>`. A hold or session record never refuses the UPS alert.

`NOT_ANSWERING_AFTER = 2 * REASK_AFTER` is four minutes from the sent pause, or the request if no pause was sent. An unanswered waiting owner gets one `shutdown.holdout` catalog push and requester message, even on Ghostty with no readable pane. The title is `Restart stuck waiting on <name> session` (or `Shutdown stuck waiting` for stop-only); the text names the account, window or pane, elapsed time, and the full scoped now command with `In a terminal on <machine>`. A named desktop is identified as a desktop. It explains that the pause asks for a safe point and a ready reply. Explicit stop-now and do-nothing choices say that now ends Claude mid-step while keeping uncommitted work, and doing nothing leaves the request waiting. `after_stop` distinguishes a restart request, which brings it back, from a stop-only request. `alerted_at` reserves delivery once; reaping owners never get this push. Saved `alerts: "none"` suppresses it. Notification workers keep delivery off the conductor's stepping thread. The catalog approval is maintained separately in `scripts/notify/push_texts_reviewed.json`.

A not-back push is sent once per new restore failure; `restore_alerted` stores the last failure reported. An unchanged failure is not pushed again.

Every progress transition appends `ProgressStep{at, kind, detail}` under `update_session`; the timestamp is the write time, so rollback progress retains its original time without reversing the trail clock. Creation includes its initial progress. Old records read with an empty trail. Archive preserves the trail, and status renders each step in the user's zone.

In a terminal on the record's machine, run `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py follow <account> --request <request-id>`. Follow reads local active records and checks history every second, never inventory; immutable history files are read once per follow, including unrelated requests. Active reads precede history reads to cover an archive between them. It prints `<HH:MM:SS> <name>: <kind> <detail>` once per trail step. A nonfinal archived record means the session was taken out: follow prints that once at observation time and counts it done. It waits through stopped/already gone when restart is pending, reads outcomes archived before it starts or between polls, and prints all stopped or all back on the target account; summaries with cancellations count each outcome. Failure, lost identity or a holdout prints the exact local action and exits 1; completion exits 0. Ctrl-C exits 130 and prints a reconnect command while the conductor continues. A terminal down with tty output follows after conductor launch; other callers receive scoped follow and cancel commands, without promising to undo a move. Each machine follows only its own records.

Conductor Python runs with `-u` and `PYTHONUNBUFFERED=1`. Its due tick inventories only live-record ids and their owned workers with `refresh_desktops=False`; stop identity re-reads also skip desktop refresh. Down resolves exact names with the light listing and passes its single selected full inventory into begin.

`report_stop` sends the requester this machine's results plus one peer-record read. Account-wide partial stops alert when their saved policy allows it. Restart uses `<label> is not fully back` for incomplete restoration. Missing Remote Control starts the local background fixer; only a failure to launch it sends an immediate Remote Control push when policy allows it; retry guidance remains only when something is still left to bring back. Lines always print; `alerts: "none"` and command `--no-alert` suppress the phone send, including after archive.

For incomplete restores, restart checks policy on both machines. With `--only`, only selected records count; with `--here`, it reads no peer. When the peer is unavailable, including an answer without the result object, account-wide policy uses every local record: no record or any record with `alerts: "user"` enables the alert. Selected policy stays restricted to chosen records; no second peer call is made. Refusals alone never alert.

### Launch checks and held sessions

`launch-blocked [account] [--restart-of SESSION_ID]` exits 0 for a hold, 1 silently when launch is allowed, 2 for an unresolved account, and 3 for unreadable state. An account hold prints `<label> is held by a shutdown (since <time>)`; a selected shutdown never blocks unrelated new work. A restore's own record overrides the account hold: stopped, already gone, lost identity, restarting, restart failed and manual restart permit it. Every other recorded progress prints `<session name> is held by a shutdown (since <time>)`. Relaunch claims first, so a timers-pending retry is permitted while restarting.

`launch_permission` returns `AllowedByShutdownState`, `BlockedByShutdown(reason)` or `ShutdownStateUnreadable(detail)`; only a silent exit 1 permits launch. `launch_barrier()` holds `<root>/launch.lock` from check through spawn, and record creation and account-hold creation share it. Only the short decision and spawn are protected, never the launched work. Account locks serialize store mutations; a conductor holds its separate lifetime lock.

Scheduled nightly review and fix jobs keep firing but skip held accounts or unreadable state. `add_unit.py` applies the check to its chosen account, including a restore's id. Manual unit resume checks `--restart-of` and continues only on silent exit 1. `held-sessions` lists every owner's and worker's id; delegate cleanup treats those active runs as live so workers survive. No caller can infer launch permission from an exception or a crash exit 1 with output.

### Remote calls

`run_remote` uses SSH and the trailing `rc=<n>` from the command; SSH's status alone is never a successful answer. A missing trailer, SSH 255 or timeout is not reached. Standard calls have a 120 s limit; restart's peer restore uses link keepalives with no overall timeout (`ServerAliveInterval=15`, `ServerAliveCountMax=4`). Each machine makes progress independently; there is no cross-machine stop claim.

## Invariants and costs

- Account isolation: unreadable account means unattributed, never the default account. Stored process identity is never replaced with an observed pid.
- Claude processes receive only `SIGTERM`, with readiness unless explicitly forced. The only pane input is the detached fixer's `/remote-control` in the restarted session's own pane while its registry shows idle. An unsupervised Ghostty window shell, or a stop-only supervised window, is closed with `SIGHUP` after the ownership check; supervised restarts retain the window; owner identity is checked before signals or resource cleanup.
- Registry process identity and socket prove relaunch liveness; Remote Control is a separate field check and never changes the restart outcome.
- A tmux id route checks the server's pid and start time in one probe and launches with a second tmux call, so a server replaced in the milliseconds between them could receive a reused `$N` or `%N`. The launch does not repeat the check: doing so would nest the resume command inside tmux's own quoting (`if-shell -F`), a larger risk to every launch than the window it closes.
- Only `AllowedByShutdownState` permits a launch; the barrier spans check to spawn. The UPS alert is unaffected by holds. Neither implementation nor tests read notification credentials.
- Record timestamps use UTC ISO 8601 at whole seconds; injected stop clocks produce the same format. User-facing times use the user's zone (`config/user_zone.conf`, read through `scripts/lib/user_zone.py`).
- Test cases derive from `ShutdownTestCase` and use temporary state and fake send, notifier, process, tmux and host commands. Tests start no real session and send no real alert.

A relaunch is confirmed by `sessions.live_sessions()`, never by pane text, and a restore through `add_unit.py` proves nothing about its session: with a `UnitRestoreLaunch`, `add_unit.main` prints `<unit> restore launched: tmux attach -t <session>` and returns 0 once spawned, while new-work launches keep the screen wait and `--timeout`. Measured on a 19-session restart of claude3 (2026-10-12, 12 m 40 s): eight sessions took 90–92 s, the whole of `add_unit.py`'s 90 s default, and ten took 2–6 s. `tmux capture-pane -p` reads only the visible screen; the panes were 80x24 on the alternate screen with no history, and the restart note pushed `/remote-control is active` off it before a poll, though the transcript and `bridgeSessionId` show Remote Control active within about 3 s. Two launches can share a tmux session that does not exist yet; creation is not serialized, because a competing creator can be another process, and the launch that loses `new-session` opens a window in the session the other created (`_tmux_launch`).

Costs: conductor pass 15 s; settle-message retry 300 s; not-answering alert once after 4 min; two stop waits of 10 s; shared registry wait up to 90 s; Remote Control wait 10 s plus one poll's reads; windows 1.2 s apart; sender timeout 60 s; launch checks and held-session queries 30 s. On macOS each `running_session` with a recorded `procStart` uses one `ps -o lstart=` per registry record per call, with a 5 s timeout; Linux reads `/proc/<pid>/stat`. The Remote Control wait avoids that process scan.

Uncommitted edits remain on disk. Readiness means idle, nothing ahead of upstream and no merge; it never commits unfinished work. A live launch with unreadable registry state remains unresolved rather than being launched twice. Restore prompts are registered as scheduled so they do not pause restored timers. A recorded tmux pane is reused only when its identity matches; the Mac has no tmux.

Code gotchas: `update_session`, `archive_session` and the withdrawals see `sessions/` files only, so a session known only through an unmigrated old file raises `NoLiveRecord` there, though `find_session` returns it and `create_session` answers `False`; `ready` does not migrate. One handler in `main` catches `InvalidRecord` around `conduct`, `ready`, `down`, `now`, `cancel` and `status`: a refused migration prints one `shutdown: <error>` line on stderr and exits 3, with no record written, no message sent and no conductor started; `restart` prints `shutdown: restart failed: <error>`. Record updates from launch threads are serialized by `_account_lock`, a `flock` on a new descriptor per call. The readiness types (`ReadinessClear`, `ReadinessBlocked`, `ReadinessCheck`) live in `record.py` because `stop.py` and `settle.py` import each other. `scripts/message/test_send.py` calls settle's private `_restore_record`. In `test_settle.py` the fake sender reads stdin only where `send.py` reads it (a message send, not `retire` or `pending`), so a test fails when the real sender would block on an open stdin. `SHUTDOWN_TMUX`, `UNIT_LOOKUP_TMUX` and `SHUTDOWN_SYSTEMD_RUN` name stand-in binaries for tests.
