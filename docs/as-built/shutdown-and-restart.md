# Shutdown and restart

Refusal-watcher inventories read cached desktop metadata. Their selected shutdown carries `REFUSAL_WATCH_INVENTORY=read existing` into the conductor's command, since `systemd-run` on Linux does not pass on the caller's environment. This prevents inventory from invoking the snapshot updater, which itself runs the notes timer. When inventory does run the updater, it sets `AGENT_SESSIONS_SKIP_AGENT_NOTES=1` (`inventory.SKIP_AGENT_NOTES`), so the updater's `main()` skips `refresh_agent_notes`, which reads every Claude login; the timer's own runs keep that refresh. An updater from before the flag ignores it and only costs the time.

The argument-free notes timer runs the refusal watcher every two minutes. Sessions on one refusing account share a selected `down --here --only ... --restart --to ... --why ...`; each record's request id joins its journal request and outcome. Restart checks the resumed process's config directory before confirming the move. A source-account process, failed launch or manual restart is a failed move; a proven target process with pending timers is confirmed while those timers remain visible. Cancellation records `failed: cancelled`, removes an assumed refusal and suppresses the unchanged transcript error. Refusal replies with model `<synthetic>` do not replace the last real model used for resume.

## What it is

`agents <verb>` runs `down`, `restart`, `status`, `cancel`, `now`, `follow`, `snapshot` and `forget` from a terminal; `/shutdown` is the in-Claude form. Down, restart and status accept an account. Without one, `CLAUDE_CODE_SESSION_ID` selects this session's account; outside Claude, down covers configured Claude accounts, status also lists unresolved recovery entries, and restart covers accounts with shutdown records, holds or recovery snapshots, including hand-run Codex sessions. A named Claude account restores only its Claude sessions. `--only` and `--here` apply to both forms. `/shutdown` stops one account's Claude sessions on natedev and the Mac through one record per top-level session. Each owner settles, stops and optionally returns independently; a busy session or a permission form delays only that owner. Workers, Codex app-servers, timers and host resources belong to their owner. `/shutdown restart` restores stopped or crashed sessions, their notes and timers. Other accounts, CI runners and system services keep running.

An account-wide request holds the account against new launches and scheduled work until the request is finished; it never keeps the account closed after that. A selected request holds only its sessions. Each machine conducts its own records; an unavailable peer leaves local work running. `commands/shutdown.md` defines the user command.

### Accounts

Both move entry points run `check_move_target(target, now) -> MoveTargetReady | MoveRefused` before any write and read members from `inventory.listing()`, never a full inventory. `accounts.move(session: str, target: str, *, dry_run=False, why="") -> MoveStarted | MoveStartFailed | MoveDryRun | MoveRefused` resolves one local live id, else exact current name. It refuses a missing or ambiguous session, a worker, a grouped session (naming `accounts.py move <group> <target>`), a session already on the target and any open record for that owner. `accounts.move_group(group, target, *, dry_run=False, why="") -> GroupMoveStarted | GroupMoveStartFailed | GroupMoveDryRun | MoveRefused` takes `units` or `showrunners`: it reads one `inventory.showrunner_registrations()` snapshot shared by the member listing and `unregistered_showrunners`, sets the group's account with `set_group_account`, then moves every off-target member. A dry run returns before any write, with one `move_preview_line(member, now)` per member built from `prompt_state`.

`move_sessions(ids, target, *, why)` groups the selected ids by source login and runs one `shutdown.py down <source label> --here --only <ids> --restart --to <target> --why <why>` per login with `REFUSAL_WATCH_INVENTORY=read existing`. Each `SessionMoveRequested` carries the request id and the required keyword `source_login`, the login that `down` ran under; `_move_output` follows each `(source_login, request_id)` through `shutdown.follow` when stdout is a tty and `CLAUDE_CODE_SESSION_ID` is unset, and otherwise prints the follow and cancel commands that `down` printed. `docs/accounts.md` (Move a session) holds the user-facing lines.

`SessionShutdown.target: NotRequired[str]` names `claudeN`; a legacy stored `default` or `~/.claude` target resolves from dated cutover evidence only, else stays unresolved. The record’s login identifies the source account, so it cannot identify the destination. Absence means retain `session.config_dir`. New targeted records also store `source_label` and `why` (default `<old label> is out of usage`); repeated requests keep every existing field, except that a move over a waiting stop takes it over (below). `settle.down` forwards `--to` and `--why` to the peer. `restart.account_move_note` supplies one stable account-move explanation for every host, including the showrunner production resume prompt and the unit's continued `/unit:direct` run. An unknown host ends at `manual restart` with that resume command, which `status` and `follow` print with its place. A Ghostty or Mac terminal window with a live supervisor attaches to the restarted herdr session in place; other window hosts get a new window, as described below.

- A process's account is the login in its Claude config dir: `CLAUDE_CONFIG_DIR` from that process's environment, or the legacy `~/.claude` login only until this machine cuts over. After cutover an absent setting means no account. The legacy home reads `~/.claude.json`; numbered folders read `<dir>/.claude.json`. The login is `oauthAccount.emailAddress`. The **label** is read from the name of the hanadocs note in `AGENT_NOTES_DIR` (default `~/rust/hanadocs/agents/`) whose parsed tool matches and whose `login:` matches case-folded (`claude2.md` → `claude2`); else the login.
- `process_config_dir(pid) -> ConfiguredClaudeFolder | NoAccountSetting | ProcessEnvironmentUnread` reads `/proc/<pid>/environ` on Linux and `ps eww -o uid=,command= -p <pid>` on darwin (`parse_darwin_config_dir(output, expected_uid)`: `ProcessEnvironmentUnread` unless the uid matches and a `HOME=` token is present; the last `CLAUDE_CONFIG_DIR=` token wins). An absent or empty setting is `NoAccountSetting`; a readable selected path is `ConfiguredClaudeFolder(path)`. `process_account_directory` maps an absent setting to the legacy home only while its login exists. An unreadable environment remains `ProcessEnvironmentUnread`. `account_of(pid) -> Account | None`.
- `own_claude_account()` raises `UnreadableAccount`; `named_claude_account(text)` takes a `claude*` note stem with a non-empty `login:`, else text holding `@` with no `/`, NUL or whitespace and no leading `.` as a login, else raises `UnknownAccountName`. A named account uses that resolver; most absent-account verbs use the own account. `restart.select_account` also infers from eligible session records and account holds on both machines when the own account is unreadable: one candidate wins, otherwise candidates are listed and restart exits 1. An unknown named account prints `shutdown: <message>` and exits 2. An unreachable or older peer cannot prove that candidate set complete, so restart asks for an account.
- A `SessionStart` hook runs `account.py --write-label`, which writes `<config dir>/account-label` (label plus newline) atomically and only on change, or deletes it when the account is unreadable. The label file is a cache; process configuration remains the authority for account attribution.
- **Status line.** `statusLine.command` is `statusline="$HOME/.claude/scripts/statusline"; . "$statusline/statusline.sh"`: sourced, not run, since a second shell measured 1.3 ms of a 4.3 ms render. `statusline.sh` reads `account-label` with the `read` builtin, names `~/.local/state/agent-notes/by-label.json` (or `/dev/null` when it is not readable, a `[` builtin test), collects the session ids in the first line (`TARGET=session:<id>`, which `write_conf` always writes first) of each `${NOTIFIER_STATE_DIR:-~/.local/state/notifier}/showrunner-*/conf`, and execs `jq -r --arg pwd … --arg account … --arg showrunners … --slurpfile labels … -f statusline.jq` (one process; the role lookup adds about 0.3 ms with five timers). Row 1 is `<role> | <path>`, the path with `~` for the home folder (user, 2026-10-19). A showrunner reads `<session> showrunner`, a unit director `<session> unit for <showrunner>` (`unit` alone with no names), the name in the role's color (user, 2026-10-18). `statusline.sh` reads the session's own record, `${NOTIFIER_SESSIONS_DIR:-~/.claude/sessions}/$PPID.json`, with a builtin (Claude Code runs the status line command, so `$PPID` is the session), and jq uses its `name` only when its `sessionId` is the input's `session_id`. The role, first match wins: `showrunner` when the input's `session_id` is a timer's target, `worker` when `UNIT_TEAM_ROLE` is non-empty (agent_bg.sh passes it through `--settings` env, which reaches the status line command; it outranks the unit mark because a background session inherits the daemon's environment, and a daemon a unit started carries `SHOWRUNNER_UNIT`), `unit director` when `SHOWRUNNER_UNIT` is non-empty, else `unassigned`. Row 2, when any part exists, joins the account, the model with its effort, the tokens (once the input has a count), `5-hour <N>% left` (only when `<N>` is under 10, user 2026-10-18) and `weekly <M>% left` with ` | `; an empty account, or one holding `@`, drops its part. Each window is the one agent_notes stored for the session's label, the number the quota alerts use, while that reading is at most 600 s old and its `resets_at` is absent or ahead; otherwise `rate_limits.five_hour` / `seven_day`, so the row never goes blank for want of a reading. `remaining($window)` floors `100 - used` and clamps to 0–100, and a missing window or non-number drops its part. With no part, no second row. Row 3, the counts row, is the session's `For you: …` line, for a session a showrunner timer targets, with each number in ANSI bold (`\e[1m…\e[22m`, added by jq at render) and each part (`2 changes`) in its type's `counts.<type>` color from `config/statusline.conf`, matched by its word (questions red, user 2026-10-20; a type with no key stays plain): `showrunner_footer.counts_line`, questions included, read from `${SHOWRUNNER_STATE_DIR:-~/.local/state/showrunner}/counts/<slug>`. `scripts/statusline/counts_row.py <instance>` writes that cache: the line, the epoch second the soonest deferred question falls due, then each file the counts were read from (the timer's `conf`, the doc, `footer_counts.sources`, which names each open proposal beside its folder, and the production's own `OUTSTANDING` file; a file not there yet is named by its nearest folder). The cache's mtime is when that reading began. `statusline.sh` reruns the writer, synchronously and only then, when a named file is `-nt` the cache or the due second has passed (`EPOCHSECONDS`: bash's, or zsh's from `zmodload -F zsh/datetime`; a shell with neither leaves a deferred question to the next change), so a render with nothing changed runs no Python: 0.5 to 1 ms more on natedev, and a rebuild 200 to 300 ms, once per change. jq shows the rows whose session id matches, and no row when nothing is counted.
- **Readings by label.** Each agent_notes run, after saving `usage.json`, rewrites `by-label.json` from the whole store: for every Claude note, its stem (the label `account-label` holds) maps to that login's `five_hour` and `weekly` as `{left, resets_at, at}` in epoch seconds, `resets_at` null when no window is open. A refused read keeps the last good reading, whose `at` the status line judges. A label holding `@` is left out, so the file carries no login.

### Inventory

`inventory(login: str, only: frozenset[str] = frozenset(), *, refresh_desktops: bool = True) -> Inventory` keeps the live records in `~/.claude/sessions/` (`NOTIFIER_SESSIONS_DIR`) whose process config directory supplies a login matching case-insensitively. An unreadable account or a `procStart` unequal to the live process start (pid reuse) goes to `unattributed` (`UnattributedSession{pid, name, reason}`, reason `account unreadable` | `process start mismatch`), never to `sessions`. A non-empty `only` keeps those ids plus the workers they own, so `down --only <director>` includes that director's workers; full records (model, transcript, host) are built only for the selection. A caller wanting one session passes `only`: filtering after a full inventory still reads every transcript. `refresh_desktops=False` skips only the desktop snapshot; every other field, the supervisor included, is still filled.

`listing(login: str | None = None, *, registrations=...) -> list[ListedSession]` is the cheap per-session read for selection: frozen `ListedSession{session_id, pid, proc_start, name, kind, config_dir: Path, login, production, doc}`, with no git, transcript, timer or host reads, built per call and never persisted. `showrunner_registrations() -> ShowrunnerRegistrations` (`entries` of `ShowrunnerRegistration{session_id, slug, doc}`) reads the showrunner update timers in-process without resolving messaging sockets; `listing` and `unregistered_showrunners` accept one shared snapshot. `transcript_path(config_dir, session_id) -> Path | None` globs one level, `config_dir/projects/*/<id>.jsonl`, newest by mtime; `last_model(path)` reads backward in 64 KiB blocks and stops at the newest real model line. `_model` reports `no reply yet` for a transcript under another account's projects dir, which never happens while every config dir's `projects` is the same tree by link. On natedev a 40-session listing takes 0.25 s and a one-session inventory 0.38 s.

- **Checkout:** `git{path, head: branch{name} | detached{commit}, upstream: tracking{ahead} | no upstream, dirty}` | `not a checkout`. **Model:** `model{name}` | `no reply yet`.

- **Account directory:** each attributed session carries `config_dir`, the path from `ConfiguredClaudeFolder` at the process boundary. One boundary reads the process directory once and resolves its account from that directory, returning `AttributedSessionConfiguration{account, config_dir}` or `UnreadableSessionConfiguration`. `process_config_dir(pid)` distinguishes `ConfiguredClaudeFolder`, `NoAccountSetting` and `ProcessEnvironmentUnread`. An absent setting retains the legacy home login only while it exists; after cutover it is unattributed, as is an unreadable environment or account. Registries and transcripts stay under the shared `~/.claude/sessions` and `~/.claude/projects` paths.

- **Servers and timers:** run markers are `<root>/active/<session id>` for each run root: `SHUTDOWN_RUN_ROOT` when set, else `/tmp/claude/unit` and `/tmp/claude/delegate` (a run started before the folder rename); a live `mesh_server.json` pid is a `CodexServer{run_dir, pid, busy_workers}`, a `mesh_roster.json` worker in `running`/`starting` is busy only with no `launcher_pid` or a live launcher; timers are `NOTIFIER_STATE_DIR/*/conf` with `TARGET=session:<id>`.

- `parse_inventory` / `parse_session` check every `kind` and field and raise `InvalidInventory` naming the field path (`inventory.sessions[0].host.kind is invalid`). The peer's inventory is always decoded through them.

### The record store

`SHUTDOWN_STATE_DIR` defaults to `~/.local/state/shutdown`. Each case-folded login directory contains `sessions/<sanitized session id>.json`, optional `hold.json`, `history/`, `lock`, and `conduct.lock`. Characters outside `[A-Za-z0-9_.-]` become `-` in session filenames. Filename collisions are refused, never resolved by overwriting another id. An archived record moves to `history/<requested_at>-<session file name>`; an existing target raises `InvalidRecord`.

`SessionShutdown` carries `login`, `label`, `machine`, `requested_at`, `request_id`, `requested_by` (session id, terminal or recovery snapshot), `hold` (`account` or `session`), `then` (`stop` or `restart`), `force` (`wait for ready` or `now`), `alerts` (`user` or `none`), `probe` (missing reads `false`), the owner's `session`, its workers in the `workers` field, timer snapshots, `settle_message`, `where`, `progress`, `trail`, `stop_issues`, and the optional `alerted_at`, `codex_seats` (Stopping, Codex workers) and `restore_alerted` (Messages and notifications). A worker never gets its own record. `AccountHold` carries the request's login, label, machine, time, id, origin and continuation. Request grouping uses `request_id`; second-resolution timestamps never establish request ownership.

Public store operations are `session_records`, `all_session_records`, `create_session`, `update_session`, `archive_session`, `set_account_hold`, `clear_account_hold`, and `clear_finished_account_hold`. `lookup_session` returns `ShutdownFound(record)` or `NoShutdown`; `lookup_account_hold` returns `AccountHeld(hold)` or `AccountOpen`. Updates run under the account lock, revalidate and write with a temp file, `fsync` and `os.replace`. Invalid paths, symlinks, invalid fields and mismatched account or session ids raise `InvalidRecord`. Absence is distinct from unreadable state.

`clear_finished_account_hold(login, *, request_ids=())` clears only when no record of the hold's request remains. Non-empty `request_ids` also require that the hold belongs to one of those requests. Selected cancellation or restore supplies the requests it finished; account-wide restore can clear a hold with no records. Account-wide cancellation always clears the hold, even when stopped records remain for restart.

`release_finished_account_hold(login, *, conducting=False)` removes a finished hold and returns `HoldReleased(hold)`, else `HoldInUse(hold)` or `AccountOpen`. A hold is finished when its registration is complete and no record of a covered request is live, waiting or stopping: each is `stopped`, `already gone`, `process identity lost`, `restarted`, `stop failed`, `restart failed`, `manual restart` or `timers pending`, or archived. A running conductor keeps the hold. With `conducting=True` the caller is that conductor, and every covered record must meet `record.shutdown_finished` (the conductor's done rule, also `settle._done`), so a restart request keeps its hold until it restarts its stopped sessions. An old record's hold is never removed here. The conductor calls it on each pass and when it ends, for `then` `stop` and `restart` alike; `launch-blocked` calls it for every launch that its own record does not decide. So a hold whose records another path archived heals on the next launch check. On 10-18 a `then stop` hold on claude2 outlived its records and refused every launch onto claude2 until 10-26. Stopped records stay for restore after their hold is released.

Reads and dry runs convert old files in memory without writing them. `migrate(login)` is called by writing operations before they use the store. It validates every old file and destination before writing any session record or moving a source file; conflicting sanitized filenames or history destinations raise `InvalidRecord`, with no session records written or sources moved. For one session id the current file wins, then the old main file, then the newest old partial file; completed old files supply no session records or hold. Conversion attaches workers, drops record-level issues, preserves an inferred account hold without replacing an explicit one, and assigns `legacy-<machine>-<requested_at>` as the request id. It moves old sources to history and prints one conversion line per source. Status, read verbs and dry runs still see unmigrated files. Internal `records --json --here` and `holds --json --here` expose the session records and account holds used for cross-machine account inference; a peer without these interfaces is not reached.

### States

Each owner's `progress` is `waiting`, `reaping{at, because, detail}`, `ready{at}`, `held by usage limit{at}`, `stopping{at}`, `stopped{at}`, `already gone{at}`, `process identity lost{at}`, `stop failed{at, reason}`, `restarting{at, prior}`, `restarted{at}`, `restart failed{at, reason}`, `manual restart{command}`, or `timers pending{at, timers}`. Stop-only terminal records remain for restore. Confirmed `restarted` records are archived and never launched again.

A `stopping` or `restarting` claim belongs to its worker for `CLAIM_STALE_SECONDS = 120`. An older claim can be replaced; a relaunch resumes from `prior`. A stop worker checks its exact claim before each write, signal and cleanup operation; a relaunch confirms only its own claim. Losing a claim transfers ownership without adding a user outcome. Conductor handoff likewise has no separate user outcome.

### Settling and selected actions

`down [account] [--here | --also MACHINE] [--only NAME[,NAME...]] [--restart] [--to claudeN] [--why TEXT] [--no-alert]` covers only this machine unless `--also` names the other machine, `--only` names sessions (each is stopped where it runs) or `--to` makes it a move (`shutdown._stop_here`; `now` follows the same rule, and `--also` must name `remote.other_machine()` and cannot join `--here`). It checks `github-warm-status` for a full shutdown (a move, with `--to`, skips the check: the checkout stays on this machine), then begins locally and launches this machine's conductor. Each new owner gets `waiting` or `reaping` from its prompt state, its workers, saved timers and stopped timers; a timer-stop failure removes only that owner's request and names it. Existing records print `<name>: already in progress` and keep their continuation, hold, policy and request origin. One exception: a move (`--to`) over a stop with no target that is still `waiting`, `ready` or `held by usage limit` takes that record over (`settle._take_over_for_move`): it sets `then`, `target`, `source_label`, `why` and `move_id`, keeps the request id, origin, pause message and saved timers, and prints `<name>: the move replaces its waiting stop`. A second move, or a stop that has begun, stays `already in progress`. For each new or taken-over move record, `settle._carry_trust` then gives the target account the source account's folder trust (`herdr.copy_claude_trust(folder, source, target)`): it sets `projects[<key>].hasTrustDialogAccepted = true` in the target's `.claude.json` for the one key the source already trusts (folder, repository root or main checkout, as `herdr.claude_trust` reads them), writes a staged `0600` file and renames it over the target, and changes no other value. A folder the source never trusted stays untrusted. A target account with no `.claude.json` is skipped quietly; any other unreadable file prints `<name>: folder trust not copied to <target>: <reason>` on stderr, and the restart then refuses with its own trust command. New owners print `<name>: added`. Repeating a request starts a conductor even when every selected owner already has a record; follow and closing commands retain those original request ids.

Without `--here`, the peer receives `down <login> --here` with the same request id, origin and continuation and conducts independently. Failure prints the peer retry command with its account, ids and `in a terminal on <machine>`; local records are not withdrawn. Non-following down exits 0 once this machine started; a tty down returns follow's result. Only an account-wide request sets an account hold.

`resolve_sessions(login, items, *, here=False)` resolves exact names or ids against account records and inventory, counting each id once and excluding workers. Local ids need no peer lookup; names are checked on both machines unless `--here`. Readable peer records remain candidates when its inventory fails. An unavailable peer prints `<peer>: not reached; names checked on <machine> only`. For `restart --only`, a live session on the selected account or any other account with no shutdown record prints `<name>: already running; skipped`. Each unknown or ambiguous name gets its own error line; the other names still restart, and the command exits 1. Other commands keep the exit 2 error for an unknown or ambiguous item. Local ids execute locally; only remaining ids go to the peer. For selected `cancel` or `now`, a local live session with no record prints `<name>: no shutdown in progress` and exits 1 without being sent to the peer.

The conductor holds `record.conductor_lock(login)` for its lifetime. A duplicate exits successfully; a quarter-second retry (`CONDUCTOR_LOCK_RETRY_DELAYS`) tolerates a status probe. After release it checks for newly added work so an ending conductor cannot leave a request unattended. Every `SETTLE_INTERVAL_SECONDS = 15`, one `run_inventory(login, <live record ids>, refresh_desktops=False)` feeds `next_step` for each owner; a record withdrawn during the tick's refusal scan raises `store.NoLiveRecord` and is skipped. The full inventory with its desktop snapshot takes up to 60 s, so the tick stays filtered. Running actions are skipped until their futures complete. Stops and non-window launches run in a `RESTART_LAUNCH_WORKERS = 6` pool; registry and Remote Control waits use the polling pool. Window hosts launch in order on the conductor's thread with one desktop state restored on exit. `_launch_conductor` names it `shutdown-<label slug>-<pid>`. On Linux it runs as a `systemd-run --user` unit, which does not pass on the caller's environment, so a `HOME` or `SHUTDOWN_STATE_DIR` exported in the calling shell does not reach it. On the Mac it starts through `detached.start_detached` with the caller's environment plus `DETACHED_STARTUP_SIGNAL=1`, output appended to a log under `shutdown_state_root()/logs`, and readiness on its `shutdown conductor started` line within 15 s; a failed start names that log. The conductor ends when no record has a step left: each is archived, or stopped with `then: "stop"`, or needs the user (`stop failed`, `restart failed`, `manual restart`, `timers pending`). It clears the account hold once a restarted record of the hold's request is archived and no record of that request remains, then sends the requester one result (`report_stop`).

A waiting non-requester gets the settle message; queued messages retry after `SETTLE_RETRY_SECONDS = 300`. Its first line is fixed, and the launching skills (`<PauseForMove>` in `/unit:direct` and `/showrunner:produce`) act on it: `Pause for move: <label> → <target> (<why>, <time>)` or `Pause for stop: <label> (<why>, <time>)`; that line stays byte-identical because the skills match its prefix. The second line, `pause_confirmation_line(record)`, says the request comes from the shutdown the user started, not from another session's own choice, cites `docs/accounts.md` "Move a session" for a move or this doc for a stop, and names `shutdown.py status <account label> --here` to run in this terminal, which lists the session under the move or stop; the label is `note_file.canonical_label(record["label"])`, never the login. The body asks a busy session to stop at once, without finishing its current step, then run `ready --where` and end its turn.

No session's consent is required. A waiting owner that is idle (status `idle` or `shell`, every worker `idle`, `blocker(...)` clear, no form showing) is stopped by `next_step` with `StopSession(idle_reason)`: with its message `not sent` or `queued` it gets no pause message and stops as `idle; nothing in progress`; with the message `sent` and the registry's `updatedAt` (`Session.updated_at`, ms) strictly later than the send, it stops as `idle after the pause message; no ready line`. An equal or earlier `updated_at` is not an answer, and a saved inventory without the field reads it as 0. A form, any blocker or a busy worker still holds. `blocker(session, moving=...)` counts work not yet pushed only for a full shutdown: a move (a record with `target`) keeps the checkout on this machine, so `next_step`, `ready` and `_stop_owner` pass `moving=True` for it and its hold details omit `ahead N on <branch>`. So the pause reaches only busy sessions, and the conductor sends no holdout alert for a `StopSession` step. A sent message with no ready mark after `REASK_AFTER = timedelta(minutes=2)` is sent once more and `reasked_at` is recorded; no further repeat follows, and a busy session accepting prompts waits for its ready mark unless the timing is `now`. A move does not wait longer: `move_overdue(saved, now)` is true once `MOVE_ANSWER_AFTER = timedelta(minutes=2)` has passed since the sent pause message (or since the request when none was sent), and `next_step` then returns `StopSession(forced=True)` for a `waiting`, `ready` or `held by usage limit` move record whose owner matches or whose account cannot be read, in place of the re-ask. A form, a busy worker, a merge or other blocker does not hold it. When the owner is `busy`, the step also carries `mid_turn=True`, and `_stop_after_telling` first saves `cut_off` (`inventory.last_tool_call(config_dir, session_id)`: the transcript's last assistant `tool_use` as `<tool>: <description, command, file_path, pattern, url or prompt>`, whitespace collapsed and cut to 200 characters, read from the last 256 KB; empty when none shows). The resume note then adds `The move stopped you in the middle of a turn; your last step was <cut_off>. Check whether that step finished, and do it again if it did not.` A reaping move whose account cannot be read stops the same way at two minutes. A full shutdown keeps every wait below. Reaping bypasses readiness after a refusal or exhausted account reading. Its stop instruction names `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py`, so a session answers through the scripts installed under its own home, whichever checkout made the request. The requester gets no settle message and runs `ready --where` itself. A queued instruction whose request was cancelled or replaced before sending is discarded and never marks another request's record. `ready --where TEXT` updates only this session's waiting, ready or `held by usage limit` record, then launches its account conductor; a duplicate exits at its lock. A launch failure leaves the ready mark in place, exits 2 and prints the conductor command with the terminal and machine where to run it. Ready owners stop with registry status `idle` or `shell`, with every worker idle, no form, no merge in progress and, for a full shutdown, nothing ahead of upstream; dirty files stay on disk. `shell` means the owner is at its prompt with a background Bash shell, which ends with the session; workers still require `idle`. Automatic idle-stop checkpoint lines gain `; a background shell was running` for `shell`, while a session's own `ready --where` line is kept. Remote Control still requires `idle` before typing into a pane. `force: "now"` bypasses readiness. Absent owners or lost identity get a stop outcome without signals. An unreadable account holds the record, except for an overdue move (above). The requester goes last among the same request's records on this machine, except under `now`, which stops it without waiting for the rest of its request; a showrunner never waits for its units.

At `conduct` entry, `_module_fingerprint` records modification nanoseconds and sizes for `shutdown.py`, `settle.py`, `stop.py`, `record.py`, `inventory.py` and `restart.py` beside `settle.py`. Each conducting pass compares those six stats until a change requests reload. If a module stat raises `OSError` during an install, that pass keeps the current fingerprint and continues owned work; the next pass tries the comparison again. The conductor logs the changed module names and time in the user's zone, takes no new session steps, and drains its stop and launch actions, pause messages, holdout sends and registry confirmations, including launches awaiting confirmation. It restores desktop state, atomically writes archived outcomes to the account state directory's `conduct_archive.json`, releases `conduct.lock`, then replaces itself with `os.execv(sys.executable, [sys.executable, "-u", *sys.argv])`, repeating the `shutdown.py conduct <login>` entry point. The replacement consumes that file under the conductor lock, merges the outcomes into its final report and deletes the handoff file. Completed launches are confirmed and archived before reload, so they are not launched again. A file holding a record of another login raises `InvalidRecord`. Since `ready` and `down` find a running conductor holding the lock and exit, this reload is how new code reaches an open request; an install needs no conductor restart.

Gotchas: `launch_permission.py` and the `scripts/lib` modules are not fingerprinted, so a change to them alone triggers no reload. `_conduct_archive_path` takes its root from `launch_permission.shutdown_state_root()` and repeats `record`'s private login checks (non-empty, no `/` or NUL, no leading `.`, case-folded directory), because `record`'s directory helpers are private; a change to those checks in `record.py` must be repeated in `_conduct_archive_path`. The entry fingerprint lets an `OSError` propagate, while a pass's comparison must not abort, or the archived outcomes are lost.

A fresh not-ready refusal returns the stop claim to `waiting`, `ready` or `held by usage limit` and keeps its `NotReadyToStop` issue for status. A stale `stopping` claim returns to `waiting`. It stays open for the conductor's next inventory pass and is not reported as finished. At the shared validated entry parser, an old `stop failed` with reason exactly `session or worker is not idle and ready` and exactly one `NotReadyToStop` is recovered to that issue's progress for both legacy account files and current session records. Other failures stay terminal, and every real stop failure replaces the previous stop issues.

`cancel [account] [--here] [--only NAME[,NAME...]]` restores timers, retires queued shutdown messages, sends `cancelled by the user: continue where you were` to a previously messaged owner, and archives the record. Restoration and the cancelled message run under the account lock before any later request can send its instruction, so cancellation cannot replace that instruction. Selected waiting, ready or `held by usage limit` owners print `<name>: taken out`. A selected `stop failed` record can be withdrawn only when the original process identity is still live; identity checking and withdrawal share the lock, and it prints `<name>: taken out, still running`. A competing stop claim keeps the record. Other retained records print their progress and a full scoped restart command with `in a terminal on <machine>`, exit 1. Selected cancellation clears a hold only if it withdrew that hold's request's last record.

`now [account] [--here] [--only NAME[,NAME...]]` sets `force: "now"` and starts the conductor; it never stops or retries a session itself. Chosen eligible owners print `<name>: stopping now`; an ineligible owner prints `<name> is <progress>; nothing to stop`, exit 1. A multi-selection exits 1 if any selected owner could not be acted on.

### Status

`status [account] [--json] [--here]` shows the inventory, then the records and applicable actions in each machine's block. Waiting, ready and `held by usage limit` lines retain `  <name>: <progress> — <hold details>` and a message note after ` · `. Hold details include `busy`, `showing a form`, `ahead N on <branch>`, `merge in progress`, `Codex worker <name> is still running`, and `message queued: <reason>`; a usage-limit hold omits the form detail. Stop issues print beneath the owner; a failure reason, pending timers and a manual restart command print on the progress line. `--json` prints the inventory with local unresolved recovery entries when present.

A read-only, non-blocking `conductor_status` probe distinguishes running, not running and unavailable. A lock filename alone is not ownership. With unfinished records and no conductor, status prints full selected down commands to resume, each with `in a terminal on <machine>`. An unreadable or unreachable probe reports `conductor ownership unavailable: <reason>`. Applicable take out, stop now and bring back actions use full script paths, the stored login and exact --only ids, grouped by machine in record order. Reaping owners have stop-now actions too.

### Stopping

`stop_session` claims before signalling and never replaces a stored pid with an observed one. An idle stop's reason (`StopSession.idle_reason`, a `stop.IdleStopReason`: the two idle texts, each also with `; a background shell was running`, beside the default `not an idle stop`) is written as the stopping claim's `where` (`said`) in the same update that moves progress to `stopping`, only when the prior progress is `waiting`. `_stop_owner` admits a `waiting` prior only for an idle reason and still runs fresh idle, worker and blocker checks. `fresh_session` distinguishes a matching owner (with workers), absent owner, lost identity and unreadable account. `stop_session(..., forced=False)` treats `forced=True` like `force: "now"`: it skips the readiness, idle, worker and blocker checks. It also lets an unreadable account through, on both checks before the signal, only when `_same_process(stored)` holds (the recorded pid still has its recorded `proc_start`); the stop then uses the stored session and no workers. Process identity is checked before each `SIGTERM`; two attempts each allow `STOP_WAIT = timedelta(seconds=10)`. No `SIGKILL` or pane input is used. Before signalling the owner, `_save_codex_seats` records its Codex workers (below). A `reaping` owner skips the readiness and idle checks and keeps the identity check before `SIGTERM`. Under `then: restart`, an owner whose host has a live supervisor gets its hold written first (`_hold_supervised_window`), then only Claude is signalled and the window is kept (`retain_window`); a failed hold write ends the stop as `stop failed` with no signal sent. After the owner exits, cleanup closes an unsupervised or stop-only Ghostty window where ownership still matches, runs `codex_mesh.py stop --pause --session-dir <run dir>` for each owned run directory (`_stop_codex_servers`), then stops its unit's exact herdr session (`docs/as-built/herdr-adoption.md`). Workers receive no process signal and keep jobs and transcripts for their next message. Cleanup issues remain on the record.

**Codex workers.** `_save_codex_seats` stores `SessionShutdown.codex_seats: list[PausedSeat]`, one per non-ended worker of the owner's run directories (`inventory.codex_seats`), except a run its director left: every worker still `paused` from an earlier stop and a `board.log` older than the oldest `<seat>.resume-prompt.md`, so the director took no worker back after that stop offered them (`_left_since_offered`; a missing board or prompt keeps the run). Each worker records `run_dir`, `seat`, `role`, `thread_id`, `turn_live` (status `running`/`starting`, or a recorded `paused_turn`) and `launcher_command`, the argv of the nearest live `implement.sh` or `review.sh` ancestor of the worker's `launcher_pid`, empty when unreadable. A record without the field reads as no workers. A cleanup retry keeps the workers first recorded, since by then the launcher has exited and its argv is gone. Every worker gets `<run_dir>/<seat>.resume-prompt.md`: `RESUME_PROMPT` (continue the earlier task) for a worker with work in progress, `IDLE_RESUME_PROMPT` (reply ready and wait) for an idle one.

`stop --pause` empties each non-ended worker's pending queue and sets it to `paused` with `paused_from` (the prior status) and `paused_turn`, under the roster lock. It then drops the thread's queued messages, interrupts a live turn on the recorded server, sets `paused_turn` from what the server reports, and reaps the run's servers. The drop and interrupt calls of all workers share one `PAUSE_INTERRUPT_SECS` (15 s) deadline (`Client(..., deadline=)` caps the connect and every call), so the reap always runs inside the 30 s `stop._run` gives the command. A worker not reached by then keeps `paused_turn` from its roster status. On 10-26 a server that did not answer kept the pause waiting until `stop._run` killed it before the reap. The server stayed up, and the move's restart refused with `owner cleanup not confirmed`. A roster write that would move a `paused` entry on the same thread to anything but `paused` or `ended` keeps the stored entry, so a launcher finishing after the pause cannot undo it. `paused` is followable (`FOLLOWABLE_STATES = {"done", "failed", "paused"}`): a follow clears `paused_from` and `paused_turn` and, with the server gone (`ServerRestartRequired`), starts a new app-server and calls `thread/resume` on the recorded thread. No stop calls `codex_mesh.py end`. Plain `stop`, which `end_session.sh` runs at run end, still ends every worker; `sweep --stop` leaves a paused worker paused.

`codex_mesh.py reopen --session-dir <D> --to <seat>` returns a worker to `paused` on its recorded thread when it reads `ended`, or `running`/`starting` with a dead launcher and no live server; it prints `reopened <seat>; send its next turn with --to <seat>`. It refuses with exit 2 and one `codex_mesh: <seat>: <reason>` line on stderr when the thread id is missing, the launcher is alive, a server is alive or the status is any other. `implement.sh --to` treats an `implementing` status with no claim file and no live roster launcher like a dead claim: it writes `error` and continues, so a launcher the stop left behind does not block the follow-up.

A Codex workers-account move is a separate path (`resume-account-move`, the `<seat>.account-move.json` marker). A launcher whose thread reads idle with no completion notice reads that marker again before ending the worker, so a turn the move interrupts between the launcher's first marker read and its idle check resumes on the same thread.

### Recovery snapshots

Each snapshot pass also saves the shared herdr session's workspace and tab order (`herdr.save_shared_layout`), and a restart's tab opens put every session back in its saved place (herdr-adoption.md, Tab order). The pass then rebuilds the local override of herdr's Claude detection rules (`detection_rules.refresh`, herdr-adoption.md, herdr behavior). Whatever replaces the snapshot timer must keep both.

`RecoverySnapshot` holds machine, canonical login, label, taken time and tagged Claude/Codex entries. Each entry keeps its session, workers, timer restores, last-seen time and running/unresolved state. Codex entries also keep `CODEX_HOME` and either a session id or an explicit resume-picker choice. A Claude entry's optional `crash` is `reboot`, `host gone` or `agent exited`; `merge_snapshots` keeps a missing entry only with one of them. The unit watchdog (`docs/accounts.md`) writes `agent exited` (`record.mark_snapshot_agent_exited`, or `restore_snapshot_agent_exited` from its own copy after the entry was dropped) when an agent exits in a live herdr host; a newer observation is never replaced, and a session seen again clears the mark. Restart turns it into `AgentExitRecovery` with `last_seen`, which the restart prompt names. `agents status` lists unresolved entries with last-seen times in the user's zone; local JSON status includes `recovery` when unresolved entries exist. `agents forget <name|id> [--account <login|label>]` acknowledges one local snapshot entry and retires its stopped or failed shutdown record without touching its process; entries still shutting down are retained. After a move one session id can have a record or snapshot entry on two accounts; a bare id or name that matches only that one session forgets every copy and prints `<name>: forgotten on <label>` per account, and `--account` forgets one copy. A name shared by two different sessions is still refused with the list.

`restart._up` selects per session id: an existing shutdown record takes precedence, while snapshot sessions with positive crash evidence join the same restart pass. It prints `from shutdown record` or `from snapshot taken <last_seen in the user zone> (<age>)`; with neither source it prints `nothing to restore for <account>`. All local accounts' records and snapshots supply account evidence before launches; archived completed restores retain that evidence after acknowledgement. Current running ids are checked independently of the stored account and skipped; a confirmed move or newer observation selects the current account (if only an old-account copy remains, it launches on the confirmed target), and conflicting evidence refuses the session and names both accounts. Snapshot-only names and ids participate in restart selection and forget; other verbs select from membership and shutdown records. Peer `up <login> --here --json` uses the same source selection and keeps the result-object protocol. A unit resumes through `add_unit.py --resume` with its Units row's Plan cell (`--standby`, `--permanent` or `--plan`), else its run record's plan; a row whose Plan cell starts with the retired marker raises `UnitRetired`, so the entry is refused with `<unit> is retired in the Units table of <doc>` and never launched.

A Claude snapshot candidate is atomically materialized as a `SessionShutdown` before launch: snapshot origin and taken time, `recovery-<taken_at>` request id, session-only hold, restart continuation and `already gone` progress. An existing request is returned untouched. Admission passes `RecordedSessionRestoreLaunchPurpose(session_id)` against the account selected for the launch, including the configured showrunner account, and requires that persisted record. Retried materialized snapshots check registry readability and the saved owner pid/start before launch. Dry runs use the pure record builder and persist nothing. Confirmation acknowledges the snapshot only after the restart succeeds; failure keeps both record and snapshot for retry.

A Codex snapshot launches directly, without a Claude hold or shutdown record: `restore_server` on the shared session, a tab titled `<owner>-codex` in its owner's workspace, opened in the recorded cwd with `CODEX_HOME`, then `start_agent(kind="codex", agent_arguments=["resume", <id>], opening=NoOpeningPrompt())`. Without a recorded id, arguments are `["resume"]` and output names the picker. A failed agent start closes that tab. A host that launches windows reuses an attached client, else opens a window; otherwise output gives `herdr session attach agents`. A successful start acknowledges that Codex entry; a running id is skipped.

### Restart

`restart [account] [--only NAME[,NAME...]] [--here] [--dry-run] [--no-alert]` expands terminal requests without an account over accounts with shutdown records, holds or recovery snapshots; explicit and in-session requests select their account through `restart.select_account` and run `up` locally and, unless restricted, on the peer. Terminal account discovery keeps known local accounts when peer records are unavailable, reports the peer failure and returns nonzero after trying the local accounts. Selected restart bypasses requester-last, so a stopped requester can return while siblings wait. Incomplete records (`waiting`, `ready`, `held by usage limit`, `reaping`, `stopping`) first require positive owner absence and confirmed worker/host cleanup through `stop_session`. An unknown liveness answer refuses recovery with its reason; live owners keep their shutdown request. Recovery preserves the request, target, timer intent, pause note and cleanup issues. A fresh relaunch claim prints `<name> is already restarting`, exit 0.

`relaunch_session(record, *, dry_run, desktop_state)` claims `restarting{at, prior}` before `launch_entry`. The caller owns and restores the desktop state. Eligible records are stopped, already gone, lost identity, manual restart, restart failed, timers pending and stale restarting; already restarted records archive without launching. A manually resumed live session is reconciled without a second launch. A record that carries `checkout_move{old, new}` (set by the hidden `down --checkout-move OLD NEW`, which needs `--here`, `--restart` and one `--only` session and refuses `--to`; `rename.py checkout` is its only caller) first runs `restart.move_checkout`, from `_up` (not on a dry run) and the conductor's `start_launch`: it calls `rename_checkout.move(old, new)` from `scripts/production`, prints `<name>: checkout move <old> -> <new> failed: <reason>` on any error, and then in one record update points `session.cwd`, `session.checkout.path`, `session.host.doc` and the same fields of each worker under `old` at the folder that holds the checkout (`new` when `new/.git` exists, else `old`) and removes `checkout_move`. So a failed move still launches in a working folder and is not tried again. A record whose folder (`session.cwd`) no longer exists is dropped before launch by `drop_restore_without_folder`, called from `_up` and the conductor's `start_launch`: it prints `<name>: folder <path> no longer exists; restore dropped`, saves that reason as `restart failed`, archives the record and sends no push, so it never holds the account's restart (a dry run prints the line and changes nothing). A saved `manual restart` that is not live prints its saved command again only for a host the launcher cannot start (`_host_needs_manual_restart`: an unknown host, or a terminal off the Mac); any other host launches again, so a record saved as manual by an older launcher comes back as an agents tab. Live `timers pending` retries only pending timers; closed sessions relaunch, and unreadable liveness never proves absence. One launch exception marks only its owner as failed. If a moved session fails to start on its target and is confirmed absent, restart tries its source account once; success records the fallback, and failure on both accounts marks it `restart failed` and pushes `shutdown.move_failed`, even when the move suppressed alerts. The record keeps the target account for the retry. A unit source fallback uses `add_unit` in the shared session with the unit marks; `--source-fallback` permits only the recorded source account. A folder no account trusts is not tried on the source: `_heal_folder_trust` already reads every account on the machine, the source included.

Non-window owners launch through the pool; window hosts, including attached herdr hosts, launch serially in `restart._up`. Account-wide order is by session name with the requester last (`_entry_order`); the requester is skipped while another record of its request is unfinished, and a showrunner never waits for its units. A pass's launched ids share one registry wait (`SESSION_WAIT_SECONDS = 90.0`, `SESSION_POLL_SECONDS = 0.5`); `confirm_entry` then restores timers and marks live sessions restarted. A moved session not live after the wait tries its source once. The same source fallback handles launch exceptions and failed prompt outcomes. A source start must submit its prompt and become live before it counts as restored. Other sessions not live after the wait end `restart failed{session not live after 90 seconds}`. In the conductor (`_confirm_relaunch_pass`) an error confirming one owner marks only that owner as a failed restart and the others in the batch finish as restarted; in `up` such an error ends the run with `<machine>: restart failed: <error>`. `wait_for_confirmation` returns `RegistryConfirmation`, retaining records from its final liveness poll for the Remote Control check. The conductor tracks `ConfirmedRelaunchPass` through `PendingRegistryConfirmation`. Records that finish are archived; failures, manual commands and pending timers remain. Real runs print `<machine>: restarted <n> in <s> s`; dry runs print planned launches without conversion, mutation, archive, hold clearing or a timing line.

- **Note** (`restart_note`): label, stop and restart times in the user's zone (`%Y-%m-%d %H:%M %Z`), the recorded `where` (for `not said`: read branch and plan), run `send.py pending` first, keep waiting if it was waiting on the user. Every first prompt is appended to `conversation_pause`'s scheduled prompts before launch (`_record_scheduled_restart_prompt`; `add_unit.py` does the same for units with the exact `prompt_for` string), so the pause hook does not treat it as typed. A failure leaves the entry unlaunched with `restart prompt not recorded: <reason>`.
- **Codex workers** (`_send_worker_resume`): after any session with recorded `codex_seats` is confirmed back (a unit director, a standalone run or a probe), restart sends it one `send.py --to session:<id> --from shutdown --key resume-workers-<session id>` message. Its first line is `Resume your Codex workers; do not open new ones.`; a worker that was working gets `<seat> (<role>, was working): <command>`, a complete command that runs as pasted; an idle worker gets `<seat> (<role>, idle): paused on its thread; nothing to run now. Your next dispatch with --to <seat> resumes it.`, because a pass needs an open phase and a run paused for the user has none; the last line is `Each worker continues its own thread; after resuming, send later work with --to as usual.` For a worker whose recorded launcher argv is complete, `_resume_worker_command` keeps its task arguments, swaps in the resume prompt and sets `--to`, dropping `--slot`, `--pool` and `--lease`. A worker with work in progress and no complete recorded argv gets a full `bash <scripts>/direct/implement.sh --to` (or `review.sh --to` for a review role; the launchers are not executable files) with the run directory, the session's cwd, the resume prompt and every argument the launcher requires, its kind and team role taken from the worker's role. An undelivered message stays for `send.py pending`; a failed send logs one `shutdown: worker resume message: <reason>` line and never fails the restart. With workers recorded, `account_move_note` adds `Your Codex workers are paused, not ended; a message lists the command that resumes each.` `<PauseForMove/>` in `commands/unit/direct.md` runs those commands before any dispatch and never opens a new worker for a role a paused worker holds.
- **Account on resume:** every launch sets a numbered `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_REMOTE_MEMORY_DIR=~/.claude`. Units and showrunners use their configured group account. Ungrouped sessions retain the recorded numbered directory. Legacy records naming `default`, `~/.claude` or lacking a directory resolve from the record's own login or a dated `cutover-home` entry in `config/accounts.json`; no evidence means unresolved and no launch. A legacy move target uses dated cutover evidence only, since the record's login identifies its source. Today's home login never resolves a past record. A resolved legacy resume uses that label's numbered folder. Herdr gets these variables directly in the pane environment; group resumes and moves use `accounts.prepared_account(target, resume=True)` and drop its removed names. The manual resume command that `_resume_shell` prints puts the same numbered directory in `CLAUDE_CONFIG_DIR=` shell assignments before `command claude`; a move runs `accounts.py exec <target>` instead. The restart subprocess strips inherited `CLAUDE_*`.

### A supervised terminal window

Every restart lands as a tab in the shared herdr session (`agents`), never in a herdr session of its own. Ghostty, Zed and Mac `terminal` hosts, legacy tmux hosts, a herdr host recorded in another session, and Codex snapshots all restart into `SharedHerdrTab` (see [herdr-adoption.md](herdr-adoption.md)). A window then only attaches to the shared session, and a legacy tmux host gets no window. `accounts.py exec` on a tty starts Claude under `relaunch.py run --` unless `RELAUNCH_SUPERVISED` is set, and a new Linux restart window runs `cd <cwd> && ~/.claude/scripts/lib/py ~/.claude/scripts/lib/relaunch.py run -- herdr session attach <name>; exec zsh` (`_herdr_attach_command`). The supervisor (`scripts/lib/relaunch.py`, standard library only, importing nothing from `scripts/accounts` or `scripts/shutdown`) shares Claude's terminal and process group, catches SIGINT, SIGQUIT and SIGTSTP itself so the child still gets them, and forwards SIGTERM and SIGHUP to its child. It starts the child with `RELAUNCH_SUPERVISED=1`, so a resumed `accounts.py exec` under it execs Claude directly and nests no second supervisor. Inventory reads `supervisor: SupervisorIdentity(kind="supervisor", pid, proc_start) | NoSupervisor` on `WindowHost` and `TerminalHost` from `_supervisor_process`, which matches the Claude parent's argv for `relaunch.py run --` (`/proc/<pid>/cmdline`, `ps -o args=` on the Mac); a supervisor that is the window shell itself reads as `NoSupervisor`. `supervisor_identity(host)` reads a host without the field as `NoSupervisor`; `live_supervisor(host)` also rechecks pid and proc start. Supervised hosts are `ghostty` on Linux and `terminal` on darwin, where `terminal_kind` maps Ghostty to `terminal`, so a Mac supervisor lives on `TerminalHost`.

For restart, stop verifies the supervisor identity and writes its hold before sending only SIGTERM to Claude. It keeps the window and scroll history. Restart atomically publishes (temp file, fsync, rename) `RelaunchRequest{argv, cwd, environment, unset, written_at, note}` to `STATE/relaunch/<supervisor pid>.json` (`STATE` is `$SHUTDOWN_STATE_DIR` or `~/.local/state/shutdown`) and returns `SessionLaunched()` without opening a window. On both machines the request's argv is `herdr session attach <name>` (the full `herdr_binary()` path on the Mac) in the recorded cwd, with empty `environment` and `unset`. The account lives in the agent pane instead: a move takes `accounts.prepared_account(target, resume=True)` variables and removals, a retained account its numbered directory, and a server whose environment holds `CLAUDE_CODE_OAUTH_TOKEN` is refused. After its child exits the supervisor reads the request, deletes it and the hold, prints the note as one line and execs itself with `run -- <argv>` in that cwd and environment, keeping its pid. A malformed request prints `could not restart here: <error>` and exits with the child's code. Registry confirmation still proves the resumed session. Stop-only uses the existing cleanup path. Only `ghostty` and `terminal` hosts are checked for a supervisor. A Zed host, or a gone or reused supervisor, gets a new window through `_herdr_window`: on Linux a `systemd-run --user` Ghostty window on the host's recorded named desktop, with the starting desktop restored after the pass; on the Mac `open -na "/Applications/Nix Apps/Ghostty.app" --args -e <herdr> session attach <name>`. A Mac restart outside the desktop whose window already started the server (`WindowServerCreated`) opens nothing more.

The hold file `STATE/relaunch/<pid>.hold` lasts `HOLD_SECONDS = 300` (`SHUTDOWN_RELAUNCH_HOLD_SECONDS` overrides). After Claude exits with no request yet, the window says `claude stopped for a restart; waiting for it here` once and checks every 0.5 s. On expiry it removes the hold, says `no restart came; this window is free`, and returns the child's exit code. A window without a live supervisor gets the new window above.

### Remote Control after relaunch

`remote_control(record: SessionRecord) -> Literal["active", "absent"]` reads `sessions_dir() / "<pid>.json"`. A non-empty `bridgeSessionId` is active; missing, empty or unreadable is absent. `SessionRecord` does not carry the field. Its null case was read from the 2.1.296 binary, not observed on a session. `add_unit.wait_for_remote_control` is a different function: it polls pane text, for new-work launches only.

`wait_for_remote_control(records, timeout)` uses the registry records just confirmed live, with `REMOTE_CONTROL_WAIT_SECONDS = 10.0` and `SESSION_POLL_SECONDS = 0.5`. It polls only those small files, never scans `sessions.live_sessions()` again, returns at once when all are active, and starts no poll after the deadline. A slow read can overrun by one poll's reads; there is no thread or timeout around each read. One shared wait per relaunch pass costs usually 1 to 3 s after registry confirmation, at most 10 s plus one poll's reads when one stays absent. The conductor runs the wait in its polling pool while other owners keep moving.

Each confirmed local session still absent starts one detached `remote_control.launch_fixer`. Repair is quiet: it sends no message or phone push and adds no requester or showrunner diagnostic. Its record finishes as restarted and its exit status stays successful. A fixer launch failure is recorded once in the local system log. The peer starts its own local fixers.

The helper starts `shutdown-remote-control-<session id prefix>-<pid>` using the restarted session's pid with `systemd-run --user --collect --quiet --no-block` on Linux, or on the Mac through `detached.start_detached` (caller's environment, a log under `shutdown_state_root()/logs`, ready on its `Remote Control fixer started` line within 15 s). Python gets `-u` and `PYTHONUNBUFFERED=1`. The internal verb takes a session id, registry pid and process start, a journal identity (`--who`) and session name (`--session`). `remote_control_who` gives `<unit without -unit> unit`, `<production> showrunner`, or the session name. The fixer has no alert option.

After each of at most `ATTEMPTS = 3` typed commands, the fixer waits `ATTEMPT_WAIT = 30` seconds for the registry bridge id or the pane's `/remote-control is active` marker (`TurnedOn`). Busy, blocked or unreadable sessions keep waiting up to `DEADLINE = 15` minutes from fixer start. A gone or replaced process ends as `SessionGone` with no input or push. Before returning any failure, a fresh observation checks for an exit, replacement or activation. A `Failed(reason)` exits 1 in the detached service without notifying anyone. Every outcome prints one journal line naming the unit, showrunner or session. Tests use a fake monotonic clock, registry and pane; no test starts this service or types into a real pane.

Internal `up <login> --here --json` returns a validated object containing `machine`, `label`, `outcome`, `lines`, `no_remote_control` and `refused`. New replies always emit `no_remote_control: []` for older readers; the new parser ignores that key, including old entries with `alerts`, and accepts its absence. `RestartRefusal` is a union: `not stopped` carries id, name and progress; `no shutdown` carries id and name. Local and peer refusals travel as this data; `up` exits 1 when the outcome is `partial` or any session was refused, and no exit status names a refusal. A peer exit other than 0 or 1, or an answer that does not validate (`parse_peer_result`), reads as not reached, without interpreting Remote Control state. `settle.unrecorded_local_sessions` supplies local selected sessions without a record to cancel, now and restore. `PeerRestartResult` validates the wire object; its `outcome` is `done`, `partial` or `nothing`.

### Messages and notifications

Shutdown messages use sender `shutdown`, which the conversation-pause hook treats as scheduled work. Settle, cancellation and restart notes use key `shutdown-<login>-<session id>`; the final requester result uses `shutdown-result-<login>`. Queued messages are read with `send.py pending` after resume. A unit's production showrunner (`showrunners.current_name(production_slug(doc))`, skipped when none runs) gets one line before the unit is stopped, `<unit> is stopping: <why>; it comes back on <target> within minutes` (or `it stays stopped until the user restarts it` for `then: stop`), and one more from the conductor's report or `restart`: `<unit> is back on <target>`, or `<unit> did not come back: <reason>`, again once per new failure. A batch reports when its last session ends, so the second line is skipped when a later request holds the session by then (`record.taken_over`: a live record or history entry on any account with a later request time, such as a stop and forget). `showrunner_told` records the last line sent; both use key `shutdown-unit-<session id>`. `settle.alert_user(RenderedPush, *, machine="")` is the phone path; the catalog render provides the title, body and ActionRequired. The conductor's alerts pass `machine="natedev"` from the Mac; `restart`'s own alert passes no machine. The not-answering text also goes to the requester under key `shutdown-holdout-<login>`. A hold or session record never refuses the UPS alert.

`NOT_ANSWERING_AFTER = 2 * REASK_AFTER` is four minutes from the sent pause, or the request if no pause was sent. An unanswered waiting owner (a busy one, since an idle owner is stopped without a pause) gets one catalog push and requester message, even on Ghostty with no readable pane. `settle.HoldoutKind.from_reason` picks the entry: `shutdown.holdout` when the owner is showing a form (its action is to answer the form), `shutdown.holdout_unanswered` for any other hold (its action is to stop the session). Both have a `Session: <session>` line above the Action line and the scoped `now <label> --here --only <id>` command with its machine. The form push has the title `<session> restart is blocked` (or `shutdown`) and a `Reason:` line. The unanswered push has the title `Your Claude restart is stuck` (or `shutdown`) and says that stopping keeps the session's uncommitted work. The command names the account label (`note_file.canonical_label`), never the email login. No raw hold-detail list reaches the push; the requester message keeps it. The requester message (`Restart stuck waiting on <name> session`, or `Shutdown`) carries `holdout_line(saved)`: the minutes, the host from `_holdout_host` (unit, `Ghostty window, <name> desktop`, Zed window, or `legacy host <name>` for a legacy record), that the pause asks for a safe point and a ready reply, both choices, and the command with `in a terminal on <machine>`; a terminal requester gets the line printed. Both say that now ends Claude mid-step while keeping uncommitted work, and doing nothing leaves the request waiting. `after_stop` distinguishes a restart request, which brings it back, from a stop-only request. `alerted_at` reserves delivery once; reaping owners never get this push. Saved `alerts: "none"` suppresses it. Notification workers keep delivery off the conductor's stepping thread. The catalog approval is kept in `scripts/notify/push_texts_reviewed.json` (`docs/as-built/message-clarity.md`).

A failed move (a record with `target`), unless its folder is one no account trusts (below), pushes `shutdown.move_failed` (`restart.move_failed_push`) from both the conductor's report and `shutdown.py restart`: it names the session, the source account and the target, and asks natedev to finish the move from the record, which starts the session on the target. If both the target and source launches fail, it sends that same alert once, even when the move suppressed alerts. A successful source fallback sends no phone push. Before a herdr restart refuses a destination that holds a live agent, `_holds_live_agent` reads `herdr agent list` again every `SESSION_POLL_SECONDS` for up to `AGENT_EXIT_SECONDS` (15 s): herdr lists a stopped agent as live for a few seconds after its process ends, and a move's restart runs about 2 s after its stop. A not-back push is sent once per new restore failure; `restore_alerted` stores the last `settle.not_back_text(saved)` pushed (`<request id> restart failed: <reason>`, `<request id> manual restart: <command>` or `<request id> timers pending: <instances>`). Every per-session outage push (the conductor's report, `shutdown.py restart`, the restart fallback and the unit watchdog) first claims that session in the outage ledger `scripts/accounts/outage_alerts.py` (`~/.local/state/accounts/unit_outage_alerts.json`), which survives the record's archive. A sender claims the sessions of one push just before it sends, names only the sessions it holds, records delivery only after a sent push and releases the claim otherwise. A claim whose owner process is gone, or that is older than 15 minutes, is taken over with a new token. `outage_alerts.clear(session_id, observed_at)` removes only entries claimed before the live observation, using `time.time()` for both clocks. Delivery retains the claim time. Every clear carries its probe time, including `_up`’s cached registry read, shared confirmations and watchdog production probes; when a newer entry survives, its record mark survives too. `_record_timer_restore_progress`, batch archiving in `_confirm_entries`, and the conductor’s `_archive_finished` do not clear them later, since a new outage may already have claimed or delivered its alert while another session was slow to confirm. So each outage sends at most one delivered alert. An unchanged failure is not pushed again, by the conductor's report or by `shutdown.py restart`: restart skips a local failed or manual-restart session whose `restore_alerted` matches its current text and marks each one it pushes (`mark_not_back_pushed`).

A retry push names its cause. `restart.restart_push(label, failures, *, machine)` takes `FailedSessionRestart` items, groups them by `restart_cause(reason)` (the reason's first line, cut to `RESTART_CAUSE_LIMIT` = 100 characters with `…`) and sends one `shutdown.restart_failed` per cause, its `{cause}` shown as `The restart gave this error: …`; each cause's sessions still split to fit the phone limits. A `restart failed` record with `trust_command` (no account on its machine trusts the folder) never gets that retry push, which would fail the same way: it gets `shutdown.restart_untrusted` (`restart.untrusted_push`), one per session, and a failed move with `trust_command` gets `shutdown.move_untrusted` (`restart.move_untrusted_push`) in place of `shutdown.move_failed`; its Action adds `That finishes the move to {target}.` Its account is the record's own label, the move's source: the record lives under that login, and its restart resumes the move on the target, whose trust the command accepts. The push goes out with the session, machine, account and the trust command, whose Action is to run the command in a terminal on that machine, trust the folder, type `/exit`, then run `/shutdown restart`. Only the session name is ever shortened to fit; the command stays whole. The restart result line for such a session is `<machine>: <name> needs folder trust: <command>` instead of `restart failed: <reason>`, and that line does not by itself call for a retry push. The machine that owns a session sends its pushes: the peer's `up --here --json` run sends them from its own ledger (unless `--no-alert`), and `shutdown.py restart` only prints the peer's lines. Both pushes are marked through `mark_not_back_pushed` like the others.

Every progress transition appends `ProgressStep{at, kind, detail}` under `update_session`; the timestamp is the write time, so rollback progress retains its original time without reversing the trail clock. Creation includes its initial progress. Old records read with an empty trail. Archive preserves the trail, and status renders each step in the user's zone.

Every user-facing line that names a command also names where to run it: `in this terminal`, `in a terminal on <machine>` or `in any Claude session on <machine>`, with a full command from `settle.shutdown_command(*arguments)` (`~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py <shlex-joined args>`) scoped by login, `--here` and `--only <session ids>`. This covers the cold-key line of a full shutdown (`github-warm-status; github-warmup`, then the `down` retry keeping `--here` or `--also`, `--only`, `--restart` and `--no-alert`), every peer-not-reached retry, `report_stop`, the showrunner outcome lines, `cancel`'s not-cancelled line, a manual restart's progress, the status actions, the pause message, the usage and epilog, and restart's owner-cleanup retry. `settle.located_detail(record, detail)` prefixes `in a terminal on <machine>: ` to a stored detail that holds a command but no place phrase; `status` and `follow` print trail steps through it.

`shutdown.py follow <account> --request <request id>` (`shutdown.follow(login, request_id) -> int`) follows one request. In a terminal on the record's machine, run `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py follow <account> --request <request-id>`. Follow reads local active records and checks history every second, never inventory; immutable history files are read once per follow, including unrelated requests. Active reads precede history reads to cover an archive between them. It prints `<HH:MM:SS> <name>: <kind> <detail>` once per trail step. A nonfinal archived record means the session was taken out: follow prints that once at observation time and counts it done. It waits through stopped/already gone when restart is pending, reads outcomes archived before it starts or between polls, and prints all stopped or all back on the target account; summaries with cancellations count each outcome. A session in `process identity lost`, `stop failed`, `restart failed`, `manual restart` or `timers pending`, a `waiting` one with `alerted_at`, or a stopped one with `stop_issues` prints `_follow_action(saved)` (its state and the scoped command with its place; for a waiting one, `holdout_line`) and exits 1; completion exits 0; a request with no records exits 1. Ctrl-C exits 130 and prints a reconnect command while the conductor continues. `settle.down` snapshots the selected records by request id before launching the conductor, because the conductor archives a finished record at once. With no session requester (`requested_by` empty and `CLAUDE_CODE_SESSION_ID` unset) and a tty on stdout, it runs follow for each local request and returns its code; a terminal opened from inside a Claude session carries `CLAUDE_CODE_SESSION_ID` and so gets the closing lines instead. A terminal request covering several accounts suppresses automatic follow while starting each account and prints each follow command. Otherwise it prints, per request, `shutdown of <label> started for <n> sessions. To follow it, in a terminal on <machine>: <follow command>. To stop the ones not yet stopped, in a terminal on <machine>: <cancel --here --only <ids>>.`; a request with a `target` says `stop the move of the ones not yet stopped`, never promising to undo a move. No local selection prints `shutdown of <label>: no local sessions selected`. Follow summaries are `all N back on <target>`, `all N stopped` and `all N done: K back on <target>, J stopped, M taken out`. Each machine follows only its own records; a peer's sessions in the same request are not followed.

`_launch_conductor` runs `env PYTHONUNBUFFERED=1 <python> -u shutdown.py conduct <login>`, so journal lines appear as written. Stop identity re-reads (`stop._fresh_inventory`) pass `refresh_desktops=False`, like the conductor tick. `resolve_sessions` returns `ResolvedSessions(session_ids, report)`: exact names come from `inventory.listing(login)` and the records, then one `inventory(login, only=…)` builds the report, which `down` passes to `settle.down` and `begin` (`report: Inventory | InventoryNeeded`); `begin` inventories only when called without one. Without `--only`, `down` inventories once and passes it the same way.

`report_stop` sends the requester this machine's results plus one peer-record read. Account-wide partial stops alert when their saved policy allows it. Restart uses `<label> is not fully back` for incomplete restoration. Remote Control recovery is quiet and never appears in these results. Retry guidance remains only when something is still left to bring back. Lines always print; `alerts: "none"` and command `--no-alert` suppress the phone send, including after archive.

For incomplete restores, restart checks policy on both machines. With `--only`, only selected records count; with `--here`, it reads no peer. When the peer is unavailable, including an answer without the result object, account-wide policy uses every local record: no record or any record with `alerts: "user"` enables the alert. Selected policy stays restricted to chosen records; no second peer call is made. Refusals alone never alert.

### Launch checks and held sessions

`launch-blocked [account] [--restart-of SESSION_ID]` exits 0 for a hold, 1 when launch is allowed (silent unless it released a finished hold), 2 for an unresolved account, and 3 for unreadable state. A hold in use prints `<label> is held by a shutdown (since <time>), <requester>`, where the requester is `requested by session <first 8 of its id>`, `requested in a terminal` or `requested by a recovery snapshot`. A finished hold is removed, and the check exits 1 with one `released account hold: <hold JSON>` line (`launch_permission.RELEASED_HOLD_PREFIX`); `launch_permission` returns it as `AllowedByShutdownState(released=ReleasedHold(label, then, requested_at, session_id))`. Shell callers that go on only on exit 1 are unchanged; a selected shutdown never blocks unrelated new work. A restore's own record overrides the account hold: stopped, already gone, lost identity, restarting, restart failed and manual restart permit it. Every other recorded progress prints `<session name> is held by a shutdown (since <time>)`. Relaunch claims first, so a timers-pending retry is permitted while restarting.

`RecordedSessionRestoreLaunchPurpose(session_id)` names a restore of any session a shutdown record holds. Without a matching record, the account hold alone decides, as for `NewWorkLaunchPurpose`: an open account permits launch and a held account blocks it. The purpose alone never proves restore authorization. `launch_permission` returns `AllowedByShutdownState`, `BlockedByShutdown(reason)` or `ShutdownStateUnreadable(detail)`; only a silent exit 1 permits launch. `launch_barrier()` holds `<root>/launch.lock` from check through spawn, and record creation and account-hold creation share it. Only the short decision and spawn are protected, never the launched work. Account locks serialize store mutations; a conductor holds its separate lifetime lock.

`add_unit.py --attach` safely hands a live conversation to a unit using `down --here --only` and its bounded follower, then completes the stopped record with `clear_running_on_target` after the marked resume launch.

The scheduled nightly review keeps firing but skips held accounts or unreadable state. `add_unit.py` applies the check to its chosen account, including a restore's id. Manual unit resume checks `--restart-of` and continues only on silent exit 1. `held-sessions` lists every owner's and worker's id; worker cleanup treats those active runs as live so workers survive. No caller can infer launch permission from an exception or a crash exit 1 with output.

### Remote calls

`run_remote` uses SSH and the trailing `rc=<n>` from the command; SSH's status alone is never a successful answer. A missing trailer, SSH 255 or timeout is not reached. Standard calls have a 120 s limit; restart's peer restore uses link keepalives with no overall timeout (`ServerAliveInterval=15`, `ServerAliveCountMax=4`). Each machine makes progress independently; there is no cross-machine stop claim.

## Invariants and costs

- Account isolation: an unreadable environment or no account setting after cutover means unattributed. Before a machine cuts over, no account setting still attributes its legacy home login. Stored process identity is never replaced with an observed pid.

- Claude processes receive only `SIGTERM`, with readiness unless explicitly forced. The only pane input is the detached fixer's `/remote-control` in the restarted session's own pane while its registry shows idle. An unsupervised Ghostty window shell, or a stop-only supervised window, is closed with `SIGHUP` after the ownership check; supervised restarts retain the window; owner identity is checked before signals or resource cleanup.

- Registry process identity and socket prove relaunch liveness; Remote Control is a separate field check and never changes the restart outcome.

- Only `AllowedByShutdownState` permits a launch; the barrier spans check to spawn. The UPS alert is unaffected by holds. Neither implementation nor tests read notification credentials.

- A shutdown stop never ends a Codex worker; run end (`end_session.sh`, plain `codex_mesh.py stop`) still ends every worker. A paused worker is resumed on its recorded thread, never replaced by a new worker. A held design role (`docs/as-built/guilds.md`) is not a worker: its mesh lives in the role store outside run directories, so neither a shutdown nor run end pauses or ends it, and `stop`, `stop --pause` and `reopen` refuse a held entry.

- Test cases derive from `ShutdownTestCase` and use temporary state and fake send, notifier, process, herdr and host commands. Tests start no real session and send no real alert.

- Record timestamps use UTC ISO 8601 at whole seconds; injected stop clocks produce the same format. User-facing times use the user's zone (`config/user_zone.conf`, read through `scripts/lib/user_zone.py`).

Costs: conductor pass 15 s; settle-message retry 300 s; a move's forced stop 2 min after its pause; the last-step read up to 256 KB of one transcript, only for a busy move; not-answering alert once after 4 min; two stop waits of 10 s; shared registry wait up to 90 s; Remote Control wait 10 s plus one poll's reads; windows 1.2 s apart; sender timeout 60 s; launch checks and held-session queries 30 s. On macOS each `running_session` with a recorded `procStart` uses one `ps -o lstart=` per registry record per call, with a 5 s timeout; Linux reads `/proc/<pid>/stat`. The Remote Control wait avoids that process scan.

## Session hosting and manual recovery

Herdr is the session host. Unit records retain `session_host: "herdr"`;
standalone records carry the server and pane. A process inside a user-managed
terminal multiplexer is an unknown host even if it inherits herdr variables.
Shutdown never observes or mutates that multiplexer.

A Mac `terminal` host restarts into a new herdr session, attached in the same
window through its supervisor, else in a new Ghostty window. An
unavailable desktop refuses with an unlock-and-restart instruction. A session
with no conversation starts fresh under its recorded id and prints a plain
explanation. `forget` retires stopped and failed shutdown-record entries as
well as recovery snapshot entries.

Old host records normalize to explicit manual-recovery states. Their names
never become herdr destinations. Unconfirmed cleanup stays in the record;
status, now and restart print the cleanup and resume commands. An old Codex
snapshot prints its recorded `CODEX_HOME` and `codex resume <id>` (or its
picker), remains unacknowledged and makes restart partial with exit 1.

The Remote Control fixer resolves the newly registered pid's herdr pane and
checks identity and idle state before input. Tests use disposable state and
fake host commands.
