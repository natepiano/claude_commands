# Shutdown and restart

Refusal-watcher inventories read cached desktop metadata. Their selected shutdown carries `REFUSAL_WATCH_INVENTORY=read existing` into the conductor's command, since the service manager does not inherit the caller's environment. This prevents inventory from invoking the snapshot updater, which itself runs the notes timer.

Claude quota refusals are detected from the transcript or from a session-specific file in `~/.local/state/accounts/assumed_refusals/`. `refusal_watch.transcript_refusal(session_id, *, config_dir=None) -> TranscriptRefusal | NoSessionRefusal` reads `<config_dir>/projects/*/<id>.jsonl` (default `~/.claude`; pass the session's own `config_dir` for another account). `_newest_exchange` reads backward in 64 KiB blocks and skips every line whose `type` is not `user` or `assistant`, so bookkeeping lines written after a refusal do not hide it; the newest exchange is a refusal when it is an assistant entry with `isApiErrorMessage: true` and `error: "rate_limit"`. Window and reset come from `quotaLimits` (`rateLimitType`, `resetsAt`) when present, else from the text. This applies to Ghostty, zed and terminal owners as well as tmux and units.

`settle.prompt_state(PromptSubject(session_id, login, config_dir), now) -> SessionPromptState` (`TakesPrompts | StoppedTakingPrompts`, each with `because`) decides each owner's path, first match wins: a newest transcript refusal → `StoppedTakingPrompts("refused in its transcript")`; a fresh reading (weekly part at most 10 minutes old) with a window at 0 → `StoppedTakingPrompts("account out of usage")`; a fresh reading with both windows → `TakesPrompts("room")`; otherwise `TakesPrompts("no fresh reading")`. A stopped state's `detail` reads like `weekly limit, resets Thu 9:00 AM` in the user's zone. `TakesPrompts("credits")` exists in the type but no session produces it, since Codex workers carry no attributed login. StoppedTakingPrompts starts reaping without a pause or readiness wait; process identity checks still apply. A refusal newer than the pause message's send time also reaps on every host, with no re-ask. The tmux screen detector remains a second detector. Status keeps the move's target and reason on the progress line.

The argument-free notes timer runs the refusal watcher every two minutes. Sessions on one refusing account share a selected `down --here --only ... --restart --to ... --why ...`; each record's request id joins its journal request and outcome. Restart checks the resumed process's config directory before confirming the move. A source-account process, failed launch or manual restart is a failed move; a proven target process with pending timers is confirmed while those timers remain visible. Cancellation records `failed: cancelled`, removes an assumed refusal and suppresses the unchanged transcript error. Refusal replies with model `<synthetic>` do not replace the last real model used for resume.

Stopping a director uses `codex_mesh.py stop --pause` for each owned run directory. It drops pending messages, interrupts live turns and retains every non-ended seat as followable `paused`, with `paused_from` and `paused_turn`. Launcher completion cannot overwrite the pause. Run-end plain `stop` still ends every seat; sweep preserves paused seats.

Before shutdown signals, `SessionShutdown.codex_seats` records each non-ended seat's run directory, name, role, thread, whether it was working and the nearest live `implement.sh` or `review.sh` ancestor's argv (empty when unreadable). Older records have no `codex_seats`, and readers treat that as none. Working seats get `<run_dir>/<seat>.resume-prompt.md` asking them to continue their earlier task. Cleanup retries retain the original argv.

After any session with recorded seats is confirmed back (a unit director, or a standalone run), restart sends one `shutdown` message through `send.py`, keyed `resume-workers-<session id>`, instructing it to resume its workers before opening seats. Each line names the seat, role, prior activity, resume command and working directory. A working seat's launcher argv retains its task arguments, replaces the prompt file and selects `--to`; idle seats or unreadable launchers get the appropriate launcher form with usual arguments supplied by the director. The message remains available through `send.py pending`; delivery failure logs one line and does not fail restart. Account-move opening prompts point to this message. Follow continues the seat's recorded thread and clears pause metadata.

## What it is

`agents <verb>` runs `down`, `restart`, `status`, `cancel`, `now`, `follow`, `snapshot` and `forget` from a terminal; `/shutdown` is the in-Claude form. Down, restart and status accept an account. Without one, `CLAUDE_CODE_SESSION_ID` selects this session's account; outside Claude, down covers configured Claude accounts, status also lists unresolved recovery entries, and restart covers accounts with shutdown records, holds or recovery snapshots, including hand-run Codex sessions. A named Claude account restores only its Claude sessions. `--only` and `--here` apply to both forms. `/shutdown` stops one account's Claude sessions on natedev and the Mac through one record per top-level session. Each owner settles, stops and optionally returns independently; a busy session or a permission form delays only that owner. Workers, Codex app-servers, timers and host resources belong to their owner. `/shutdown restart` restores stopped or crashed sessions, their notes and timers. Other accounts, CI runners and system services keep running.

An account-wide request holds the account against new launches and scheduled work. A selected request holds only its sessions. Each machine conducts its own records; an unavailable peer leaves local work running. `commands/shutdown.md` defines the user command.

### Accounts

Both move entry points run `check_move_target(target, now) -> MoveTargetReady | MoveRefused` before any write and read members from `inventory.listing()`, never a full inventory. `accounts.move(session: str, target: str, *, dry_run=False, why="") -> MoveStarted | MoveStartFailed | MoveDryRun | MoveRefused` resolves one local live id, else exact current name. It refuses a missing or ambiguous session, a worker, a grouped session (naming `accounts.py move <group> <target>`), a session already on the target and any open record for that owner. `accounts.move_group(group, target, *, dry_run=False, why="") -> GroupMoveStarted | GroupMoveStartFailed | GroupMoveDryRun | MoveRefused` takes `units` or `showrunners`: it reads one `inventory.showrunner_registrations()` snapshot shared by the member listing and `unregistered_showrunners`, sets the group's account with `set_group_account`, then moves every off-target member. A dry run returns before any write, with one `move_preview_line(member, now)` per member built from `prompt_state`.

`move_sessions(ids, target, *, why)` groups the selected ids by source login and runs one `shutdown.py down <source label> --here --only <ids> --restart --to <target> --why <why>` per login with `REFUSAL_WATCH_INVENTORY=read existing`. Each `SessionMoveRequested` carries the request id and the required keyword `source_login`, the login that `down` ran under; `_move_output` follows each `(source_login, request_id)` through `shutdown.follow` when stdout is a tty and `CLAUDE_CODE_SESSION_ID` is unset, and otherwise prints the follow and cancel commands that `down` printed. `docs/accounts.md` (Move a session) holds the user-facing lines.

`SessionShutdown.target: NotRequired[str]` names `claudeN`; a legacy stored `default` or `~/.claude` target resolves from dated cutover evidence only, else stays unresolved. The record’s login identifies the source account, so it cannot identify the destination. Absence means retain `session.config_dir`. New targeted records also store `source_label` and `why` (default `<old label> is out of usage`); repeated requests keep every existing field. `settle.down` forwards `--to` and `--why` to the peer. `restart.account_move_note` supplies one stable account-move explanation for every host, including the showrunner production resume prompt and the unit's continued `/unit:direct` run. An unknown host ends at `manual restart` with that resume command, which `status` and `follow` print with its place. Supervised Ghostty windows restart in place; legacy windows use the recorded desktop fallback described below.

Targeted non-unit launches on a shell host wrap the usual resume argv in `accounts.py exec <target>`, dropping inherited OAuth tokens and checking readiness again. A herdr launch (a herdr host, or a tmux showrunner) uses `accounts.prepared_account(target, resume=True)` instead, applies its variables to the pane environment and drops its removed variable names. Units pass the configured units account as `--account <claudeN>`, plus their recorded `--model`, to `add_unit.py`; new and resumed units use that same group account, and any explicit account or config directory must match it. New unit launches use herdr and write no tmux options. A manual unit resume takes its model from an explicit `--model`, then a shutdown record, then the live unit's tmux `@claude_model` option or, for herdr, the transcript's last assistant model (`add_unit.transcript_model`); without one it uses the director model. `MoveStartFailed` and `GroupMoveStartFailed` retain the shutdown exit and output when it exits nonzero; the CLI propagates that failure. `swap unit` and `set-role unit` refuse and name `accounts.py move units <claudeN>`.

- A process's account is the login in its Claude config dir: `CLAUDE_CONFIG_DIR` from that process's environment, or the legacy `~/.claude` login only until this machine cuts over. After cutover an absent setting means no account. The legacy home reads `~/.claude.json`; numbered folders read `<dir>/.claude.json`. The login is `oauthAccount.emailAddress`. The **label** is read from the name of the hanadocs note in `AGENT_NOTES_DIR` (default `~/rust/hanadocs/agents/`) whose parsed tool matches and whose `login:` matches case-folded (`claude2.md` → `claude2`); else the login.
- `process_config_dir(pid) -> ConfiguredClaudeFolder | NoAccountSetting | ProcessEnvironmentUnread` reads `/proc/<pid>/environ` on Linux and `ps eww -o uid=,command= -p <pid>` on darwin (`parse_darwin_config_dir(output, expected_uid)`: `ProcessEnvironmentUnread` unless the uid matches and a `HOME=` token is present; the last `CLAUDE_CONFIG_DIR=` token wins). An absent or empty setting is `NoAccountSetting`; a readable selected path is `ConfiguredClaudeFolder(path)`. `process_account_directory` maps an absent setting to the legacy home only while its login exists. An unreadable environment remains `ProcessEnvironmentUnread`. `account_of(pid) -> Account | None`.
- `own_claude_account()` raises `UnreadableAccount`; `named_claude_account(text)` takes a `claude*` note stem with a non-empty `login:`, else text holding `@` with no `/`, NUL or whitespace and no leading `.` as a login, else raises `UnknownAccountName`. A named account uses that resolver; most absent-account verbs use the own account. `restart.select_account` also infers from eligible session records and account holds on both machines when the own account is unreadable: one candidate wins, otherwise candidates are listed and restart exits 1. An unknown named account prints `shutdown: <message>` and exits 2. An unreachable or older peer cannot prove that candidate set complete, so restart asks for an account.
- A `SessionStart` hook runs `account.py --write-label`, which writes `<config dir>/account-label` (label plus newline) atomically and only on change, or deletes it when the account is unreadable. The label file is a cache; process configuration remains the authority for account attribution.
- **Status line.** `statusLine.command` is `statusline="$HOME/.claude/scripts/statusline"; . "$statusline/statusline.sh"`: sourced, not run, since a second shell measured 1.3 ms of a 4.3 ms render. `statusline.sh` reads `account-label` with the `read` builtin, names `~/.local/state/agent-notes/by-label.json` (or `/dev/null` when it is not readable, a `[` builtin test), collects the session ids in the first line (`TARGET=session:<id>`, which `write_conf` always writes first) of each `${NOTIFIER_STATE_DIR:-~/.local/state/notifier}/showrunner-*/conf`, and execs `jq -r --arg pwd … --arg account … --arg showrunners … --slurpfile labels … -f statusline.jq` (one process; the role lookup adds about 0.3 ms with five timers). Row 1 is `<role> | <account> | <dirname> | <tokens> | <model [effort]>`, and an empty account, or one holding `@`, drops its field. The role, first match wins: `showrunner` when the input's `session_id` is a timer's target, `worker` when `PLAN_DELEGATE_TEAM_ROLE` is non-empty (agent_bg.sh passes it through `--settings` env, which reaches the status line command; it outranks the unit mark because a background session inherits the daemon's environment, and a daemon a unit started carries `SHOWRUNNER_UNIT`), `unit director` when `SHOWRUNNER_UNIT` is non-empty, else `unassigned`. Row 2, when any part exists, joins `5-hour <N>% left` and `weekly <M>% left` with ` | `. Each window is the one agent_notes stored for the session's label, the number the quota alerts use, while that reading is at most 600 s old and its `resets_at` is absent or ahead; otherwise `rate_limits.five_hour` / `seven_day`, so the row never goes blank for want of a reading. `remaining($window)` floors `100 - used` and clamps to 0–100, and a missing window or non-number drops its part. With no part, no second row.
- **Readings by label.** Each agent_notes run, after saving `usage.json`, rewrites `by-label.json` from the whole store: for every Claude note, its stem (the label `account-label` holds) maps to that login's `five_hour` and `weekly` as `{left, resets_at, at}` in epoch seconds, `resets_at` null when no window is open. A refused read keeps the last good reading, whose `at` the status line judges. A label holding `@` is left out, so the file carries no login.

### Inventory

`inventory(login: str, only: frozenset[str] = frozenset(), *, refresh_desktops: bool = True) -> Inventory` keeps the live records in `~/.claude/sessions/` (`NOTIFIER_SESSIONS_DIR`) whose process config directory supplies a login matching case-insensitively. An unreadable account or a `procStart` unequal to the live process start (pid reuse) goes to `unattributed` (`UnattributedSession{pid, name, reason}`, reason `account unreadable` | `process start mismatch`), never to `sessions`. A non-empty `only` keeps those ids plus the workers they own, so `down --only <director>` includes that director's workers; full records (model, transcript, host) are built only for the selection. A caller wanting one session passes `only`: filtering after a full inventory still reads every transcript. `refresh_desktops=False` skips only the desktop snapshot; every other field, the supervisor included, is still filled.

`listing(login: str | None = None, *, registrations=...) -> list[ListedSession]` is the cheap per-session read for selection: frozen `ListedSession{session_id, pid, proc_start, name, kind, config_dir: Path, login, production, doc}`, with no git, transcript, timer or host reads, built per call and never persisted. `showrunner_registrations() -> ShowrunnerRegistrations` (`entries` of `ShowrunnerRegistration{session_id, slug, doc}`) reads the showrunner update timers in-process without resolving messaging sockets; `listing` and `unregistered_showrunners` accept one shared snapshot. `transcript_path(config_dir, session_id) -> Path | None` globs one level, `config_dir/projects/*/<id>.jsonl`, newest by mtime; `last_model(path)` reads backward in 64 KiB blocks and stops at the newest real model line. `_model` reports `no reply yet` for a transcript under another account's projects dir, which never happens while every config dir's `projects` is the same tree by link. On natedev a 40-session listing takes 0.25 s and a one-session inventory 0.38 s.

- **Kind:** `showrunner` when its id is the `TARGET` of a `showrunner-<slug>` notifier instance whose checked production doc reads (`showrunner_registrations()`); `unit` from the `SHOWRUNNER_UNIT` / `SHOWRUNNER_UNIT_ID` marks on its tmux or herdr pane, read once for every production (`unit_lookup.every_marked_unit`, which files a mark from before a production rename under the current slug) and kept only for a production with a showrunner timer, whose doc a restart needs; `worker` when the record's `kind` is `bg`, owned through any `active/<director id>` run folder's `workers` ledger (`WorkerOwner` = `director{session_id}` | `no director`); else `top-level`.
- **Host** (`Host`): `UnitHost{production, unit, doc, session_name, session_host: tmux | herdr, plan: plan{path} | no run record}` (plan from the newest run record whose `main_agent.session_id` matches); `TmuxHost{tmux_session, session_ref: TmuxSessionId{session_id} | TmuxSessionIdNotRecorded, server: TmuxServer{pid, started_at} | TmuxServerNotRecorded, pane: TmuxPane{pane_id, pane_pid} | PaneNotRecorded}` from `TMUX_PANE` without marks; `HerdrHost{herdr_session, pane_id}` from the pane environment and its ancestor herdr server; `WindowHost{kind: ghostty | zed, window_shell, desktop: named{name} | not in snapshot}` from a parent walk starting at the session's pid (natedev desktops from `~/rust/hanadocs/agent sessions.md`, the `agent-sessions-snapshot` output); `TerminalHost` (Mac Ghostty or Terminal); `UnknownHost`. `window_shell` is the ancestor directly beneath the terminal process. One tmux display reads the current session name, its `$N` id, the pane pid, the server pid (`#{pid}`) and the server start time (`#{start_time}`, epoch seconds). A missing session id or missing/non-integer server pid or start time is `not recorded`; older hosts without `session_ref`, `server` or the server pid parse the same way.
- **Checkout:** `git{path, head: branch{name} | detached{commit}, upstream: tracking{ahead} | no upstream, dirty}` | `not a checkout`. **Model:** `model{name}` | `no reply yet`.
- **Account directory:** each attributed session carries `config_dir`, the path from `ConfiguredClaudeFolder` at the process boundary. One boundary reads the process directory once and resolves its account from that directory, returning `AttributedSessionConfiguration{account, config_dir}` or `UnreadableSessionConfiguration`. `process_config_dir(pid)` distinguishes `ConfiguredClaudeFolder`, `NoAccountSetting` and `ProcessEnvironmentUnread`. An absent setting retains the legacy home login only while it exists; after cutover it is unattributed, as is an unreadable environment or account. Registries and transcripts stay under the shared `~/.claude/sessions` and `~/.claude/projects` paths.
- **Servers and timers:** run markers are `<root>/active/<session id>` for each run root: `SHUTDOWN_DELEGATE_ROOT` when set, else `/tmp/claude/unit` and `/tmp/claude/delegate` (a run started before the folder rename); a live `mesh_server.json` pid is a `CodexServer{run_dir, pid, busy_workers}`, a `mesh_roster.json` worker in `running`/`starting` is busy only with no `launcher_pid` or a live launcher; timers are `NOTIFIER_STATE_DIR/*/conf` with `TARGET=session:<id>`.
- `parse_inventory` / `parse_session` check every `kind` and field and raise `InvalidInventory` naming the field path (`inventory.sessions[0].host.kind is invalid`). The peer's inventory is always decoded through them.

### The record store

`SHUTDOWN_STATE_DIR` defaults to `~/.local/state/shutdown`. Each case-folded login directory contains `sessions/<sanitized session id>.json`, optional `hold.json`, `history/`, `lock`, and `conduct.lock`. Characters outside `[A-Za-z0-9_.-]` become `-` in session filenames. Filename collisions are refused, never resolved by overwriting another id. An archived record moves to `history/<requested_at>-<session file name>`; an existing target raises `InvalidRecord`.

`SessionShutdown` carries `login`, `label`, `machine`, `requested_at`, `request_id`, `requested_by` (session id, terminal or recovery snapshot), `hold` (`account` or `session`), `then` (`stop` or `restart`), `force` (`wait for ready` or `now`), `alerts` (`user` or `none`), `probe` (missing reads `false`), the owner's `session`, its workers in the `workers` field, timer snapshots, `settle_message`, `where`, `progress`, `trail`, `stop_issues`, and optional `alerted_at`. A worker never gets its own record. `AccountHold` carries the request's login, label, machine, time, id, origin and continuation. Request grouping uses `request_id`; second-resolution timestamps never establish request ownership.

Public store operations are `session_records`, `all_session_records`, `create_session`, `update_session`, `archive_session`, `set_account_hold`, `clear_account_hold`, and `clear_finished_account_hold`. `lookup_session` returns `ShutdownFound(record)` or `NoShutdown`; `lookup_account_hold` returns `AccountHeld(hold)` or `AccountOpen`. Updates run under the account lock, revalidate and write with a temp file, `fsync` and `os.replace`. Invalid paths, symlinks, invalid fields and mismatched account or session ids raise `InvalidRecord`. Absence is distinct from unreadable state.

`clear_finished_account_hold(login, *, request_ids=())` clears only when no record of the hold's request remains. Non-empty `request_ids` also require that the hold belongs to one of those requests. Selected cancellation or restore supplies the requests it finished; account-wide restore can clear a hold with no records. Account-wide cancellation always clears the hold, even when stopped records remain for restart.

Reads and dry runs convert old files in memory without writing them. `migrate(login)` is called by writing operations before they use the store. It validates every old file and destination before writing any session record or moving a source file; conflicting sanitized filenames or history destinations raise `InvalidRecord`, with no session records written or sources moved. For one session id the current file wins, then the old main file, then the newest old partial file; completed old files supply no session records or hold. Conversion attaches workers, drops record-level issues, preserves an inferred account hold without replacing an explicit one, and assigns `legacy-<machine>-<requested_at>` as the request id. It moves old sources to history and prints one conversion line per source. Status, read verbs and dry runs still see unmigrated files. Internal `records --json --here` and `holds --json --here` expose the session records and account holds used for cross-machine account inference; a peer without these interfaces is not reached.

### States

Each owner's `progress` is `waiting`, `reaping{at, because, detail}`, `ready{at}`, `held by usage limit{at}`, `stopping{at}`, `stopped{at}`, `already gone{at}`, `process identity lost{at}`, `stop failed{at, reason}`, `restarting{at, prior}`, `restarted{at}`, `restart failed{at, reason}`, `manual restart{command}`, or `timers pending{at, timers}`. Stop-only terminal records remain for restore. Confirmed `restarted` records are archived and never launched again.

A `stopping` or `restarting` claim belongs to its worker for `CLAIM_STALE_SECONDS = 120`. An older claim can be replaced; a relaunch resumes from `prior`. A stop worker checks its exact claim before each write, signal and cleanup operation; a relaunch confirms only its own claim. Losing a claim transfers ownership without adding a user outcome. Conductor handoff likewise has no separate user outcome.

A partial stop is `record.stop_incomplete`: `stop failed`, or a terminal stop with non-empty `stop_issues`. A Codex server or unit tmux session left running can therefore coexist with progress `stopped`. Status shows the issues. `/shutdown now --only <name>` has the conductor retry it: a `stop failed` record repeats the stop, forced; a stopped one retries only the cleanup recorded with cause `stop not confirmed` (`_retry_owner_cleanup`) and sends no signal. Issues with cause `owner identity lost` are never retried. A retry that fails again sets `force` back to `wait for ready`, so it is reported once. `relaunch_session` runs the same cleanup retry before it launches a record with unconfirmed cleanup, and ends `restart failed{owner cleanup not confirmed; run /shutdown restart again}` when it stays unconfirmed.

### Settling and selected actions

`down [account] [--here] [--only NAME[,NAME...]] [--restart] [--to claudeN] [--why TEXT] [--no-alert]` checks `github-warm-status`, then begins locally and launches this machine's conductor. Each new owner gets `waiting` or `reaping` from its prompt state, its workers, saved timers and stopped timers; a timer-stop failure removes only that owner's request and names it. Existing records print `<name>: already in progress` and keep their continuation, hold, policy and request origin. New owners print `<name>: added`. Repeating a request starts a conductor even when every selected owner already has a record; follow and closing commands retain those original request ids.

Without `--here`, the peer receives `down <login> --here` with the same request id, origin and continuation and conducts independently. Failure prints the peer retry command with its account, ids and `in a terminal on <machine>`; local records are not withdrawn. Non-following down exits 0 once this machine started; a tty down returns follow's result. Only an account-wide request sets an account hold.

`resolve_sessions(login, items, *, here=False)` resolves exact names or ids against account records and inventory, counting each id once and excluding workers. Local ids need no peer lookup; names are checked on both machines unless `--here`. Readable peer records remain candidates when its inventory fails. An unavailable peer prints `<peer>: not reached; names checked on <machine> only`; an unknown or ambiguous item exits 2 and lists candidates. Local ids execute locally; only remaining ids go to the peer. For selected `cancel`, `now` or `restart`, a local live session with no record prints `<name>: no shutdown in progress` and exits 1 without being sent to the peer.

The conductor holds `record.conductor_lock(login)` for its lifetime. A duplicate exits successfully; a quarter-second retry (`CONDUCTOR_LOCK_RETRY_DELAYS`) tolerates a status probe. After release it checks for newly added work so an ending conductor cannot leave a request unattended. Every `SETTLE_INTERVAL_SECONDS = 15`, one `run_inventory(login, <live record ids>, refresh_desktops=False)` feeds `next_step` for each owner; a record withdrawn during the tick's refusal scan raises `store.NoLiveRecord` and is skipped. The full inventory with its desktop snapshot takes up to 60 s, so the tick stays filtered. Running actions are skipped until their futures complete. Stops and non-window launches run in a `RESTART_LAUNCH_WORKERS = 6` pool; registry and Remote Control waits use the polling pool. Window hosts launch in order on the conductor's thread with one desktop state restored on exit. `_launch_conductor` starts it with `systemd-run --user` (Linux) or `launchctl submit` (macOS) as `shutdown-<label slug>-<pid>`; neither passes on the caller's environment, so a `HOME` or `SHUTDOWN_STATE_DIR` exported in the calling shell does not reach it. The conductor ends when no record has a step left: each is archived, or stopped with `then: "stop"`, or needs the user (`stop failed`, `restart failed`, `manual restart`, `timers pending`). It clears the account hold once a restarted record of the hold's request is archived and no record of that request remains, then sends the requester one result (`report_stop`).

A waiting non-requester gets the settle message; queued messages retry after `SETTLE_RETRY_SECONDS = 300`. Its first line is fixed, and the launching skills (`<PauseForMove>` in `/unit:direct` and `/showrunner:produce`) act on it: `Pause for move: <label> → <target> (<why>, <time>)` or `Pause for stop: <label> (<why>, <time>)`; that line stays byte-identical because the skills match its prefix. The second line, `pause_confirmation_line(record)`, says the request comes from the shutdown the user started, not from another session's own choice, cites `docs/accounts.md` "Move a session" for a move or this doc for a stop, and names `shutdown.py status <account label> --here` to run in this terminal, which lists the session under the move or stop; the label is `note_file.canonical_label(record["label"])`, never the login. The body asks a busy session to stop at once, without finishing its current step, then run `ready --where` and end its turn.

No session's consent is required. A waiting owner that is idle (status `idle` or `shell`, every worker `idle`, `blocker(...)` clear, no form showing) is stopped by `next_step` with `StopSession(idle_reason)`: with its message `not sent` or `queued` it gets no pause message and stops as `idle; nothing in progress`; with the message `sent` and the registry's `updatedAt` (`Session.updated_at`, ms) strictly later than the send, it stops as `idle after the pause message; no ready line`. An equal or earlier `updated_at` is not an answer, and a saved inventory without the field reads it as 0. A form, any blocker (unpushed work included) or a busy worker still holds. So the pause reaches only busy sessions, and the conductor sends no holdout alert for a `StopSession` step. A sent message with no ready mark after `REASK_AFTER = timedelta(minutes=2)` is sent once more and `reasked_at` is recorded; no further repeat follows, and a busy session accepting prompts waits for its ready mark unless the timing is `now`. Reaping bypasses readiness after a refusal or exhausted account reading. Its stop instruction names `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py`, so a session answers through the scripts installed under its own home, whichever checkout made the request. The requester gets no settle message and runs `ready --where` itself. A queued instruction whose request was cancelled or replaced before sending is discarded and never marks another request's record. `ready --where TEXT` updates only this session's waiting, ready or `held by usage limit` record, then launches its account conductor; a duplicate exits at its lock. A launch failure leaves the ready mark in place, exits 2 and prints the conductor command with the terminal and machine where to run it. Ready owners stop with registry status `idle` or `shell`, with every worker idle, no form, no merge in progress and nothing ahead of upstream; dirty files stay on disk. `shell` means the owner is at its prompt with a background Bash shell, which ends with the session; workers still require `idle`. Automatic idle-stop checkpoint lines gain `; a background shell was running` for `shell`, while a session's own `ready --where` line is kept. Remote Control still requires `idle` before typing into a pane. `force: "now"` bypasses readiness. Absent owners or lost identity get a stop outcome without signals. An unreadable account holds the record. The requester goes last among the same request's records on this machine, except under `now`, which stops it without waiting for the rest of its request; a showrunner never waits for its units.

At `conduct` entry, `_module_fingerprint` records modification nanoseconds and sizes for `shutdown.py`, `settle.py`, `stop.py`, `record.py`, `inventory.py` and `restart.py` beside `settle.py`. Each conducting pass compares those six stats until a change requests reload. If a module stat raises `OSError` during an install, that pass keeps the current fingerprint and continues owned work; the next pass tries the comparison again. The conductor logs the changed module names and time in the user's zone, takes no new session steps, and drains its stop and launch actions, pause messages, holdout sends and registry confirmations, including launches awaiting confirmation. It restores desktop state, atomically writes archived outcomes to the account state directory's `conduct_archive.json`, releases `conduct.lock`, then replaces itself with `os.execv(sys.executable, [sys.executable, "-u", *sys.argv])`, repeating the `shutdown.py conduct <login>` entry point. The replacement consumes that file under the conductor lock, merges the outcomes into its final report and deletes the handoff file. Completed launches are confirmed and archived before reload, so they are not launched again. A file holding a record of another login raises `InvalidRecord`. Since `ready` and `down` find a running conductor holding the lock and exit, this reload is how new code reaches an open request; an install needs no conductor restart.

Gotchas: `launch_permission.py` and the `scripts/lib` modules are not fingerprinted, so a change to them alone triggers no reload. `_conduct_archive_path` takes its root from `launch_permission.shutdown_state_root()` and repeats `record`'s private login checks (non-empty, no `/` or NUL, no leading `.`, case-folded directory), because `record`'s directory helpers are private; a change to those checks in `record.py` must be repeated in `_conduct_archive_path`. The entry fingerprint lets an `OSError` propagate, while a pass's comparison must not abort, or the archived outcomes are lost.

A fresh not-ready refusal returns the stop claim to `waiting`, `ready` or `held by usage limit` and keeps its `NotReadyToStop` issue for status. A stale `stopping` claim returns to `waiting`. It stays open for the conductor's next inventory pass and is not reported as finished. At the shared validated entry parser, an old `stop failed` with reason exactly `session or worker is not idle and ready` and exactly one `NotReadyToStop` is recovered to that issue's progress for both legacy account files and current session records. Other failures stay terminal, and every real stop failure replaces the previous stop issues.

At every check, the conductor reads the owner's screen through `settle._screen`: a tmux or unit owner's pane by the pane id in its matching session registry record, an owner on a `HerdrHost` through `session_pane.read_place`; any other host has no pane (`no pane host`). A non-busy owner showing `hit your session limit`, `hit your usage limit`, `hit your weekly limit`, `usage limit reached` or `wait for limit to reset` in its last 15 non-empty lines enters `held by usage limit`, replacing the settle turn. It stops once the owner is `idle` or `shell` and all workers are idle, no merge is in progress and nothing is ahead of upstream; the limit menu does not block it as a form. The held state returns to `waiting` when the limit no longer shows, the owner is busy or the pane cannot be read. Leaving the hold sets the settle message to `not sent` in the same locked write, so the owner is asked again at that check, even if its earlier message was sent or queued. A held session gets no holdout alert. For every host, a newest transcript refusal after the pause enters reaping before the screen detector runs; assumed refusals still supply the separate usage hold. Form checks also read the owner's pane by id.

`cancel [account] [--here] [--only NAME[,NAME...]]` restores timers and footers, retires queued shutdown messages, sends `cancelled by the user: continue where you were` to a previously messaged owner, and archives the record. Restoration and the cancelled message run under the account lock before any later request can send its instruction, so cancellation cannot replace that instruction. Selected waiting, ready or `held by usage limit` owners print `<name>: taken out`. A selected `stop failed` record can be withdrawn only when the original process identity is still live; identity checking and withdrawal share the lock, and it prints `<name>: taken out, still running`. A competing stop claim keeps the record. Other retained records print their progress and a full scoped restart command with `in a terminal on <machine>`, exit 1. Selected cancellation clears a hold only if it withdrew that hold's request's last record.

`now [account] [--here] [--only NAME[,NAME...]]` sets `force: "now"` and starts the conductor; it never stops or retries a session itself. Chosen eligible owners print `<name>: stopping now`; an ineligible owner prints `<name> is <progress>; nothing to stop`, exit 1. A multi-selection exits 1 if any selected owner could not be acted on.

### Status

`status [account] [--json] [--here]` shows the inventory, then the records and applicable actions in each machine's block. Waiting, ready and `held by usage limit` lines retain `  <name>: <progress> — <hold details>` and a message note after ` · `. Hold details include `busy`, `showing a form`, `ahead N on <branch>`, `merge in progress`, `Codex worker <name> is still running`, and `message queued: <reason>`; a usage-limit hold omits the form detail. Stop issues print beneath the owner; a failure reason, pending timers and a manual restart command print on the progress line. `--json` prints the inventory with local unresolved recovery entries when present.

A read-only, non-blocking `conductor_status` probe distinguishes running, not running and unavailable. A lock filename alone is not ownership. With unfinished records and no conductor, status prints full selected down commands to resume, each with `in a terminal on <machine>`. An unreadable or unreachable probe reports `conductor ownership unavailable: <reason>`. Applicable take out, stop now and bring back actions use full script paths, the stored login and exact --only ids, grouped by machine in record order. Reaping owners have stop-now actions too.

### Stopping

`stop_session` claims before signalling and never replaces a stored pid with an observed one. An idle stop's reason (`StopSession.idle_reason`, a `stop.IdleStopReason`: the two idle texts, each also with `; a background shell was running`, beside the default `not an idle stop`) is written as the stopping claim's `where` (`said`) in the same update that moves progress to `stopping`, only when the prior progress is `waiting`. `_stop_owner` admits a `waiting` prior only for an idle reason and still runs fresh idle, worker and blocker checks. `fresh_session` distinguishes a matching owner (with workers), absent owner, lost identity and unreadable account. Process identity is checked before each `SIGTERM`; two attempts each allow `STOP_WAIT = timedelta(seconds=10)`. No `SIGKILL` or pane input is used. Before signalling the owner, shutdown records its Codex resume data. A `reaping` owner skips the readiness and idle checks and keeps the identity check before `SIGTERM`. Under `then: restart`, an owner whose host has a live supervisor gets its hold written first (`_hold_supervised_window`), then only Claude is signalled and the window is kept (`retain_window`); a failed hold write ends the stop as `stop failed` with no signal sent. After the owner exits, cleanup closes an unsupervised or stop-only Ghostty window where ownership still matches, pauses Codex seats and stops their servers, then removes its unit's exact tmux session. Workers receive no process signal and keep jobs and transcripts for their next message. Cleanup issues remain on the record.

### Recovery snapshots

`agents snapshot` calls `inventory.snapshot_inventory()`. A `PartialInventory` prints its failed sources and exits 1 without replacing any recovery file. A complete observation merges into `<shutdown state>/snapshots/<login>.json`: observed sessions are running. An absent session stays unresolved with its original `last_seen` only when its boot id changed or its herdr server, tmux server or terminal process is gone. A session that exits while its host stays alive is dropped. Sessions stopped by `agents down` restore through their shutdown records, separately from snapshots. Snapshotting changes no session, pause, timer or vault note. Files remain on disk across reboot and stay machine-local. The snapshot producer runs on Linux.

`RecoverySnapshot` holds machine, canonical login, label, taken time and tagged Claude/Codex entries. Each entry keeps its session, workers, timer restores, last-seen time and running/unresolved state. Codex entries also keep `CODEX_HOME` and either a session id or an explicit resume-picker choice. `agents status` lists unresolved entries with last-seen times in the user's zone; local JSON status includes `recovery` when unresolved entries exist. `agents forget <name|id> [--account <login|label>]` acknowledges one local entry without touching its process or shutdown record.

`restart._up` selects per session id: an existing shutdown record takes precedence, while snapshot sessions with positive crash evidence join the same restart pass. It prints `from shutdown record` or `from snapshot taken <last_seen in the user zone> (<age>)`; with neither source it prints `nothing to restore for <account>`. All local accounts' records and snapshots supply account evidence before launches; archived completed restores retain that evidence after acknowledgement. Current running ids are checked independently of the stored account and skipped; a confirmed move or newer observation selects the current account (if only an old-account copy remains, it launches on the confirmed target), and conflicting evidence refuses the session and names both accounts. Snapshot-only names and ids participate in restart selection and forget; other verbs select from membership and shutdown records. Peer `up <login> --here --json` uses the same source selection and keeps the result-object protocol.

A Claude snapshot candidate is atomically materialized as a `SessionShutdown` before launch: snapshot origin and taken time, `recovery-<taken_at>` request id, session-only hold, restart continuation and `already gone` progress. An existing request is returned untouched. Admission passes `RecordedSessionRestoreLaunchPurpose(session_id)` against the account selected for the launch, including the configured showrunner account, and requires that persisted record. Retried materialized snapshots check registry readability and the saved owner pid/start before launch. Dry runs use the pure record builder and persist nothing. Confirmation acknowledges the snapshot only after the restart succeeds; failure keeps both record and snapshot for retry.

A Codex snapshot launches directly, without a Claude hold or shutdown record: an exclusive `start_new_server` with a generated cwd-based name and a session-identity suffix, one pane in the recorded cwd with `CODEX_HOME`, then `start_agent(kind="codex", agent_arguments=["resume", <id>], opening=NoOpeningPrompt())`. Without a recorded id, arguments are `["resume"]` and output names the picker. Occupied names refuse before a pane opens; a failed agent start stops its newly created server. A previously attached/window presentation gets a Ghostty window; otherwise output gives `herdr session attach <name>`. Existing attached clients are reused. A successful start acknowledges that Codex entry; a running id is skipped.

### Restart

`restart [account] [--only NAME[,NAME...]] [--here] [--dry-run] [--no-alert]` expands terminal requests without an account over accounts with shutdown records, holds or recovery snapshots; explicit and in-session requests select their account through `restart.select_account` and run `up` locally and, unless restricted, on the peer. Terminal account discovery keeps known local accounts when peer records are unavailable, reports the peer failure and returns nonzero after trying the local accounts. Selected restart bypasses requester-last, so a stopped requester can return while siblings wait. Incomplete records (`waiting`, `ready`, `held by usage limit`, `reaping`, `stopping`) first require positive owner absence and confirmed worker/host cleanup through `stop_session`. An unknown liveness answer refuses recovery with its reason; live owners keep their shutdown request. Recovery preserves the request, target, timer intent, pause note and cleanup issues. A fresh relaunch claim prints `<name> is already restarting`, exit 0.

`relaunch_session(record, *, dry_run, desktop_state)` claims `restarting{at, prior}` before `launch_entry`. The caller owns and restores the desktop state. Eligible records are stopped, already gone, lost identity, manual restart, restart failed, timers pending and stale restarting; already restarted records archive without launching. A manually resumed live session is reconciled without a second launch. Live `timers pending` retries only pending timers; closed sessions relaunch, and unreadable liveness never proves absence. One launch exception marks only its owner as failed.

Non-window owners launch through the pool; window hosts, including attached herdr hosts, launch serially in `restart._up`. Account-wide order is by session name with the requester last (`_entry_order`); the requester is skipped while another record of its request is unfinished, and a showrunner never waits for its units. A pass's launched ids share one registry wait (`SESSION_WAIT_SECONDS = 90.0`, `SESSION_POLL_SECONDS = 0.5`); `confirm_entry` then restores timers and marks live sessions restarted. A session not live after the wait ends `restart failed{session not live after 90 seconds}`. In the conductor (`_confirm_relaunch_pass`) an error confirming one owner marks only that owner as a failed restart and the others in the batch finish as restarted; in `up` such an error ends the run with `<machine>: restart failed: <error>`. `wait_for_confirmation` returns `RegistryConfirmation`, retaining records from its final liveness poll for the Remote Control check. The conductor tracks `ConfirmedRelaunchPass` through `PendingRegistryConfirmation`. Records that finish are archived; failures, manual commands and pending timers remain. Real runs print `<machine>: restarted <n> in <s> s`; dry runs print planned launches without conversion, mutation, archive, hold clearing or a timing line.

- **Launch by host.** Resume parts hold the cwd, environment assignments, Claude arguments, opening prompt and retained or target account. Tmux (non-showrunner) and Mac terminal hosts render those parts as the same shell string: `cd <quoted cwd> && ENABLE_TOOL_SEARCH=true command <shlex.join([claude, --resume, id, -n, name, --remote-control, name, (--model, name), --settings, '{"disableAgentView": true}', prompt])>; exec zsh`, one argv item to `zsh -ic`. Unit → `add_unit.py --production <doc> <unit> --plan <plan> --resume <id> --cwd <cwd> --session-name <name> --host-session <session> --restart-note <file> [--probe]`, or `--standby` in place of `--plan` when the row's Plan cell is `standby`. A unit whose row names no Plan and that has no run record is not launched: its entry is `restart failed` with that reason (a dry run prints `cannot restart <name>: <reason>`), never a command with a `<plan>` placeholder. `<unit>` is the recorded unit id exactly: `add_unit` strips one trailing `-unit` from the name it is given and appends its own, so `x-unit` and `x-unit-unit` each resolve to themselves; stripping it in restart as well turned `x-unit-unit` into `x-unit`, a twin unit. `<plan>` is the unit's Plan cell in the production doc's Units row, read at launch (`_units_row_plan` through `add_unit.unit_table` / `cell_value`); the run record's plan is used only when the doc has no single row for the unit. A unit first added from a brief has no run record until its plan runs; its row names the stub plan, which it resumes with. `add_unit` refuses a resume whose plan differs from the row, and a run record's plan differs once the plan moves to as-built. A restore whose row matched adopts that row: `add_unit` skips the recorded-add-mode check and the Production-header check on the plan, both of which describe new work, so a unit first added from a brief, or whose Plan cell now names its as-built doc, restarts. The row also names the restored unit's worktree and branch: the naming pattern `add_unit` gives new work (`<checkout>-<unit>`, `<slug>-<unit>`) is never compared with the row or reserved against other rows on a restore, so a unit whose worktree or branch does not follow the pattern restarts. The session launches in the recorded `--cwd`, where its transcript lives; no worktree or branch is created and the row is never rewritten. A recorded cwd that is not the row's Worktree, or that has another branch checked out than the row's Branch, is launched in without comment: a unit made from an existing session keeps that session's directory while its worktree is elsewhere, so the difference is normal, and its prompt names the row's Worktree and Branch, where it edits. A restore with no Units row is refused (`unit <id> has no Units row; a restore never adds one`), never added as a new unit. Showrunner → prompt `/showrunner:produce <doc> resume`, its note sent as a `shutdown` message once live. `WindowHost` → Claude starts in a new herdr session named by `generated_session_name(session["name"])`; an occupied name refuses without a suffix retry. A live Ghostty supervisor receives `herdr session attach <name>` in a relaunch request, keeping the window (see A supervised terminal window). A missing supervisor, or Zed, opens one Ghostty window attached to that session → `kdotool set_desktop <n>` (from `~/.config/kwinrc` `[Desktops]`), `systemd-run --user --collect --quiet -- ghostty -e zsh -ic …`, 1.2 s apart, then back to the starting desktop; a Zed session comes back in Ghostty. `TerminalHost` → `open -na "/Applications/Nix Apps/Ghostty.app" --args -e zsh -ic …`. Every new window wraps its attach argv (or Mac resume argv) in the supervisor. `TmuxHost` → `respawn-pane -k -t <pane_id> -c <cwd> zsh -ic …` when the recorded pane answers and is dead or still has the recorded `pane_pid` with no child. Pane and session ids are used only while the recorded server pid and start time both match the running server; a restarted server numbers `$N` and `%N` from zero again and can reuse those ids for unrelated sessions. `#{start_time}` is in whole seconds, so the pid tells apart a replacement server started in the same second. Without a recorded server (or with one recorded without its pid), the pane route and both session-id routes are skipped and the recorded name is used. No route compares session names, so a renamed session on the same server does not prevent reuse. Otherwise a new window goes first to the occupied pane's current session id (read in the same pane probe), then to the recorded session id if `display -p -t $N '#{start_time}\t#{pid}'` reports the same server pid and start time (`has-session -t $N` cannot tell a new server's reused id), then to the recorded name if `has-session -t =<name>` answers. Id targets are `$N:`, name targets `=<name>:`. If none answers, `new-session -d -s <recorded name>` creates the session; if another launch created it first, the failed creator opens a window there. Every `UnitHost`, `session_host` tmux or herdr, goes through `add_unit.py --host-session <recorded session name>`, which starts a herdr session of that name (characters outside `[A-Za-z0-9_.-]` become `-`). A `TmuxHost` showrunner does not take the tmux routes: it resumes in a new herdr session named by `generated_session_name(tmux_session)` (`NewHerdrSession`), and its shutdown record keeps its `TmuxHost`. `UnknownHost` → `manual restart` with the command printed.
- **Herdr resume.** `_herdr_launch(parts, destination, session, *, dry_run)` takes `RecordedHerdrPane(name, pane_id)` for a herdr host or `NewHerdrSession(name)` for a tmux showrunner or a Ghostty or Zed host. New destinations use exclusive `start_new_server`, refusing any running server of that name; recorded panes keep the adopting `start_server`. It starts the named server and opens a workspace in the recorded cwd with a pane environment built from `named_account_environment` and the resume parts. A server started here closes the workspaces herdr restored. After the server start, every launch reads `herdr.server_environment(name)`, including a freshly started server. If it holds any name from `prepared.remove`, or `CLAUDE_CONFIG_DIR` or `CLAUDE_CODE_OAUTH_TOKEN` for a main-account launch, restart refuses before opening a pane and prints the variable plus `herdr --session <name> server stop` and retry instructions. An unreadable server environment refuses too: pane variables cannot remove inherited server variables. Before opening the new pane, restart closes a recorded pane only when `client.pane_activity(pane)` returns `PaneAtShell`. `PaneRunning(commands)` refuses with the session, pane and running commands; no pane is closed or opened. A missing recorded pane needs no close. An agent still occupying the recorded pane, or any pane of a `NewHerdrSession` server, refuses the restart. Herdr receives the typed resume parts directly, without rendering or parsing a shell command. `--kind claude` selects the executable; arguments after `--` contain only `--resume <id>`, the recorded name and model, Remote Control and settings, with no executable or account wrapper; the restart prompt is sent once as `OpeningPrompt(parts.opening_prompt)` after agent readiness. It is recorded once as scheduled work. `HerdrHost.presentation` is `"attached window"` when inventory sees `ClientsAttached`, otherwise `"detached"`; unreadable clients and old records read as detached. Attached-window restores open one Ghostty window running `herdr session attach <name>` without a recorded desktop; detached restores print that command. An untrusted folder refuses before starting the server, and a readiness refusal sends no key. Dry runs start no herdr program. Herdr and tmux units both use `add_unit.py --host-session` (`UnitRestoreLaunch.host_session`); the old `--tmux-session` spelling is gone. An account move into herdr (`MoveResumeAccount`) calls `accounts.prepared_account(target, resume=True)`: an `AccountRefused` raises before any herdr call, and the pane environment gets its `variables` with every `remove` name dropped. Its arguments remain Claude arguments. Old records with `tmux_session` or no `session_host` remain tmux records. No herdr Claude integration is installed.
- **Note** (`restart_note`): label, stop and restart times in the user's zone (`%Y-%m-%d %H:%M %Z`), the recorded `where` (for `not said`: read branch and plan), run `send.py pending` first, keep waiting if it was waiting on the user. Every first prompt is appended to `conversation_pause`'s scheduled prompts before launch (`_record_scheduled_restart_prompt`; `add_unit.py` does the same for units with the exact `prompt_for` string), so the pause hook does not treat it as typed. A failure leaves the entry unlaunched with `restart prompt not recorded: <reason>`.
- **Account on resume:** every launch sets a numbered `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_REMOTE_MEMORY_DIR=~/.claude`. Units and showrunners use their configured group account. Ungrouped sessions retain the recorded numbered directory. Legacy records naming `default`, `~/.claude` or lacking a directory resolve from the record's own login or a dated `cutover-home` entry in `config/accounts.json`; no evidence means unresolved and no launch. A legacy move target uses dated cutover evidence only, since the record's login identifies its source. Today's home login never resolves a past record. A resolved legacy resume uses that label's numbered folder. Herdr gets these variables directly in the pane environment; group resumes and moves use `accounts.prepared_account(target, resume=True)` and drop its removed names. Shell hosts render the same numbered directory as assignments. The restart subprocess strips inherited `CLAUDE_*`; assignments inside the command reach tmux independently of its server environment.

### A supervised terminal window

Linux Ghostty and Zed relaunches start Claude in herdr and wrap `herdr session attach <name>` in the supervisor. Mac terminal relaunches keep `_resume_shell(parts, supervised=True)`, which wraps resume argv with `~/.claude/scripts/lib/py ~/.claude/scripts/lib/relaunch.py run --`, inside the existing shell. The supervisor (`scripts/lib/relaunch.py`, standard library only, importing nothing from `scripts/accounts` or `scripts/shutdown`) shares Claude's terminal and process group, catches SIGINT, SIGQUIT and SIGTSTP itself so the child still gets them, and forwards SIGTERM and SIGHUP to its child. It starts the child with `RELAUNCH_SUPERVISED=1`, so a resumed `accounts.py exec` under it execs Claude directly and nests no second supervisor. Inventory reads `supervisor: SupervisorIdentity(kind="supervisor", pid, proc_start) | NoSupervisor` on `WindowHost` and `TerminalHost` from `_supervisor_process`, which matches the Claude parent's argv for `relaunch.py run --` (`/proc/<pid>/cmdline`, `ps -o args=` on the Mac); a supervisor that is the window shell itself reads as `NoSupervisor`. `supervisor_identity(host)` reads a host without the field as `NoSupervisor`; `live_supervisor(host)` also rechecks pid and proc start. Supervised hosts are `ghostty` on Linux and `terminal` on darwin, where `terminal_kind` maps Ghostty to `terminal`, so a Mac supervisor lives on `TerminalHost`.

For restart, stop verifies the supervisor identity and writes its hold before sending only SIGTERM to Claude. It keeps the window and scroll history. Restart atomically publishes (temp file, fsync, rename) `RelaunchRequest{argv, cwd, environment, unset, written_at, note}` to `STATE/relaunch/<supervisor pid>.json` (`STATE` is `$SHUTDOWN_STATE_DIR` or `~/.local/state/shutdown`) and returns `SessionLaunched()` without opening a window. For a Linux window the request runs `herdr session attach <name>` in the recorded cwd; the agent pane carries its explicit numbered account variables and drops inherited OAuth tokens. On the Mac the request keeps Claude resume argv: a move uses `accounts.prepared_account(target, resume=True)` variables and removals; retained accounts also keep their numbered directory, and `CLAUDE_CODE_OAUTH_TOKEN` is always unset. After its child exits the supervisor reads the request, deletes it and the hold, prints the note as one line and execs itself with `run -- <argv>` in that cwd and environment, keeping its pid. A malformed request prints `could not restart here: <error>` and exits with the child's code. Registry confirmation still proves the resumed session. Stop-only uses the existing cleanup path. A gone or reused supervisor falls back to the existing window launcher: Linux uses the request-time named desktop and restores the old desktop; Darwin uses its existing Ghostty application launch.

The hold file `STATE/relaunch/<pid>.hold` lasts `HOLD_SECONDS = 300` (`SHUTDOWN_RELAUNCH_HOLD_SECONDS` overrides). After Claude exits with no request yet, the window says `claude stopped for a restart; waiting for it here` once and checks every 0.5 s. On expiry it removes the hold, says `no restart came; this window is free`, and returns the child's exit code. Legacy or manually started windows without a supervisor retain their previous new-window behavior.

### Remote Control after relaunch

`remote_control(record: SessionRecord) -> Literal["active", "absent"]` reads `sessions_dir() / "<pid>.json"`. A non-empty `bridgeSessionId` is active; missing, empty or unreadable is absent. `SessionRecord` does not carry the field. Its null case was read from the 2.1.296 binary, not observed on a session. `add_unit.wait_for_remote_control` is a different function: it polls pane text, for new-work launches only.

`wait_for_remote_control(records, timeout)` uses the registry records just confirmed live, with `REMOTE_CONTROL_WAIT_SECONDS = 10.0` and `SESSION_POLL_SECONDS = 0.5`. It polls only those small files, never scans `sessions.live_sessions()` again, returns at once when all are active, and starts no poll after the deadline. A slow read can overrun by one poll's reads; there is no thread or timeout around each read. One shared wait per relaunch pass costs usually 1 to 3 s after registry confirmation, at most 10 s plus one poll's reads when one stays absent. The conductor runs the wait in its polling pool while other owners keep moving.

Each confirmed local session still absent starts one detached `remote_control.launch_fixer`. Repair is quiet: it sends no message or phone push and adds no requester or showrunner diagnostic. Its record finishes as restarted and its exit status stays successful. A fixer launch failure is recorded once in the local system log. The peer starts its own local fixers.

The helper starts `shutdown-remote-control-<session id prefix>-<pid>` using the restarted session's pid with `systemd-run --user --collect --quiet --no-block` or macOS `launchctl submit`. Python gets `-u` and `PYTHONUNBUFFERED=1`. The internal verb takes a session id, registry pid and process start, a journal identity (`--who`) and session name (`--session`). `remote_control_who` gives `<unit without -unit> unit`, `<production> showrunner`, or the session name. The fixer has no alert option.

`fix(..., clock=...)` checks the process and registry identity at every half-second poll. Each observation reads and parses the registry once; identity, idle status and bridge id come from that same write. `sessions.parse_session` shares the existing validation without another file read. It waits `FLAG_WAIT = 60` seconds for the launch flag to take effect (`AlreadyOn`). Then `session_pane.record_place` resolves the confirmed pid's own tmux or herdr pane, without selecting another process sharing the session id. No pane, including Ghostty or Zed windows, fails immediately after that wait. Only a registry `status: "idle"` authorizes typing `/remote-control`; herdr `AgentBlocked` leaves the attempt unconsumed; other input errors consume an attempt and retry, retaining the last error for a final failure. Identity and status are rechecked after pane resolution, immediately before input. This is the sole exception to shutdown's prohibition on typing into panes.

After each of at most `ATTEMPTS = 3` typed commands, the fixer waits `ATTEMPT_WAIT = 30` seconds for the registry bridge id or the pane's `/remote-control is active` marker (`TurnedOn`). Busy, blocked or unreadable sessions keep waiting up to `DEADLINE = 15` minutes from fixer start. A gone or replaced process ends as `SessionGone` with no input or push. Before returning any failure, a fresh observation checks for an exit, replacement or activation. A `Failed(reason)` exits 1 in the detached service without notifying anyone. Every outcome prints one journal line naming the unit, showrunner or session. Tests use a fake monotonic clock, registry and pane; no test starts this service or types into a real pane.

Internal `up <login> --here --json` returns a validated object containing `machine`, `label`, `outcome`, `lines`, `no_remote_control` and `refused`. New replies always emit `no_remote_control: []` for older readers; the new parser ignores that key, including old entries with `alerts`, and accepts its absence. `RestartRefusal` is a union: `not stopped` carries id, name and progress; `no shutdown` carries id and name. Local and peer refusals travel as this data; `up` exits 1 when the outcome is `partial` or any session was refused, and no exit status names a refusal. A peer exit other than 0 or 1, or an answer that does not validate (`parse_peer_result`), reads as not reached, without interpreting Remote Control state. `settle.unrecorded_local_sessions` supplies local selected sessions without a record to cancel, now and restore. `PeerRestartResult` validates the wire object; its `outcome` is `done`, `partial` or `nothing`.

### Messages and notifications

`accounts.py exec --probe <account> -n <name>` sets `CLAUDE_PROBE_SESSION=1`. Inventory treats only the exact value `1` as a probe; unreadable or missing environments read false. `settle.begin` saves `probe: true` and forces `alerts: "none"` for probes. Old session and shutdown records read `probe: false`. Resume carries the marker forward: `_resume_parts` adds `CLAUDE_PROBE_SESSION=1` to the resume environment, and every unit restore, from tmux or herdr, passes `add_unit.py --probe` (hidden; requires `--restart-note`), which explicitly sets the marker in the new herdr pane environment instead of copying the caller's environment. `send.py --to user` also exits successfully before review, logging or delivery when its own environment has the marker, printing `not sent: probe sessions never push to the phone`.

Shutdown messages use sender `shutdown`, which the conversation-pause hook treats as scheduled work. Settle, cancellation and restart notes use key `shutdown-<login>-<session id>`; the final requester result uses `shutdown-result-<login>`. Queued messages are read with `send.py pending` after resume. A unit's production showrunner (`showrunners.current_name(production_slug(doc))`, skipped when none runs) gets one line before the unit is stopped, `<unit> is stopping: <why>; it comes back on <target> within minutes` (or `it stays stopped until the user restarts it` for `then: stop`), and one more from the conductor's report or `restart`: `<unit> is back on <target>`, or `<unit> did not come back: <reason>`, again once per new failure. `showrunner_told` records the last line sent; both use key `shutdown-unit-<session id>`. `settle.alert_user(RenderedPush, *, machine="")` is the phone path; the catalog render provides the title, body and ActionRequired. The conductor's alerts pass `machine="natedev"` from the Mac; `restart`'s own alert passes no machine. The not-answering text also goes to the requester under key `shutdown-holdout-<login>`. A hold or session record never refuses the UPS alert.

`NOT_ANSWERING_AFTER = 2 * REASK_AFTER` is four minutes from the sent pause, or the request if no pause was sent. An unanswered waiting owner (a busy one, since an idle owner is stopped without a pause) gets one catalog push and requester message, even on Ghostty with no readable pane. `settle.HoldoutKind.from_reason` picks the entry: `shutdown.holdout` when the owner is showing a form (its action is to answer the form), `shutdown.holdout_unanswered` for any other hold (its action is to stop the session). Both have the title `<session> restart is blocked` (or `shutdown`), a `Session: <session>` line above the Action line, a `Reason:` line, and the scoped `now <label> --here --only <id>` command with its machine. The command names the account label (`note_file.canonical_label`), never the email login. No raw hold-detail list reaches the push; the requester message keeps it. The requester message (`Restart stuck waiting on <name> session`, or `Shutdown`) carries `holdout_line(saved)`: the minutes, the host from `_holdout_host` (tmux session and pane, unit, `Ghostty window, <name> desktop`, Zed window), that the pause asks for a safe point and a ready reply, both choices, and the command with `in a terminal on <machine>`; a terminal requester gets the line printed. Both say that now ends Claude mid-step while keeping uncommitted work, and doing nothing leaves the request waiting. `after_stop` distinguishes a restart request, which brings it back, from a stop-only request. `alerted_at` reserves delivery once; reaping owners never get this push. Saved `alerts: "none"` suppresses it. Notification workers keep delivery off the conductor's stepping thread. The catalog approval is kept in `scripts/notify/push_texts_reviewed.json` (`docs/as-built/message-clarity.md`).

A not-back push is sent once per new restore failure; `restore_alerted` stores the last failure reported. An unchanged failure is not pushed again.

Every progress transition appends `ProgressStep{at, kind, detail}` under `update_session`; the timestamp is the write time, so rollback progress retains its original time without reversing the trail clock. Creation includes its initial progress. Old records read with an empty trail. Archive preserves the trail, and status renders each step in the user's zone.

Every user-facing line that names a command also names where to run it: `in this terminal`, `in a terminal on <machine>` or `in any Claude session on <machine>`, with a full command from `settle.shutdown_command(*arguments)` (`~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py <shlex-joined args>`) scoped by login, `--here` and `--only <session ids>`. This covers the cold-key line (`github-warm-status; github-warmup`, then the `down` retry keeping `--here`, `--only`, `--restart`, `--to`/`--why` and `--no-alert`), every peer-not-reached retry, `report_stop`, the showrunner outcome lines, `cancel`'s not-cancelled line, a manual restart's progress, the status actions, the pause message, the usage and epilog, and restart's owner-cleanup retry. `settle.located_detail(record, detail)` prefixes `in a terminal on <machine>: ` to a stored detail that holds a command but no place phrase; `status` and `follow` print trail steps through it.

`shutdown.py follow <account> --request <request id>` (`shutdown.follow(login, request_id) -> int`) follows one request. In a terminal on the record's machine, run `~/.claude/scripts/lib/py ~/.claude/scripts/shutdown/shutdown.py follow <account> --request <request-id>`. Follow reads local active records and checks history every second, never inventory; immutable history files are read once per follow, including unrelated requests. Active reads precede history reads to cover an archive between them. It prints `<HH:MM:SS> <name>: <kind> <detail>` once per trail step. A nonfinal archived record means the session was taken out: follow prints that once at observation time and counts it done. It waits through stopped/already gone when restart is pending, reads outcomes archived before it starts or between polls, and prints all stopped or all back on the target account; summaries with cancellations count each outcome. A session in `process identity lost`, `stop failed`, `restart failed`, `manual restart` or `timers pending`, a `waiting` one with `alerted_at`, or a stopped one with `stop_issues` prints `_follow_action(saved)` (its state and the scoped command with its place; for a waiting one, `holdout_line`) and exits 1; completion exits 0; a request with no records exits 1. Ctrl-C exits 130 and prints a reconnect command while the conductor continues. `settle.down` snapshots the selected records by request id before launching the conductor, because the conductor archives a finished record at once. With no session requester (`requested_by` empty and `CLAUDE_CODE_SESSION_ID` unset) and a tty on stdout, it runs follow for each local request and returns its code; a terminal opened from inside a Claude session carries `CLAUDE_CODE_SESSION_ID` and so gets the closing lines instead. A terminal request covering several accounts suppresses automatic follow while starting each account and prints each follow command. Otherwise it prints, per request, `shutdown of <label> started for <n> sessions. To follow it, in a terminal on <machine>: <follow command>. To stop the ones not yet stopped, in a terminal on <machine>: <cancel --here --only <ids>>.`; a request with a `target` says `stop the move of the ones not yet stopped`, never promising to undo a move. No local selection prints `shutdown of <label>: no local sessions selected`. Follow summaries are `all N back on <target>`, `all N stopped` and `all N done: K back on <target>, J stopped, M taken out`. Each machine follows only its own records; a peer's sessions in the same request are not followed.

`_launch_conductor` runs `env PYTHONUNBUFFERED=1 <python> -u shutdown.py conduct <login>`, so journal lines appear as written. Stop identity re-reads (`stop._fresh_inventory`) pass `refresh_desktops=False`, like the conductor tick. `resolve_sessions` returns `ResolvedSessions(session_ids, report)`: exact names come from `inventory.listing(login)` and the records, then one `inventory(login, only=…)` builds the report, which `down` passes to `settle.down` and `begin` (`report: Inventory | InventoryNeeded`); `begin` inventories only when called without one. Without `--only`, `down` inventories once and passes it the same way.

`report_stop` sends the requester this machine's results plus one peer-record read. Account-wide partial stops alert when their saved policy allows it. Restart uses `<label> is not fully back` for incomplete restoration. Remote Control recovery is quiet and never appears in these results. Retry guidance remains only when something is still left to bring back. Lines always print; `alerts: "none"` and command `--no-alert` suppress the phone send, including after archive.

For incomplete restores, restart checks policy on both machines. With `--only`, only selected records count; with `--here`, it reads no peer. When the peer is unavailable, including an answer without the result object, account-wide policy uses every local record: no record or any record with `alerts: "user"` enables the alert. Selected policy stays restricted to chosen records; no second peer call is made. Refusals alone never alert.

### Launch checks and held sessions

`launch-blocked [account] [--restart-of SESSION_ID]` exits 0 for a hold, 1 silently when launch is allowed, 2 for an unresolved account, and 3 for unreadable state. An account hold prints `<label> is held by a shutdown (since <time>)`; a selected shutdown never blocks unrelated new work. A restore's own record overrides the account hold: stopped, already gone, lost identity, restarting, restart failed and manual restart permit it. Every other recorded progress prints `<session name> is held by a shutdown (since <time>)`. Relaunch claims first, so a timers-pending retry is permitted while restarting.

`RecordedSessionRestoreLaunchPurpose(session_id)` names a restore of any session a shutdown record holds. Without a matching record, the account hold alone decides, as for `NewWorkLaunchPurpose`: an open account permits launch and a held account blocks it. The purpose alone never proves restore authorization. `launch_permission` returns `AllowedByShutdownState`, `BlockedByShutdown(reason)` or `ShutdownStateUnreadable(detail)`; only a silent exit 1 permits launch. `launch_barrier()` holds `<root>/launch.lock` from check through spawn, and record creation and account-hold creation share it. Only the short decision and spawn are protected, never the launched work. Account locks serialize store mutations; a conductor holds its separate lifetime lock.

Scheduled nightly review and fix jobs keep firing but skip held accounts or unreadable state. `add_unit.py` applies the check to its chosen account, including a restore's id. Manual unit resume checks `--restart-of` and continues only on silent exit 1. `held-sessions` lists every owner's and worker's id; delegate cleanup treats those active runs as live so workers survive. No caller can infer launch permission from an exception or a crash exit 1 with output.

### Remote calls

`run_remote` uses SSH and the trailing `rc=<n>` from the command; SSH's status alone is never a successful answer. A missing trailer, SSH 255 or timeout is not reached. Standard calls have a 120 s limit; restart's peer restore uses link keepalives with no overall timeout (`ServerAliveInterval=15`, `ServerAliveCountMax=4`). Each machine makes progress independently; there is no cross-machine stop claim.

## Invariants and costs

- Account isolation: an unreadable environment or no account setting after cutover means unattributed. Before a machine cuts over, no account setting still attributes its legacy home login. Stored process identity is never replaced with an observed pid.
- Claude processes receive only `SIGTERM`, with readiness unless explicitly forced. The only pane input is the detached fixer's `/remote-control` in the restarted session's own pane while its registry shows idle. An unsupervised Ghostty window shell, or a stop-only supervised window, is closed with `SIGHUP` after the ownership check; supervised restarts retain the window; owner identity is checked before signals or resource cleanup.
- Registry process identity and socket prove relaunch liveness; Remote Control is a separate field check and never changes the restart outcome.
- A tmux id route checks the server's pid and start time in one probe and launches with a second tmux call, so a server replaced in the milliseconds between them could receive a reused `$N` or `%N`. The launch does not repeat the check: doing so would nest the resume command inside tmux's own quoting (`if-shell -F`), a larger risk to every launch than the window it closes.
- Only `AllowedByShutdownState` permits a launch; the barrier spans check to spawn. The UPS alert is unaffected by holds. Neither implementation nor tests read notification credentials.
- Record timestamps use UTC ISO 8601 at whole seconds; injected stop clocks produce the same format. User-facing times use the user's zone (`config/user_zone.conf`, read through `scripts/lib/user_zone.py`).
- Test cases derive from `ShutdownTestCase` and use temporary state and fake send, notifier, process, tmux and host commands. Tests start no real session and send no real alert.

A relaunch is confirmed by `sessions.live_sessions()`, never by pane text, and a restore through `add_unit.py` proves nothing about its session: with a `UnitRestoreLaunch`, `add_unit.main` prints `<unit> restore launched: herdr session attach <name>` (or `tmux attach -t <label>` when a live tmux unit was found) and returns 0 once the opening prompt is sent, while new-work launches keep the screen wait and `--timeout`. Measured on a 19-session restart of claude3 (2026-10-12, 12 m 40 s): eight sessions took 90–92 s, the whole of `add_unit.py`'s 90 s default, and ten took 2–6 s. `tmux capture-pane -p` reads only the visible screen; the panes were 80x24 on the alternate screen with no history, and the restart note pushed `/remote-control is active` off it before a poll, though the transcript and `bridgeSessionId` show Remote Control active within about 3 s. Two launches can share a tmux session that does not exist yet; creation is not serialized, because a competing creator can be another process, and the launch that loses `new-session` opens a window in the session the other created (`_tmux_launch`).

Costs: conductor pass 15 s; settle-message retry 300 s; not-answering alert once after 4 min; two stop waits of 10 s; shared registry wait up to 90 s; Remote Control wait 10 s plus one poll's reads; windows 1.2 s apart; sender timeout 60 s; launch checks and held-session queries 30 s. On macOS each `running_session` with a recorded `procStart` uses one `ps -o lstart=` per registry record per call, with a 5 s timeout; Linux reads `/proc/<pid>/stat`. The Remote Control wait avoids that process scan.

Uncommitted edits remain on disk. Readiness means owner status `idle` or `shell`, idle workers, nothing ahead of upstream and no merge; it never commits unfinished work. A live launch with unreadable registry state remains unresolved rather than being launched twice. Restore prompts are registered as scheduled so they do not pause restored timers. A recorded tmux pane is reused only when its identity matches; the Mac has no tmux.

Code gotchas: `update_session`, `archive_session` and the withdrawals see `sessions/` files only, so a session known only through an unmigrated old file raises `NoLiveRecord` there, though `find_session` returns it and `create_session` answers `False`; `ready` does not migrate. One handler in `main` catches `InvalidRecord` around `conduct`, `ready`, `down`, `now`, `cancel` and `status`: a refused migration prints one `shutdown: <error>` line on stderr and exits 3, with no record written, no message sent and no conductor started; `restart` prints `shutdown: restart failed: <error>`. Record updates from launch threads are serialized by `_account_lock`, a `flock` on a new descriptor per call. The readiness types (`ReadinessClear`, `ReadinessBlocked`, `ReadinessCheck`) live in `record.py` because `stop.py` and `settle.py` import each other. `scripts/message/test_send.py` calls settle's private `_restore_record`. In `test_settle.py` the fake sender reads stdin only where `send.py` reads it (a message send, not `retire` or `pending`), so a test fails when the real sender would block on an open stdin. `SHUTDOWN_TMUX`, `UNIT_LOOKUP_TMUX` and `SHUTDOWN_SYSTEMD_RUN` name stand-in binaries for tests.
