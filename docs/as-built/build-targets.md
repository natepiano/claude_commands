# Build targets

## What it is

Each machine that can run a build job is a build target with its own rules. natedev is a `local` target: it takes as many jobs as its existing limits admit (the memory gate, the cargo token, build-folder turns). The Mac is an `ssh` target: it takes one job at a time, under the `mac_test.py` claim. A hold names one target. natedev's hold is the build hold (`build_hold.py`); the Mac's hold is the Mac block (`mac_test.py block`). The tools enforce holds themselves: `verify.sh` waits out a natedev hold before any local step, and the BRP launch gate refuses a launch while natedev is held, except for the session whose own hold is the only one in force. `verify.sh test` goes to the first free target it may use, Mac first, and waits when every eligible target is held or full; it never falls back to a held target. A Mac claim whose Mac has run nothing for 15 minutes is released and its holder told, so an idle claim cannot turn tests away for long. `/build:report` counts natedev's steps in its tables and shows the Mac's in a section of its own.

## How it works

### Targets: `config/build_targets.conf` and `scripts/build_targets/target_config.py`

- The config is in the `key=value` form `sweep.config_values` reads. `targets=mac,natedev` lists the targets in the order a job tries them. natedev is `kind.natedev=local`, `platform.natedev=linux`. The Mac is `kind.mac=ssh`, `platform.mac=macos`, `settings.mac=mac_test.conf`; its own settings (host, mirror, size budgets, CI switch, battery and disk floors, `linux_only.<repo>`) stay in `config/mac_test.conf`.
- `target_config.py` imports only `sweep`. It holds `Platform = Literal["linux", "macos"]`, the frozen dataclasses `LocalTarget(name, platform)` and `SshTarget(name, platform, settings: Path)`, `Target = LocalTarget | SshTarget`, `ConfigError(ValueError)` and `read_targets(path=None) -> tuple[Target, ...]`. Target names must be distinct and non-empty; a missing or unsupported `kind`, `platform` or `settings` key, or a settings file that does not exist, is a `ConfigError` naming the key. `BUILD_TARGETS_CONFIG` replaces the path, for tests.
- `targets.py` re-exports those names, so callers import them from one place. `build_hold.py` imports `read_targets` from `target_config` directly; going through `targets` would form the import cycle `build_hold` → `targets` → `build_hold`.
- A future `ssh` target is a new entry plus its own settings file, and it reuses the same runner (probe, copy, run, release). Every `ssh` target today shares the Mac's claim, block and backoff state under `~/.local/state/mac-test`; a second `ssh` machine needs its own coordination storage before it can run beside the Mac.

### Target state and eligibility: `scripts/build_targets/targets.py`

- `target_state(target) -> TargetState` writes nothing and opens no connection. `TargetState = Free | Running(what, since) | Held(holder, reason, since, end: HoldEnd) | Unreachable(reason) | StateUnreadable(reason)`, with `HoldEnd = ExpiresAt(when) | ReleaseEstimated(when) | UntilReleased | AwaitingBlockRemoval`. All are frozen dataclasses.
- natedev is `Held` when `build_hold.read_holders` finds any holder file: `ReleaseEstimated` when the hold carries an eta, else `UntilReleased`. It reads holder files, not the release record, so natedev stays `Held` until the last release turn ends.
- The Mac is `Held` whenever a block record exists (`read_claim_block`, the same reader `claim` uses): `ExpiresAt` before its expiry, `AwaitingBlockRemoval` after it. It is `Running` when `run.json` names a live run (a kept remote claim counts as live), otherwise `Free`.
- `StateUnreadable` carries the `OSError`, `UnicodeError` or `mac_test.StateReadError` text. `Unreachable` comes only from `build_targets.py status --probe`.
- `target_eligibility(repo_root, package, routing: Routing) -> tuple[EligibleTarget | ExcludedTarget, ...]` gives one result per configured target in config order. `Routing = AnyEligibleTarget | LocalRequired(reason)`, with `ANY_ELIGIBLE_TARGET` as the shared value. A `linux` target is always eligible. A `macos` target is excluded with the `LocalRequired` reason under `--local`, with `repo` when the repository is unknown or its settings have no `linux_only.<repo>` key, and with `linux_only` when the package is listed there. Each `ssh` target is judged by its own settings file.

### The target command: `scripts/build_targets/build_targets.py`

Every command decides "held" through `target_state` and reads admission through `build_hold.read_admission`. Exits: 0 free or admitted, 10 held and the call still needs its turn, 12 hold state unreadable (with `verify.sh: natedev's hold state cannot be read (<reason>); not starting.`), 2 a usage or config error.

| Command | Role |
| --- | --- |
| `status [--probe]` | One line per target through `format_state`, in the user's zone: `natedev: free`, `mac: held by <holder> since <HH:MM> until <HH:MM> — <why>`, `release expected <HH:MM>` for an eta, `mac: running <what> since <HH:MM>` (with `, idle since <HH:MM>` while the claim watcher has seen the Mac idle, read from `run.json` through `mac_test.claim_idle_clause` when its `since` matches the state), `<name>: unreachable — <reason>`, `<name>: state unreadable — <error>`. `--probe` adds a read-only `ssh true` per `ssh` target (`offload.probe_reachability`). `/build:targets` runs it. |
| `eligible --repo-root <p> --package <n> [--local <why>]` | One tab-separated line per target: name, `eligible`/`excluded`, reason (`-` when eligible), settings path (`-` for a local target). Errors print `build targets: <error>`, exit 2. |
| `check-admission --call-id <id>` | Never blocks, never registers. Routing and each build step use it. |
| `register-local --call-id <id> --pid <pid>` | Records a call's demand for natedev and returns at once. Prints `verify.sh: natedev is held by <holder> for <reason>.` on exit 10, plus `verify.sh: natedev has been held for 2 h by <holder>; ask them.` once the hold is 2 h old. |
| `wait-local --call-id <id> [--pid <pid>]` | Blocks until natedev is free or the call is released. Prints `verify.sh: natedev is held by <holder> for <why>; waiting (tests that can run on the Mac keep running there).` once, polls every 15 s, prints the 2 h line once and keeps waiting. SIGINT and SIGTERM remove the call and exit 130 and 143. Appends its waited seconds to `BUILDLOG_HOLD_WAIT_FILE`. |
| `check-local` | The launch gate's read. Prints its refusal on stdout. |
| `interrupt-local --call-id <id> [--signal INT\|TERM]` | Signals a running `wait-local` for that call, checked by pid and process-start identity. |
| `finish-local --call-id <id>` | Withdraws a registration named in `BUILDLOG_HOLD_REGISTRATION_FILE`. |

- A call registers one way, `register_local_call(key, call_id, pid) -> build_hold.Admission`: under `build_hold.waiter_key(call_id)`, with the given pid, writing `BUILDLOG_HOLD_REGISTRATION_FILE`. `verify.sh` passes its own pid, so the registration outlives the helper. `--pid` refuses zero or less at argument parsing.
- `record_admission(admission: build_hold.AdmittedTurn)` writes `<cycle id> <generation>` to `BUILDLOG_HOLD_ADMISSION_FILE`. An admitted call keeps its admission for its remaining steps while the set of holders is unchanged, so it never requeues behind another call while it holds its run's cargo token. A holder that joins ends that for steps not yet started.
- `BUILD_TARGETS_POLL_S` and `BUILD_TARGETS_ESCALATE_S` replace the 15 s poll and the 2 h escalation; `BUILD_TARGETS_NOW` replaces the clock. All three are test overrides.

### Holds: `scripts/build_hold/build_hold.py`

- `build_hold.py hold|release [--target <name>]`, default `natedev`. `--target` is parsed by `parse_hold_target` into `HoldTarget = NatedevHoldTarget | MacHoldTarget | UnknownHoldTarget(name, configured) | UncheckedHoldTarget(name, reason)`. Only a name other than `natedev` or `mac` reads the config: a readable one answers `unknown target <name>; configured targets: <list>`, an unreadable one (`ConfigError` or `UnicodeError`) answers `unknown target <name>; the target config cannot be read: <reason>`; both exit 2 before any lookup or record.
- `--target mac` forwards to `mac_test.py block --holder <name> --for <why>` or `unblock --holder <name>` (`run_mac_hold`, `MacHoldResult(status, stdout, stderr)`, `print_mac_hold_result`) and passes the child's output and status through unchanged. It writes no natedev record or event. `--release-eta`, `--zone` and `--resume` print `<option> is not supported with --target mac`, exit 2. `release_mac_hold` survives a session rename: on `blocked by <name>` naming the caller's given or former name (`formerNames` in the live session registry), it retries `unblock` once with that name.
- A natedev hold file is named by its holder's Claude session id (`holder_of`, `HolderIdentity(key, name)`); a holder that is no live session keeps its given name as the key. The hold notice is `natedev is held for <why>. verify.sh waits by itself; an app launch is refused until the release, so launch again after it. Tests that can run on the Mac keep running there. Stop only cargo you started outside verify.sh. No release after 2 h: ask me.` Recipients take no action.
- `natedev_holds(directory) -> NatedevHolds(in_force, releasing)` reads holder files once, reads no release record when there are none, and otherwise splits them through `live_holds`: a holder file is in force unless a `cycle["holders"]` entry that maps to its file name (through `holder_path(directory, key).name`) has the same `since` and a `released_at`.
- Holder files, the hold cycle, release states, the CLI table and recorded hold intervals are covered in [build-memory-admission.md](build-memory-admission.md) under "Build hold". The Mac block, its CI switch and its free message are in [mac-test-offload.md](mac-test-offload.md).

### Admission while natedev is held

- `owning_session() -> OwningSession(session_id) | NoOwningSession` names the session a call's build is credited to: the session whose active-run marker under `/tmp/claude/delegate/active` (`PLAN_DELEGATE_ACTIVE_DIR`) holds the call's run (`PLAN_DELEGATE_BOARD_DIR`, else `PLAN_DELEGATE_SESSION_DIR`, compared as an exact string, newest marker first), else `CLAUDE_CODE_SESSION_ID`, else none. The marker comes first because a Codex worker's shell carries the id of the session that started its Codex server, and that id goes stale when the session restarts. `waiter_key(call_id)` is that session id, else `verify:<call id>`.
- `read_admission(key, call_id="") -> NoCycle | AwaitingTurn | AdmittedTurn | AdmissionReadError` is the one admission read. A changed holder signature answers `AwaitingTurn` for the next generation; otherwise it returns `turn_answer(cycle, key, call_id)`, which reads no file and takes no lock. `register_wait` chooses its line from the same function, so what a key is told and what it is answered cannot differ.
- The release record is grouped by session key. `ReleaseEntry` carries `calls` (`PendingCall`: call id, pid, process start, admitted generation), `active_call_id`, `session_pending`, `session_admitted_generation` and `delivery: GenerationDelivery`; `HoldCycle` carries `release_started_at`, `holder_generation` and `holder_signature`. The driver drops a pending call whose process is gone or whose pid was reused.
- `release_started_at` closes the queue. `release_cycle` sets it when the last holder releases; a holder that joins clears it and raises the generation. What was waiting at that instant (pending calls of an earlier generation, entries with `session_pending`, told sessions not yet sent their release) gets one turn each, and the release ends. A build or launch arriving later starts at once through the memory gate alone: `turn_answer` gives it `AdmittedTurn`, it registers nothing, and it still gets its admission file. The one exception is a call from a session whose turn is open (`open_turn`: not a `verify:` key, no active call, delivery of the current generation, state `ReleasedAwaitingAdmission` or `DeliveryQueued`); that call takes the open turn and its gate mark ends it.
- Every session the hold told is released, registered or not. A silent turn with no bound call ends after `RELEASE_SETTLE_S` (60 s) while another entry is `AwaitingRelease`, else after `NO_ADMISSION_ACK_S` (900 s); a bound call keeps 900 s. At each 15 s poll an unbound turn whose session is gone (`socket_for` answers `RecipientGone`) ends at once. The final line names sessions not reached: ` Not reached, tell them yourself: <name> (session gone | send failed | queued, no answer)`.
- A running release stops when its own holder places a new hold. `release_cycle` keeps the holder file's `since` from its first pass and checks it under `release.lock` before each later pass: a changed `since` returns `release stopped: <holder> placed a new hold at <HH:MM TZ>; that hold's release serves the sessions still waiting.`; a removed file returns `release ended: another release command finished it; ...`. Neither writes anything. `release --resume` refuses while any hold is in force.
- The full driver, its states, turn limits and lines are in [build-memory-admission.md](build-memory-admission.md) ("Release driver").

### Where a job runs: `scripts/delegate/verify.sh`

- check, clippy, lint, doc, `example` and `final` run on natedev only. Only `test` routes.
- `route_test` runs after the per-call wait files and cleanup trap exist, and before the per-call `wait-local` and the cargo token. It reads the `eligible` table and records an excluded Mac at once (`BUILDLOG_MAC=declined`, and its reason in `BUILDLOG_MAC_REASON` and `BUILDLOG_LOCAL_REASON` unless `--local` was given), also when `offload.py` is never called. It then visits the eligible targets in config order:
  - natedev: `build_hold_check_admission`. Exit 0 sends the test to natedev with no further routing. Exit 10 or 12 goes on to the next target, so a filtered test can still pass on the Mac when natedev's hold state cannot be read.
  - an `ssh` target: `try_mac_test <settings>` runs `offload.py run --settings <path>`. A `busy` or `blocked` decline puts the target on the retry list. A full pass prints `verify.sh: passed on the Mac (macOS); now confirming on natedev, which is the gate.` and falls through to natedev. A failure exits with the Mac's status. A filtered pass records `passed_filter` and exits 0. A lost run or any other decline ends the Mac tries and the test waits for natedev.
- With a retry list and no admission on natedev, the call waits for whichever frees first. Each pass: `register_routing_demand` (`register-local`), sleep `BUILD_TARGETS_POLL_S` (15 s), then, for each listed Mac target that `mac_test.py free-now` reads as free, `withdraw_local_demand` (`finish-local`) and another try, passing `--last-decline <reason>`. The Mac goes before the next `register-local`, so a Mac that freed wins over a release turn granted during the sleep. Exit 0 from `register-local` sends the test to natedev; admission is read from that exit, never from the holder file. The demand is withdrawn before every Mac attempt: a registration left in place through a Mac run can be granted a release turn nobody uses for 900 s. free-now gates the attempt so that a busy Mac never costs a turn the call holds.
- Leaving for the Mac (`run_local_test`): `MAC_LEAVE_SETTINGS` names a Mac that declined `busy` or `blocked`; a full pass, a lost run or another decline clears it. While it is set, the local `run_nextest` runs with `LINT_QUEUE_LEAVE_HOOK` set to `mac_test.py free-now --settings <path>`. On status 75 (the step left the memory wait before it started; `run_once` removed its `BUILDLOG_HOLD_STARTED_FILE` mark), the call withdraws its local demand, so a hold release moves to the next session, and runs `try_mac_test` with those settings. A failure or a filtered pass ends the call with `BUILDLOG_TARGET=mac`; another `busy` or `blocked` waits locally again with the hook; a full pass, a lost run or another decline runs locally without it. `try_mac_test` restores its caller's INT/TERM/HUP traps, and a filtered Mac pass clears `RUN_KEY` so no pass record is written.
- The waiting lines appear once and again only on change: `register_routing_demand` compares `register-local`'s stderr with the last text shown, and `verify.sh: waiting for the Mac (<reason>) or natedev's release.` repeats only when the Mac's decline reason changes. The Mac prints its own `mac_test: running on the Mac (macOS, host <host>); tree copied in <N> s` once the claim is held and the tree copied; `verify.sh` prints `verify.sh: running on natedev` when tests start locally.
- After routing, every command waits once per call with `wait-local`, then takes the cargo token. A Mac run is never delayed by a natedev hold, because the wait comes after the Mac attempt. A wait-local exit 12 stops the call: a build never starts on hold state nobody can read.
- Per step, `scripts/lint/invoke.sh` `run_once` rechecks the hold after each memory admission: on `check-admission` exit 10 it gives back the memory reservation, waits out the hold and goes through the memory gate again. The recheck runs only for a local `verify.sh` call (a call id, and not `BUILDLOG_CALLER=verify-mac`); the standalone `lint` and the Mac's run keep the memory gate alone.
- Exports for the build log: `BUILDLOG_TARGET` is `mac` from the start of a Mac attempt and for a call that ends there, empty after a decline or a lost run, `natedev` once tests start locally (a Mac pass confirmed on natedev is `natedev` with `BUILDLOG_MAC=passed`). `BUILDLOG_HOLD_WAIT_S` sums every wait a hold caused: routing sleeps, each declined Mac retry's seconds, and `wait-local`'s; memory waits are not counted. `BUILDLOG_MAC_HOLDER` carries a `busy` decline's `holder=` value and is passed on the `record.py call` line, never exported.

### The no-hold shortcut: `scripts/lint/memory_gate.sh`

- `build_hold_nothing_held` returns 0 only when the holder directory (`BUILD_HOLD_DIR`, default `~/.local/state/build-hold`) is a readable, searchable directory with no entry at all (dot files and dangling links count), and the shell expands patterns unfiltered (no `noglob`, `GLOBIGNORE` or `failglob`). `BUILD_HOLD_DIR` set but empty, a missing directory, or any doubt returns 1, and the Python runs.
- `build_hold_wait_local`, `build_hold_check_admission`, `register_routing_demand` and the per-call `wait-local` in `verify.sh` all return through it before starting Python. With nothing held a local call starts no hold-check process anywhere, and an unreadable `config/build_targets.conf` stops only a `test` call (at `eligible`).
- `build_hold_mark` passes `mark --call-id <id>` (plus the cycle id and generation from the admission file) for a local `verify.sh` call; `mark` then marks the key `waiter_key` resolves and binds the mark to that call. With no call id it marks the resolved owner, so a Codex worker's build moves its owning session's entry.

### The launch gate: `scripts/hooks/pre-tool-use-brp-launch-gate.sh`

- The hook sets `CLAUDE_CODE_SESSION_ID` from its input, sources `memory_gate.sh`, clears `BUILDLOG_CALL_ID` and runs `build_targets.py check-local`. A non-zero exit becomes a PreToolUse deny with the printed reason (`natedev is held by <holder> for <why>; launch after the release.`, or the hold-state diagnostic); a denied launch does no memory admission and writes no mark. Otherwise it runs the memory gate and marks `MemoryGateReturned`.
- `command_check_local` admits the launch with no output and no write when `holds_only_own(owner, directory)` is true: a hold is in force and every hold in force carries the caller's key. A second session's hold beside the caller's, a hold placed under a name that is no live session, holds already releasing (these go through `read_admission`), and read errors keep their old answers. When the launch is not admitted and has a session id, it calls `register_wait(key)` before refusing, so a refused session is queued for its turn.

### Installed-script guard: `scripts/build_hold/override_guard.sh` and `override_guard.py`

- An installed script stops with one line on stderr and exit 2 when any of `BUILD_HOLD_DIR`, `BUILD_HOLD_RELEASE_DIR`, `MAC_TEST_STATE_DIR`, `MAC_TEST_CONFIG`, `BUILD_TARGETS_SCRIPT`, `BUILD_TARGETS_CONFIG`, `BUILD_TARGETS_NOW`, `PLAN_DELEGATE_ACTIVE_DIR` is in the environment (an empty value included), or when `HOME` is set and is not the password database's home. A checkout's script runs with them, so tests keep their overrides.
- "Installed" means the same file (device and inode, links followed) as `<home>/.claude/scripts/<fixed path>`, where `<home>` comes from the password database, never from `HOME`. Shell uses `[[ a -ef b ]]`, Python `os.path.samefile`.
- The line: `<file>: <NAME> is set to '<value>'; the installed scripts under <home>/.claude/scripts do not run with it. Unset it and run again.` The shell guard also refuses every script when `HOME` is read-only in the shell.
- `override_guard.sh` is sourced, bash 3.2 syntax, builtins only. `verify.sh` and `memory_gate.sh` source it first, above any line that reads `HOME`, and call `build_override_refusal "${BASH_SOURCE[0]}" <path under scripts/> || exit 2`. Status 2 is also how a PreToolUse hook blocks its tool call, so the launch hook blocks with no code of its own.
- `override_guard.refuse_overrides(Path(__file__), "<dir>/<file>")` is the first statement of `main` in `build_hold.py`, `build_targets.py`, `mac_test.py`, `offload.py`, `audit.py`, `dailies_input.py`, and of `build_hold_active` in `rust_release.py`. `refusal(...) -> OverridesAllowed | OverridesRefused(line)` reads no file when nothing is set.

### The Mac side

The runner, the claim and the block are covered in [mac-test-offload.md](mac-test-offload.md). The parts this feature depends on:

- The probe checks reachability (with the unreachable backoff), battery, the free-disk floor, the block and the claim. It counts no processes: `ProbeSnapshot(power, free_gib, hostname)` has no `procs`, and others' cargo on the Mac no longer turns a test away. `mac_busy` stays in `MacDeclineReason` for old build-log rows.
- `offload.py run --settings <path>` reads that target's settings; `--last-decline busy|blocked` silences a decline line (and the claim's holder output) that repeats the last reason. A failed probe prints `mac_test: could not reach the Mac: <reason>`.
- A lost run keeps the Mac busy until its leftovers are gone. The runner claims with `--remote <host>`; the claim (`RemoteJobClaim`) outlives its process until the printed `mac_exit=<n>` line with a confirmed cleanup marker, or a leftover check that counted no process (`check_leftovers` → `LeftoversEnded | LeftoversRemain(count) | LeftoverCheckFailed(reason)`). A later `claim --remote` takes a kept claim over (exit 13). Leftovers decline `busy`; a failed check declines `unreachable`.
- Every claim, remote or process-bound, starts a claim watcher (`mac_test.py watch-claim`, one at a time under `claim_watch.lock`). Every `claim_poll_seconds` (60) it checks the claim's host over ssh for the user's mirror work, `cargo`, `rustc`, `cargo-nextest` or binaries under a `/target/` path, sending no signal. After `claim_idle_minutes` (15) with none it deletes the unchanged claim and messages the holder's session (`holder_session`) how to claim again. A failed check changes nothing. Details are in [mac-test-offload.md](mac-test-offload.md) ("The idle claim").
- A `busy` decline names its holder: `BusyMacDecline(holder: MacHolder)`, `MacHolder = KnownMacJob(what) | LostRunLeftovers | UnreadableMacHolder`, written as `holder=` in the result file.
- `remote_test_command` sets `MACOSX_DEPLOYMENT_TARGET=14.0` (module constant `MACOSX_DEPLOYMENT_TARGET`), so a test binary that reaches a Swift bridge loads on the Mac. It also sends `BUILDLOG_SENT_TREE_KEY` when `copy_tree_with_key` read the same known tree key before and after the copy, and `LINT_SKIP_SWEEP=1` so the Mac's steps start no detached sweep. After the tests it removes the mirror's `target` folder only when the Mac's free space is below `free_floor_gib` (100 GiB), and keeps it otherwise (`mac_cleanup=kept`); a run that names `--target-dir` skips the cleanup with one line.
- `scripts/production/mac_run.sh` (the showrunner's Mac build) claims without `--remote`, so its claim lapses with its process. It builds hana and each example with `MACOSX_DEPLOYMENT_TARGET=14.0 ~/.cargo/bin/cargo build`, so a build typed in the Mac's clone reuses them. When `git merge-base --is-ancestor <sha> <clone head>` holds, it checks the commit out in one ssh call with no bundle.

### The commands: `commands/build/`

| Command | Script | Role |
| --- | --- | --- |
| `/build:hold` | `build_hold.py` | Hold or release natedev (default) or the Mac (`target mac`), check quiet, show holds. The protocol every holder follows. |
| `/build:mac` | `mac_test.py` | Block, unblock, settle and show the Mac; audit which packages belong on it; claim it for a job of one's own (released after 15 idle minutes). |
| `/build:targets` | `build_targets.py status [--probe]` | Each target's state, read only. |
| `/build:report` | `buildlog report` | The build report: natedev's steps in its tables, the Mac's in its `### Mac` section, natedev's power-profile changes in `### Power profile`; see [build-report-session.md](build-report-session.md) and [build-followups.md](build-followups.md). |
| `/build:mac_report` | `buildlog mac-report` | How often tests finish on the Mac when it is usable. |

Each command shows its script's output unchanged; each script answers in about a second. There are no stubs at the old names `/builds`, `/build_hold` or `/mac_test`.

### What the reports read

- A call row has `target`, `hold_wait_s` and `mac_holder` (index schema 14 and later); older rows read `not recorded` / `holder not recorded`. `record.py hold-event <began|ended> <target> <key> <holder> <reason> <at> [<until>]` writes one row per hold beginning or end, for natedev's holder files and the Mac's block alike, through a detached recorder started after the coordination lock closes. The index's `holds` view pairs them into intervals.
- `scripts/buildlog/holds.py` is the one read of recorded intervals and of what is in force now (`read_current_holds`, from the coordination records, never from `hold_events`). Both reports open with its `Now:` lines.
- `/build:report` splits by host. `mac_outcome.natedev_step_predicate(step="steps")` returns `{step}.host = 'natedev'`, and every step reader in `report.py` takes it: the kind tables, Rebuilds, the lead block's counts, waits, test routing, the caller-host count, the Summary tables, Power profile and Memory pressure (through `memory.instrument_lines` in its unqualified form). With one host left, callers carry no `(host)` suffix. `mac_section` then shows every step with `host <> 'natedev'`, by caller and kind; its layout is in [mac-test-offload.md](mac-test-offload.md) ("Build log and report"). `mac_report.py` reads Mac steps through `is_mac_step`, never through the predicate.
- `mac_outcome.usable_share` is the shared reading of the Mac's usable share: a candidate is a `verify.sh test` call that reached the Mac decision for a package the Mac may run; `blocked`, `backoff`, `unreachable`, `battery`, `disk` and `off` are set aside as "not usable".
- `power_profile_section(connection, day)` emits `### Power profile` directly after the Test builds section. It reads natedev's power profile from the 60 s samples (`samples.power_profile` and `power_profile_since`, [buildlog-memory-stalls.md](buildlog-memory-stalls.md)):
  - `profile_changes(connection) -> list[ProfileChange]` walks natedev's samples with a non-NULL profile in time order and keeps the first sample of each run of one profile as `ProfileChange(at, profile)`, `at` being its `power_profile_since`, else the sample's own `at`. A later sample of the same profile with a newer `power_profile_since` is the daemon rewriting its file, not a change.
  - The section counts only changes before the end of the report day. It opens with `Profile now: <profile>, since <YYYY-MM-DD HH:MM:SS zone>.` for the latest of them. Then, for each change in the 7 days ending at the end of the report day, newest first: `Before <local time> (<previous profile>) vs after (<profile>):`, the earlier side reading `profile not recorded` when no change precedes it.
  - The before window is the 7 days before the change, cut at the previous change; the after window runs to the next change or the end of the report day. `profile_step_durations(connection, start, end)` groups passing natedev steps (`natedev_step_predicate`, `status = 0`, `step <> 'sweep'`, known `duration_s`) by step kind, caller and rebuild class (`rebuild_bin(crates_compiled)`, `—` when NULL).
  - The table is `Kind | Caller | Rebuild | Before runs | Before p50 | After runs | After p50 | Change`: one row per group with runs on both sides, the busiest after side first; Caller is `caller_label`, p50 is `nearest_rank`. Change is `(after − before) / before` as a signed whole percent, shown only with at least `MIN_PROFILE_RUNS` (10) runs on each side, else `—`. Its `Source:` line says load and time of day are not matched.
  - With no shared group the table is replaced by `No step ran with the same kind, caller and rebuild class on both sides.` A latest change older than the 7 days gives only the `Profile now:` line; with no profiled natedev sample the section is omitted.
- Report layouts, the share lists, interval rules and the same-tree comparison are in [mac-test-offload.md](mac-test-offload.md) ("Build log and report", "Hold events and tree evidence").

## Invariants

- Linux stays the gate. A full `verify.sh test` that passed on the Mac still confirms on natedev, and that confirmation waits out a natedev hold. check, clippy, lint, doc, example and final never leave natedev.
- natedev's own limits are unchanged: the memory gate, the cargo token, build-folder turns.
- A job never runs on a held target and never falls back to one. When every eligible target is held or full it waits and says what it is waiting on.
- Code that picks a target counts `StateUnreadable` and `Held(end=AwaitingBlockRemoval)` as not free, and every reader of `TargetState` handles all five cases.
- Admission is read from the release record (`read_admission`), never from the holder file. The holder file stays until the last release turn ends; the shell shortcut and `target_state` both depend on that.
- No command registers a call without blocking except `register-local`, and every registering path ends in that call's gate mark or its `finish-local`. A registration is withdrawn before each Mac attempt.
- A hold nobody releases still escalates after 2 h: the waiter prints the holder and asks the agent to ask them.
- Defaults are "go": no load threshold and no check for others' processes on any target. The claim watcher's activity check counts processes only to release an idle claim, never to turn a test away.
- The scripts keep their arguments and exit codes: `build_hold.py hold|wait|nothing-to-build|mark`, `mac_test.py claim|release|block|unblock|status`, and `build_targets.py`'s 0/10/12/2. `claim` takes no required argument beyond `--pid` and `--what`; `watch-claim` is the claim watcher's own entry point.
- The guard lines stay first in `verify.sh` and `memory_gate.sh`, above every line that reads `HOME` or a listed variable. The guard runs at an entry point, never inside a function that reads a directory: `dailies_input.py` sets `BUILD_HOLD_DIR` in its own process on every run.
- Callers and `override_guard.sh` arrive in one commit: a tree with the callers and without the guard refuses every build. `mac_test.py` and `offload.py` run on the Mac too, so its checkout takes the same commit before the next Mac test.
- `MACOSX_DEPLOYMENT_TARGET` stays at 12.0 or above and follows the value hana's development shell exports on the Mac; `offload.py` and `mac_run.sh` carry the same value.
- A module added to `scripts/build_hold`, `scripts/build_targets`, `scripts/buildlog` or `scripts/lint` shares no name with one in the others: importing `build_hold`, `targets` or `offload` puts several of them on `sys.path`.

## Calibration / gotchas

- Numbers: poll 15 s (`BUILD_TARGETS_POLL_S`, `RELEASE_POLL_S`); escalation 2 h (`BUILD_TARGETS_ESCALATE_S`); silent unbound turn 60 s while another entry waits, 900 s otherwise; settle 60 s; session lookup `LOOKUP_TRIES` 3, `LOOKUP_RETRY_S` 1 s. A release lasts at most the turns owed when it began times about 1,920 s each.
- Cost while a holder file exists: each compiling step of a local call starts Python twice (`wait-local`, then `check-admission`), about 70 ms each. With nothing held, the shell shortcut answers in under 1 ms (it was 210 to 250 ms per call). Importing `build_hold` adds about 9 ms per start, paid only while a holder file exists. The shell guard costs 0.03 ms per call, the Python guard 1.3 microseconds, with nothing set.
- On a machine that never held, the holder directory is missing, so steps keep starting Python until the first hold creates it.
- The launch hook always starts `check-local`; it has no shell shortcut.
- `offload.py` is imported by `targets.py` (every `build_targets.py` command) and by both reports, and it imports `treekey` at module level. A module-level import added there runs in every hold check, launch check and report.
- `BUILDLOG_TARGET` becomes `mac` when a Mac attempt starts, before the claim is decided; it names where the call was when it ended, not proof that tests ran there.
- A session whose call takes the shared turn and then starts a second build of its own can put two builds in that turn.
- Silent told sessions shorten each other's turns: three silent sessions take 1 min, 1 min and 15 min. One silent told session still keeps the holder file up to 15 minutes, though no build waits on it.
- A launch with no session id has the key `""`; during a release it is admitted and the memory gate alone guards it. A hold placed under a name that is no live session keys its file by that name, so no session's launch matches it.
- Cargo a session starts outside `verify.sh` after its turn was cut is not counted.
- `holders_in_force` resolves every release-record holder key through `holder_path`, which raises `ValueError` on a key such as `.`; a new reader of `natedev_holds` catches it, as `holds_only_own` does. `target_state` does not catch `ReleaseRecordReadError`.
- `parse_hold_target` runs as argparse's `type=`, so an exception other than `ConfigError` or `UnicodeError` from `read_targets` prints a traceback. `sweep.config_values` catches only `OSError`, so a non-UTF-8 config reaches the caller as `UnicodeDecodeError`.
- `mac_test.py unblock` matches the stored holder name, not the session id; the rename retry runs at most one extra `unblock`.
- Install rules: change `build_hold.py` on the live machine only while natedev is free and no release runs, because a waiter or driver keeps the code it started with. Install `mac_test.py` and `offload.py` together with no active Mac claim and no old `watch` or waiting `claim` running: the old `live_run` deletes a kept claim.
- The build log carries two Mac host names (`Mac` and `Nates-MacBook-Pro-2023`), so report code selects the Mac as `host <> 'natedev'`, never by one name. The `scripts/buildlog/buildlog` wrapper runs the installed copy; check worktree report code with `~/.claude/scripts/lib/py scripts/buildlog/cli.py` and `BUILDLOG_DIR` on a scratch copy of the log.
- The claim watcher's ssh activity check has a fixed 10 s total limit beside the configurable connect timeout. A live check of worktree claim code runs `mac_test.py` through `~/.claude/scripts/lib/py` with scratch `MAC_TEST_STATE_DIR` and `MAC_TEST_CONFIG`; the installed copy refuses those overrides.
- The leftover check ends every process under the Mac's mirror root, for every repository, a person's shell or editor there included. ssh's exit status proves nothing (Tailscale SSH returns 0 whatever ran); only printed lines are read.
- `MACOSX_DEPLOYMENT_TARGET` was unset because the remote command runs in a non-login ssh shell and the mirror is outside `~/rust`, so direnv never runs there; rustc then links for macOS 11.0. Below 12.0 the SDK records `@rpath/libswift_Concurrency.dylib` and a binary with no rpath aborts at load (exit 104). A changed value costs one rebuild on the Mac (a cold hana build measured 12 min 35 s); nothing in the mirror is deleted by hand.
- Guard limits: a checkout or any other copy of the scripts accepts the variables, so a worker that runs a copy still passes a hold. Report-only programs and variables outside the list (`VERIFY_MAC_RUNNER`, `LINT_CONFIG_READER`, `MAC_TEST_SESSIONS`, `MAC_TEST_SEND`, the `BUILDLOG_HOLD_*` files) are not guarded. A shell caller started through a link outside `scripts/` looks for `override_guard.sh` beside the link and stops with status 2.
- Tests: every fixture that can reach the hold wait needs temporary `BUILD_HOLD_DIR`, `BUILD_HOLD_RELEASE_DIR` and `PLAN_DELEGATE_ACTIVE_DIR` and cleared `BUILDLOG_CALL_ID` and `BUILDLOG_CALLER`; one that reaches the installed scripts through the real `HOME` rewrites the live release record. Run the suites from a worktree, not inside `~/.claude`, where every case that sets a listed variable meets the refusal. A fixture that writes a set `release_started_at` makes every call a late arrival, so a case that waits for a registration never ends. A test that changes `cycle.json` mid-wait writes it whole under `release_lock()` (`change_cycle`), never with `Path.write_text`. A case that reaches a hold-event write sets a temporary `BUILDLOG_DIR` and waits for the detached recorder before checking that no further event was written. The full `scripts/delegate` suite takes about 12.5 minutes and is the only check that a sibling import loads where tests import a module as `scripts.<dir>.<file>`.
- The test stand-in for `mac_run.sh` answers "not an ancestor" when the sha equals the clone head, where git answers "is an ancestor"; the bundle-path cases depend on that.

## Why

- **Targets with their own rules, not one global hold.** natedev and the Mac fail for different reasons and have different capacity. One rule per target lets a natedev timing run hold natedev alone while tests keep reaching the Mac, and a new machine needs only a config entry and a settings file.
- **Enforcement inside the tools.** A broadcast asking every session to stop depended on each agent obeying it and stopped Mac work too. `verify.sh` and the launch gate now wait or refuse by themselves, so the notice needs no action.
- **Mac first, then natedev, never a held target.** The Mac is spare capacity, so it is tried first and natedev keeps its limits for everything else. Falling back to a held target would break the timing run the hold protects.
- **Registration is withdrawn before a Mac attempt, and only `register-local` registers without blocking.** A registration left during a Mac run can be granted a release turn nobody uses for 900 s.
- **The wait comes after the Mac attempt and before the cargo token.** A Mac run is never delayed by a natedev hold, and a call never waits for a hold while holding its run's cargo token.
- **Admission from the record, not the holder file.** The holder file stays through the whole release so the shell shortcut and `target_state` stay correct; the record says who may run.
- **The queue closes when the release begins.** Before, every late call joined the queue and added a turn of at least 60 s; one release ran more than 61 minutes while its queue grew from 3 rows to 6.
- **A silent turn yields after one minute while others wait.** Every turn used to keep 900 s, costing live sessions 15 minutes for each silent session ahead of them. The last silent turn keeps 15 minutes because the release message lets its session build at once. Sending the release to more than one session at a time was ruled out: four sessions once started builds within 73 s of one release.
- **The driver checks its holder file's `since`.** Without it, a new hold's empty `released_at` read as the driver's own release request, and the driver released sessions into the new hold's timing run.
- **The holder may launch its own apps.** A session holding natedev for a timing run needs its own app running; admitting it while another session's hold is also in force would break that session's timing. The hold file's name already is the session id, so no field was added.
- **The guard compares files, not variables.** The installed root comes from the password database, so a worker cannot point the hold check at an empty directory by setting a variable or `HOME`. Tests keep their overrides because a checkout is a different file. Moving installed code to read no variable would have meant moving about 25 test files to per-process copies and adding a Python start to every build step.
- **No process count or load cutoff on the Mac.** The user asked that apps running on the Mac never stop a build, and the count turned tests away whenever anyone built there. The claim already keeps two of our jobs apart, and the default is "go". The kept remote claim and the leftover check replace what the count used to catch after a lost run.
- **An idle claim ends by itself.** Sessions claimed the Mac for their own work and then left the claim with nothing running; on one measured day 340 of 407 usable candidates declined `busy`. The watcher releases on a read-only activity check, never on the leftover check's answer, which kills what it finds, and messages only the holder, the one who can act.
- **The report splits by host.** Mac steps with no recognized caller used to land in natedev's tables and Summary as `unknown (<Mac host>)`, while the offloaded runs appeared nowhere but a p50. Counting natedev alone keeps natedev's timings clean, and the Mac section shows the Mac's runs, times and failures.
- **The deployment target, not an rpath.** One environment word fixes every crate in one place; crates that emit `-Wl,-rpath,/usr/lib/swift` cover only their own binaries.
- **The power-profile comparison keys on the samples, like with like.** Every change the samples show gets a comparison, so no switch needs a hand-kept marker. Rows match step kind, caller and rebuild class so a cold build is never set against an edited-crate rebuild, and Change is withheld below 10 runs a side.
- **One row per hold event, not per hold.** `forget` of one source file would otherwise leave half an interval. In-force state comes from the coordination records only, because an event can be lost.
