---
description: Frame Hana's camera on a stored or ad hoc view over BRP and save a timed screenshot (full window or cropped to the target). Args - shot|views|pose|targets|stats|launch|shutdown ...
---

1. One line launches a test Hana, shoots, and shuts it down. Run it from the Hana worktree; build first (`cargo build -p hana`):

   ```bash
   python3 ~/.claude/scripts/hana_shot/hana_shot.py shot --port 15791 --launch --view home --view log-panel-front --out <scratchpad>/shots --shutdown
   ```

   Take every view you need in one call: repeat `--view`, or `--view all`. Stdout prints one PNG path per shot. Stderr prints the time per phase. Exit 0 means every shot was saved; 1 means a shot failed; 2 means refused; 3 means a screenshot timed out.
2. Pick your own port; port 15702 is the user's Hana and is always refused. `--launch` uses a scratch `XDG_CONFIG_HOME`, waits for "scene revealed" and a frame time under 50 ms, and records the instance. `--shutdown` stops it, prints any panic lines from its log, and deletes the scratch. Use `launch --port N` and `shutdown --port N` alone to keep one Hana open across several calls. Never Save Scene in it.
3. Ad hoc shots: `shot --port N --target <selector> [--mode fit|pose|hana-frame|home] [--yaw R --pitch R --margin 0.1] [--crop entity --padding 8] [--window 1280x720] [--settle N] [--setup <hana command>]`. A `--window` size, or a stored view's `window`, is logical; the PNG is that size times Hana's scale (2560x1440 for 1280x720 at 2x). Selectors: `name:<Name>`, `marker:<type path>`, `tool:<Kind>[#n]` (such as `tool:Grayscale`, numbered by tool id from 1), `entity:<id>` (this call only). `targets --port N` lists what resolves now. `pose get|set --port N` reads or sets the orbit pose; `set` changes only the values you pass.
4. Modes: `fit` frames the target from yaw and pitch (world radians; yaw 0 faces +Z, π shows a tool's back). `pose` sets focus, yaw, pitch and radius. `hana-frame` is Hana's own F framing. `home` lands on Hana's home pose in one frame (the script zeroes its 2 s animation for the move, then restores it). `--crop entity` crops to the target: extras crops an entity with its own Aabb; for a hierarchy such as a tool, the script projects the visible meshes the fit measures and crops with extras' `rect` when it has one, else with `magick`.
5. Views live in the Hana repo at `crates/hana/brp_views.toml`, so each branch has its own. `views list`, `views show <name>`, `views add <name> --target <selector> [--from-current --port N]` (reads yaw and pitch from the live camera and solves the margin that matches its distance; `--mode pose` stores the pose), `views check --port N [--launch --shutdown]` (each view must resolve to one entity, its fit must not be rejected, its shot must not be black, its crop must not be empty; passes stamp `verified`). Run `views check` in a phase's smoke when the scene changed, and commit the stamped file with the phase. `--view all` shoots every view.
6. Each `shot` call, including `--view all`, appends one JSON line to `~/.cache/hana-shot/timings.jsonl`; `views check` does the same after its black-image and empty-crop checks. Ctrl-C, SIGTERM and SIGHUP end the run with exit code 128 plus the signal number, which this timing line records. The invocation has `status` (`success` or `failure`), integer `exit_code`, and `failure_reason` on failure. `session` is `{"state":"present","value":"..."}` when `CODEX_THREAD_ID` or `CLAUDE_CODE_SESSION_ID` is set, otherwise `{"state":"absent"}`. `CODEX_THREAD_ID` comes first because a Codex seat can inherit another agent's Claude session ID. `attempts` is an ordered array of views; each has `status`, `label`, `view` (string or null), and `image_paths` (array of absolute PNG paths, possibly empty). Each successful attempt also has its own sha, port, target, mode, crop, window, frame time, phase times, frame count and image size; failed attempts have `failure_reason`. A failed attempt lists an image only when its file was written after that attempt began, so an older file at `--out` is excluded. A successful invocation retains the last view's prior top-level timing fields for older readers. `stats [--since 2026-10-01]` counts each successful attempt on new lines and each old-format success line once, then prints medians per mode and crop plus failure counts by reason. Failure reasons are `timeout` (BRP did not answer), `already_in_progress` (capture stayed busy), `black_capture` (check found a black shot), `empty_crop` (crop failed its check or was off screen), `no_app` (Hana did not answer or exited), `invalid_request` (arguments or view refused), `no_target` (target resolved to zero or several entities), `invalid_png` (capture was not PNG), `copy_failed` (remote copy failed), `brp_error` (other BRP error), and `shot_failed` (other shot failure). If the timing file cannot be written, the call keeps its own exit code and prints one warning on stderr. Without `--out`, shots go to `~/.cache/hana-shot/shots/`, pruned after 7 days or past 1 GiB.
7. Rules the script keeps: target ids are re-read on every call; a screenshot refused as "already in progress" is resent a frame later; a screenshot that times out is never resent (a late capture can crash Hana); every capture writes a unique staging name. Never use `world.observe+watch` on Hana's animation events by hand: `AnimationEnd` fails to serialize and bevy_remote 0.19.1 panics, which kills Hana.
8. Mac: a hidden window captures black. On macOS the script temporarily sets the window level to AlwaysOnTop and runs `caffeinate -u` before the first shot; success, failure, Ctrl-C, SIGTERM and SIGHUP put the level back and end the keep-awake. Signal exits use 128 plus the signal number. A stale AlwaysOnTop is repaired to Normal. Keep the display awake. macOS ignores `XDG_CONFIG_HOME`, so a launched Hana reads your real config there.
9. A Hana on the Mac, shot from here: add `--remote natemccoy@mac` to `shot` or `views check`, with `--port` set to the local end of the ssh tunnel to its BRP port; each shot is copied back with scp, and on a macOS host the script raises the window to AlwaysOnTop, puts the level back to what it was when the run ends, and keeps the display awake until then. `--launch` and `--shutdown` are refused with `--remote`.
New timing lines include `invocation_kind`: `shot` or `views_check`. A line without it has unknown kind. `views_check` stays outside screenshot episodes.
